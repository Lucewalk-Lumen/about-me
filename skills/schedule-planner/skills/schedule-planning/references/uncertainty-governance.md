# 不确定性治理规范（v4 · 含 A/B 两类事实与交叉路由）

> **适用范围**：方案依赖**外部源材料**（图片 / 截图 / PDF / 表格 / 聊天记录 / 他人转述 / 校历文件）时，或排程需要**日期性质**（节假日 / 调休上班日 / 教学周次）判定时。
> **目标**：**在排程前把"不确定"暴露出来，而不是把它藏进方案里。**
> **唯一放行权**：fact-verifier。

---

## 0. 为什么需要这份规范

真实案例：一份课表截图被单次转写后直接排程，导致——楼名形近读错（乐 / 勤 / 敏 / 博学楼只差一字）、非法值混入（"教学楼"不在校区楼名内）、整格课程漏读（周五 1-2、11-12 节消失）、模糊项未标注直接进方案。错误一路穿透到精力分析与转场评估才被发现。

**根因不是模型能力不足，而是流程缺闸门。**以下规范逐一封堵。

> **v4 补记**：v3 只治理了"材料转写"这一类不确定，却把"某天放不放假"这类**日期性质**的事实交给了排程者自己判定——等于让裁判员兼运动员。v4 把它并入同一套治理：先分域，再核验，交叉处两段串行。

---

## 1. 事实域划分（先分域，再治理）★ v4 新增

| 域 | 回答的问题 | 典型字段 | 判定依据 | 确定性载体 |
|---|---|---|---|---|
| **A 类 · 材料事实** | 排程**对象**是什么？ | 课程名 / 时间 / 地点 / 周次规则 / 教师 / 人员名单 | 双通道独立转写 + diff + 枚举白名单卡控 | 转写稿 + 覆盖率 |
| **B 类 · 日历事实** | 某个**日期**是什么性质？ | 法定假日 / 调休上班日 / 普通周末 / 教学周第 N 周 / 考试周 | 本地数据文件查表 + 置信度分级 + 放行签字 | `data/holidays-<year>.json` 条目编号 |

**总原则**：**按「事实描述的对象」分域，不按「文件格式」分域。**
同一份文件可以同时含两类事实（典型：校历截图既是材料、又含日期断言）→ 走 §7 交叉路由。

**第四条边界**：「事实判定完之后，这天到底放不放假 / 排不排课」是**决策**，不是事实，归 schedule-architect；且它只能引用台账编号，不得自行判定日期性质。

## 2. 六类高频缺陷与对应机制

| # | 缺陷 | 封堵机制 |
|---|---|---|
| 1 | 图像不可直读，转写为单点失败 | 双通道独立转写 + 覆盖率声明（§4） |
| 2 | 相似词无约束（形近字 / 音近名） | 枚举白名单 + 形近卡控（§3） |
| 3 | 一次性转写、无交叉校验 | 通道 A/B diff，差异项强制人工裁决（§4） |
| 4 | 缺置信度标注 | 四级 confidence，low / unknown 一律进待确认（§5） |
| 5 | 缺"先锚定再排程"闸门 | 排程前 Gate，待确认未清零不放行（§6） |
| 6 | 枚举源（地图 / 图例）未当白名单用 | 强制优先提取权威枚举源（§3） |
| 7 | 错误跨阶段放大 | 台账冻结 + 回退重核，禁止就地修正（§8） |
| 8 | **日期性质由排程者自证**（v4 新增） | B 类事实统一归 fact-verifier 查表 + 签字；消费者只引编号（§5.2 / §7） |

## 3. 枚举白名单锚定（治本）

### 3.1 枚举源优先级

1. **官方列表**（教务处课表、系统导出、公示名册）
2. **材料内附的地图 / 图例 / 说明页**（如校区平面图页）——**最常被忽略但极其好用**
3. **已确认的历史台账**
4. **无** → 必须显式声明"无白名单"，全程按 `medium` 及以下处理

### 3.2 三类卡控

- **存在性卡控**：值 ∉ 白名单 → 标红，进待确认（例："教学楼702"）
- **形近卡控**：与白名单某项编辑距离 ≤ 1 → 标黄，强制确认（例：乐 / 勤 / 敏 / 博）
- **空值卡控**：白名单中应出现却未出现的项 → 提示"是否漏读"（例：某栋楼整周无课，可疑）

### 3.3 建立白名单的最小动作

```text
1. 在材料中找"图例 / 地图 / 说明 / 表头 / 代码表"
2. 抽取全部候选值，去重，排序
3. 与用户确认一次："合法楼名是否是这 N 个？"
4. 冻结为白名单，用于全部后续卡控
```

**这一步 30 秒，能省掉后面整轮返工。**

## 4. 双通道独立转写 + diff（A 类）

| 通道 | 方式 | 目的 |
|---|---|---|
| A | 结构化逐格扫读（按行 / 列 / 单元格编号推进） | 保证**覆盖率**，防漏读 |
| B | 语义整体通读（按语义块 / 课程块推进） | 抓上下文与异常标记 |

**硬性要求**

- 两通道**互不看对方结果**，独立完成。
- 必须报告**覆盖率**：已核验格数 / 总格数。低于 100% 必须说明缺了哪些格。
- 图像若无法直读像素（需 OCR 子代理间接转写），**必须显式声明单点失败风险**，且双通道为强制项，不得省略。

**易漏格清单（逐项点名检查）**

- 表格首行 / 末行 / 末列
- 跨页边缘、合并单元格
- 字号异常小的单元格
- 带角标、括号、上下标的附注格
- **周次标记格**：含"单""双""1-9周""18-19周""实验""上机"字样

## 5. 置信度四级

### 5.1 通用分级表

| 级别 | 判定 | 处置 |
|---|---|---|
| `high` | 双通道一致 + 白名单内 + 清晰 | 直接采用 |
| `medium` | 双通道一致但字迹小 / 边缘，或字段无白名单覆盖 | 采用，写入假设声明 |
| `low` | 双通道不一致 / 形近易混 / 不在白名单 | **待确认，用户拍板** |
| `unknown` | 完全不可辨识 | **待确认，禁止猜测填补** |

### 5.2 B 类日历事实分级表 ★ v4 新增

| 情形 | `confidence` | `status` | 处置 |
|---|---|---|---|
| 官方已发布 + 数据文件命中 + 多源一致 | `high` | `official` | 直接采用，参与排程 |
| 官方已发布但仅单源 / 未逐条核验原文 | `medium` | `official` | 采用，写入假设声明 |
| 未官宣（如 2027）+ 多源一致 | `medium` | `predicted` | 写入假设声明，**默认不参与排程** |
| 未官宣 + 来源互斥（如春节三套预测） | `low` / `unknown` | `predicted` | 进待确认清单，用户拍板 |
| **数据文件无命中** | `unknown` | — | **禁止推断**，标注未知，进待确认清单 |
| **校历声明与国家安排冲突** | `low` | — | 进待确认清单，用户三选一（见 §7） |

**B 类硬纪律**

1. **fact-verifier 不手算**：日期性质的查表与调休穿透一律由 `scripts/holiday_lookup.py` 输出，成员只做**分级与放行签字**。
2. **`references/china-calendar-rules.md` 的通用规则已降级为提示口径**，不得作为事实来源推算当年安排。
3. **调休上班日必须穿透**：`make_up_workday` 条目按**工作日**计容量，并显式提示"本周六要上班"。不得被"周末即休息"吞掉。

**严禁**

- 用"看起来合理""大概率是"填补 low / unknown
- 把同类格的值自动推广到未知格（"其他课都单周所以这节也单周"）
- 因为"影响不大"就跳过确认（课表上一个地点错了，就是一次白跑）

## 6. 排程前闸门（Gate）

```text
材料 → 双通道转写 → diff → 白名单校验 → 打置信度
   → 待确认清单 ──非空──> 抛用户（一次性、选择题形式）──> 回填重核
                └──为空──> 放行，台账冻结 → 进入排程
```

**闸门规则**

- 放行权归 fact-verifier，主理人负责把待确认项**一次性集中**抛给用户。
- 最多 2 轮确认；仍残留 `unknown` 时，按最保守方式处理（如提醒中不含该项、方案标注"未知"），并在假设声明中写明。
- **闸门未放行，任何排程类成员不得启动。**

**待确认清单的写法**（决定用户回复率）

- 选择题："周三 3-4 节地点？① 勤学楼702 ② 敏学楼702 ③ 乐学楼702"
- 开放题（反例）："周三那节课在哪？"
- 合并同类项，一次问完，不零敲碎打。

## 7. 交叉路由（校历 vs 国家数据）★ P1 正解，不得简化

> **场景**：用户给的是**校历截图 / 校历 PDF / 教务系统导出**——它既是材料（A 类），又包含日期断言（B 类）。

**两段串行，顺序不可颠倒**：

```text
输入（校历截图）
   |
   +-- 段 1 · A 类材料转写 -- fact-verifier 双通道（逐格扫读 / 语义通读）+ 枚举白名单
   |        产出：校历原文条目（term_start、周次、节假日声明、调休声明）
   |        覆盖率必须声明（已核验格数 / 总格数）
   |
   +-- 段 2 · B 类日历比对 -- 调 scripts/holiday_lookup.py 对 data/holidays-<year>.json 逐条比对
   |        +-- 一致            -> confidence=high, status=official -> 放行
   |        +-- 校历缺 / 数据缺 -> confidence=unknown -> 待确认清单，禁止脑补
   |        +-- 冲突（校历说放假、国家说补班，或反之）
   |                            -> 一律降 confidence=low -> 待确认清单，由用户拍板
   |
   +-- 两段都过 -> 台账冻结 -> 交 schedule-architect 消费（只引用编号）
```

**冲突处置（写死，无自由裁量）**：

| 步骤 | 动作 |
|---|---|
| 1 | 一律降为 `confidence=low`，**禁止成员自行择一** |
| 2 | 进待确认清单，候选固定三项：① 以校历为准 ② 以国家安排为准 ③ 两者都记（分别标注） |
| 3 | 由用户拍板 |
| 4 | 用户回填后更新台账并重新裁决闸门 |

**为何必须这样**：校历是校内权威、国家安排是法定权威，二者冲突时成员**没有任何一方可以单方面裁定**——这不是信息不足，是权限不足。把它降 `low` 交给用户，是唯一不会出错的处理。

**消费侧纪律**：schedule-architect 只能引用台账编号（假期区间 `H-<年份>-xx`、调休上班日 `HM-<年份>-xx`），不得自行应用通用规则推算日期性质。

### 7.1 判定口诀（写死）

> **「先问是不是日子，再问是不是从材料里读出来的；两者都是 → 先转写、后比对，两段都过才放行。」**
