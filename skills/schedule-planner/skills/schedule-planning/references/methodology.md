# 日程规划方法论

> 供 task-decomposer / schedule-architect / review-coach 在各自阶段引用。

## 一、任务拆解（WBS）

1. **以交付物为锚**：一级任务按交付物（报告章节、系统模块、活动环节）划分，不按时间划分。
2. **2 小时定律**：叶子任务预估工时 ≤ 2 小时；超过必须继续拆。
3. **工时估算三法**：
   - 类比估算：参照做过的类似任务
   - 分项估算：拆到最小单元分别估后加总
   - 修正系数：新领域任务 ×1.5，干扰多的环境 ×1.3
4. **优先级（艾森豪威尔矩阵 → P0-P2）**：
   - P0：重要且紧急 / 直接决定交付成败
   - P1：重要不紧急，须主动排入
   - P2：紧急不重要（可委托/压缩）与不重要不紧急（默认不排）
5. **依赖检查**：依赖关系不得成环；关键路径上的任务优先保护时段。

## 二、排程规则

1. **负载上限**：日程负载 ≤ 85%；超出必须预警并给砍量建议。
2. **缓冲设计**：任务间留 10-15 分钟缓冲；每半天至少留 1 个 30 分钟空档吸收溢出。
3. **时间盒（Timebox）**：弹性任务给固定盒而非无限时长，到点即止、未完顺延至下一盒。
4. **三类冲突检测**：
   - 时间重叠：两任务占用同一时段
   - 超载：总工时 > 可用时长 × 85%
   - 依赖倒置：后置任务的排期早于前置任务的完成时间
5. **稳定区/弹性区**：
   - 稳定区（🔒）：固定会议、通勤、专注保护区——变动须用户确认
   - 弹性区（📋）：可移动任务——波动时只在弹性区内调整，避免全表重排（防"过度重排失控"）
6. **重排三原则**：最小变动（只动受影响块）、先问后动（稳定区变动须确认）、留痕（输出变更说明）。

## 三、中国本地化默认值

| 项目 | 默认值 |
|---|---|
| 标准工作时段 | 09:00-12:00, 14:00-18:00 |
| 午休 | 12:00-14:00（不排任务，或只排轻任务） |
| 通勤缓冲 | 早晚各 45 分钟（按用户提供值优先） |
| 单日任务容量 | 6 小时有效工作 × 85% ≈ 5 小时 |

> 法定节假日与调休的**通用口径**见 `references/china-calendar-rules.md`；**某一年的具体放假安排与调休上班日**以 `data/holidays-<year>.json` 为准，由 `scripts/holiday_lookup.py` 查表、fact-verifier 分级签字后放行。通用规则不得作为事实来源直接推算。

## 四、复盘方法

1. **双口径完成率**：任务数口径 + 工时口径；P0 任务完成率必须单列。
2. **四类偏差归因**：
   - 计划过载：总负载长期 > 100%
   - 估算失真：单项实际工时持续超出估算 30% 以上
   - 外部打断：插队任务/临时会议挤占
   - 动力缺失：无外部约束的任务持续顺延
3. **迭代策略映射**：
   - 过载 → 砍 P2、降交付标准、分周滚动
   - 失真 → 新领域任务 ×1.5 系数、加检查点
   - 打断 → 每日预留 1 小时"插队缓冲盒"
   - 动力 → 绑定截止/同伴/奖励，拆小首步
4. **复盘节奏**：日复盘 5 分钟（只记录），周复盘 30 分钟（归因+迭代）。
