# 价值度量方法论（metrics-methodology）

> 适用成员：安档

## 1. 口径声明

本方法论的指标口径**形态中立**：不绑定 IMA/Obsidian/任何单一宿主平台的统计接口。宿主平台导出的数据可作为输入，但指标定义以本文为准。IMA 平台特有口径（调用量/共享库订阅）见 hosts/ima-host.md 特例。

## 2. 四类核心指标

| 类 | 指标 | 口径 |
|---|---|---|
| 存量 | 各池条目数（idea/draft/official/archive） | 统计日快照 |
| 流量 | 区间新增条目数、区间晋级条数 | 按 created/status 变更日志计 |
| 质量 | 巡检发现数（按严重度）、死链数、重复对数 | 消费齐证/苏航当期巡检结论 |
| 成熟度 | 晋级率 = 区间晋级条数 / 期初 idea+draft 存量 | 消费关晋结论，安档不做晋级判定 |

## 3. 健康分（health_score_calc.py）

健康分由脚本闭式计算，维度与权重以脚本 `--help` 输出为准。默认维度（假设估算口径，可用脚本参数调整）：

| 维度 | 默认权重 | 说明 |
|---|---|---|
| 结构健康 | 25% | 目录/索引/链接完整性（死链、孤儿占比） |
| 内容新鲜度 | 25% | 逾期未复核 official 占比、滞留 draft 占比 |
| 质量巡检 | 30% | 高/中严重度发现项扣分 |
| 成熟度分布 | 20% | 四池分布合理性（idea 淤积、official 占比） |

- 报告必须附脚本原始输出，不四舍五入口述。
- 单次得分无意义，趋势才有意义：≥2 个区间数据才出趋势判断。

## 4. 采纳与价值（运营向，可选）

- **采纳漏斗**（团队库适用）：触达 → 查阅 → 引用 → 复用。各层口径由用户库的使用日志定义，本团不提供埋点实现。
- **ROI 切入原则**：优先度量「知识库替人省下的重复劳动」（重复提问减少、新人上手周期），而非内容生产量。产出量是过程指标，不是价值指标。
- **监控频率**：核心指标月度，快照随月度体检出。

## 5. 报告纪律

1. 指标表 + 健康分（脚本输出原文）+ 趋势判断 + 建议，四段固定。
2. 数字必须可复算：注明统计区间、口径、脚本参数。
3. 不临时发明新口径；需新增指标先在本文登记口径再进报告。
4. 趋势判断需 ≥2 个区间；单区间只给快照。
