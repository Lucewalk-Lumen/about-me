# 冷启动能力地图（capacity-map-bootstrap）

> 适用成员：库正（W5 冷启动搭建的蓝图步骤）

## 1. 适用场景

从零搭建一个知识库（个人 vault / 团队库 / 企业文档库），用户说不清该收什么、怎么组织时，用能力地图三步法先把「这个库要支撑什么工作」讲清楚，再落到目录、索引与四池。

> **前置**：本三步法假设目标库**已建好且可访问**。若用户连工具都还没装、库还没建（如未装 Obsidian / 未在 IMA 建库），先做环境就绪——见 `environment-setup.md`，环境就绪后再回到这里。

## 2. 三步法

### 第一步：工作地图

列出这个库要支撑的真实工作场景：谁、在什么任务里、会查/会写什么样的内容。产出 5-10 条场景清单，每条写明「场景 → 需要的知识类型」。

### 第二步：技能地图

把每条场景映射到八域能力的子集：这个库侧重采集（资料多而杂）还是问答（查询高频）？需要严格晋级门禁（对外复用）还是轻量流转（个人草稿）？产出「域 × 重视度」表（高/中/低）。

### 第三步：融合成蓝图

由技能地图推出落地配置：
- 目录体系建议（交林归类设计）
- 初始 MOC 骨架（交苏航搭建）
- 四池与门槛档位（交关晋设定；对外复用型库建议严格档）
- 巡检节奏建议（周/双周/月的启动频率）

## 3. 蓝图交付结构（W5 终产物）

1. 工作地图（场景清单）
2. 技能地图（域 × 重视度）
3. 目录体系方案（林归类产出）
4. 初始 MOC（苏航产出）
5. 四池门槛配置（关晋产出）
6. 巡检与度量节奏（库正汇总）

## 4. 纪律

- 蓝图每一格都要能指回某个真实工作场景，不做「先建全套体系再找用途」。
- 冷启动第一原则：**先有 10 条真实内容再谈体系**——空库不做重型分类设计，先走 W4 采集入库把种子内容收进来。
- ROI 切入：优先支撑「重复劳动最重」的场景，不平均用力。
