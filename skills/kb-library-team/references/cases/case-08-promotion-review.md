# case-08：成熟度晋级评审（四池门槛 + 逐条确认）

> 场景分类：成熟度晋级 ｜ 涉及成员：关晋（主）、安档、苏航、库正 ｜ 对应 Workflow：W6

## 1. 场景

用户的库跑了一段时间，idea / draft 池里积了一批条目，部分已具备升级条件。用户想做一次周期性晋级评审：哪些 idea 够格升 draft、哪些 draft 够格升 official，要求逐条给出门槛核对结论、用户逐条确认后才执行；晋级后要登记日志并同步索引状态。

## 2. 前置条件

- 库形态：已按四池（idea/draft/official/archive）组织，条目带 frontmatter 元数据基线（created/updated/source/status）。
- 用户需准备：评审范围（指定池 / 指定主题 / 全库）；评审周期（默认月度）。
- 门槛判据：以 `$PKG_ROOT/skills/kb-governance-playbook/references/four-pool-maturity.md` 的门槛条目为准（idea→draft 5 条、draft→official 8 条）。

## 3. 指令示例

> 帮我把这季度的 idea 和 draft 做一次晋级评审：每条给门槛核对结论，我逐条确认后再晋级；晋级完登记日志并更新索引状态。

## 4. 预期产出

- 关晋产出：晋级评审报告（候选清单 × 门槛核对 × 逐条〔够格/不够格/待补〕结论），门槛预检数字以 `promotion_gate_check.py` 输出为准。
- 确认断点：每条晋级执行前用户逐条确认，关晋不越权直接晋级。
- 安档产出：晋级日志（只追加格式，登记条目/原档位/新档位/时间/评审人）。
- 苏航产出：索引状态同步（条目在四池间的落位变化反映到 MOC）。
- 模板：晋级评审报告按 `$PKG_ROOT/skills/kb-governance-playbook/templates/maturity-review-report.md`。

## 5. 涉及成员与分工

| 成员 | 本案例中的职责 | 产出 |
|---|---|---|
| 库正 | 建团编排、逐条确认断点、信息中转 | 任务单 / 待确认清单 |
| 关晋 | 候选扫描、门槛核对、评审结论（唯一判定者） | 晋级评审报告 |
| 安档 | 晋级日志登记（只追加，不判定） | 晋级日志片段 |
| 苏航 | 索引状态同步 | 索引更新方案 |
