# case-01：300 条混杂笔记的整理归类

> 场景分类：整理归类 ｜ 涉及成员：林归类（主）、齐证、库正 ｜ 对应 Workflow：W1

## 1. 场景

一位用户的笔记库积累了约 300 条笔记（假设估算，处于「约 500 条内单次可扫」黄金窗口内的典型规模），全部堆在根目录，没有文件夹。内容横跨工作项目、学习资料、灵感碎片，找东西全靠全文搜索。用户希望建立一个可持续的分类体系，而不是一次性收拾完又乱回去。

## 2. 前置条件

- 库形态：单库、根目录扁平堆放、无既有文件夹（对应完整模式触发条件：已有文件夹 == 0）。
- 用户需准备：库根路径；偏好声明（保留现有命名习惯 / 允许重构）；分类轴倾向（主题 / PARA / 四阶段，可交由团队论证）。

## 3. 指令示例

> 我的笔记库根目录堆了约 300 条笔记，完全没分类。帮我扫描现状，设计一套分类体系，给我 2-3 个方案选一个，然后出映射表，我逐批确认后再移动。每批不要超过 10 条。

## 4. 预期产出

- 主理人汇总：内容画像（条数/类型分布/高频主题词）→ 候选方案对比 → 映射表 → 分批计划 → 验证报告。
- 关键中间产物：归类映射表（csv 风格：条目 × 旧位置 × 新位置 × 匹配规则）、分批移动计划（每批 ≤10 条）。
- 确认断点（3 处）：①方案选择（2-3 个候选由用户拍板）②归类预览确认（含未匹配条目逐条指定）③逐批移动确认。

## 5. 涉及成员与分工

| 成员 | 本案例中的职责 | 产出 |
|---|---|---|
| 库正 | 建团、任务单下发、三处确认断点把守、汇总 | 任务单 / 汇总报告 / 待确认清单 |
| 林归类 | 扫描现状、方案设计、映射表、分批计划、验证清单 | 分类方案书 + 映射表 + 批量计划 |
| 齐证 | 移动后抽检验证（总数一致性、遗漏项） | 验证结论 |
