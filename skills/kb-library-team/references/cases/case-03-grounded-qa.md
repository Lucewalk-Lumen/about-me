# case-03：基于库的专业问答（引用先行 + 三态标注）

> 场景分类：查询回答 ｜ 涉及成员：齐证（主）、罗采（补充入库）、库正 ｜ 对应 Workflow：W3（可转 W4）

## 1. 场景

用户的库里沉淀了过去一年的项目复盘、方法论和会议记录。用户想问一个综合问题（例如「我们处理这类客户投诉的标准动作是什么」），要求回答必须有据可查：每条结论标出处，库里没有的就明说没有，不允许拿通用知识冒充库内结论。

## 2. 前置条件

- 库形态：有可检索的正式内容；最好已有主题索引（无索引时齐证先做全文定位，并在结果末尾列「建议纳入索引的条目」）。
- 用户需准备：具体问题；检索范围（全库 / 指定主题）。

## 3. 指令示例

> 基于我的知识库回答：我们处理这类客户投诉的标准动作是什么？逐条标注依据来源与置信度；库里没有依据的部分明说，不要编。

## 4. 预期产出

- 齐证产出（固定四段）：相关条目与引用片段 → 缺口说明 → 答案正文（逐段〔已核实〕/〔已综合〕/〔待验证〕标签）→ grounding 三态汇总表 + 整体置信度。
- 含「库内无据」项时：库正提示用户补充入库，用户同意后转 W4，罗采出登记与入库候选清单（确认断点：入库执行前确认）。
- 确认断点：本案例主体为只读问答，无写操作；仅当转入库流程时出现入库确认断点。

## 5. 涉及成员与分工

| 成员 | 本案例中的职责 | 产出 |
|---|---|---|
| 库正 | 轻量直调路由；无据项的补库提示与转 W4 编排 | 路由结论 / 补库建议 |
| 齐证 | 检索定位、引用先行、三态标注、置信度 | 带引用的答案（qa-grounding-template） |
| 罗采 | （转入库时）登记 + 提取 + 护栏校验 | 入库登记表 + 候选清单 |
