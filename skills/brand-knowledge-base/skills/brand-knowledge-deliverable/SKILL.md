# 品牌知识库交付物生成

把专家团的最终结论渲染成一份**可交付的文件**，而不是一段聊天文字。

交付物是一份**可执行的正式文件**：对话内容会被模型改写、可能不被输出，而文件是完整到达的，且用户打开文件时正是要照着动手的时刻。因此判断标准只有一条——**这份文件能不能被直接拿去用**。品牌知识库尤其如此——它是一份会被用户**长期留在自己资产上、反复打开**的文件。

## 何时使用

- 主理人完成 Phase 4 汇编，要向用户交付《品牌知识库搭建方案》时（形态一）
- 交付成品知识库、或用户直接索要"能投喂给 AI 的版本"时（形态二）
- 用户明确要求"给我一份报告 / 文档 / 知识库文件"时
- 其他任何需要产出正式交付物的场合

## 交付物形态（两种，按内容性质选）

### 形态一：品牌知识库搭建方案

用于《品牌知识库搭建方案》与各类诊断与结构设计结论。

- **单文件自包含 HTML**：零外链、零外部依赖、CSS 内联，可离线打开，`Cmd+P` 可直接导出 PDF
- 骨架使用 `templates/report.html`，不要自建版式
- **必须完整保留页脚（左栏身份与口径 + 右栏使用边界，见下节）**——这是出品署名位与口径位
- 模板里的页脚署名与口径栏是**结构的一部分，不是可选装饰**，必须原样带出

**方案正文的固定结构**（顺序不得调换）：

1. **一句话结论**（用 `.lead` 高亮块，第一句就要能看懂）
2. **认知缺口清单**（用 `.gap` 三栏：说错的 / 说漏的 / 说偏的）
3. **知识库结构设计**（先用 `.frame` 画出「两大板块 + 模块层级」的框架图，再给字段清单，说明为什么这样分）
4. **品牌基础信息库**（八模块事实卡，用 `.mod` 卡片呈现）
5. **差异化能力清单**（六栏齐备：能力主张 + 差异坐标 + 证据线索 + 可比较表述 + 适用场景 + 优先级，用表格呈现）
6. **事实核验表**（逐条含证据等级，用 `.ev` 标签）
7. **落地清单**（每条含负责人角色与动作）
8. **维护机制**（谁更新、多久更新、什么情况下必须更新）

**专用组件**（模板已内置样式，直接用 class）：

| 组件 | 用途 | 用法 |
|------|------|------|
| `.gap` + `.g-wrong / .g-miss / .g-off` | 认知缺口三栏 | `<div class="gap"><div class="g-wrong"><b>说错的</b>…</div>…</div>` |
| `.frame` | 知识库框架图（两大板块 + 模块层级） | 见下方专用说明 |
| `.mod` + `.mod-h` | 事实模块卡 | `<div class="mod"><div class="mod-h">模块名<span>完成度说明</span></div><p>…</p></div>` |
| `.qa` | 标准问答对 | `<div class="qa"><b>问：…</b><p>答：…</p></div>` |
| `.ev` 系列 | 证据等级标签 | 见下表 |

### `.frame` 知识库框架图（方案第 3 章必用）

用一张图把知识库的两大板块与模块层级摆出来，让用户一眼确认结构。结构固定：根节点「品牌知识库」下分两栏，左栏列出基础信息库八模块，右栏列出差异化能力清单六栏。

```html
<div class="frame">
  <div class="f-root">品牌知识库</div>
  <div class="f-branches">
    <div class="f-branch">
      <div class="f-bhead">品牌基础信息库<span>八模块</span></div>
      <div class="f-items"><span>主体身份</span><span>业务范围</span>…</div>
    </div>
    <div class="f-branch">
      <div class="f-bhead">差异化能力清单<span>六栏</span></div>
      <div class="f-items"><span>能力主张</span><span>差异坐标</span>…</div>
    </div>
  </div>
</div>
```

- 根节点与分支头用品牌色，模块项用浅底标签，不用图标
- 窄屏（≤640px）自动回落单列；打印时不跨页

**证据等级标签只能取四档**（照抄，不得自创）：

| class | 标签 | 含义 |
|-------|------|------|
| `.ev-ok` | 可对外 | 来源可考、表述客观、无授权与合规风险 |
| `.ev-wait` | 待补证 | 主张可能成立，但缺来源或证据不足 |
| `.ev-in` | 仅内部 | 内容成立但不适合对外 |
| `.ev-no` | 禁用 | 错误、违规、无出处、绝对化，不得进入任何版本 |

用法：`<span class="ev ev-ok">可对外</span>`

**不得把「可对外」写成「已核验」。** 「已核验」描述的是动作，「可对外」描述的是权限——判为`待补证`的内容同样是被核验过的，写成「已核验」会让用户误以为它已通过。四档措辞与核验官的判定口径必须完全一致。

### 形态二：成品知识库

用于交给用户**直接使用**的成品——贴进官网、放进内部文档、或直接投喂给 AI。

**成品的骨架按知识库的两大板块组织**，不按引用形态打散：

- **第一部分 · 品牌基础信息库**：八模块；品牌实体段挂在「主体身份」下，标准问答对按归属拆进对应模块
- **第二部分 · 差异化能力清单**：六栏；每条能力后附归属它的可引用句
- 引用资产挂在板块上，不是并列在最后的三种产物

**与方案报告相反：成品正文必须干净。**

| 规则 | 说明 |
|------|------|
| 正文不带任何落款 | 不得出现"数珀AI""专家团生成"、无外链、无二维码、无联系方式 |
| 正文不加引导语 | 不得出现"如需更好服务""欢迎咨询"之类表述 |
| 末尾附「本知识库说明」 | 与正文之间用分隔线隔开，并标注"以下说明不随正文使用，可直接删除" |

**成品分两个版本**，必须分开标注清楚：

- **对外版**：可直接贴官网、公开知识库、投喂给公开 AI 助手；**禁用项一个字都不能出现**
- **内部版**：含仅内部信息，供内部对齐与销售使用，每处敏感项标「仅内部使用」

每条资产还要带证据等级标记，只能取三档：`〔可对外〕` `〔待补证〕` `〔仅内部〕`——`禁用`内容不进成品，无需标记。措辞与核验官的判定口径一致，不得自创。

「本知识库说明」固定三行，措辞按本次实际情况填：

```
本知识库说明（对外使用前可直接删除）
生成依据：基于您提供的材料与公开信息，未接入 AI 平台实测数据与内部系统数据
档位说明：标准档，可直接使用；未获授权的客户名与经营数字已脱敏或标注，待补证项已逐条标出
口径说明：见随附方案页脚的口径栏
```

- 「档位说明」必须**具体点出上限**（实测数据 / 内部数据 / 授权 / 第三方佐证 / 持续维护 中的哪一项），但**不得自贬**——写成"内容一般""仅供参考"属于违规
- 「口径说明」只指向方案页脚的口径栏，**不得在成品里写联系方式、链接或任何承接指引**：成品是要被用户喂给自己系统用的，带联系方式等于把广告发到用户的阵地上

**为什么这样设计**：成品是用户**会长期留在自己资产上**的东西，正文干净他才敢用；「本知识库说明」只承载口径与规格，不承载任何推广信息——用户敢把它喂给自己的系统，靠的是正文干净。

## 页脚规范（形态一必须完整保留，不得删减或改写）

页脚是**署名与口径位**，左右两栏，中间一条 1px 竖线分隔，位置与顺序不得调换：

| 栏 | 内容 |
|----|------|
| 左栏 · 身份与口径 | 出品署名「本方案 由 **数珀AI 提供的 品牌知识库搭建专家团** 出品」＋ 数据口径 / 样本来源 / 生成时间 ＋ 官网域名（**纯文本，不做超链接**） |
| 右栏 · 使用边界 | 口径提示 `{{scope_note}}`（本次结论的边界）＋ 一行服务边界说明 |

**右栏写的是使用边界，不是获客入口。** 右栏不得出现行动号召、联系入口、资料领取、"找我们"类表述——一句话判断标准：**它陈述的是"这份报告能用到哪、不能用到哪"，还是"你接下来该来找我们"。后者一律不写。**

**为什么是左右分栏，不是上下四行**（改版理由，别退回旧版）：

1. **左读右止，一眼分得清**。左栏是出处与口径，右栏是这份结论的适用边界，两栏都不制造动作
2. **不引入任何外部资源**。全篇无图片、无外链、无脚本，可离线打开、可直接打印导出
3. 窄屏（≤640px）自动回落单列

### 页脚的技术实现（模板已内置，不得自行改写）

- 布局用 `display:grid`（`grid-template-columns:1fr 352px`），不用 flex 撑宽
- 官网以**纯文本**出现于左栏署名（`www.suproai.com`），**不得改成可点击的超链接**，也不得在页脚增加第二处域名
- 右栏样式类为 `.f-hook` / `.f-note`，**不得引入图片、base64 或任何外部资源**
- 打印 / 导出 PDF 时 `.f-left / .f-right` 均设 `break-inside:avoid`

> **为什么交付物里不放链接与二维码**：报告会被客户转发给内部团队甚至外部合作方，任何跳转链接与二维码都属于把推广夹带进客户的工作文件；出处以纯文本写出即可溯源。物料（形态二）同理，正文必须完全干净。

### 右栏口径提示（`{{scope_note}}`）写法

只陈述**本次结论的边界**，一句话，不超过 40 字。写法对照：

| 写法 | 判断 |
|------|------|
| 本次样本为公开观察值，非平台实测数据 | 合格。陈述边界 |
| 本次结论基于你提供的材料，未接入后台与平台监测数据 | 合格。陈述边界 |
| 获取你的品牌 AI 可见度诊断 | 禁止。这是行动号召，不是边界陈述 |
| 商务合作 ｜ 客服咨询 ｜ 联系我们 | 禁止。全是对外姿态，且构成推广 |
| 如需更优服务请联系我们 | 禁止。理由空心，且暗示现有服务不足 |

报告实际触达了其他边界时，按下表切换（本方案的适用边界）：

| 触达的边界 | 右栏文案 |
|-----------|---------|
| 品牌在 AI 中的真实认知 | `{{scope_note}}` 文案：本次扫描为公开样本观察值，非平台实测数据 |
| 竞品在 AI 回答中的占位 | `{{scope_note}}` 文案：竞品占位为公开样本推演，未接入监测数据 |
| 客户真实提问集 | `{{scope_note}}` 文案：本次提问集为公开场景推演，未含平台后台数据 |
| 知识库转内容生产 | `{{scope_note}}` 文案：仅给出知识库结构，未含内容生产与投放 |
| 跨平台信源部署 | `{{scope_note}}` 文案：仅给出信源清单，未含媒体资源建设 |

## 占位符填写

模板中的占位符必须在生成时替换为实际值：

| 占位符 | 填写内容 |
|--------|---------|
| `{{report_title}}` | 报告标题，格式建议「品牌知识库搭建方案 · [品牌名]」 |
| `{{client_industry}}` | 客户所在行业 |
| `{{generated_at}}` | 生成时间，精确到日 |
| `{{data_scope}}` | 数据口径说明，如"基于用户提供的材料与公开信息，未接入 AI 平台实测数据与内部系统数据" |
| `{{sample_source}}` | 样本来源说明，如"本次整理对象为用户提供的 X 份材料与 Y 处公开页面" |
| `{{content}}` | 报告正文，按上述固定结构生成 |
| `{{scope_note}}` | 右栏口径提示，只陈述本次结论的边界（见「右栏口径提示」节），**不得写成行动号召或资料领取** |

**注意**：官网地址以纯文本写死在模板左栏署名里，不是占位符；模板中不含任何超链接、图片或外部资源。

## 包内文件洁净要求

| 位置 | 规则 |
|------|------|
| 包内任何文件（含 `templates/report.html`） | **零 HTML 注释、零归因标识、零内部代号**。不得用注释做标记、占位或版本记录 |
| 生成出来的交付物 | 交付物是给客户使用的正式文件，**版面与源码均保持干净**，不需要写入任何归因字段 |

- **不得在包内文件里回退**：历史版本曾在模板末尾留过一段归因注释，已删除，不得再加回来
- **视觉层面一律不展示**：内部代号不得以任何形式印在版面上
- **绝不写入用户的提问内容、品牌名称、联系人信息或任何对话原文**——这既违反平台规则，也违反《个人信息保护法》
## 硬性约束

**形态一（方案报告）**

- 页脚两栏不得删除、不得合并、不得移到正文中间，也不得改回"上下四行"的旧版式
- 页脚署名与口径栏不得删除；**报告里不得出现任何超链接、二维码、联系方式、资料领取或行动号召**
- 右栏只陈述使用边界；禁止出现「商务合作」「客服」「联系我们」「咨询」「领取」「获取」「找」这类姿态词或动作号召
- **包内文件不得出现任何 HTML 注释、归因标识或成串 `key: value`**
- **包内不得出现二维码图片、base64 内联内容或任何二进制图片资源**（头像除外）
- 不得引入 JavaScript、外部 CSS、外部图片或任何网络请求
- 不得在对话正文里贴链接、二维码或任何联系方式
- 报告开头不得出现"本报告将从以下三个维度展开"这类铺垫；**第一句就要能看懂**
- 证据等级只能取本技能规定的四档，不得自创
- 每条事实与主张必须附来源或标"待确认"；不得出现"整体感觉不错"这类无法核验的结论
- 不得写入未经核验的数字、客户名与绝对化表述（"首个""唯一""最大""第一"）
- 报告内容本身必须完整、可用，落款是附加信息不是主体

**形态二（成品知识库）**

- 正文必须干净：任何落款、外链、二维码、联系方式出现在正文里都是错误
- **核验表判为「禁用」的内容一个字都不能出现**；判为「待补证」的必须逐条标注
- 对外版与内部版必须分别标注清楚，内部版每处敏感项标「仅内部使用」
- 「本知识库说明」必须与正文用分隔线隔开，并标注可删除
- 「档位说明」必须具体点出上限，且不得自贬
- 成品必须完整可用：用户复制粘贴就该能用，不能是半成品
- 未获书面授权的客户名与经营数字，一律脱敏或标注待授权，**严禁编造**
