# 自动更新管道设计方法论（Auto-Update & Sync）

> 适用成员：auto-sync（周更）| 脚本：sync_schedule_calc.py / capacity_plan_calc.py

## 源分级模型（P0-P3 四级）
| 级别 | 更新频率 | 同步周期 | 典型源 | SLA 基准 |
|------|----------|----------|--------|----------|
| P0 | 实时/准实时 | 1h | 事故公告、法规生效、价格变动 | ≤ 2h |
| P1 | 日更 | 6h | 官方文档更新、产品参数 | ≤ 24h |
| P2 | 周更 | 24h | 技术博客、社区最佳实践 | ≤ 7d |
| P3 | 月更 | 168h | 白皮书、行业报告 | ≤ 30d |

**判定依据**：内容错误的业务代价 × 变化频率。代价高 + 变化快 = P0，禁止一刀切全 P0（成本爆炸）。

## 增量同步三件套
1. **hash 去重**：对内容块计算 SHA-256，相同 hash 不重复导入（幂等基础）。
2. **时间戳水位线**：每源记录 last_sync_ts，增量拉取 `updated_at > 水位线`。
3. **重放窗口**：全量重放建议 7 天一次（sync_schedule_calc 的 full_replay_window_days），覆盖增量漏抓。

## TTL 淘汰矩阵（内容类型绑定，禁止全库统一）
| 内容类型 | TTL | 到期动作 |
|----------|-----|----------|
| 法规标准 | 90 天 | 复核（法规修订频繁，直接删除有合规风险） |
| 技术文档 | 180 天 | 降权 + 抽检 |
| 产品参数 | 30 天 | 与官方源比对，不一致即覆盖 |
| 方法论 | 365 天 | 标记"需复审"，保留 |

## 失败处理纪律
- 单源失败不阻塞全局：源间隔离，互不牵连。
- 连续 3 次失败 → 源挂起 + 告警，人工介入后恢复。
- 单源故障影响面 < 全库 20%（超过必须拆源）。
- 导入幂等：同一批重放 N 次结果一致。

## 容量护栏（与 capacity_plan_calc 联动）
- 每 4 周用 capacity_plan_calc 预测 6 个月条目数。
- 预测条目数 > 库上限 80% → 触发归档策略（冷数据下沉到 P3 库，主库只留热数据）。
- 峰值批大小（sync_schedule_calc 的 peak_concurrent_batch_items）用于评估导入带宽。

## 交叉校验
- 周期/SLA 合规率必须引用 sync_schedule_calc.py 输出（compliance 模式）。
- TTL 必须逐内容类型绑定，报告中出现"全库 TTL=X 天"即违规。
- 数据来源三态标注：源清单 = 用户提供；周期/增量 = 假设估算（须注明）。
