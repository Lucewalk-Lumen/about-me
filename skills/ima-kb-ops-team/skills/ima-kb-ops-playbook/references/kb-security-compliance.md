# 知识库安全与合规方法论（KB Security & Compliance）

> 适用成员：kb-security（顾护）| 脚本：kb_security_calc.py

## 核心原则
1. **deny-by-default**：默认拒绝一切访问，授权必须显式。任何"默认允许"设计即违规。
2. **分级最小权限**：数据按 公开/内部/受限/机密 四级，权限面随级别收敛。
3. **可溯源审计**：受限/机密级条目的每次访问必须留痕，日志不可篡改。
4. **PII 最小化**：能不存则不存，能脱敏则脱敏，必须明文则加密 + 限期删除。

## 数据分级矩阵
| 级别 | 定义 | 访问面系数 | 审计强度 | 典型内容 |
|------|------|------------|----------|----------|
| 公开 | 对外可披露 | 1.0 | 低 | 产品公开文档、帮助 |
| 内部 | 仅限员工 | 0.5 | 中 | 内部流程、规范 |
| 受限 | 按角色授权 | 0.2 | 高 | 客户数据、经营数据 |
| 机密 | 强管控 | 0.05 | 极高 | 密钥、财务、未公开专利 |

## 权限模型
- 角色 × 级别矩阵，交叉点 = 读/写/管理 三态
- 越权访问（用户角色默认无权）必须走申请 + 审批 + 时限
- 管理员权限分离：内容管理 / 权限管理 / 审计查看 三权分立

## PII 处置策略
| PII 类型 | 默认处置 | 触发删除条件 |
|----------|----------|--------------|
| 直接标识（姓名/证件/手机号） | 脱敏存储 | 业务结束即删 |
| 敏感属性 | 加密存储 | 法定保留期到期 |
| 行为轨迹 | 聚合去标识 | 保留 90 天后匿名化 |

## 风险量化（对应 kb_security_calc.py）
- **暴露面** = Σ(分级条目数 × 访问面系数) / 总条目数（值越高，越多条目向宽面暴露）
- **高危占比** = (受限 + 机密) / 总条目数
- **合规风险分 R** = 100 × (0.5×高危占比 + 0.3×(1−审计覆盖率) + 0.2×PII未处置占比)
  - R ≥ 70 高危（须限期整改）/ 40–69 中 / <40 低
- 三项输入：分级条目数（用户提供）、审计覆盖率（有来源）、PII 未处置占比（用户提供/估算）

## 交叉校验
- 权限矩阵出现"默认允许" → 违规
- 受限/机密条目审计覆盖率 < 100% → 高危，必须补日志
- PII 条目无处置策略 → 高危
- 风险分必须引用 kb_security_calc.py 输出，禁止手写
- 报告落款标注三态
