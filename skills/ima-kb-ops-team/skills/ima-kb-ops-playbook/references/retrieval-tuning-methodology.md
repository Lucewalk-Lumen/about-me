# 检索调优方法论（Retrieval Tuning）

> 适用成员：retrieval-tuner（寻微）| 脚本：retrieval_metrics_calc.py / retrieval_tuning_calc.py

## 调优铁律（违反即回退）
1. **单变量**：一轮只改一个维度（分块 / 嵌入 / Top-K / rerank），否则无法归因。
2. **同集重测**：调优前后必须用同一组 bad-case（≥10 条）重测，口径不可变。
3. **延迟护栏**：P99 延迟超 SLA → 该候选直接判否，不允许"先上后调"。
4. **指标说话**：所有结论必须引用 retrieval_metrics_calc.py 输出，禁止手写估算。

## 四个调优维度

### 1. 分块粒度（chunk size）
| 候选 | 适用 | 影响 |
|------|------|------|
| 200 token | 问答对、FAQ | Recall 高，Precision 易碎（上下文短） |
| 500 token | 技术文档默认值 | 均衡 |
| 800 token | 长论述、法规条文 | 完整性好，但易稀释关键句 |

- 标题驱动 > 语义分块 > 固定长度（有标题结构时优先）。
- 改 chunk 必须先重算 K_max（retrieval_tuning_calc 的 kmax 模式），否则 Top-K 会超出上下文窗口。

### 2. 嵌入策略
- 通用嵌入适合冷启动；领域词占比 > 30% 时评估领域微调（成本另计，标注假设）。
- 混合检索（向量 + BM25 关键词）对"型号/专有名词"类查询提升最大，纯语义检索对这类查询 MRR 普遍偏低。

### 3. Top-K 选择
- K 必须 ≤ K_max（上下文预算约束，retrieval_tuning_calc 的 kmax 模式）。
- P@K 随 K 衰减曲线（curve 模式）：K 超过相关文档数后 P@K 必然下降，收益全在 Recall。
- 上下文占用率（occupancy）> 70% 时预留给 rerank 与指令的空间不足，考虑降 K。

### 4. 相关性反馈闭环
- bad-case → 标注"该返回哪条" → 进入回归测试集。
- 每 4 周用回归测试集重测一次，指标回退 > 5% 触发回滚（联动 version-manager 快照）。
- reranker 上线前先在离线集对比 NDCG@5，提升 < 3% 不值得其延迟开销。

## 通过/回退准则（默认值，可按 SLA 调整）
| 指标 | 通过 | 回退 |
|------|------|------|
| MRR | 提升 ≥ 10% | 任何回退 |
| NDCG@5 | 提升 ≥ 5% | 任何回退 |
| Recall@5 | 提升 ≥ 5% | 下降 > 3% |
| P99 延迟 | 不超 SLA | 超 SLA 直接回退 |

## 交叉校验
- 调优方案必须含"假设表 + 单变量实验设计 + 同一 bad-case 集前后重测"三件套。
- 报告落款标注"有来源/用户提供/假设估算"三态。
