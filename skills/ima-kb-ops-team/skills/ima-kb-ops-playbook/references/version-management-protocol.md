# 版本管理协议

## 1. 语义化版本号规范

**格式**：`主版本.次版本.修订号`（x.y.z）

| 段位 | 递进条件 | 示例 |
|------|----------|------|
| 主版本（x） | 重大内容重构、架构变更、不兼容的API修改 | 1.x.x → 2.0.0 |
| 次版本（y） | 新增内容模块、功能增强、向后兼容的变更 | 1.0.x → 1.1.0 |
| 修订号（z） | 错误修正、内容微调、拼写/格式修复 | 1.0.0 → 1.0.1 |

**初始版本**：1.0.0

## 2. 变更分类与记录

| 变更类型 | 描述 | 版本影响 |
|----------|------|----------|
| 新增内容 | 新增知识库条目或 Skill | +次版本 |
| 内容更新 | 更新现有条目内容 | +修订号 |
| 内容删除 | 删除过时/错误条目 | +修订号 |
| 结构变更 | 调整文件夹体系或标签 | +主版本 |
| Skill 更新 | 修改 Skill 配置 | +次版本 |
| 安全修复 | 修复数据泄露等安全问题 | +修订号 |

**变更记录模板**：
```
## v1.2.0 (2024-01-15)
- 新增：永磁电机热管理章节
- 更新：电磁设计章节（更新2024版标准）
- 修复：修正绕组系数计算公式错误
```

## 3. 快照机制

**触发条件**：
- 主版本发布前
- 重大内容调整前
- 定期快照（建议每月一次）

**快照内容**：
- 完整知识库结构（文件夹树）
- 条目清单（标题、来源、日期、版本）
- Skill 配置包（SKILL.md + references + templates）
- 质量审计报告

**存储方式**：
- 独立文件夹：`snapshots/v1.0.0/`
- 导出备份：`snapshots/v1.0.0-backup.zip`

## 4. 回滚流程

**回滚触发条件**：
- 内容错误率 >5%
- 用户投诉 >10 次/周
- 检索命中率下降 >20%

**回滚步骤**：
1. 确认回滚目标版本
2. 恢复快照（结构 + 条目 + 配置）
3. 验证内容完整性（条目数、标签覆盖率）
4. 通知相关方（内容团队、运营团队）
5. 记录回滚原因与处理过程

## 5. 版本兼容性矩阵

| 版本 | 兼容性 | 说明 |
|------|--------|------|
| v1.0 | 完全兼容 | 初始版本 |
| v1.1 | 向后兼容 | 新增内容，不影响现有 Skill |
| v2.0 | 需升级 | 架构变更，Skill 需适配 |
| v2.1 | 向后兼容 | 内容增强，Skill 可正常使用 |
