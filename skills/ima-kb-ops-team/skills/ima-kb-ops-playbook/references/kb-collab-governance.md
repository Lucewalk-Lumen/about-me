# 共享知识库协作治理方法论（KB Collaboration Governance）

> 适用成员：kb-collab（众协）| 脚本：collab_conflict_calc.py
> 平台前提：腾讯 ima 支持个人知识库（仅自己）与共享知识库（可邀请成员协作）

## 形态判定
| 形态 | 适用 | 限制 |
|------|------|------|
| 个人知识库 | 仅自己使用 | 不可协作 |
| 共享知识库 | 团队共同资料 | 需权限矩阵 + 冲突治理；**涉密源禁止共享** |

**裁决**：成员 >1 且需协作 → 共享库；含 restricted/confidential 源 → 触发 kb-security 联合门禁，共享形态直接否决。

## 最小权限原则
默认全员**只读问答**（基于知识库问答使用），写权限按角色白名单逐级放开：

| 操作 | 问答使用 | 导入 | 编辑 | 删除 | 邀请 | 库管理 |
|------|---------|------|------|------|------|--------|
| 只读成员 | ✓ | | | | | |
| 内容编辑 | ✓ | ✓ | ✓ | | | |
| 管理员 | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |

权限覆盖 = 已授权操作 / 应授权操作（最小权限基线），过度授权要收敛。

## 冲突模型（collab_conflict_calc.py 闭式）
- **单次变更冲突概率 = (1 − 1/角色数) × 同主题重叠率**
  - 角色数≥2 才可能冲突；重叠率 0-1
- 月冲突数 = 月变更量 × 冲突概率
- 冲突等级：低(<5%) / 中(5-15%) / 高(>15%)
- 月评审工时 = 月冲突数 × 单条分钟 / 60
- 评审缺口 = max(0, 评审工时 − 评审人数×人均可用工时)，缺口 >0 需分级评审

## 同名条目归属（必须显式二选一，禁止沉默）
- **先到优先**：先入库的为准，后到的标"同源引用"
- **权威源优先**：官方/权威来源覆盖个人来源

## 变更规范（与 version-manager 对接）
- 变更日志字段：who / what / when / which_entry / 影响面
- 回滚锚点：每次共享库结构性变更打一个可回滚版本

## 交叉校验
- 涉密源必须触发 kb-security 门禁，共享形态否决
- 权限矩阵最小权限，默认只读
- 冲突率/评审负载引用 collab_conflict_calc.py，禁止拍脑袋
- 同名归属必须显式规则，禁止沉默
- 报告落款三态标注
