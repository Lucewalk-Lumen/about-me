# 知识库规划方法论

## 1. 知识库拆分决策树

```
开始
│
├── 单领域内容量 < 500条？
│    ├── 是 → 单知识库
│    └── 否 → 继续判断
│
├── 内容更新频率差异大？
│    ├── 是 → 按更新频率拆分
│    └── 否 → 继续判断
│
├── 目标用户群体不同？
│    ├── 是 → 按用户群体拆分
│    └── 否 → 按子领域拆分
│
└── 默认策略：按领域-子领域-主题三级结构
```

## 2. 文件夹命名规范

**格式**：`[领域]-[子领域]-[主题]-[属性]`

| 要素 | 说明 | 示例 |
|------|------|------|
| 领域 | 一级分类，核心业务域 | 永磁电机、新能源汽车 |
| 子领域 | 二级分类，专业方向 | 设计、控制、材料、制造、测试 |
| 主题 | 三级分类，具体主题 | 电磁设计、矢量控制、永磁体 |
| 属性 | 四级分类，内容属性 | 基础理论、仿真分析、代码实现 |

**命名要点**：
- 层级深度 ≤5 级
- 单文件夹条目数 50-200
- 名称即内容描述，消除多义性
- 避免标签歧义（如"Java"既指编程语言也指咖啡）

## 3. 标签体系设计

**三级标签结构**：`领域.主题.属性`

| 标签类型 | 数量 | 示例 |
|----------|------|------|
| 领域标签 | 10-20 | #永磁电机 #新能源汽车 |
| 主题标签 | 30-50 | #电磁设计 #矢量控制 |
| 属性标签 | 20-30 | #基础理论 #计算公式 |

**标签使用原则**：
- 总量控制在 50 个以内
- 建立同义词映射表，统一使用首选词
- 避免标签歧义

## 4. 容量规划指南

| 维度 | 限制 | 说明 |
|------|------|------|
| 知识库数量 | 无明确限制 | 个人账号可创建多个 |
| 单库条目数 | 建议 <10000 | 过多影响检索性能 |
| 单文件大小 | ≤100MB | 大文件需拆分 |
| 单次导入URL数 | 建议 ≤50 | 批量导入需分批 |
| 文件夹层级 | 建议 ≤5 级 | 过深影响检索效率 |

## 5. 常见架构反模式

| 反模式 | 问题 | 正确做法 |
|--------|------|----------|
| 单库堆砌 | 检索精度下降，响应慢 | 按领域拆分知识库 |
| 文件夹过深 | 检索路径复杂 | 控制在 3-5 级 |
| 条目过长 | 分块丢失上下文 | 拆分为逻辑章节 |
| 标签泛滥 | 检索噪声大 | 精简标签体系 |
| 重复条目 | 检索结果冗余 | 去重+版本管理 |
