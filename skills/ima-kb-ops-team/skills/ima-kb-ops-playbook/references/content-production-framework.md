# 内容生产框架

## 1. 分块（Chunk）策略

| 策略 | 块大小 | 适用场景 | 重叠率 |
|------|--------|----------|--------|
| 固定长度 | 500-1000 token | 通用文档 | 20% |
| 语义切分 | 按段落/章节 | 结构化文档 | 0% |
| 滑动窗口 | 重叠20% | 需要上下文连续的场景 | 20% |

**推荐配置**：
- 技术文档：800-1200 token
- 通用内容：500-800 token
- 长文档（>10万字）：按章节拆分

## 2. 元数据标注规范

每个条目必须包含：
- **标题**：含核心关键词，≤50字
- **来源**：原始素材编号/URL/文件名
- **作者**：内容创建者
- **日期**：创建/更新日期（YYYY-MM-DD）
- **版本**：语义化版本号
- **标签**：≥2 个，来自标签体系

## 3. 去重检测流程

```
原始素材 → 格式规范化 → 内容指纹（SimHash/MinHash）→ 相似度计算
│
├── 相似度 ≥85% → 标记为重复，建议合并
├── 相似度 60-84% → 标记为高度相似，人工复核
└── 相似度 <60% → 视为独立条目
```

## 4. 条目组织最佳实践

1. **单文件夹条目数控制**
   - 建议：50-200条
   - 上限：不超过500条
   - 超过阈值时按主题进一步拆分

2. **单条目的内容量控制**
   - 技术文档：5,000-20,000字
   - 论文/报告：按章节拆分
   - 长文档：拆分为逻辑章节

3. **检索友好性**
   - 标题包含关键词
   - 内容有明确主题句
   - 避免过长段落
   - 重要信息前置

## 5. 内容解析状态机

```
MEDIA_INIT        → 初始状态（刚上传）
MEDIA_PARSING     → 解析中（正在处理）
MEDIA_PARSE_SUCCESS → 解析成功（可读取）
MEDIA_PARSE_ERROR   → 解析失败（需重新上传）
MEDIA_PARSE_TIMEOUT → 解析超时（需重新上传）
```

**生产前检查**：确保所有素材处于 `MEDIA_PARSE_SUCCESS` 状态。
