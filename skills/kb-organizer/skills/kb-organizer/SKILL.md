## 〇、专家级路由（v2.0.0）

**专家定位**：把知识库从"一堆散落资源"变成"有条理的知识体系"——扫描判模式→出分类方案→建夹→归类→移动→验证，移动前留原路径、不误删不覆盖。
**五维评估**：
- 适用场景：①无文件夹/需重新分类（完整模式）②根目录散乱（整理模式）③多知识库体系梳理
- 能力边界：不做新建知识库（→ima-knowledge）；不做内容搜索阅读；不做笔记管理；不做单篇文档编辑
- 依赖资产：`references/`（case-library/writing-templates/quality-checklist + marketplace-intro/usage-guide）；平台接口 `get_knowledge_list`（分页 50/次，上限 10 次）、`create_folder`、`move_knowledge`（每批 ≤10）
- 交付质量：分类方案先出供确认；移动前留原路径记录；整理前后总数一致；接口无删除能力，禁删禁覆盖
- 性能表现：约 500 条内单次可扫；大库分批处理
**四级响应（L1-L4）**：
- L1 轻量问答 → 直接答：两大模式与适用
- L2 标准任务 → 扫描 + 模式判定
- L3 复杂任务 → 出方案 + 建夹 + 归类移动
- L4 专家任务 → 完整模式全流程（分析→提案→建夹→归类→移动→验证）
**黄金窗口**：单知识库；>500 条分批；每批移动 ≤10 条。
**专家件索引**：`references/case-library.md`、`references/writing-templates.md`、`references/quality-checklist.md`、`references/marketplace-intro.md`、`references/usage-guide.md`。

# 知识库智能整理大师

## 核心能力

本技能将知识库从"一堆散落资源"变成"有条理的知识体系"。分为两大工作模式：

| 模式 | 适用场景 | 核心流程 |
|------|---------|---------|
| **完整模式** | 知识库无文件夹/需重新分类 | 分析 → 提案 → 建夹 → 归类 → 移动 → 验证 |
| **整理模式** | 有文件夹但根目录散乱 | 扫描 → 归类 → 移动 → 验证 |

> 先通过一次快速扫描判断当前知识库的状态，自动选择模式。

---

## Phase 0：快速扫描与意图对齐

### 第一步：获取知识库基础信息

使用 `search_knowledge_base` 确认 `kb_id` 和基础信息。

### 第二步：扫描根目录

调用 `get_knowledge_list` 获取根目录全部内容。**必须处理分页**——API 单次最多 50 条，`is_end=false` 时用 `next_cursor` 翻页。设定翻页上限 10 次（约 500 条）。

记录以下信息：
- **已有文件夹数**（media_type == 99）
- **散落资源数**（非文件夹条目）
- **资源类型分布**（PDF/公众号/网页/笔记/PPT 等）
- **标题关键词分析**（提取高频词，判断内容主题领域）

### 第三步：判断模式

```python
if 已有文件夹 == 0:
    → 完整模式（需要分析内容、提案分类、建夹、归类）
elif 散落资源数 > 5:
    → 整理模式（归入已有文件夹）
else:
    → 告知用户"根目录已整洁，无需整理"，直接结束
```

并向用户简要说明当前知识库状态和推荐模式，等待确认后继续。

## Phase 1：深度内容画像

### 搜索内容主题

使用 `search(source="kb", kb_id=xxx)` 对知识库进行**内容语义搜索**，用以下查询理解知识库的内容面：

- 搜索"工具 教程 指南"——是否有大量教程类内容
- 搜索"AI 人工智能 智能化"——是否以AI为主题
- 搜索"教学 课堂 教师 学生"——是否涉及教育领域
- 搜索"政策 报告 文件 通知"——是否有政策文件
- 搜索"设计 图片 海报 视频"——是否有创意类素材

> 提示：每次 search 调用消耗 ≈ 扫描 200 条标题，所以优先 scan 标题而非大量 search。

### 统计媒体类型分布

从已获取的 `knowledge_list` 中统计 `media_type` 分布：

| media_type | 含义 |
|-----------|------|
| 1 | PDF |
| 2 | 网页 |
| 6 | 公众号文章 |
| 7 | Markdown |
| 11 | 笔记 |
| 99 | 文件夹 |

### 标题关键词聚类

对全部非文件夹资源的标题进行关键词聚类，识别高频主题词：

- 遍历标题，提取核心主题词（排除"的""了""是""在"等停用词）
- 统计出现频次，找出 Top 15 高频主题词
- 根据关键词组合判断内容领域（教育 / 科技 / 金融 / 医疗 / 设计 / 编程等）

### 如果你在完整模式

**Before：确认门**——将内容画像结果整理输出，让用户"看一眼就知道知识库里有什么"：

```markdown
📊 AI工具箱知识库内容画像

📁 当前已有文件夹：0 个
📄 总资源数：214 条
┌──────────────┬──────┐

│ PDF文档       │  15  │
│ 网页链接      │  10  │
│ PPT           │   5  │
│ 笔记          │   4  │
└──────────────┴──────┘

🔍 内容主题分布：

   课件、设计、视频、ima、课题、工具
```

### 生成分类方案

基于内容画像，生成 **2-3 个分类方案**，每个方案包含：
- 方案名称和核心理念
- 文件夹列表及预计放入的资源数
- 优缺点说明

**典型方案模板：**

#### 方案A：按应用场景分类（推荐）
最直观实用，适合"我需要解决什么问题→去哪个文件夹找"的使用习惯。

| 文件夹 | 预计资源数 | 典型内容 |
|--------|-----------|---------|
| 01-教学备课与课件制作 | ~40 | 教案、课件、教学设计 |
| 02-论文写作与课题研究 | ~12 | 论文、课题申报、科研 |
| 03-AI生图与视觉设计 | ~17 | 图片、海报、绘画工具 |
| ...基于实际数据... | ... | ... |

#### 方案B：按内容类型分类
适合按"这是什么"而非"用在哪儿"的人。

#### 方案C：按工具/平台分类
适合熟悉各工具名称的用户。

> 如果知识库已经有一些文件夹（整理模式），跳过此阶段，直接进入 Phase 4 映射归类。

**重要：必须等待用户选择方案后再进入 Phase 3。**

---

## Phase 3：创建文件夹

根据用户选定的方案，调用 `create_folder` API 在知识库根目录下创建所有文件夹。

**API 调用要点：**
- 使用 `knowledge_base_id` 和 `name` 字段
- 可选传 `kb_name` 用于二次校验
- 记录返回的 `media_id`（即 `folder_xxxxx` 格式）作为后续移动的目标 `dst_folder_id`

**并行创建：** 多个文件夹可同时创建，互不依赖。

成功创建后告知用户文件夹结构。

---

## Phase 4：智能归类与批量移动

### 4.1 构建归类规则

基于用户选定的分类方案和文件夹名称，构建**关键词归类映射表**。规则优先级：

1. **专有名词/品牌词优先**：如"WorkBuddy""龙虾""ima""Coze"等平台名称
2. **功能词匹配**：如"备课""课件""教案" → 教学类
3. **内容形式词**：如"论文""课题""申报" → 学术类
4. **兜底规则**：未匹配的按语义相似度归入最近文件夹

**切勿硬编码——必须根据实际文件夹名称动态构建规则。**

### 4.2 规则构建方法

```
对每个文件夹名称，提取核心关键词：

文件夹: "01-教学备课与课件制作"
→ 核心词: [教学, 备课, 课件, 教案, 课堂, 教师, 学生, 上课, 授课, 考试, 复习, AI助教, 教育, 班级, 班主任, AI教学, 课例, 课程, 作业, 习题, 互动, padlet]

文件夹: "07-WorkBuddy龙虾专区"
→ 核心词: [workbuddy, 龙虾, workbuddy教程, openclaw, qclaw, 万剑诀, workbuddy技能, 工作流, agent工作流]

文件夹: "06-提示词工程与Skills"
→ 核心词: [提示词, prompt, skill, skills, 智能体, agent, coze, 扣子, 调教, 系统提示词]
```

### 4.3 执行归类

遍历根目录全部非文件夹资源，逐条匹配：

```python
for item in all_items:
    title = item["title"].lower()
    
    # 按文件夹顺序匹配（优先级高的在前）
    for folder in ordered_folders:
        if any(keyword in title for keyword in folder_keywords[folder]):
            classified[folder].append(item)
            break
    else:
        unclassified.append(item)
```

**输出归类预览给用户确认**（仅展示各文件夹数量统计和未分类条目）：

```markdown
### 归类方案预览

| 目标文件夹 | 条数 |
|-----------|------|
| 01-教学备课与课件制作 | 40 |
| 02-论文写作与课题研究 | 12 |
| ... | ... |
| **未分类** | **3** |

未分类条目需您指定归入哪个文件夹：
1. xxx —— 建议归入？
2. yyy —— 建议归入？

确认后执行，或您直接修改？(回复"确认"开始移动)
```

> **用户在之前已清晰表达过意图时，可以跳过此确认直接执行。** 例如用户说"按方案A直接做"或已经确认过方案——此时归类预览改为快速展示，直接进入移动。

### 4.4 批量移动

调用 `move_knowledge` API：

**关键参数：**
```json
{
  "src_knowledge_base_id": "同一知识库ID",
  "dst_knowledge_base_id": "同一知识库ID",
  "dst_folder_id": "目标文件夹ID（folder_前缀）",
  "dst_folder_name": "目标文件夹名称（二次校验用）",
  "infos": [{"media_id": "资源ID"}, ...]
}
```

**移动策略：**
- 同一目标文件夹的资源，合并为批次移动
- 每批次最多 **10 条**（API 限制）
- 同一文件夹分多批次的，连续执行

**错误处理：**
- 每批次返回 `move_results`，检查每个 `ret_code`
- ret_code=0 → 成功
- ret_code≠0 → 记录失败项的 `media_id` 和 `err_msg`，在总结中报告

## Phase 5：验证与总结

### 5.1 根目录验证

再次调用 `get_knowledge_list` 检查根目录，确认：
- 是否只剩余文件夹
- 是否有遗漏的散落资源

### 5.2 输出整理报告

```markdown
## ✅ 知识库整理完成

### 整理前后对比
```
之前：根目录 214 条散落资源
之后：11 个分类文件夹，0 条散落资源
```

### 最终结构

```
📁 根目录
├── 📁 01-教学备课与课件制作（40条）
├── 📁 02-论文写作与课题研究（12条）
├── 📁 03-AI生图与视觉设计（17条）
├── ... ...
└── 📁 11-办公效率与数据分析（7条）
```

### 如有失败
| 资源 | 原因 | media_id |
|------|------|----------|
| xxx | 移动失败（err_msg） | xxxx |
```

### 5.3 可选：重复文件检测

**先询问用户是否需要检测重复文件。**

> 重复检测需要遍历所有文件夹，耗时较长。仅在用户明确需要时执行。

如果用户确认，检测规则：
- 文件名高度相似（标题相同或仅差后缀如"（1）""-副本""_copy"）
- 文件类型相同（media_type 一致）
- 列出疑似重复清单，让用户确认是否删除（注意：API 不支持删除操作，需告知用户手动处理）

## 边界情况处理

| 场景 | 处理方式 |
|------|---------|
| 根目录已整洁 | 告知用户，直接结束 |
| 资源无法归入任何文件夹 | 列出清单，让用户指定或新建"其他"文件夹 |
| 文件夹名含义模糊 | 浏览文件夹内容后再判断适合放入哪些资源 |
| API 返回错误 | 区分可重试错误（网络超时）和不可重试错误（参数错误），可重试的自动重试一次 |
| 超大知识库（>500条） | 按主题分批处理，先处理主题最清晰的类别 |
| 用户说"直接做" | 跳过确认门，全自动执行 |

## 工作流示例

### 示例1：完整模式——从零开始整理一个知识库

```
用户："帮我整理一下这个AI知识库"
Agent：
  1. Phase 0：扫描发现0个文件夹、200+条散落资源
  2. Phase 1：搜索内容，统计发现80%是AI工具教程、15%教学设计
  3. Phase 2：输出3个方案 → 用户选方案A（按场景分类）
  4. Phase 3：创建8个文件夹
  5. Phase 4：关键词归类，预览确认后批量移动
  6. Phase 5：验证，输出整理报告
```

### 示例2：整理模式——知识库有文件夹但根目录乱

```
用户："帮我把根目录清一下"
Agent：
  1. Phase 0：扫描发现5个文件夹、30条散落资源
  2. Phase 1→2：快速归类映射到已有文件夹
  3. Phase 3：跳过（已有文件夹）
  4. Phase 4：归类预览→确认→移动
  5. Phase 5：验证输出
```
