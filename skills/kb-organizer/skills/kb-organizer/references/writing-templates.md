# 模板库 — 知识库智能整理大师

> 用途：直接复制下方骨架改成自己的任务，省去从零搭结构。
> 三个模板分别对应流程前端（出方案）、中段（执行留痕）、末端（交付报告），按顺序使用即可。

---

## 模板 1｜分类方案表（文件夹 / 收纳范围 / 判定规则）

**用途**：Phase 2 生成分类方案、交付给用户确认时使用。完整模式必用；整理模式跳过本表，直接从已有夹名反推规则。

**结构骨架**（可直接复制）：

```
## 分类方案 <A/B/C>：<方案名称>
核心理念：<一句话，说明按什么维度分，例如"按项目阶段分，用哪个阶段的资料就进哪个夹">

| 序号 | 文件夹名称 | 收纳范围（放什么） | 判定规则（命中即归入） | 预计条数 |
|------|-----------|------------------|---------------------|---------|
| 01 | <两位序号-主题> | <一类内容的一句话描述> | 标题含：<关键词1>/<关键词2>/<关键词3> | <N> |
| 02 | | | 标题含： | |
| ... | | | | |
| 99 | 其他 | 暂无法归入前序任一夹的资源 | 兜底 | <N> |

- 根目录散件总数：<N>　各夹预计条数合计：<N>　（两者必须相等）
- 兜底规则：未命中任何规则时进入"其他"夹，逐条列给用户指定
- 方案优点：<适合什么样的查找习惯>
- 方案缺点：<什么情况下找不到>
```

**填写说明**：
- **必填**：文件夹名称、收纳范围、判定规则、预计条数。缺"判定规则"的方案无法执行，退回重写。
- 文件夹数量控制在 **8-12 个**；超过 15 个用户会找不到，需合并同级或改为主夹-子夹两级。
- 文件夹名统一用"两位序号-主题"（01-、02-…），保证按名称排序时顺序稳定；不要与同库既有命名写法混用。
- **判定规则必须写成"标题含哪些词"**，不能写"相关的内容""类似的资料"这类无法执行的描述。
- 关键词用 `/` 分隔，排序原则：专有名词/品牌词 > 功能词 > 形式词。品牌词放前面，否则语义相近的两类会互相抢条目。
- 预计条数合计必须等于根目录散件总数，出现负数、空缺或对不上即为方案不合格。
- 一次只出 2-3 个方案，且**必须等用户明确选一个再建夹**。

**真实示例**（案例 2 场景，数字为示例）：

```
## 分类方案 A：按应用场景分类（推荐）
核心理念：按"我要解决什么问题"分，用哪个场景就进哪个夹

| 序号 | 文件夹名称 | 收纳范围 | 判定规则 | 预计条数 |
|------|-----------|---------|---------|---------|
| 01 | 01-教学备课与课件制作 | 教案、课件、教学设计 | 标题含：教学/备课/课件/教案/课堂/教师 | 40 |
| 02 | 02-论文写作与课题研究 | 论文、课题申报、科研 | 标题含：论文/课题/申报/研究 | 12 |
| 03 | 03-AI生图与视觉设计 | 图片、海报、绘画工具 | 标题含：生图/绘画/海报/设计/图片 | 17 |
| 07 | 07-WorkBuddy龙虾专区 | 平台教程与工作流 | 标题含：WorkBuddy/龙虾/工作流/agent | 22 |
| 99 | 其他 | 暂无法归入前序任一夹 | 兜底 | 3 |

根目录散件总数：214　各夹预计条数合计：214（示例数据）
兜底规则：未分类 3 条逐条列给用户指定归属
方案优点：与"遇到问题再找资料"的习惯一致，检索路径最短
方案缺点：同一工具同时用于两个场景时，只能进一个夹
```

## 模板 2｜归类执行清单（建夹回执 + 批次移动留痕）

**用途**：Phase 3、Phase 4 边执行边记录；移动完成后立即保存。这是**出问题时唯一的还原依据**，不得事后补写。

**结构骨架**（可直接复制）：

```
# 归类执行清单 —— <知识库名>（kb_id：<kb_id>）
执行时间：<YYYY-MM-DD HH:MM>
模式：<完整模式 / 整理模式>
采用方案：<方案A 按应用场景>

## 一、文件夹清单（create_folder 回执）
| 序号 | 文件夹名称 | dst_folder_id | 创建状态 |
|------|-----------|---------------|---------|
| 01 | | folder_xxxxx | 成功 |
| 02 | | | |

## 二、批次移动记录（move_knowledge）
| 批次 | 目标文件夹 | 条数 | media_id（前 3 条 + …） | ret_code | err_msg |
|------|-----------|------|----------------------|----------|---------|
| B01 | 01-xxx | 10 | id1 / id2 / id3 / … | 0 | — |
| B02 | 01-xxx | 8 | | 0 | — |
| B03 | 02-xxx | 10 | | 106 | <错误原文> |

## 三、失败项汇总（ret_code ≠ 0）
| 资源标题 | media_id | 原所在位置 | err_msg | 处置（已补移/待用户处理） |
|---------|----------|-----------|---------|---------------------|
| | | 根目录 | | |

## 四、未分类待定
| 资源标题 | media_id | 建议归属 | 用户决定 |
|---------|----------|---------|---------|
| | | | |
```

**填写说明**：
- **必填**：kb_id、模式、文件清单中的 dst_folder_id、批次记录中的 ret_code。
- 每批 **≤10 条**（API 限制），按目标文件夹分组；同一文件夹跨批次时批次号连续。
- `ret_code=0` 才记成功，其余一律进"三、失败项汇总"，并抄录 `err_msg` 原文，不要转述成"移动失败"四个字。
- 失败项必须带 **media_id + 原所在位置**（根目录还是某个旧文件夹）。移动前先记录原位置，否则失败项无法定位、无法还原。
- 批次记录里 media_id 只记前 3 条 + 省略号即可；完整列表随批次请求体一并留存。
- 本清单与模板 3 配套：模板 3 的数字口径来自复扫结果，本清单提供失败项的明细来源。

**真实示例**（案例 1 节选）：

```
# 归类执行清单 —— 项目资料库（kb_id：Pqtle...【待核：完整ID】）
执行时间：2026-09-11 15:40
模式：完整模式　　采用方案：方案A 按项目阶段+专业

一、文件夹清单
| 03 | 03-结算送审与审计 | folder_ab12cd | 成功 |
| 06 | 06-农民工保证金 | folder_ef34gh | 成功 |

二、批次移动记录
| B07 | 03-结算送审与审计 | 10 | id_31 / id_32 / id_33 / … | 0 | — |
| B08 | 03-结算送审与审计 | 6 | id_41 / id_42 | 0 | — |
| B09 | 06-农民工保证金 | 10 | id_51 / id_52 | 106 | 参数校验失败：dst_folder_name 不匹配 |

三、失败项汇总
| <保证金账户开立批复> | id_51 | 根目录 | 参数校验失败：dst_folder_name 不匹配 | 已核对名称后补移成功 |
```

## 模板 3｜整理前后对照表（交付报告主体）

**用途**：Phase 5 验证后的交付报告主体。用户靠这张表一眼确认"东西没丢、结构变了"。

**结构骨架**（可直接复制）：

```
## 整理结果 —— <知识库名>

### 一、整理前后对照
| 指标 | 整理前 | 整理后 | 变化 |
|------|-------|-------|------|
| 根目录散件数 | <N> | 0 | -<N> |
| 文件夹数 | <N> | <N> | +<N> |
| 资源总数 | <N> | <N> | 0（必须为 0） |
| 未分类条目 | — | <N> | — |
| 失败项 | — | <N> | — |

### 二、最终结构
```
📁 根目录
├── 📁 01-<名称>（<N> 条）
├── 📁 02-<名称>（<N> 条）
└── 📁 <N>-其他（<N> 条）
```

### 三、异常与待办
| 资源 | 原因 | media_id | 待办 |
|------|------|----------|------|
| | | | |
```

**填写说明**：
- **资源总数整理前后必须一致（变化列 = 0）**。这是"没有丢东西"的唯一证据；对不上就重新全量扫描，不要用"大致一致"交付。
- 数字口径全部来自 `get_knowledge_list` 的两次扫描（整理前一次、整理后一次），不估算。
- "整理后根目录散件数"应为 0；若不为 0，写清剩余散件是什么、为什么不移。
- 失败项引用模板 2 的"三、失败项汇总"，此处只放结论与待办，不重复 err_msg 全文。
- 未分类条目写清是"用户已指定归属"还是"仍待用户决定"。
- 交付顺序：对照表 → 结构树 → 异常节；不要先讲过程。

**真实示例**（案例 2 场景，示例数据）：

```
### 一、整理前后对照
| 指标 | 整理前 | 整理后 | 变化 |
|------|-------|-------|------|
| 根目录散件数 | 214 | 0 | -214 |
| 文件夹数 | 8 | 8 | 0 |
| 资源总数 | 214 | 214 | 0 |
| 未分类条目 | — | 0 | — |
| 失败项 | — | 0 | — |

### 二、最终结构
📁 根目录
├── 📁 01-教学备课与课件制作（40 条）
├── 📁 02-论文写作与课题研究（12 条）
└── 📁 08-办公效率与数据分析（7 条）

### 三、异常与待办
| 资源 | 原因 | media_id | 待办 |
|------|------|----------|------|
| — | 无 | — | — |
```
