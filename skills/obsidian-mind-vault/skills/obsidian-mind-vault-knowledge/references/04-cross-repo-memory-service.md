# 04 · 跨仓检索与记忆服务

## 1. 要解决的问题

在一个业务仓库里工作的会话，对「当初为什么这么决定」没有持久记忆。知识存在，但**目录不可达**。通用记忆服务解决的是错误的一半——它存的是「这次会话聊了什么」，而不是「这个组织在这些项目上积累了什么」。

## 2. 服务端不止一个面

| 表面 | 方向 | 是什么 | 谁触发 |
|------|------|--------|--------|
| `instructions` | 库 → 会话 | 库的规则，连接时注入调用会话的系统提示 | **自动**，每连接一次 |
| `tools` | 会话 → 库 | `search` / `expand` / `recall` / `remember` / `record_work` / `reason` / `health` | **模型**决定 |
| `resources` | 会话 → 库 | 可按 `vault://note/<path>` 列出与读取的笔记 | 模型或客户端 |
| `prompts` | 人 → 库 | `recall_topic` / `prior_art` 等调用侧斜杠命令 | **人**决定 |

### 核心不对称律

> **禁令会传播，路由指令不会。**
> 一条禁令（「绝不把会话链接写进提交」）在直接压力与权威覆盖下都守住了。一条正面指令（「问历史决策前先查库」）只是建议性的，一旦附近有更近的来源就会被跳过。
> **服务端能让一个会话不做某件事；它无法让一个会话主动去找。**

这条不对称律决定了整个层的设计取向：**能用禁令表达的用禁令；需要 agent 主动的，必须在调用侧装钩子（第二步安装），不能只靠服务端声明。**

## 3. 四档延迟阶梯

| 档 | 是什么 | 调用时代价 |
|----|--------|-----------|
| **0 presence** | 契约到达调用会话 | 一次性，不派生额外会话 |
| **1 retrieval** | `search`、`expand`、resources | 秒级，**除本地嵌入外无模型调用** |
| **2 capture** | `recall`、`remember`、`record_work` | 无模型调用 |
| **3 reasoning** | `reason`：派生一个会话读库并判断 | 秒到分钟 |

> **阶梯衡量的是延迟，不是钱。** 第 3 档跑的是用户自己的 CLI、在自己机器上、用自己的授权。能用第 1 档解决就用第 1 档，理由是**它两秒出答案**，不是因为派生会话有风险。

## 4. 身份握手

「谁在提问」几乎是所有后续判断的前提。

- 身份**由客户端握手派生**（服务端可以问客户端「调用会话打开了哪些目录」）
- **绝不信任工具参数里的自述**
- 握手是**异步的**，且必须在任何可见性判定之前完成
- 拿不到身份时按最保守档处理（见 §6）

## 5. 曝光策略

### 5.1 配置字段

| 字段 | 语义 |
|------|------|
| `mcp_exposed_roots[]` | 可暴露根；**为空时回落到用户内容根** |
| `mcp_never_expose[]` | 无论位于哪个目录都一律不暴露的**文件名**列表 |
| `memory_root` | 跨仓记忆根 |
| `mcp_inbox` | `record_work` 无法归类时的兜底落点 |

### 5.2 五条恒成立规则（与配置无关）

1. **记忆根永不作为普通笔记服务**——它在根列表里被无条件剔除，遍历时再剔一次
2. **符号链接先做包含性检查再跟随**——遍历对每个条目做 lstat，任何链接都对根的真实路径解析
3. **`mcp_never_expose` 扣留所有大小写拼法**，不只声明的那个
4. **头部窗口内未闭合的元数据视为私有**——头部读取在 **1,200 字符**处停止，无法完整检视的文件一律扣留
5. **每次读取都写审计日志**——记录调用仓与查询文本；日志轮转在 **5 MB**，保留一代

### 5.3 曝光清单**不是**安全边界

> 它决定服务端**服务**哪些笔记，**不是出口控制**：一个以「额外目录」启动的会话无论如何都能读整个库。
> 把库内容挡在公开提交之外，靠的是**规则注入面里的禁令**（被实测证明有效的那种形式）**加上审计日志**。

### 5.4 两个谓词，各自唯一实现

- *哪些笔记存在* → 由「可见文件集」解析
- *这一个路径能否读* → 由「解析单个暴露笔记」解析

**两者是不同的问题，各自只有一个实现。** 新增表面必须调用其中之一，**不得长出第三个**。

> 原因：这一层反复出现的缺陷就是**第二条读取路径**——它用自己的路线到达笔记，应用了不同的规则。历史上两处重新推导**各自都放行了本该被策略扣留的笔记**。

## 6. 记忆可见性：顺序即设计

判定**按顺序**求值，而顺序本身就是设计：

1. **`general` 触达所有人**——唯一做到这一点的作用域，所以写入路径对它管得最严
2. **显式项目列举永远优先**，无论声明的 scope 是什么
3. **`platform` 触达共享同一平台的任何调用方**——一条 iOS 经验要能到达下一个 iOS 应用，且**必须不到达 Web 应用**
4. **否则不可见**——差一点命中不会浮上来
5. **无 roots 的调用方只看到 `general`**——这是对「我不知道你是谁」最安全的解读，它**降级到无用，而不是降级到全开**

**性质**：
- 每条记忆在写入时**声明自己的触达范围**
- **读取方永远不得放宽写入方声明的范围**
- 这是**相关性规则，不是访问控制规则**

## 7. 检索路径

### 7.1 三条性质

1. **先语义检索，再按可见性过滤——绝不反过来**
2. **语义排序只重排，不过滤**
3. **相关性只在组内排序，不跨越取代边界**

> 索引缺失时只降级**排序**，不降级**可用性**。「库什么都不知道」不是接线问题的可接受答案。

### 7.2 一次搜索调用的端到端

1. 解析调用方身份
2. 取出可见集合
3. 向检索服务发查询
4. 按可见性过滤结果
5. 返回

### 7.3 读取开销控制

- 记忆索引**只缓存「解析」结果，不缓存文件内容**
- 头部读取用**有界前缀**替代整文件读取，消除随字节数增长的代价

## 8. 记忆写入路径

### 8.1 三条不变式

1. **库不向自己的记忆层写入**（库内会话的写入被拒绝）
2. **声明是原子的**——用独占创建。原先的「先查后写」在六进程并发下**报告成功却只产出四个文件**
3. **索引更新与向量嵌入分离**：`update` 决定这条笔记能否被检索到，因此**同步**；`embed` 只决定它**排在多前**，因此异步

### 8.2 一个特殊点

库内正常的索引刷新走写后钩子，但**跨仓写入不是宿主的工具调用，因此没有钩子触发**——写入路径必须自己负责刷新。

## 9. 记忆的生命周期

| 机制 | 做什么 |
|------|--------|
| **近重复检测** | 分词 + 词干化 + 相似度，防止记忆库随增长静默劣化 |
| **显式取代** | 新知识标记覆盖旧知识，避免扁平记忆库同时持有互相矛盾的条目 |
| **置信度** | 每条记忆带置信度，未达「已验证」的进入待复核视图（**最旧优先**） |
| **加性提升** | 把稳定结论**复制**进长期主题笔记并加块锚点，再在捕获上写提升标记。**复制，永不移动** |
| **发现与自愈** | 用户改名或改配置后重新发现记忆根、暴露根、检索启动器；报告孤儿项目与索引归属冲突 |

### 提升块的对外服务边界

- **服务是 opt-in**（必须显式带提升标记）
- **策略仍由曝光解析决定**——提升只替换**内容**，可见性仍由原始捕获声明计算
- **降级而非放宽**
- **服务内容封顶 40 行、8,000 字符**，达到上限时告知调用方；**一级标题锚点直接拒绝**

> **记录在案但未解决的残余风险**：一个被提升的块可以说得比它来源的捕获更多。

### 一个真实缺陷的教训

空提升标记即可清除卫生标记，导致「服务路径在生产中是死的」。修法不是强制，而是**让梯度可见**——健康自检报告区分「可服务的」与「仅命名的」两类计数。

## 10. 派生推理（第 3 档）

- 为什么必须另起会话：服务协议的采样能力在主流宿主上尚未实现，因此经**用户自己的 CLI** 启动
- 用**隔离的服务配置**启动（递归防护）
- 结论是**推断的**，因此保留记录用于溯源与成本复核，但**绝不作为库知识提交**——由调用会话决定其中是否有值得留下的
- 含审计记录与进程清理

## 11. 安装是两步，且两步都必需

1. **消费方注册服务**（用户级作用域：装在自己的配置里，**机器上每个目录都可用**，无需往任何仓库里加东西）
2. **消费方自己的操作手册里加一段指针**

> **第二步不是文档装饰。实测：服务接好了但仓库侧没有指令时，一个会话做了零次库调用，并实现了一个库里明确记录为「已否决」的设计。**

## 12. 失败模式

这一层**每个失败都表现为「无结果」**。因此：

- 健康自检工具**不是可选项**
- 启动时应校验索引名在五个调用方之间一致
- 不应注册**裸检索服务**——它直接搜所有笔记，没有「哪条记忆是为哪个项目写的」的概念。在索引之上套用声明的 scope 正是本层提供的东西；绕过它返回的是**错误**的结果，而不只是更多。
