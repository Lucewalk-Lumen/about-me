# 06 · 绩效证据与组织记忆

## 1. 证据链的核心机制

> **能力笔记不手工维护证据列表。证据靠反向链接被动累积。**

- 工作笔记在 `## Related` 里链到能力笔记
- 能力笔记保持**定义性**（它是什么、熟练度分级、成长笔记）
- 查询视图里「证据数」= **反向链接数**（全库唯一直接消费图结构的地方）

这条机制的价值：评审季你不需要「整理」证据，证据在你日常写作时就已经累积好了。手工列表一定会腐烂。

## 2. 战功文档（Brag Doc）

### 2.1 五节结构

| 节 | 内容 |
|----|------|
| 能力证据 | 每条能力下的具体证据 |
| 影响与交付物 | 交付了什么、产生了什么影响 |
| 技术成长 | 学到/掌握了什么 |
| 协作 | 跨团队、指导、被指导 |
| 反馈 | 收到的评价与评价来源 |

### 2.2 索引与详情

- 索引页：季度表格（季度 / 亮点 / 回顾）
- 详情页：`perf/brag/QN YYYY.md`，一篇一季
- 每条战功必须**链回证据**（工作笔记、事故、评审证据）

## 3. 评审材料

### 3.1 三档可见度

| 版本 | 面向谁 | 可以写什么 | 禁止写什么 |
|------|--------|-----------|-----------|
| **私有版** | 只有自己 | 全部，包括人际动态与策略 | — |
| **经理版** | 直属经理 | 影响、能力、成长、需要支持的地方 | 同事的私下评价 |
| **同伴版** | 参与评审的同事 | 与协作相关的具体事实 | 人际细节、个人战略、经理私下反馈 |

> **可见度不得过度声明。** 参与 / 被评审 / 被告知三档必须分清。把「参与」写成「主导」是这类材料最常见也最致命的错误。

### 3.2 写作禁止项

- ❌ 不写工单号
- ❌ 不统计代码行数
- ❌ 不把「周末还在干活」当奉献证据
- ❌ 不给所有人同一句模板化的成长建议（发展领域必须**因人而异**）
- ❌ 保密评论不得原样重复

### 3.3 字数控制

评审工具通常有字符上限。交付前必须用字数工具**实测**，超限时删弱项，**不删证据链接**。

## 4. 事实核查（评审草稿专用）

逐条核查六类声明：

| 类型 | 核查什么 |
|------|---------|
| 数字 | 数字是否与证据一致 |
| 时间线 | 时间顺序是否成立 |
| 归属 | 谁做的 |
| 比较词 | 「首个」「最大」「唯一」是否站得住 |
| 性质描述 | 描述是否超出证据支持 |
| 星期与日期 | 星期几与日期是否对应 |

**四分类输出**：已证实 / 未证实 / 存疑 / 需核日期。

> **核查者不得是起草者。** 这是硬分工。

## 5. 组织记忆

| 内容 | 位置 | 维护 |
|------|------|------|
| 人物档案 | `org/people/<Full Name>.md` | 从工作笔记接收反链；记录角色、团队、关键节点 |
| 团队笔记 | `org/teams/` | 成员、范围、交互方式 |
| 组织索引 | `org/People & Context.md` | 角色与组织 / 团队 / 绩效回顾 / 经理时间线 / 人员 / 回顾目标 / 复现成长主题 |

## 6. 1:1 记录

- 命名：`<Person> YYYY-MM-DD.md`（**日期后缀**，点时刻记录）
- 内容：谈话要点、关键节点、行动项
- 回写：补充人物笔记、更新工作索引、必要时把关系变化写进记忆主题索引
- ⚠️ **元数据存在两套并存格式**（由两个不同命令写入）：一套写 `status: completed`，另一套写 `person` 字段。清单要求的 `quarter` 两套都可能缺。遇到时**指出冲突，不要擅自合并**。

### 慢性循环检测

跨最近多篇 1:1 记录做行动项差分：**连续 2 篇以上未勾选的同义项**判定为长期未解决项。

> 只看最后一篇是发现不了的——这正是需要跨篇比对的原因。

## 7. 事故复盘

### 7.1 九节结构

背景 / 根因 / 处置 / 时间线 / 影响 / 涉及人员 / 备注 / 分析 / 关联

### 7.2 硬要求

- 时间线必须带**精确时间戳**
- 引语保留**原话**，不改写、不美化
- 涉及人员要建/更新人物档案
- 归档后要判断哪些内容可以进入对外材料（评审简报）

## 8. 证据采集

### 8.1 代码评审深扫

- 扫描指定人、指定周期内的评审记录
- **数量有上限**（默认 200）
- 标注 revert 与已关闭项
- 产出写入 `perf/evidence/<Person> PRs - <Period>.md`

### 8.2 聊天记录考古

- **分页全量读取**（频道 100 / 线程 200）
- 保留精确时间戳
- 引语保留原话
- 重建时间线

## 9. 端到端路径

```
日常工作 → 工作笔记（链到能力笔记）
   │
   ├─ 事故 → 事故笔记（九节）+ 战功条目
   ├─ 1:1  → 1:1 记录 + 人物笔记 + 记忆主题
   └─ 交付 → 战功条目（五节）
                │
                ▼
        能力笔记的反链自动累积（证据数 = 反链数）
                │
                ▼
        评审季：深扫证据 → 评审简报（三档）→ 事实核查 → 交付
```

## 10. 常见错误

| 错误 | 后果 |
|------|------|
| 手工维护能力笔记的证据列表 | 一定会腐烂，且与反链机制重复 |
| 把 1:1 谈话要点写进同伴版 | 直接破坏信任 |
| 用「参与」描述「主导」 | 评审时被质疑，整份材料可信度受损 |
| 不实测字数就交付 | 被工具截断，最后一段丢失 |
| 只读最后一篇 1:1 就判断「已解决」 | 漏掉慢性循环 |
| 把事故时间线写成「大约下午」 | 复盘失去可辩护性 |
