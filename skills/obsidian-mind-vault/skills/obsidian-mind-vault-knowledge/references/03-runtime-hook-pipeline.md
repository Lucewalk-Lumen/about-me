# 03 · 运行时钩子管道

## 1. 五个生命周期钩子

| 事件 | 时机 | 做什么 | 关键约束 |
|------|------|--------|---------|
| 会话开始 | 会话启动 / 恢复 / 清空 / 压缩后 | 注入日期头、目标摘录、主题索引、近 48 小时变更、开放任务、活跃工作、文件清单 | 受字节预算约束，**以注入计量表结尾**；把库路径写进宿主环境变量 |
| 每条消息 | 用户每次提交 | 按信号表分类消息并注入路由提示；同时领取上一轮的收尾报告 | ~100 token；信号表是**数据驱动**的，含对中日韩文本友好的正则边界处理 |
| 写工具之后 | 每次写 / 改文件后 | 校验元数据与链接；拦截错放的记忆文件；检出超限体积与写入时主题簇 | ~200 token；并触发去抖的索引刷新 |
| 压缩之前 | 上下文压缩前 | 备份会话转录 | 保留最近 30 份 |
| 每轮回复后 | 对话边界 | 收尾清单 + 卫生漂移发现 | 同会话内同一发现**不重复上报**，内容变化时才再报；用户看每节一行摘要，agent 在下一条消息拿到全文 |

> **三宿主落点差异**：清单落点不同（两个宿主用「回复后」，一个宿主用「会话结束」）；有一个宿主**没有压缩前事件**。

## 2. 注入预算体系

| 项 | 值 | 语义 |
|----|----|------|
| 宿主钩子输出硬上限 | **10,000 字符** | 不可通过配置提高；超出后会话只拿到文件路径与前 **2,000 字符** |
| 常驻注入预算 | **9,100 字节** | = 上限 − 计量表空间；脚本会把任何设定值**夹到此上限内** |
| 指令通道预算 | **20,000 字节** | 走指令文件通道时可用（不受同一上限约束） |
| 文件清单折叠阈值 | **12** | 文件夹内笔记数超过该值即折叠为一行 |

**三层加载模型**：

| 层 | 内容 | 时机 | 代价 |
|----|------|------|------|
| 常驻 | 操作手册 + 会话开始注入块 | 会话开始 | 受预算约束，本身压在硬上限之下 |
| 按需 | 语义检索结果 | 需要特定上下文时 | 定向 |
| 触发 | 分类路由提示 | 每条消息 | ~100 token |
| 触发 | 写后校验 | 每次写 md 后 | ~200 token |
| 罕见 | 整文件读取 | 仅显式需要 | 可变 |

## 3. 卫生漂移扫描（五类）

| 类别 | 判定 | 处置方向 |
|------|------|---------|
| 超大笔记 | 超过约 25 KB（字节） | 拆分，**不裁剪** |
| 主题簇 | 活跃目录里新出现多篇同主题笔记 | 建议成组 |
| 开放循环 | 指定目录内「行动项 / 需关注」章节里未闭环的条目，超期或超量 | 列出待清理项 |
| 收件箱压力 | 会议收件箱堆积 | 提示路由处理 |
| 记忆收件箱压力 | 跨仓记忆积压未处理 | 提示提升或复核 |

扫描同时服务三个入口：会话开始、每轮回复后、写后校验。

## 4. 去重与去抖

### 4.1 同一发现不重复报

为每份报告计算**稳定身份哈希**，主动**剔除易变字段**（体积、年龄天数、最老天数）与排序差异。这样「同一个发现」在数值微调后仍被认作同一件事，不会重复刷屏。

> 改动哈希的输入字段时要意识到：这会**重置「已报过」的记忆**，导致所有历史发现重新播报一次。

### 4.2 提示状态老化

按会话记录钩子已展示过的内容，防止每轮都触发的钩子反复刷屏。

- 老化 7 天
- 会话上限 200，超出自剪枝
- **缺会话标识时 fail-open**（宁可重复报，不可漏报）

### 4.3 索引刷新去抖

多个钩子共用同一份去抖流程，以**哨兵文件**实现，间隔 **30 秒**。刷新作为后台分离进程运行，父进程忽略其标准输出，失败静默。

## 5. 收尾报告的交接协议

1. 「每轮回复后」钩子把**完整报告**落盘到交接目录
2. 用户只看到**每节一行的摘要**
3. 下一条用户消息触发分类钩子时，把**完整报告**领走交给 agent
4. 交接文件带**过期清理**（超过时限自动清除）

> 这样设计的原因：收尾发现属于 agent 需要知道的信息，但直接打印会污染用户的阅读体验。

## 6. 写入原子性与竞态

**原子写**：不覆盖既有文件地落盘（临时文件 + 改名语义），并支持**文件名抢占**。

> 历史事故：写入原先用「先查后写」。**六个进程报告成功，实际只产出四个文件。** 现在改为原子独占创建。

## 7. 脚本层结构（分层与依赖）

```
顶层入口（13 个代码文件）
├── 5 个钩子：会话开始 / 消息分类 / 写后校验 / 压缩前备份 / 收尾清单
├── 3 个 CLI：字数统计 / 生成自动记忆索引 / 确定性卫生修复
├── 2 个服务启动器（透明 shim，只做 spawn）
├── 1 个后台 worker（索引刷新）
└── 1 个类型声明
lib/（44 个模块 / 382 个导出 / 约 12,450 行）
├── G1 运行时原语 8：钩子 I/O、主模块守卫、项目目录解析、模式标志、字段读取、头部读取、正则转义、原子写
├── G2 会话装配与卫生 7：上下文装配、活跃卫生、交接、报告形态、提示状态、报告身份、更正扫描
├── G3 服务面 11：服务端、协议、上下文、曝光、工具表、调用方、检索客户端、图遍历、捕获、记忆桥、派生推理
├── G4 记忆层 8：写入、召回、相似度、取代、索引缓存、提升、发现自愈、自动记忆索引
├── G5 检索集成 5：调用 helper、刷新、引导、忽略同步、模型选择
└── G6 内容解析 5：元数据、链接、字数、匹配、信号表
```

**依赖图实测**：

| 方向 | 边数 | 说明 |
|------|------|------|
| 顶层 → lib | 50 | 13 个顶层代码文件中 10 个依赖 lib |
| lib → lib | 63 | **环数 = 0**（126 个模块节点 DFS 三色标记） |
| 测试 → lib | 71 | 42 / 44 个 lib 模块被测试直接引用 |
| 顶层 → 顶层 | 1 | 一个 CLI 复用另一个 CLI 的导出 |

**扇入扇出极值**：

| 指标 | 模块 | 值 |
|------|------|----|
| 最大扇出 | 服务端主模块 | 18 个 lib 模块 |
| 最大跨层扇入 | 钩子 I/O | 16 个 importer（含 6 个顶层脚本） |
| lib 内最大扇入 | 正则转义 / 钩子 I/O | 各 6 个 |
| 导出最多 | 会话装配 helper | 41 个 |
| 导出最少（非零） | 正则转义 | 1 个 |

**三处「同名不同层」不构成环**：顶层钩子入口与同名 lib helper 职责不同；顶层 CLI 壳与 lib 实现同名；均无回边。

## 8. 测试规模

| 项 | 值 |
|----|----|
| 测试文件 | 68 个（另 1 个共享 helper） |
| 用例数 | **1,594** |
| 运行器 | 宿主语言内置测试框架，**零外部测试依赖** |
| 覆盖方式 | 进程内直接 import 纯函数；子进程跑真实钩子（复刻宿主的启动形态）；子进程跑 CLI；真启服务启动器 |
| 配置一致性 | 有测试断言宿主配置里的钩子接线与脚本名一致 |
| 并发时序 | 有独立文件覆盖写入并发与派生推理并发 |
| 测试隔离 | 共享 helper 在加载时创建临时目录并设置哨兵，避免测试触发真实索引更新 |
