# decompose-review-modules — 模块拆解

别按作者排队，要按问题拆战场。综述最怕写成"张三说、李四说、王五说"——这是结构问题，不是语言问题。

## 适用场景

- 已经有问题锚之后，需要把它拆成可独立写作的小节。
- 已经读了 30+ 篇文献，需要做一次结构体检（模块是否重叠、是否漏关键维度）。
- 一篇论文同时属于多个模块，说明拆得有问题。

## 输入

```
研究问题：[在此粘贴你的问题锚]
（可选）已有模块：[列出你目前的模块划分]
（可选）已读文献：[文献分类现状]
```

## 执行步骤

1. **拆解**：把研究问题拆成 3-5 个模块，每个模块配"这一节真正要回答的问题"。
2. **体检**（已有模块时）：检查模块之间是否重叠、是否漏掉关键维度（如中间机制、能力类型等）。
3. **命名**：模块名要带判断力，不要写"研究现状/影响因素/存在问题/对策建议"这类没分析力的目录式标题。

## 输出

- 模块表（模块名 | 这一节真正要回答的问题）
- 结构体检意见（重叠维度、遗漏维度、可切入的文献密度低区）

## 调用示例

```
请使用「模块拆解」微技能，把下面这个研究问题拆成 3-5 个文献综述模块：
大学生使用 AI 写作工具时，为什么会从辅助性使用走向依赖性使用？

（体检模式）
我现在有四个模块：工具使用行为、写作能力、学术伦理、学习效果。
请用「模块拆解」微技能检查这四个模块是否重叠，是否漏掉关键维度。
```

## 避坑提示

- 拆完以后，每一节都应"在回答一个小问题"，而不是"介绍某类文献"。
- 模块名带判断：如"工具便利性与认知卸载""写作能力差异与依赖路径"，而不是"研究现状"。
- 标题一变，写出来的段落也会跟着变。
