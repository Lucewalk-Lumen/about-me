# Deep Distill（论文深度蒸馏）

> **随本包维护**：报告以本地 Markdown 文件交付。
> 配套包：`obhrm-research-collaboration-team`（位于 `skills/literature-review/references/micro-skills/deep-distill.md`）。
> 上游：可被 `skill:research-collector` Step 4 调研报告（元数据池）喂入；下游：深度蒸馏模式默认自动衔接温书恒证据-论点映射（G2 证据映射门），报告生成后询问一次是否衔接（可取消）。
> 挂靠：`obhrm-literature-review`（温书恒）L1 文献筛选 → L3 阅读分类的精读增强。

---

## 触发条件

当用户提出以下需求时激活本 micro-skill：
- "帮我速览这个 PDF"
- "蒸馏这篇论文的核心内容"
- "快速提取这篇文献的关键信息"
- "分析这个 PDF 的研究方法和结论"
- 用户上传单个 PDF 文件或指定本地 PDF 路径
- 用户提供学术文献的在线链接（arXiv、知网、PubMed 等）

---

## 核心架构：三层六模块深度蒸馏模型（基础 M1–M3 / 洞察 M4–M5 / 衔接 M6）

> 本模型旧称「4+2 深度蒸馏模型」，按实际结构（基础层 3 + 洞察层 2 + 衔接层 1 = 六模块）统一命名为「三层六模块」。

| 层级 | 模块 | 核心内容 |
| :--- | :--- | :--- |
| **基础层** | **M1: 结构化元数据** | 标题、作者、机构、来源、年份、DOI。**快速标签**：学科分类、研究方法、核心技术。 |
| | **M2: 逻辑骨架还原** | **论证链条**（问题→理论→方法→结论）、**精简摘要**、**关键图表说明**。 |
| | **M3: 引用文献网络** | 核心参考文献列表（Top 10），为后续深入阅读提供指引。 |
| **洞察层** | **M4: 批判性思考** | **研究缺口**、局限性分析、可能的改进方向。 |
| | **M5: 知识图谱关联** | 前置知识提示、同类方法对比、领域定位。 |
| **衔接层** | **M6: 温书恒证据-论点映射钩子（G2 证据映射门）** | 自动转化为温书恒证据-论点映射输入格式（字段对齐 `../../knowledge/evidence_claim_map.json`，作为 G2 证据映射门输入，并为 G3 提纲结构门的文献链闭环提供支撑） |

---

## 执行流程

### 步骤 0: 用户目的确认（首要步骤）

在处理任何输入之前，**必须首先询问用户的分析目的**：

**询问方式**：以对话形式向用户提问，清晰列出三个选项并等待选择：
1. **深度蒸馏**：完整的三层六模块模型分析，包含 M1-M6 全部模块，适合深入研究
2. **快速阅读**：仅生成 M1（元数据）+ M2（精简摘要 + 论证链条）+ M3（Top 10 文献），跳过 M4-M6，适合快速浏览
3. **简单了解**：仅提取标题、作者、摘要和核心结论，适合初步筛选

**默认建议**：若用户未明确指定，默认为"快速阅读"模式。

### 步骤 1: 输入类型判断

根据用户提供的输入，判断是 PDF 原件还是在线链接：

**判断逻辑**：
- **PDF 原件**：文件扩展名为 `.pdf`，或用户直接上传文件
- **在线链接**：以 `http` / `https` 协议（即 `http(s)://`）开头的 URL

**处理分支**：
- 若为 PDF 原件 → 跳转到 **步骤 2A**
- 若为在线链接 → 跳转到 **步骤 2B**

### 步骤 2A: PDF 原件处理流程

1. **文件接收与验证**：
   - 检查扩展名是否为 `.pdf`
   - 检查文件头是否以 `%PDF` 开头
   - 检查文件大小 > 1000 bytes

2. **内容提取**：使用 Read 工具深度解析 PDF 内容（Read 工具支持直接读取 PDF 文件并提取文本；对图片型 PDF 可用多模态 Read 读取）

3. **根据用户目的执行相应蒸馏级别**

4. **生成 Markdown 报告**（本地交付）

### 步骤 2B: 在线链接处理流程

1. **链接类型判断**：
   - 使用 WebFetch 工具尝试访问链接
   - 判断是否为开源/公开网站

**开源/公开网站判定标准**：
- [OK] **开源网站**：arXiv.org、biorxiv.org、medrxiv.org、PubMed Central (PMC)、DOAJ 收录期刊
- [OK] **预印本平台**：arXiv、bioRxiv、medRxiv、SSRN、ResearchGate（公开部分）
- [X] **非开源网站**：IEEE Xplore、ScienceDirect、SpringerLink、Wiley Online Library、知网（CNKI）、万方数据等需要机构订阅的平台

2. **若为开源/公开网站**：
   - 直接使用 WebFetch 获取页面内容
   - 尝试提取 PDF 下载链接
   - 若成功获取 PDF，按 **步骤 2A** 处理
   - 若无法获取 PDF，使用 WebSearch 搜索该论文的 PDF 版本

3. **若为非开源网站**：
   - **立即询问用户**（以对话形式向用户提问）：
     ```
     [!] 检测到该链接来自非开源/需订阅的网站（如 IEEE、ScienceDirect、知网等），可能导致 PDF 下载失败。
     
     如果下载失败，您是否接受以下降级方案？
     - 将分析模式从"深度蒸馏"降级为"快速阅读"
     - 我将在全网搜集该论文的相关信息（标题、作者、摘要、核心结论等）
     - 基于搜集到的信息形成总结文档
     
     请选择：
     1. 接受降级方案，继续处理
     2. 不接受，我将自行寻找其他途径获取 PDF
     3. 取消本次任务
     ```

   - **若用户选择"接受降级方案"**：
     - 使用 WebSearch 全网搜索该论文的相关信息
     - 搜索关键词包括：论文标题、作者、DOI、"filetype:pdf"
     - 优先搜索 arXiv、ResearchGate、作者个人主页等可能提供公开版本的渠道
     - 基于搜索结果提取可用信息
     - 执行"快速阅读"级别的蒸馏（M1 + M2 精简版）
     - 在生成的文档中明确标注："[!] 本文档基于全网公开信息整理，非完整 PDF 分析，部分细节可能缺失"

   - **若用户选择"不接受，自行寻找"**：
     - 提示用户："请提供该论文的 PDF 文件，或寻找其他公开渠道获取 PDF 后再次提交"
     - 终止当前任务

   - **若用户选择"取消"**：
     - 终止当前任务

### 步骤 3: 三层六模块深度蒸馏（M1–M6）

#### M1: 结构化元数据提取

| 字段 | 提取策略 |
|------|---------|
| 标题 | PDF 首页大字号文本或元数据中的 Title 字段 |
| 作者 | 标题下方的作者列表，逗号或换行分隔 |
| 机构 | 作者姓名后的上标或括号内机构名称 |
| 来源 | 期刊/会议名称（通常在页眉页脚或首页底部） |
| 年份 | 出版年份（从来源或 DOI 中提取） |
| DOI | 若有则提取，否则标注"未找到" |
| 页数 | PDF 总页数 |
| 语言 | 检测主要语言（中文/英文） |

**自动生成快速标签**：
- 学科分类：根据标题和摘要关键词判断（如 #NLP #计算机视觉 #强化学习）
- 研究方法：识别研究类型（如 #实证研究 #理论分析 #综述 #案例研究）
- 核心技术：提取关键技术术语（如 #Transformer #注意力机制 #深度学习）

#### M2: 逻辑骨架还原

**论证链条重构**（用简洁语言概括）：
```
 研究问题 →  理论基础 →  方法论 →  实验设计 →  主要发现 → [OK] 结论
```

**精简摘要生成**（150-200字）：
- 用通俗语言总结研究核心
- 突出创新点和关键结论
- 避免过多技术细节

**关键图表说明**：
- 提取重要图表的标题和简要说明
- 标注图表所在页码（便于用户回查原文）

#### M3: 引用文献网络（仅深度蒸馏模式）

提取参考文献列表中的**核心 10 条**：

```markdown
### 核心参考文献（Top 10）

1. 作者. 标题. 期刊/会议, 年份.
2. ...
```

- 优先选择被多次引用的经典文献
- 标注近 3 年的最新研究
- 若原文有"Related Work"章节，优先提取其中提到的关键文献

#### M4: 批判性思考（仅深度蒸馏模式）

基于内容进行快速分析：

**研究缺口识别**：
- 该方法未覆盖的场景或限制条件
- 实验设计的不足之处（如数据集规模、评估指标单一）
- 未讨论的潜在问题

**局限性分析**：
- 计算复杂度或资源需求
- 泛化能力限制（特定领域/数据集）
- 理论假设的合理性

**可能的改进方向**：
- 方法层面的优化建议
- 实验设计的扩展思路
- 跨领域应用的潜力

#### M5: 知识图谱关联（仅深度蒸馏模式）

**前置知识提示**：
- 理解本文需要的基础概念（2-3 个关键点）
- 相关技术或理论的简要说明

**同类方法对比**（若文中提到基线方法）：

| 方法 | 核心思路 | 优势 | 劣势 |
|------|---------|------|------|
| 本文方法 | ... | ... | ... |
| 基线方法1 | ... | ... | ... |

**领域定位**：
- 用 1-2 句话说明该研究在领域中的位置
- 例如："这是将 Transformer 应用于时间序列预测的最新尝试，继 Informer 和 Autoformer 之后的又一重要进展"

#### M6: 温书恒证据-论点映射钩子（G2 证据映射门 · 深度蒸馏模式自动衔接）

**目的**：将本蒸馏报告字段对齐温书恒 `obhrm-literature-review` 的证据-论点映射（`../../knowledge/evidence_claim_map.json`），作为温书恒 **G2 证据映射门**（证据-论点映射准入门）的输入，并为 G3 提纲结构门（文献链闭环）提供支撑。门控编号以 `../../knowledge/stage_gates.json` 为真源：G2 = 证据映射门（position ④论证评估 → ⑤拟定提纲前）；G3 = 提纲结构门。

**字段对齐**（蒸馏报告 → 温书恒 G2 证据映射门输入，列名与 `evidence_claim_map.json` 列定义对齐）：

| 本 micro-skill 字段 | 温书恒 G2 证据映射门字段 | 说明 |
|---|---|---|
| M1 元数据（标题/作者/年份/来源）| `citation[]`（对齐 Citation 列） | 文献引用条目 |
| M2 论证链条（问题→方法→结论）| `claim_chain[]`（对齐 Supported claim 列） | 论点链 |
| M3 Top 10 引用文献 | `related_works[]` | 关联工作列表 |
| M4 研究缺口 | `gap_claim` | GAP 论点（empirical / theoretical）|
| M5 领域定位 | `paradigm_position` | 范式定位 |
| 原始 PDF 路径 / URL | `source_url` | 来源追溯 |

**调用方式（衔接语义）**：
- **深度蒸馏模式默认自动衔接**：蒸馏报告生成后，将 M6 字段并入证据-论点映射（`../../knowledge/evidence_claim_map.json`），作为温书恒 G2 证据映射门输入。
- **报告生成后询问一次是否衔接（可取消）**：温书恒在报告生成后向用户询问一次是否衔接；用户选择"否"则仅保留本地报告文件，不做衔接。
- L3 阅读分类运行时产物（`<用户工作目录>/README.md`，由 `skill:obhrm-research-base` 的 `scripts/build_readings.py --codes` 写入，非技能包文件）中的 evidence-claim 条目即 M6 字段的落点；L3 阅读密码见 `../../knowledge/reading_codes.json`（SPL/CPL/GAP/RAT/ROF）。

## 输出规范

### 交付物形式

- **主要产物**：本地 Markdown 报告文件（结果面板自动呈现）
- **报告命名**：` 论文速览：{论文标题}`（标题前缀保留以保持可读性）
- **报告内容**：根据用户选择的蒸馏级别生成相应内容
- **（深度蒸馏模式默认自动衔接）** 报告生成后由温书恒询问一次是否衔接（可取消）

### 质量标准

1. **速度优先**：单篇文献处理时间控制在 1-2 分钟内
2. **核心准确**：M1 元数据和 M2 论证链条必须准确
3. **简洁可读**：避免冗长描述，用列表和表格呈现
4. **可追溯性**：明确标注原始 PDF 路径或 URL 和页码引用
5. **实用导向**：M4/M5 提供 actionable 的洞察和建议
6. **透明标注**：若为降级方案，必须在文档中明确标注数据来源限制
7. **零第三方依赖**（强制）

### 关键约束

- [OK] **支持多种输入**：接受本地 PDF 文件和在线学术链接
- [OK] **用户目的确认**：处理前必须询问用户分析目的
- [OK] **非开源链接处理**：检测到非开源链接时必须询问用户是否接受降级方案
- [OK] **本地 Markdown 输出**：必须写入本地报告文件并告知路径，禁止仅在对话中输出全文
- [OK] **不虚构信息**：缺失字段明确标注"未找到"
- [OK] **区分事实与推断**：M4/M5 标注为分析观点
- [OK] **保留原文引用**：关键结论使用原文表述并加引号
- [X] **不调用任何第三方在线文档 SDK**
- [X] **不处理加密 PDF**：提示用户先解密
- [X] **不处理损坏文件**：记录错误并告知用户
- [X] **不做深度学术评审**：仅提供快速浏览和初步洞察

## 常见问题处理

| 场景 | 处理方式 |
|------|----------|
| PDF 为扫描版（图片型） | 提示用户："检测到扫描版 PDF，文本提取效果可能不佳，建议使用 OCR 工具预处理" |
| 某字段提取失败 | 在报告中标注"未找到"，继续处理其他字段 |
| 参考文献格式混乱 | 尽力标准化，无法标准化的保留原样 |
| 文件过大（>50MB） | 提示用户："文件较大，解析可能需要较长时间，是否继续？" |
| 用户需要批量处理 | 参见 `distill_batch.sh` 脚本 |
| 在线链接无法访问 | 使用 WebSearch 搜索该论文的替代来源 |
| 非开源链接且用户拒绝降级 | 提示用户提供 PDF 文件或寻找其他公开渠道 |
| 降级方案信息不足 | 在文档中标注"部分信息缺失，建议获取完整 PDF 后重新分析" |
