# 验证协议

> 核心理念：声称完成必须有验证证据（DOI 三态标注 + 期刊来源核验）。

---

## 核心原则

**声称完成而没有验证，是不诚实的表现。**

没有验证证据，就不能声称完成。

---

## 验证门控流程

在声称任何状态或表达满意之前：

1. **确认**：什么命令/操作能证明这个声称？
2. **执行**：运行完整的验证操作
3. **读取**：完整输出，检查结果
4. **验证**：输出是否确认声称？
   - 如果否：说明实际状态和证据
   - 如果是：说明声称和证据
5. **然后才能**：做出声称

跳过任何步骤 = 撒谎，不是验证。

---

## 证据链三态标注

在上述五步门控的"读取→验证"环节，对每一条引用的证据链必须落到三态之一，并与门控串联：任一引用未达"已核实"即不得声称综述完成。

| 三态 | 含义 | 门控动作 |
|------|------|----------|
| [通过] 已核实 DOI | 已获取原文、DOI 可核实、观点归属已证实 | [绿/通过] 可进入成稿 |
| [注意] 未获取原文 | 引用条目存在但原文未取得，无法核对具体论断 | [红/不通过] 置于报告顶部待补；如引用须显著标记「来源未经确证」（本库不保证其真实性，严禁编造出处） |
| [注意] 未证实归属 | 已见原文但该观点是否出自该作者尚未证实 | [红/不通过] 标红待研究者核实；如引用须显著标记「来源未经确证」（本库不保证其真实性，严禁编造出处） |

**串联规则**：所有"未获取原文 / 未证实归属"项须统一列在报告顶部的待办清单，与五步门控的第 4 步（验证：输出是否确认声称）联动——存在任一 [红/不通过] 项时，第 5 步"做出声称"须先在正文显著标记「来源未经确证」并经自我核查（本库不保证其真实性，严禁编造出处）。这与 `../knowledge/red_flags.json` 的验证场景「论断有引用但未做证据链核查 → [红/不通过]」一致。

## 验证场景对照表

| 声称 | 需要的验证 | 不充分 |
|------|----------|--------|
| 综述完成 | 字数统计、结构检查、closed_loop_check.py 通过 | "应该写完了" |
| 引用真实 | DOI 可访问、CrossRef API 确认 | "看起来像真的" |
| 论点有支撑 | evidence-claim map 中有段落级证据 | "这段写得像综述" |
| 格式正确 | 运行 format_references.py | 目测检查 |
| 无AI痕迹 | 运行 closed_loop_check.py | "读起来还行" |
| 文献搜索完成 | 结果数量、DOI 列表、JSON 文件存在 | "搜过了" |
| 综述结构完整 | 五要素覆盖检查（动机/定位/问题/框架/边界） | "看起来有" |

---

## 借口与事实

| 借口 | 事实 |
|------|------|
| "应该行了" | 运行验证命令 |
| "我很确信" | 确信 != 证据 |
| "就这一次" | 没有例外 |
| "格式检查过了" | 格式检查 != 内容正确 |
| "代理说成功了" | 独立验证 |
| "我累了" | 疲劳不是借口 |
| "部分检查够了" | 部分证明不了什么 |

## 关键验证模式

### 章节完成验证

```
[通过] [运行字数统计] [看到：5000字] "章节字数达标"
[通过] [检查文件存在] [看到：draft.md 存在] "文件已创建"
[通过] [运行闭环检查] [看到：0 violations] "自检通过"
[不通过] "应该写完了" / "看起来完整"
```

### 引用验证

```bash
# 第一步：通过平台 WebSearch/WebFetch 逐条查询 DOI（CrossRef API）并保存为 crossref.json
# 第二步：离线生成三态引证报告
python skills/obhrm-methodology/scripts/format_citation_report.py draft.md --crossref crossref.json --readings READINGS.md

# 输出示例：
# [通过] 文献一 — DOI: 10.1000/xxx — 验证通过
# [不通过] 文献二 — DOI 不可达 — 需人工核实
# [注意] 文献三 — 无 DOI — 建议补充
```

### 论点支撑验证

```
[通过] [检查 evidence-claim map] [看到：每个核心论点对应>=1条来源] "论点有支撑"
[通过] [检查 citation slot] [看到：段落P2使用 E05+E07] "引用位置明确"
[不通过] "相关工作看起来完整" / "这段有学术感"
```

### 文献搜索验证

```bash
# 第一步：通过平台 WebSearch/WebFetch 获取学术 API 检索结果并保存为 raw.json
# 第二步：离线去重、排序与格式化输出
python skills/obhrm-methodology/scripts/format_search_results.py --input raw.json --query "transformational leadership creativity" --limit 20 --format json -o results.json

# 验证结果
# [通过] [检查 JSON 文件] [看到：20条结果，每条有DOI] "搜索完成"
# [不通过] "搜过了" / "应该有结果"
```

## 验证检查清单

每项工作完成前必须验证：

- [ ] 运行了验证命令
- [ ] 读取了完整输出
- [ ] 确认结果支持声称
- [ ] 没有依赖"应该"或"可能"
- [ ] 证据在当前消息中呈现

---

## 底线

**验证没有捷径。**

运行命令。读取输出。然后才能声称结果。

这是不可协商的。
