# 返修回应信 QA 审计清单（rebuttal-audit）

> 定位：对**已写好的返修回应信草稿**做逐条审计（per-comment coverage + gaps + risk flags）。
> 与 C10 返修回应信（生成）互补：C10 负责"写"，本清单负责"审"。
> 触发：用户已有回应信草稿，要求"审计我的回复 / 检查是否遗漏审稿人意见 / 评估回复质量"。
> 注意：本清单只做 QA 审计，**不重新生成回复**；如只有审稿意见无草稿，请走 C10 生成。

## 审计步骤

### Step 1：意见清单对齐（coverage）
1. 读取审稿意见原稿，逐条编号（R<审稿人序号>-<意见序号>，与 C10 编号规则一致）。
2. 读取回应信草稿，逐条标记"已回应 / 未回应 / 部分回应"。
3. 输出覆盖率表：

| 意见编号 | 审稿人核心关切 | 是否已回应 | 回应位置 | 风险 |
|---------|--------------|-----------|---------|------|
| R1-01 | … | [OK] | 第2节 | 低 |

### Step 2：逐条质量检查（每条回应 5 项）
- [ ] **直接回应**：是否正面回答意见，而非绕开或模糊带过？
- [ ] **证据支撑**：回应的修改是否有稿件对应位置（页码/行号/章节）？
- [ ] **新结果标注**：如有补充实验/分析，是否明确标注"新增"？
- [ ] **未完成项诚实**：无法完成的事项是否如实说明原因，而非声称完成？
- [ ] **语气合规**：是否保持专业克制，无过度承诺（如"保证录用"）？

### Step 3：风险标记（risk flags）
-  **遗漏意见**：审稿人提出但回应信未覆盖 → 必须补。
-  **回应不一致**：回应声称的修改与稿件实际不一致 → 核对。
-  **语气过强**：对批评性意见使用辩解/对抗语气 → 重写。
-  **证据缺口**：回应提及新结果但无对应材料 → 补充。

### Step 4：输出审计报告
```
覆盖率：X/Y 条意见已回应（Z 条部分回应）
遗漏意见：[列出编号+原文关切]
风险项：[/ 列表]
总体判断：通过 / 需补 Z 条 / 建议重写
```

## 边界
- 只审计**已有草稿**，不生成新回复（生成走 C10）。
- 不弱化审稿意见原语气，不替作者做学术判断（如"是否补实验"由作者决定）。
- 无法定位修改位置的条目标为"待核验"。
