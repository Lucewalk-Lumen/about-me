## 闭环 1：诊断结果自动回灌

### 触发规则

当用户在同一个会话中先执行了 审稿路径（诊断），再执行 论文/基金路径（生产），AI 必须执行以下规则：

**第 1 步**：从诊断中提取「诊断摘要」
- 列出 审稿路径诊断中发现的所有问题（按严重程度分类）
- 标注每个问题的归属阶段（如：选题/A1、文献/A2、理论/A3……）

**第 2 步**：生成「预防检查清单」
- 将 审稿路径发现的问题转化为 A/基金路径的前置检查项
- 例如：审稿路径发现「假设缺乏竞争假设」→ A3 阶段自动附加「请在输出每条假设时同时给出竞争假设」

**第 3 步**：注入执行过程
- 在 论文/基金路径对应的阶段加载预防检查清单
- 该阶段完成后，额外检查历史诊断中该阶段曾出现的所有问题是否已避免

### 回灌示例

```
审稿路径诊断发现的问题：
- [A1] 选题缺乏反直觉性
- [A3] 假设缺乏竞争假设
- [A4] 未考虑共同方法偏差
- [A5] 多处使用「大量研究表明」虚指

→ 下次执行 论文路径时自动注入：
  A1 阶段：额外加载「你是否有一个反直觉的研究谜题？」检查
  A3 阶段：每条假设强制要求标注 1 个竞争假设
  A4 阶段：强制完成「内生性威胁自检清单」
  A5 阶段：执行「AI 痕迹检测」后输出
```

## 闭环 2：内置轻量版诊断

### 设计理念

在每个 A/B 阶段输出完成后，不等待用户主动要求诊断，而是自动运行一个「轻量版 审稿路径诊断」。

轻量版诊断：
- [通过] 消耗更少的 token（约标准诊断的 20%）
- [通过] 仅覆盖当前阶段的范围
- [通过] 输出简洁的评分 + 关键警告
- [不通过] 不生成完整诊断报告
- [不通过] 不包含审稿意见格式化

### 轻量版诊断的 7 维度快速评分

每个阶段输出后，自动评分（1-5）：

| 维度 | 当前可评分的阶段 |
|------|-----------------|
| 选题质量 | A1/B2 |
| 文献覆盖 | A2/B3 |
| 理论深度 | A3/B4 |
| 方法严谨 | A4/B5 |
| 写作质量 | A5/B7 |
| 创新程度 | A1-A6/B1-B6 |
| 发表潜力 | A6/B8 |

### 红灯/黄灯规则

- **红灯**：任何维度 ≤ 2 分 → 自动建议「当前阶段输出可能存在严重问题，建议在当前阶段修正后再继续」
- **黄灯**：任何维度 = 3 分 → 记录但不阻断，在下一阶段开始前提示「上一阶段有改进空间」

## 闭环 3：高频缺陷知识库

### 设计理念

通过 审稿路径诊断积累识别出的高频问题，形成「缺陷模式库」。当 A/基金路径执行到对应阶段时，这些模式自动被激活为预防规则。

### 高频缺陷模式表

| 编号 | 缺陷模式 | 出现阶段 | 触发条件 | 预防规则 |
|------|----------|----------|----------|----------|
| DEF-001 | 假设无竞争解释 | A3 | 输出假设时 | 每条假设必须标注 1 个竞争假设 |
| DEF-002 | 文献虚指 | A2/A5 | 输出含「研究表明」 | 强制替换为「作者(年份)发现」 |
| DEF-003 | Gap 泛化 | A2 | 输出含「研究较少」 | 必须说明「什么条件下什么结论不成立」 |
| DEF-004 | 方法描述不具体 | A4 | 输出含「采用问卷法」 | 必须说明「量表来源+时间点+分析技术」 |
| DEF-005 | 贡献泡沫 | A5 | 输出含「首次」「创新性」 | 改为「与 XX(年份)不同，本研究」 |
| DEF-006 | 理论匹配浅 | A3 | 输出理论模型 | 必须填写 Whetten 四问 |
| DEF-007 | 文献链不足 | A2 | 文献链 < 3 条 | 强制要求 ≥ 3 条文献链 |
| DEF-008 | 样本量无论证 | A4 | 提及样本量但无理由 | 要求 G*Power 或经验法则论证 |
| DEF-009 | 统计报告不标准 | A5 | 报告 p 值/效应量时 | 按 APA 7.0 统计报告标准检查 |
| DEF-010 | 虚构文献嫌疑 | A2/C4 | 引用不完整的文献 | 要求补充 DOI/卷号/页码 |

### 使用方式

执行 A/基金路径时，AI 在进入对应阶段后，自动检查以上「缺陷模式表」，匹配当前阶段的预防规则，并将其作为该阶段的额外约束。

## 闭环 4：用户写作风格学习

### 设计理念

长时间多次使用后，AI 应学习用户个人的写作风格特征，在写作阶段（A5/B7）自动适配。

### 学习维度

| 维度 | 具体学习内容 | 学习方式 |
|------|-------------|----------|
| 句子长度 | 用户偏好短句（15-25 字）还是长句（30-50 字）？ | 分析用户提供的已有文档 |
| 段落结构 | 用户偏好短段落（3-5 句）还是长段落（8-12 句）？ | 同上 |
| 术语偏好 | 用户用「建言行为」还是「员工建言」？「组织公民行为」还是「OCB」？ | 追踪用户使用的术语变体 |
| 语气风格 | 用户偏好肯定语态（「我们发现」）还是谨慎语态（「结果倾向于表明」）？ | 分析 hedging 使用频率 |
| 引用习惯 | 用户偏好「作者(年份)」还是「(作者, 年份)」引用格式？ | 分析引用句式模式 |

### 应用规则

- 写作阶段开始时，如果已有用户文档，先分析并记录上述 5 个维度的特征
- 在输出文本时，默认匹配已学习的风格特征
- 如果风格特征与目标层级要求冲突（如用户喜欢长句但目标期刊要求简洁），以目标层级要求为准，但向用户说明冲突
