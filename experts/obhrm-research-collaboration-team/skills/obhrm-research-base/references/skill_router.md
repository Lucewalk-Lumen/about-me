# 路由中枢：此刻研究进行到哪一步

> 本文件是入口文档 `../SKILL.md` 的**路由子系统（路径级）**：用户带着研究场景进来，按本表判定入口**域文件**、阶段序列与执行要点。与 `skill_refs.md`（文档级触发映射）分工：**router 管"研究到哪条路径"（路径级），refs 管"路径内加载哪些 references 文档"（文档级）**——两文件职责互补，不重复。
> 详细规则（方法层真源、蒸馏三落点、协作交接、字数/门控）见 `skill_rules.md`；文档级触发映射见 `skill_refs.md`。

## 路由顺序硬性原则

用户带着研究场景进来，**先按研究生命周期阶段从① ② ③ ④ 顺序判定**，再读对应域文件。> 生命周期阶段→域映射的**机器可读定义即本表**（本表在其上补充语言/文件触发维度，不重复 stage 语义）。

**判定依据 = 用户的话（语言触发）或上传的文件（文件触发）**：
- 语言触发看关键词（"帮我写""审一下""分析这份数据"）
- 文件触发看文件类型（Word/PDF 草稿→写作或审稿、数字型数据文件（CSV 等）→定量分析、访谈稿/田野笔记→质性分析）

**关键路由规则**：
- **综述路径 = ① 入口硬挂钩**（找 GAP 与收敛选题必须经综述）
- **基金路径 = ① + ② 联动**（写基金前先完成 GAP 识别再进 B1 立项）
- **质量自检（投稿前轻量）与去 AI 改写（成稿后深度）= 两条不同强度路径**，不混用
- **审稿路径的量化版/质性版分支由稿件类型自动判定**——稿件含质性方法（扎根/案例/访谈）→ 质性版；否则 → 量化版

> **触发→执行的最小闭环**：下表每行都是「用户说/传了什么 → 你该读哪个域文件 → 按哪个阶段序列执行」。**大模型不知道怎么做时，就按本表定位入口文件，读完后逐阶段推进**——不要跳步、不要自己发明流程。

## 关键路径定位说明

> **综述路径的生命周期定位**：文献综述首要服务于 **① 问题从哪来**——通过系统梳理文献寻找研究 GAP、收敛选题；同时支撑 ②（成稿后回灌引言/相关工作）与 ④（独立产出综述成稿）。综述路径已拆分为独立兄弟技能 `../../literature-review/`（顶层独立域），**所有 ① 阶段入口必须先经综述路径**。论文路径（论文生产）从 A0 头脑风暴起即应联读综述路径；基金路径（基金）从 B1 立项依据起即应联读综述路径。

> **基金路径的双阶段属性**：基金路径同时跨 ①（立项依据 = GAP 识别+前沿综述）与 ②（怎么做成研究 = 技术路线+可行性）。**写基金不等于直接进基金路径**——必须先完成 GAP 识别（综述路径 L3），再 B1 起立项。这一点对国自科/国社科尤其关键：评审第一关就是"立项依据是否紧迫、是否识别了真 GAP"。B 域方法学已下沉到 `../../grant-writing/references/goal_hierarchy_rules.md`。

> **去 AI 双路径边界**：`quality-assurance` 的「AI 痕迹 ①-⑤ 轻量自检」是**投稿前 1 步快扫**（1-2 分钟，结果是评分块），与 `humanize` 的「成稿后深度改写」是**不同动作**——前者是"打多少分"，后者是"逐句改写"。**用户说"改自然"→ 走 humanize 深度改写；用户说"查一下 AI 味"→ 走 quality-assurance 轻量评分**。

> **同行评审唯一真源：本技能 审稿路径 = 评审标准唯一出处**。零外部审稿包、零第二份审稿 SOP。审稿改进只改本技能 审稿路径。

> **数据分析域三分支**：数据分析路径内部按证据形态分三个子分支——**定量·一手**（t/ANOVA/回归，处理研究者自采的数字型数据）、**定量·二手**（效应量聚合，处理已发表研究的数字型结果）、**定性·质性**（扎根理论/案例/访谈，处理文字型数据）。三者同属兄弟技能 `../../data-analysis/` 父域，**共同回答"怎么证明结论成立"，但方法族互不混用**：数字型数据文件（CSV/Excel）→ 定量分支；文字型数据文件（访谈稿/田野笔记）→ 定性分支。

> **审稿路径的多版本机制**：审稿路径分**量化版**（默认；八维评分 + 种子缺陷 + Trust Boundary）与**质性版**（`path_type: C-qualitative`；八维 = 6 维通用 + 方法严谨重写为 5 子项 + 新增"质性特异性"5 检查项）。下游脚本判定质性稿件须改为 `path_type == "C-qualitative"` 或 `path_type.startswith("C")`。详见 `../../peer-review/SKILL.md`。

> **双桥接层职责切分（消除重复入口）**：本包有两层"构念↔资产"桥接，**职责已明确切分、不重复**——(1) **obhrm-bridge（概念入口层 · 人类用语）**：用户用自然语言概念词（如「情感」「领导力」）查询时，经 `query_concept.py` 一次返回「教材锚点 + 理论 + 量表 + R 方法」四库联动，是"某构念连哪些理论/量表/方法"的**首选人类入口**（覆盖 107 概念词表）；(2) **knowledge-graph（构念索引层 · 程序/ID）**：已知 `construct_id` / `scale_id` / `theory_id` 或需取 scale↔theory 关联边（62 条边）与 134 构念聚合节点时，经 `query_graph.py` 做精确索引，用于假设推导确认构念根基、方法适用性判定等**程序化/精确 ID** 场景。**判定口诀：用"词"问人话 → obhrm-bridge；用"ID"做精确/批量关联 → knowledge-graph。** 两者不得互相替代，亦不得在同一诉求中双调。

> **Agent 与 Skill 的层级边界（防职责漂移）**：**Agent = 角色/路由器**（主理人沈知行与六位团员是"谁来做、按什么顺序做"的编排层，不持有资产真源）；**Skill = 真源/能力**（量表/理论/R/教材/期刊/桥接/索引等资产与检索入口的唯一出处）。任一专业结论须由对应 Agent 经对应 Skill 的检索脚本取回后再采信——**禁止 Agent 凭记忆编造资产内容，禁止 Skill 越权编排任务**。本路由中枢只管"研究到哪条路径 + 调哪个 Skill 取真源"，不替代任何 Agent 的调度职责。

> **entities.json 用途声明**：`theory-library/knowledge/theories/entities.json` 与 `scale-library/knowledge/scales/entities.json` 是各自资产库的**合并扁平记录图**（全量 Txxx/Sxxx 以 ID 为键汇于单文件），专供**整库批量扫描/跨记录比对**使用，与逐条 `Txxx.json`/`Sxxx.json` 原文文件、`_theory_index.json`/`_scale_index.json` 概览索引三者并存、互不替代：逐条精读走单文件，快速概览走 `_*_index.json`，整库扫描走 `entities.json`。检索脚本内部自动择源，调用方无需手动读取本文件。
