> 本文件是入口文档 `../SKILL.md` 的规则子系统：方法层真源、蒸馏三落点、协作交接 15 条链路、引用保真四铁律、字数/阶段门控。

## 方法层真源对齐

方法论层判断（缺口类型、理论视角选用、贡献类型、论证链标准、综述方法、质量闸门）以**本技能 `references/` 为唯一真源**——套件内理论视角/缺口/贡献/论证/闸门各 reference 即执行依据，独立分发、零外部依赖。

- **唯一真源**：本技能 `references/` 为方法论层与执行层共同唯一真源，不在包外寻找第二处标准。
- **演融入口**：发现方法论层教训不要直接改文档——走本技能「distillation 域」（详见 `../domains/distillation/distillation.md`，三落点判层：方法论层 → `governance/method_accumulation.md`；操作层 → 对应 reference；路径内层 → 对应 `domains/<path>/<path>.md`），各自留痕、可回滚。

| 教训形态 | 落点 | 文件 | 写前动作 | 验证门槛 |
|---------|-----|------|---------|---------|

> **改前必看**：详见 `../domains/distillation/distillation.md` 四阶段法（候选标记 → 三重验证 → 判层三落点 → 版本备份 → 写前自检 → 用户确认）。

## 协作与交接协议（十五条链路，跨路径不丢信息）

各功能路径（论文/基金/审稿/数据分析/综述/选刊）+ distillation 之间的信息流转，字段级规格见 `templates/handoff-protocol.md`（跨路径任务必读）：

1. **论文→数据分析 委托分析**：论文路径（论文）交付假设清单+变量表+数据文件 → 数据分析路径（定量一手）按 D1–D4 检验 → 结果回传（链路 2）。
2. **数据分析→论文 结果回传**：数据分析路径交付 APA 统计结果+检验决策+图表登记 → 论文路径写 A5 结果与讨论，续接可追溯矩阵。基金路径预研数据同理（数据→基金）。
3. **写作→评审（写作→审稿）**：论文/基金路径交付稿件+可追溯矩阵+自检 → 审稿路径独立八维诊断（同包内交接，零转换损耗；质性稿件自动走 审稿路径质性版）。
4. **评审→返修（审稿→写作）**：八维诊断+严重程度分级+返修方向 → 论文路径建返修对照表逐条处理。
5. **返修→再审（写作→审稿 C9）**：修改稿+回应函 → 审稿路径 C9 逐条核验。
6. **任意→蒸馏（→蒸馏块）**：任何路径产生可复用教训 → 标记候选 → distillation 路径先判层（三落点：方法论层/操作层/路径内层）再落点（链路六）。
7. **论文↔综述 综述协作**：论文写作中用户要「单独产出一篇综述」或「先搞定文献综述章节」→ 移交综述路径主导（七阶段）；成稿后回灌论文引言/相关工作 → 交回论文路径续写（链路七）。
8. **A6→选刊 / 选刊→审稿 适配**：论文进入 A6 投稿 → 移交选刊路径做选刊匹配（13 标准画像+粗略推荐）；评审后亦可由审稿路径反查候选刊适配度；若候选刊对方法/格式有特殊要求 → 回审稿路径微调稿件（链路八）。
9. **元分析→论文 / 元分析→基金 结果回传**：元分析完成后回论文 A5 Discussion / 基金 B2 立项依据的字段级规格。
10. **一手定量→元分析 桥接**：数据分析路径定量一手证据不足以独立成文时，转 定量二手（元分析）作为输入研究的字段级规格；效应量嵌套处理复用 `../../data-analysis/quantitative/references/methods-knowledge.md` §2.9（元分析；方法族总览见枢纽 §1）。
11. **D→Q 量化补质性**：数据分析路径一手量化结论需质性证据补充/解释时，转质性分析路径（Q1–Q5）的字段级规格。
12. **Q→D 质性浮现变量量化验证**：质性分析浮现的构念/关系需量化验证时，转数据分析路径做检验的字段级规格。
13. **Q→A 质性成稿回灌论文**：质性研究报告回灌论文质性章节 / 讨论的字段级规格。
14. **A→Q 论文嵌质性章节**：论文路径需嵌入质性研究章节时，转质性分析路径的字段级规格。
15. **Q→C 质性稿送审**：质性稿件送诊断审稿路径（质性版）的字段级规格。

> 全局闸门（引用保真 + 四铁律 + Trust Boundary + 蒸馏可回滚 + 方法论唯一真源）对所有路径恒定生效，交接产物同样受检，0 violations 才放行。

## 引用保真 + 四铁律

任何研究产出都必须满足：

1. **不编引用** — 引用必须真实可查（DOI / 数据库可验证），不补造、不"看起来合理"
2. **不归观点** — 文献观点归属到具体作者+年份，不归到"有研究表明"
3. **标注无支撑** — 没有支撑的论断必须显式标注"无支撑"（不静默漏过）
4. **不超范围** — 不替用户做学术决策（如不替人背书、不美化、不替单稿问题下"普适"判断）

## 字数与阶段门控

| 路径 | 每部分字数 | 关键确认点 |
|------|----------|----------|
| 论文路径 A | ≥ 300 字/节（分阶段细则见 `../../paper-writing/SKILL.md` 路径概览表） | A1（选题）/A5（成稿）/A6（投稿）必须停下来确认 |
| 基金路径 B | ≥ 300 字/节（分阶段细则见 `../../grant-writing/SKILL.md` 路径概览表，B2 ≥1500 字） | B1（立项）/B2（综述）/B8（摘要）/B9（成稿）必须停下来确认 |
| 审稿路径 C | ≥ 200 字/维（总评 ≥800 字） | C5（诊断）/C9（返修）必须停下来确认 |
| 数据分析 D/M | ≥ 300 字/段 + APA 报告 ≥800 字 | 输出完整 APA 报告 + 图表登记 |
| 质性研究 Q | Q1-Q4 ≥400 字/步 / Q5 ≥800 字 | 三级编码 + 学派声明 + 理论饱和证明 |
| 综述 L | L1-L6 ≥400 字 / L7 ≥300 字 | G1+/G2/G3/G5 门控 |
| 选刊 J | 单刊 ≥200 字 / 策略 ≥300 字 | 双模式推荐结果须确认 |
| 问卷 A4 | 每维度 ≥3 题 + 计分规则 ≥300 字 | A4 题项确认 |
| 蒸馏 DI | 候选 ≥300 字 / 方法论 ≥400 字 | DI-4 确认 |

> **唯一真源**：本表为全包字数门控唯一真源；各领域技能 `SKILL.md` 的「路径概览」表为分阶段细化（不得低于本表最小值），二者冲突时以本表为准。

> **关键节点 B1/B2/B8/B9、A1/A5/A6、C5/C9**：停下来问"A.继续 B.修改 C.暂停"，等用户选择。
> **普通节点**：告知下一阶段后自动推进。
> **C9 终点**额外问"结束 还是 改进"。
> **自检不过关最多改两轮**，两轮后告知用户卡在哪里，问是否接受。

## 全局严重度分级（P0/P1/P2）

把审稿路径已有的「严重度分级」提升为**跨路径统一闸门**（对齐 `quality_gates.json` 的 `severity_p0_p1_p2`）。任何路径交付前先按 P0/P1/P2 排序：

- **P0**：可能推翻核心结论、违反诚信/伦理/合规或阻止提交（未关闭占位符 / 缺失参考文献 / 编造引用 / Trust Boundary 违反）→ **阻断确认点**，0 才放行
- **P1**：核心结论可能成立，但证据 / 方法 / 报告 / 复现 / 材料完整性不足（超范围强化主张 / 未引用条目 / 状态谎报）→ **必须修复后放行**
- **P2**：语言 / 衔接 / 格式 / 展示问题，不影响核心结论（标题跳级 / 空泛表达 / 题注重复）→ 建议修复

> **严重度双体系映射**：内容严重度 4 级（必须修改 / 强烈建议修改 / 建议修改 / 可选改进，真源见 peer-review SKILL「C5 诊断格式」）为单条意见措辞；全局缺陷级（P0/P1/P2，本表）为交付前闸门分级。对应关系：必须修改 ≈ P1（必须修复后放行）；强烈建议修改 ≈ P1/P2（视证据影响）；建议修改 ≈ P2（建议修复）；可选改进 ≈ P2（可选）。P0 不落入内容严重度，专指推翻结论 / 诚信伦理 / 占位符 / Trust Boundary 类阻断项。

> 与 `templates/traceability-ledger.md` 的状态机联合使用：P0 项对应 `blocked` 就绪态，`VERIFIED_DONE` 要求可检查产物。

## 可追溯账本（稳定 ID + 工作状态机）

把既有「贡献→假设→结果→图表」可追溯矩阵从概念落成**可执行机制**：跨路径产物用稳定 ID 串联（`S` 材料/`L` 文献/`C` 主张/`D` 数据/`F` 图/`T` 表/`A` 外部/`E` 编辑/`R` 审稿/`V` 修订，一次分配固定不复用）、用统一状态机标记完成度（`VERIFIED_DONE` 等 7 态）与就绪度（`ready_to_submit` 等 4 态）。**ID 全集、状态枚举、字段规格的唯一真源为 `templates/traceability-ledger.md`**（判层为套件操作层，向后兼容）；长周期/跨路径任务直接复用 `templates/traceability-ledger.md` 作为轻量状态账本（00-scope → 06-revision-brief 按需拆分，字段与真源一一对应，无需独立目录）。

## 来源可信分级（M1/M2/F/U）

拿到什么层级材料就只能做该层级允许的动作，把「引用保真 + 四铁律·标注无支撑」落成内容层级契约。详见 `governance/source_trust_tiers.md`：

- **M1** 元数据：仅核验身份，不写结论 / 引语 / 页码
- **M2** 摘要：转述须标「基于摘要」，不写直接引语 / 页码 / 数值
- **F** 全文：核对原文位置后可做内容分析
- **U** 线索：记录待核验，不写入正文事实

## 5 步执行细则

**1. 明确产出**：阅读该阶段参考文档，确认所有输出要素。不知道规范是什么就看 `references/` 里对应的文件。

**2. 完整写出**：产出可直接使用的完整段落。如果超过 4000 字，可以分步输出，每步是完整的一节。

**3. 自检**：问三个问题——
- 该有的都写了吗？
- 每部分够详细吗？
- 有没有"大量研究表明""通常""可能"这类虚指需要替换？

**4. 标记完成**：输出「[阶段X 完成]」。

**5. 确认下一步**：见上方"关键确认点"表。

## 评审唯一真源：审稿路径

本技能 审稿路径 是评审标准唯一出处，评审标准本身仅依赖 Python 标准库（评审产出 Word 报告所需的外部包见 `DEPENDENCIES.md`），零第二处审稿 SOP：

- 内置：审稿路径全能力（种子缺陷库、Trust Boundary、C3 文献检索锚定、C5 评分块 defects_found+preventions_applied、C8 输出自检）以 `../../peer-review/SKILL.md` 为评审唯一真源、`review/review_criteria.md` 为种子缺陷唯一维护点；能力清单与条目见两文件，本文件**不重复维护**（防漂移）。
- Word 报告/PDF 清洗用本技能自有脚本（`../scripts/generate_review_docx.py` / `../scripts/clean_pdf_text.py`）；渲染/解析依赖 `requirements.lock` 中**已声明**的 Python 包（python-docx / pdfplumber 等），均已通过高危/严重级漏洞扫描并已归档物料清单，运行前需 `pip install -r requirements.lock`（缺失时脚本打印明确安装提示并以退出码 1 终止，不静默失败）。
- 审稿改进只改本技能，不设第二处审稿标准。
