## 1. AI 使用披露

### 必须披露的要素
- [ ] 已使用的 AI 工具名称（如 "Claude"、"GPT-4"、"Gemini"）
- [ ] AI 参与范围明确说明：
  - [ ] 文献检索辅助
  - [ ] 来源筛选
  - [ ] 证据综合
  - [ ] 初稿撰写
  - [ ] 编辑/修订
  - [ ] 数据分析
  - [ ] 翻译
- [ ] 人工监督描述（谁在哪个阶段审核了什么内容）
- [ ] AI 局限性已说明（可能产生幻觉、知识截止日期等）
- [ ] AI 版本/日期已记录（便于复现）

### 披露声明模板
```
AI 披露声明：本研究在 [AI 工具名称]（版本/日期）的辅助下完成。
AI 被用于 [具体任务]。所有研究发现均已由 [人工角色] 与
引用来源进行核实。研究团队对所有内容的准确性和解释承担全部责任。
```

### 披露位置
- 方法部分（详细说明）
- 摘要或作者注（简要说明）
- 脚注（针对特定 AI 生成的分析）

## 2. 引用诚信

### 引用伦理
- [ ] 每项事实性主张都有至少一个支持性引用
- [ ] 无虚构或幻觉参考文献
  - 核实方法：至少抽查 20% 的参考文献确认其存在性
  - 交叉核对 DOI、出版年份、作者姓名
- [ ] 改写是实质性的（非仅调换词语顺序）
- [ ] 直接引用准确并标注出处
- [ ] 思想归属到原始作者，而非转引来源
- [ ] 自引比例适当（不过度或排他性地引用自己）

### AI 相关引用风险

| 风险 | 描述 | 缓解措施 |
|------|------|----------|
| 幻觉参考文献 | AI 生成看似合理但实际不存在的引用 | 逐一与数据库核实每条引用 |
| 合并引用 | AI 将多个来源的细节混在一起 | 交叉核对每条引用的各要素 |
| 作者错误 | AI 将错误作者归到作品上 | 与实际发表记录核实作者姓名 |
| 年份错误 | AI 使用错误的出版年份 | 与数据库记录交叉核对 |
| 幽灵引用 | 参考文献列表中列出但正文中未引用 | 审计参考文献列表与正文引用的一致性 |

## 3. 双重用途评估

> **核心原则**：对具体可操作内容进行筛查，而非对研究主题本身进行判断。敏感的、政治性的或批判机构的**主题**不构成双重用途触发条件。公共利益研究——记录机构滥用、揭露监控实践、权力问责——必然会涉及有害主题，不得仅因主题而标记。只有当研究本身提供了**具体的可操作细节**，实质性地降低了造成危害的门槛时，才触发双重用途。

### 筛查问题
每个问题关注的是**本研究的具体内容**（而非主题）是否提供了具体信息：

1. 本研究是否提供了具体的操作细节，使读者能够**实施**对个人或社区的伤害（而非仅描述该伤害的存在）？
2. 是否披露了**具体的、当前可利用的**漏洞，并附带足够的利用细节（而非仅说明漏洞存在）？
3. 是否提供了构建监控或控制机制的**可用方法**（而非分析或批判这些机制）？
4. 是否包含**可武器化的具体信息**——配方、设计或程序——而非关于武器化风险的讨论？
5. 是否提供了歧视某一群体的**具体手段**（而非记录歧视现象的存在）？

如果答案依赖于"主题敏感"而非"文本中存在具体的可操作细节"，则等级为"无"。

### 风险等级与应对

> 本评估为**建议性**——引导至负责任使用声明，而非硬性阻断。仅诚信违规适用硬性阻断。升级依据具体可行规范，而非研究主题本身。

| 等级 | 所需行动 |
|------|----------|
| 无 | 无需额外行动 |
| 低 | 在局限性部分简要说明 |
| 中 | 在报告中添加负责任使用声明 |
| 高 | 显著警告 + 建议限制传播范围 |
| 极高 | 负责任使用声明 + 建议发表前经机构伦理委员会审查（建议性——不自动阻断；由人工而非 Agent 裁定极高等级标记） |

### 负责任使用声明模板
```
负责任使用声明：本研究旨在 [既定用途]。作者承认，与 [敏感领域]
相关的研究发现可能被以本研究未预期的方式加以利用。呼吁本研究的使用者
审慎考虑其应用所带来的伦理影响，并优先遵循 [具体伦理原则]。
```

## 4. 公平表述

### 平衡表述检查清单
- [ ] 争议性问题上呈现了多种视角
- [ ] 少数/异议观点未被忽略或不加讨论地驳回
- [ ] 研究对象和社区被准确描述
- [ ] 语言尊重、无污名化
- [ ] 在相关情况下承认文化背景
- [ ] 考虑了权力动态（谁研究谁）
- [ ] 来源涵盖地理和文化多样性

### 敏感主题的处理
- **原住民知识**：尊重 OCAP 原则（所有权、控制权、获取权、拥有权）
- **残障**：使用"以人优先"语言，除非社群偏好"以身份优先"
- **性别/性取向**：使用包容性、最新的术语
- **种族/族群**：使用所讨论社群偏好的术语
- **社会经济地位**：避免缺陷框架
- **心理健康**：避免污名化语言

### 表述审计问题
1. 谁的声音被置于中心？谁的声音缺失？
2. 社区是否被以自身的语言来描述？
3. 框架中是否存在隐性偏见？
4. 研究对象/社区是否能在该描述中认出自己？

## 5. 数据伦理

### 数据来源伦理
- [ ] 所有数据来源均为合法使用
- [ ] 公共数据：确认公共领域或适当许可
- [ ] 授权数据：使用符合许可条款
- [ ] 爬取数据：遵守 robots.txt 和服务条款
- [ ] 个人数据：符合 GDPR/隐私法（如适用）
- [ ] 机构数据：已确认授权访问

### 隐私保护
- [ ] 未经同意不包含个人身份信息（PII）
- [ ] 尽可能使用汇总数据
- [ ] 小样本组受保护，防止个体被识别
- [ ] 非公开机构的机构身份受保护
- [ ] 数据保留/删除计划（如为原始数据收集）

### AI 相关数据风险
- [ ] 已承认 AI 训练数据的偏差
- [ ] 已注明 AI 知识截止日期
- [ ] AI 生成的数据已明确标注
- [ ] 无循环引用（AI 引用 AI 生成的内容）

## 6. 利益冲突

### 需评估的冲突类型
- [ ] **经济利益**：资助来源、咨询关系
- [ ] **机构利益**：作者评估自己所在机构
- [ ] **学术利益**：作者为自己先前的工作辩护
- [ ] **个人利益**：与研究对象/利益相关者的关系
- [ ] **政治利益**：政府资助研究政府政策
- [ ] **商业利益**：行业关联或产品利益
- [ ] **AI 特定利益**：AI 工具公司对研究设计的影响

### 披露要求
任何已识别的利益冲突必须在报告中披露，并评估其是否可能影响了研究发现。

## 7. 可复现性伦理

### 文档记录要求
- [ ] 检索策略已记录（数据库、检索词、日期）
- [ ] 纳入/排除标准已记录
- [ ] 分析方法以可复现的详细程度描述
- [ ] AI 提示词/指令已记录（如相关）
- [ ] 数据处理步骤已记录
- [ ] 代码/脚本已共享（如适用）

### 可复现性声明模板
```
可复现性声明：本研究使用的检索策略、纳入标准和分析方法
已在 [章节/附录] 中详细记录。AI 辅助部分使用了 [具体提示词/参数]。
希望复现或拓展本研究的研究者请注意 [相关局限或条件]。
```

## 8. 人类受试者伦理

### 8.1 人类受试者判定
- [ ] 本研究是否收集、使用或分析与人相关的数据？
- [ ] 如果是，数据是否包含个人身份信息？
- [ ] 如果数据为公开可用且已去标识化，是否已与伦理委员会确认免审资格？

### 8.2 伦理审查等级

| 审查等级 | 适用条件 | 审查周期 |
|----------|----------|----------|
| **免审** | 公开数据、去标识化数据、匿名调查（无敏感主题） | 1–2 周 |
| **快速审查** | 最小风险、非脆弱人群、一般性调查/访谈 | 2–4 周 |
| **全委会审查** | 超过最小风险、脆弱人群、敏感主题、欺骗性实验 | 4–8 周 |

- [ ] 已确定适用的伦理审查等级
- [ ] 审查周期已纳入研究项目时间表
- [ ] 研究者已完成研究伦理培训（如 CITI 或同等课程）

### 8.3 知情同意
- [ ] 知情同意书包含研究标题、目的、程序、风险和收益
- [ ] 明确说明参与的自愿性（可随时退出，无惩罚）
- [ ] 提供研究者和伦理委员会联系方式
- [ ] 特殊情况已处理：
  - [ ] 在线调查：电子同意（点击"同意"）
  - [ ] 录音/录像：单独勾选项
  - [ ] 未成年人：法定监护人同意 + 受试者同意
  - [ ] 原住民研究：社区同意 + 个人知情同意

### 8.4 数据去标识化
- [ ] 移除直接标识符（姓名、学号、身份证号）
- [ ] 评估间接标识符风险（院系 + 年级 + 性别组合）
- [ ] 小样本再识别风险评估（小院系可能允许个体再识别）
- [ ] 从质性引文中移除可识别细节
- [ ] 加密数据存储并设置访问控制
- [ ] 建立数据保留和销毁时间表

### 8.5 脆弱人群保护

| 人群 | 额外保护措施 |
|------|-------------|
| **未成年人** | 法定监护人同意 + 适龄同意书 |
| **残障人士** | 评估同意能力，提供无障碍同意程序 |
| **学生（研究者为教师）** | 避免权力动态影响自愿性，使用第三方招募 |
| **原住民** | 社区协商与同意，尊重 OCAP 原则 |
| **经济困难者** | 报酬不得构成不当诱导 |
| **服刑人员** | 额外伦理审查，确保非强迫参与 |

- [ ] 已识别研究中涉及的脆弱人群
- [ ] 已规划相应的额外保护措施
- [ ] 伦理审查等级已考虑脆弱人群因素

> 伦理委员会审批流程请参考所在机构的具体伦理审查规定。

## 交付前快速自检清单

交付前确认以下所有项目（本检查为自检，非否决性）：

- [ ] AI 披露声明完整且准确
- [ ] 所有参考文献已抽查核实（至少 20%）
- [ ] 未检测到虚构引用
- [ ] 双重用途评估已完成
- [ ] 公平表述已审查
- [ ] 数据来源合法且合乎伦理
- [ ] 利益冲突已披露
- [ ] 可复现性文档已提供
- [ ] 写作语言包容且尊重
- [ ] 报告惠及目标受众且不造成可预见伤害

## 一、研究设计阶段：首次诚信检查（预审诚信审查）

**触发时机**：文献检索与理论建构完成后，进入评审诊断之前
**目的**：确保所有参考文献和数据在提交评审前无捏造或错误

```
执行步骤：
1. 对论文执行初始诚信验证
2. 验证范围：
 - 阶段A：100%参考文献存在性 + 书目准确性 + 幽灵引用检查
 - 阶段B：≥30%引用上下文抽查
 - 阶段C：100%统计数据验证
 - 阶段D：≥30%原创性抽查 + 自抄袭检查
 - 阶段E：30%论断验证抽查（至少10个关键论断）
3. 结果处理：
 - 通过 → 记录检查点 → 进入评审阶段
 - 未通过 → 生成修正清单 → 逐项修正 → 重新验证修正项
 - 修正后通过 → 记录检查点 → 进入评审阶段
 - 三轮仍未通过 → 通知用户，列出无法验证的项目
```

## 二、定稿检查阶段：终稿诚信审查（返修后终检）

**触发时机**：返修完成后、最终交付前
**目的**：确认修改稿100%正确，可交付发表

```
执行步骤：
1. 对修改稿执行终稿诚信验证
2. 验证范围：
 - 阶段A：100%参考文献验证（含返修中新增的引用）
 - 阶段B：100%引用上下文验证（不再抽查，全面检查）
 - 阶段C：100%统计数据验证
 - 阶段D：≥50%原创性抽查（新增/修改段落100%检查）
 - 阶段E：100%论断验证（零严重失实 + 零不可验证内容）
3. 专项检查：与研究设计阶段结果对比，确认先前问题全部解决
4. 结果处理：
 - 通过（零问题）→ 记录检查点 → 进入最终交付
 - 未通过 → 修正 → 重新验证 → 通过 → 最终交付
5. [注意] **铁律**：必须零问题通过才能进入最终交付
```
