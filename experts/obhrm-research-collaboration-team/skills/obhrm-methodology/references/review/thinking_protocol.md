# 三阶段推理协议（C6 联动）

> 注意：本文件为审稿路径 C6 三阶段推理协议，与 ../reasoning/thinking_protocols.md（通用推理协议）不同，勿混淆。

> 与 `multi_perspective_engine.md` 配套。本文档定义审稿推理的三阶段逻辑；引用均指向本技能现有文件。

## 阶段一：深度诊断

### 诊断思维
不满足于表面问题，追问：这个问题背后的理论逻辑缺陷是什么？作者为什么会这样处理？这种处理方式在方法论上有什么后果？

### 严重程度校准
| 如果... | 则... |
|---------|-------|
| 核心贡献会崩溃 | 必须修改 |
| 显著影响论文可信度 | 强烈建议修改 |
| 修改后质量明显提升 | 建议修改 |
| 锦上添花 | 可选改进 |

致命缺陷的额外检查：必要条件相关维度（理论贡献 / 方法论 / 实证证据）评分低于 **3.0/5** 时，其问题不能全部归入「建议改进」级。

## 阶段二：文献检索（R2 强制验证）

文献检索目的：验证作者声称的 gap 是否真实、发现遗漏的关键文献、判断研究在既有文献中的定位。
- 工作流（强制前置 + Phase A 自动 + Phase B [暂停] 用户导出 + 四类转化）详见 `r2_literature_verification.md`。
- 检索机制（怎么查）遵循 `../methods/evidence_retrieval_protocol.md`，可用平台 WebSearch/WebFetch 取数后经 `../../scripts/format_search_results.py` 整理。

## 阶段三：意见撰写

### 输出结构
总体印象 (1段)
  → 按论文流程的审稿意见（研究问题→引言→理论→方法→结果→讨论→伦理→写作）
    每个节点下用 1. 2. 3. 序号，严重问题排前
  → 六项 Emerald 评价总结
  → Recommendation

### 一致性校准
Recommendation 与最严重问题的级别匹配；≥3 个致命缺陷不能写 Minor Revision。

### 语气辩证法
批评要直接但不刻薄。指出问题→分析后果→给出方向。用证据而非情绪支撑判断。

## 三角色交叉审视（C6）

C5 逐项诊断完成后，以三角色交叉审视诊断结果（完整机制与冲突解决见 `multi_perspective_engine.md`）。

### 角色 1：审稿人（内容视角）
- 诊断是否覆盖了稿件的核心贡献和关键缺陷？
- 是否因对某个领域不熟悉而遗漏了重要文献？
- 语气是否符合学术共同体的表达习惯？

### 角色 2：方法审计师（技术视角）
- 研究设计能否真正检验作者声称的假设？
- 统计方法与研究设计是否匹配？
- 缺陷是否可以通过语言修正缓解，还是必须重做？

### 角色 3：主编（决策视角）
- 致命缺陷数量是否过多（≥5 时直接建议 Reject）？
- 对照 `review_criteria.md`「评审结论校准」：触发以下任一即建议 **Reject**：
  ① 核心贡献崩溃；② 必要条件维度存在致命缺陷且无法靠语言修正缓解；③ 学术诚信问题（Trust Boundary 命中）；④ ≥5 个「必须修改」级问题；⑤ 命中目标层级「一票否决」项（见 `review_criteria.md`「目标层级评审标准」）。
- Recommendation 是否与问题严重程度匹配？
- 如果作者认真修改，这篇论文有多大可能达到发表标准？

### 冲突解决
- 学术诚信问题：直接升级为致命缺陷，不得降级。
- 角色间冲突：以方法审计师的技术判断为准，主编的出版判断为辅。
