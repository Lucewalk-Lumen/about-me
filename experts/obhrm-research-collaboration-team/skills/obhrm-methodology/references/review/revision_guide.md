## 一、返修流程总览

收到审稿意见后，按以下 5 步执行：

1. **通读与分类**：逐条阅读审稿意见，按严重程度和修改类型分类
2. **制定修改计划**：确定每条意见的处理策略和对应位置
3. **逐条修改稿件**：按优先级执行修改，标记改动位置
4. **撰写返修回应信**：逐条回应审稿意见，说明修改内容和位置
5. **修改后自检**：确认修改无遗漏、无矛盾、格式合规

---

## 二、审稿意见分类

### 按严重程度分类

| 级别 | 含义 | 处理策略 |
|------|------|----------|
| **必须修改** | 影响结论可信度或录用决定 | 必须接受并实质性修改，不得仅解释 |
| **强烈建议修改** | 影响研究质量或审稿印象 | 优先处理，尽可能接受 |
| **建议修改** | 可提升但非致命问题 | 根据合理性选择性接受 |
| **可选改进** | 锦上添花 | 视时间和精力决定 |

### 按修改类型分类

| 类型 | 说明 | 示例 |
|------|------|------|
| **内容修改** | 需要在正文中增删改内容 | 补充理论推导、增加控制变量、重新分析 |
| **结构修改** | 需要调整章节/段落组织 | 重写讨论部分、移动内容到附录 |
| **格式修改** | 引用格式、图表规范、字数等 | 补充缺失引用、修改 APA 格式 |
| **说明回应** | 无需改正文，仅需解释说明 | 解释样本量选取理由、说明方法选择依据 |

## 三、逐条回应策略

对每条审稿意见，采用以下四种回应方式之一：

### 1. 完全接受并修改（推荐）

适用：审稿人意见合理且可操作。

回应模板：
> 感谢审稿人的建议。我们已按照建议进行了修改，具体如下：
> - 修改位置：第 X 节第 Y 段（原稿第 Z 页）
> - 修改内容：[简述具体改动]
> - 修改后文本：[引用修改后的关键句子]

### 2. 部分接受并修改

适用：审稿人意见部分合理。

回应模板：
> 感谢审稿人的意见。我们部分采纳了该建议：
> - 采纳部分：[说明接受的部分及对应修改]
> - 未采纳部分及理由：[说明为何未采纳，需有充分学理依据]
> - 替代方案：[如有，说明采取的替代处理方式]

### 3. 仅说明不修改

适用：审稿人理解有偏差或已有内容已涵盖。

回应模板：
> 感谢审稿人的关注。关于此问题，我们已在原稿第 X 节中进行了讨论：[引用原文]。经审慎考虑，我们认为当前处理是合适的，原因如下：[说明理由]。若审稿人认为仍需进一步阐述，我们愿意继续完善。

### 4. 补充证据/分析

适用：审稿人要求额外验证或补充。

回应模板：
> 感谢审稿人的建议。我们进行了补充分析/验证，结果如下：
> - 补充内容：[描述新增的分析或验证]
> - 修改位置：新增于第 X 节/附录 X
> - 主要发现：[简述补充分析的核心结论]

> **重要原则**：
> - 尽量采用策略 1，避免过度使用策略 3
> - 使用策略 3 时必须有充分学理依据，且语气礼貌
> - "必须修改"类意见不得仅解释不修改
> - 每条意见必须有明确回应，不得遗漏

## 四、返修回应信结构

### 标题格式

```
Response to Reviewers: [论文标题]
Manuscript ID: [稿件编号]
Journal: [期刊名称]
```

### 正文结构

```
致编辑和审稿人：

感谢您对我们稿件的审阅。我们认真研究了每一条审稿意见，
并已进行了相应的修改。以下是逐条回应：

--- 审稿人 1 ---

意见 1：[原文引用审稿意见]
回应：[按上述策略回应]

意见 2：[原文引用审稿意见]
回应：[按上述策略回应]

...（逐条回应）

--- 审稿人 2 ---

...（同上）

--- 主要改动汇总 ---

1. [改动1简述] → 修改位置：第X节/第Y页
2. [改动2简述] → 修改位置：新增附录X
3. [改动3简述] → 修改位置：全文范围

感谢审稿人宝贵的建议，这些意见显著提升了稿件质量。
```

> **格式要点**：
> - 逐条引用原文（用引号或缩进格式），确保审稿人能对照
> - 每条回应都要标明修改位置（精确到章节/段落/页码）
> - 如有全文性修改（如语言润色），在汇总中一次性说明
> - 语气专业、尊重、不带情绪

## 五、稿件修改要点

### 修改原则

1. **逐条对应**：每条审稿意见都有对应的正文修改
2. **标记改动**：用修订模式或高亮标记修改位置，方便审稿人查阅
3. **保持一致**：修改一处后检查全文是否有矛盾
4. **不降低质量**：为回应审稿人而删减重要内容
5. **记录版本**：保留各版本稿件（原稿→修改稿1→修改稿2…）

### 常见返修问题及处理

| 问题类型 | 正确处理 | 错误做法 |
|----------|----------|----------|
| 理论贡献不清晰 | 重写贡献段落，明确与已有文献的区分 | 只在回应信中解释 |
| 控制变量不足 | 补充控制变量并重新分析 | 仅说明"已有文献也未控制" |
| 样本量偏小 | 补充数据或进行稳健性检验 | 仅引用小样本研究先例 |
| 讨论不充分 | 扩展讨论，与更多文献对话 | 仅增加一段泛泛的讨论 |
| 引用缺失 | 补充真实可检索的文献 | 编造或猜测文献 |
| 共同方法偏差 | 补充 CMB 检验（如 Harman 单因子、标记变量） | 仅声明"不影响结论" |

## 六、返修后自检清单

修改完成并撰写回应信后，逐项检查：

### 内容完整性

- [ ] 每条审稿意见都有对应回应（无遗漏）
- [ ] "必须修改"类意见均有实质性正文修改
- [ ] 修改后全文无自相矛盾之处
- [ ] 新增引用均真实可检索
- [ ] 新增分析/数据已整合到正文中

### 格式与一致性

- [ ] 返修信格式规范（逐条引用+回应+位置标注）
- [ ] 正文引用格式与期刊要求一致（APA 7.0 等）
- [ ] 新增内容字数符合期刊要求
- [ ] 图表编号和正文引用一致
- [ ] 修改标记已清除或符合期刊要求（部分期刊要求清除修订标记）

### 质量保障

- [ ] 修改未降低原稿质量（未删减重要内容）
- [ ] 新增讨论有文献支撑（非空洞论述）
- [ ] 语言已重新润色（非仅修改涉及的段落）
- [ ] 摘要已根据正文修改同步更新
- [ ] 已请同行/导师审阅修改稿

## 七、特殊场景处理

### 多轮返修（R&R2、R&R3）

- 仔细阅读上一轮回应中编辑/审稿人的 follow-up 意见
- 上一轮已解决的问题简要说明（"已在上一轮修改中处理"）
- 重点回应新一轮提出的具体问题
- 避免反复解释同一问题，若审稿人持续追问，考虑实质性修改

### 审稿人意见矛盾

- 优先回应主编和审稿人 1 的意见
- 对矛盾意见分别说明处理方案
- 必要时在回应信中说明如何平衡不同审稿人的要求
- 向编辑说明时保持客观，不评判审稿人

### 拒稿后申诉（Appeal）

- 仅在以下情况考虑申诉：审稿人存在明显事实错误、遗漏关键文献、严重误解研究设计
- 申诉信需简短、有据，聚焦于具体错误而非表达不满
- 提供修正后的分析或补充证据
- 申诉成功率较低，需审慎评估是否值得

### Major Revision vs. Minor Revision

| 维度 | Major Revision | Minor Revision |
|------|---------------|---------------|
| 修改范围 | 大面积修改（理论、方法、分析） | 局部调整（补充分析、语言润色） |
| 回应信篇幅 | 详尽（每条意见 1-2 段回应） | 简洁（每条意见 1-2 句回应） |
| 修改稿篇幅变化 | 可能大幅增加 | 通常小幅调整 |
| 二次审稿 | 几乎必定送审 | 可能编辑直接决定 |

## 工作流程

```
输入：
1. 首轮审稿意见及修改路线图
2. 修改稿
3. 修改回应信（可选）

阶段0：读取修改路线图，构建核实清单
阶段1：逐一核实每条修改意见的回应情况
阶段2：综合评判 → 新决定
```

## 核实逻辑

对修改路线图中的每一条意见：

**优先级1（必须修改）**：
 -> 检查修改稿中是否有对应修改
 -> 评估修改质量（完全回应 / 部分回应 / 未回应 / 修改后更差）
 -> 所有优先级1项目必须完全回应方可录用

**可追溯性规则**：对于每条优先级1项目，审稿人必须：
1. 阅读作者在修改回应信中的声明
2. 导航到修改稿中所述的修改位置
3. 独立核实声明与实际修改是否一致
4. 若作者声明为空或模糊（如"已按要求修改"），标记为"无法核实"并在质量评估中标记

**优先级2（建议修改）**：
 -> 逐一检查
 -> 至少80%应有回应
 -> 未回应项需作者提供解释

**优先级3（可选改进）**：
 -> 检查但不影响最终决定

## 承诺履行验证

对于每一条审稿意见中包含的具体承诺，按以下状态逐一验证：

- **已履行** — 所需证据类型存在且实质性回应了承诺内容。验证位置取决于证据类型：
 - 新增章节/图/表/引用/方法段落/讨论段落/文字修改 — 在修改稿中指定位置核实
 - 仅致谢型承诺 — 在修改回应信中核实（而非修改稿差异）
 - 其他类型 — 提示作者明确指定证据位置以便核实

- **部分履行** — 所需证据存在但未完全回应承诺（如在数据集Y上运行实验而审稿人要求X；3种子标准误而非要求的5种子）

- **未履行** — 所需证据缺失

- **明确拒绝并给出理由** — 作者明确拒绝回应该承诺；需记录拒绝理由

对于任何履行状态为"部分履行""未履行"或"明确拒绝"但缺乏理由说明的承诺，需在评审输出中标记**承诺缺口**（提示性标记，非阻断性），促使用户补充说明。

---

## 新问题检测

除检查原有意见外，还需扫描：
- 修改过程中新增内容是否引入新问题
- 新增参考文献是否正确（深度验证留给定稿诚信审查）
- 修改是否导致前后不一致

---

## 再评审后的苏格拉底式引导

若再评审决定为"大修"：
 -> 激活残余问题指导
 -> 引导用户进行结构化反思：
 1. 差距分析 — "首轮修改解决了多少问题？剩余问题为何难处理？"
 2. 根因诊断 — "是证据不足、论证不清，还是结构性问题？"
 3. 权衡决策 — "哪些可以标记为研究局限？"
 4. 行动计划 — 为每个残余问题制定修改方案
 -> 最多5轮对话
 -> 用户可说"直接修改"跳过引导
