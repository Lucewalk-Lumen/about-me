# 审稿意见交付规范（套件 v3 · 8 节点 + 逐条编号 + 六项 Emerald 总结 + 双语 + 去AI化）

> 本规范定义 **C8 最终审稿报告** 的交付形态：采用「8 节点论文流程骨架」组织正文，**每个节点下的问题按「1.」「2.」「3.」逐条编号列举**（每条完整保留问题判断 / 理由 / 稿件证据 / 修改建议，不合并、不笼统）+ **六项 Emerald 评价总结**
> + 中英双语（先中后英）+ 聊天简要结果 + Word 完整版；交付前强制过 **去AI化（humanize）A 档**。
> 本规范为 C8 报告结构的**单一真源**，替代原 C0–C9 分阶段 Markdown 报告形态。
>
> **口径分工**：套件八维诊断（选题/文献/理论/方法/写作/创新/图表/逻辑）是 **C5 内部分析语言**（颗粒更细、
> 对元分析等更有效）；**对外交付一律 8 节点 + 六项 Emerald 总结**。两者通过第三节映射桥接：
> 八维 → 8 节点正文 → 六项总结。**禁止把八维维度名当作 Word 章节标题，禁止把八维总结（8 项）
> 直接当六项总结（6 项）输出。**

---

## 一、交付方式

默认「聊天简要结果 + Word 完整版」。

- **Word** 文件名：`<manuscript_id_or_title_slug>_review_comments.docx`（同名追加时间戳）。
- 保存目录：按环境默认（通常为 workspace 或 Desktop）；若不可写则落当前 workspace 并说明原因。
- **聊天简要结果**含：题名/ID、Recommendation、3–5 条主要问题（含严重度标签）、**六项评价一句话概览**、Word 绝对路径。
- **DOCX 校验**：文件存在、size > 0、可作 ZIP 打开、含 `word/document.xml`。
- 若材料不足，Word 与聊天摘要均标注为 preliminary review。

## 二、报告结构（8 节点论文流程骨架 + 六项 Emerald 总结）— 单一真源

```
总体评价 (2–3 段)
  → 按论文流程的审稿意见（8 节点，顺序固定）
      1. 研究问题
      2. 引言与文献综述
      3. 理论基础与假设推导
      4. 研究设计与方法
      5. 实证结果与分析
      6. 讨论与启示
      7. 研究伦理与透明度
      8. 写作质量
  → Recommendation
  → 六项评价总结（Emerald 标准，6 项，每项 1–3 句）
  → 结语
```

> 该骨架与套件八维诊断**解耦**：八维是 **C5 内部分析语言**，8 节点 + 六项是**对外交付语言**。
> 任一节点的内容可由一个或多个八维映射而来（见第三节映射表）。C5 八维诊断结论须先映射到
> 这 8 个节点、再按「三·五」节重组为逐条编号正文——**不得直接把八维评分块当作最终报告正文输出**，也**不得把八维总结
> （8 项）冒充六项总结（6 项）**。Word 生成脚本默认强校验（issues 必须 8 节点键、six_criteria
> 必须恰好 6 项字符串），不匹配报错拒绝，见脚本 `generate_review_docx.py`。

## 三、八维诊断 → 8 节点映射

| 八维 | 主要映射节点 | 备注 |
|------|------------|------|
| 选题质量 | ① 研究问题 | 选题价值 / 可回答性与证据基匹配 |
| 文献覆盖 | ② 引言与文献综述 | R2 四类转化落此；缺口声称锚定 |
| 理论深度 | ③ 理论基础与假设推导 | 机制链 / HARKing / 假设预注册 |
| 方法严谨 | ④ 研究设计与方法、⑤ 实证结果与分析 | 含 DEF-R01/R03/R04/R06；RoB 评估落 ⑦ |
| 写作质量 | ⑧ 写作质量 | 语言 / 术语 / 格式 / 校对 |
| 创新程度 | ②、⑥ 讨论与启示 | 原创性声称落 ②；新意再定位落 ⑥ |
| 图表呈现 | ⑤ 实证结果与分析、⑧ 写作质量 | 森林图 / 漏斗图 / PRISMA 图落 ⑤；编号与图注落 ⑧ |
| 逻辑连接 | ③、⑥ 讨论与启示 | 设计→因果结论、偏倚→无偏倚等断链落 ⑥ |

> 跨节点问题（如「因果结论越界」同时涉及 ① 与 ⑥）在主要节点展开，相关节点以互引衔接，不重复成段。

## 三·五、C5 八维 → C8 8 节点重组（显式操作步骤）

**C8 前必须走完**：

1. **筛选**：从 C5 八维诊断结果中筛出需写入审稿意见的问题（可选改进级别可酌情省略）。
2. **分组**：按论文流程将问题归入 8 个节点（分组结构见下表）。
3. **排序**：节点内按严重程度排序（必须修改 → 强烈建议修改 → 建议修改 → 可选改进）。
4. **编号列举（逐条完整，不得合并）**：每个节点下的所有问题按「1.」「2.」「3.」**依次连续编号**，跨节点重新从 1 开始；每条问题**独立成条**，完整保留四要素（问题判断 / 理由解释 / 稿件证据 / 修改建议），**禁止把多条问题挤进一条或合并成笼统一段**；编号不得缺号、跳号或重复。
5. **补六项**：按第八节六项 Emerald 标准撰写总结（6 项，每项 1–3 句），**不得**把八维结论直接罗列。
6. **校准**：回头检查 Recommendation 是否与最严重问题的级别一致（见第七节）。

### 分组结构（八维诊断 → 8 节点正文）

| 论文流程节点 | 对应八维（C5 内部语言） | 包含内容 |
|------------|----------------------|---------|
| ① 研究问题 | 选题质量 | 原创性、选题价值、可回答性与证据基匹配 |
| ② 引言与文献综述 | 文献覆盖、创新程度 | R2 四类转化、缺口声称锚定、原创性声称 |
| ③ 理论基础与假设推导 | 理论深度、逻辑连接 | 机制链（How/Why/When）、HARKing、假设间逻辑 |
| ④ 研究设计与方法 | 方法严谨 | 设计匹配、样本、测量、统计模型、因果识别（含 DEF-R01/03/04/06） |
| ⑤ 实证结果与分析 | 方法严谨、图表呈现 | 结果与假设匹配、意外结果处理、报告透明度、森林图/漏斗图/PRISMA |
| ⑥ 讨论与启示 | 逻辑连接、创新程度 | 结论是否由结果支持、实践启示、限制与未来研究、新意再定位 |
| ⑦ 研究伦理与透明度 | 方法严谨（RoB） | 数据开放、流程复现、伦理审批、AI 使用 |
| ⑧ 写作质量 | 写作质量、图表呈现 | 语言 / 术语 / 格式 / 校对、图编号与图注 |

## 四、逐条编号列举 + 语体（无标签 + 老模板语体 + 禁 AI 腔）

将 C5 八维诊断的每条问题转化为**编号列举条目**，确保「每条问题独立呈现、要点完整、便于逐条整改」：

- **编号规则（硬性）**：每个 8 节点下所有问题按「1.」「2.」「3.」……依次连续编号；跨节点重新从 1 开始；**不得缺号、跳号、重复，不得把多条问题合并进同一条**。
- **每条内容完整**：每条问题必须完整保留四要素——①问题判断（哪里不对）②理由解释（为什么不对、影响什么）③稿件证据（指向具体段落/数据/图表）④修改建议（可执行方向）。四要素写成完整学术句子，**不得**压缩成标签式短语（如只写"样本量小"）。
- **每条篇幅**：单条问题一般 1–3 段展开（复杂问题可多段），以把四要素讲透为准，不因编号而缩水。
- **Word 正文中禁止**出现「问题判断：」「理由：」「【必须修改】」等**诊断标签**；严重程度通过措辞自然体现（编号「1. 2. 3.」是列举序号，不是严重程度标签，允许使用）。
- **禁止格式**：
  > "问题判断："+"理由解释："+"稿件证据："+"修改建议："（字段标签式）
  > "（1）问题：（2）原因：…"（一行挤四要素）
  > "【Must Revise】""[Major]" 等前缀标签
  > "该问题体现在以下几个方面：1. 2. 3."（一条塞多条）

**语体基准（对齐旧单 agent 模板库）**：参考 `review_template.md` 的中英模板——
克制学术、第一人称（中文「我」/ 英文 "I"）、以 "I encourage the authors to…" / "建议作者…" 收尾具体修改方向；
先肯定价值再指出实质问题，但不为礼貌削弱判断。

**禁用 AI 腔填充词（A 档即删，详 `../../domains/humanize/references/banned-words.md` 第四节）**：
此外、同时、值得注意的是、需要指出的是、不难发现、基于以上分析、综上所述、总而言之、
首先/其次/最后、一方面/另一方面、换言之、由此可见、值得一提的是、不可否认、毋庸置疑、
事实上、不得不说、坦率地说、客观来讲、众所周知、毫无疑问、显而易见。
连接词精简，避免连续排比与三段式；**严禁网文腔强调词**（更要命 / 太离谱了 / 说真的 等，属 B 档用语，A 档禁用）。

## 五、语言策略（agent 自决；英文 / 国际期刊默认中英双语）

- **自决原则**：agent 依据稿件语言、作者母语、目标期刊决定输出语言；不硬编单一语言。
- **默认中英双语（先中后英）**：当稿件为英文且目标为国际期刊时，默认产出**完整中文版 + 完整英文版**，
  两版**先后排列、分页**（不逐条中英混杂），以对齐旧单 agent 对英文期刊稿的形态。
- **中文单语**：仅当稿件为中文 / 中文期刊 / 作者中文母语自评且无对外英文需求时采用。
- Word 生成：中文宋体（macOS = Songti SC / Win = SimSun）+ 英文 Times New Roman；双语时先中文后英文分页。

> **提交版禁含语言自指声明**：C8 成稿交付（Word / Markdown / 聊天摘要）一律**不得**出现「本报告以中文/中英双语输出」类自指声明（提交版红线，见「九·五」节）——语言策略仅决定内容语种，不作自指说明。

## 六、去AI化（humanize）强制终道

C8 成稿后、交付前**必须**过 `../../domains/humanize/humanize.md` 的 **A 学术轻量档**：

1. **先出样张**：改 1–2 段给用户对齐强度，确认后再全篇铺开（不可跳过）。
2. **学术保护红线（与四铁律一致，一个字不动）**：`〔R-xx〕` `〔综述·X〕`、参考文献条目、统计数字、
   DOI、构念/理论/期刊/方法专名、事实与口径、章节层级与编号——只改「怎么说」，不改「说什么」。
3. **A 档最小必要改动**：删口癖（说白了）、删空话套话（见第四节禁用词表）、个别超长句为换气轻断；
   **严禁**引入网文腔强调词、**严禁**动标点体系（A 档）。
4. **自检**：L1（禁用词零命中）+ L4（活人感 / 学者语气终审：庄重感丢了即返工）。
5. 参考 `../../domains/humanize/references/banned-words.md`、`structures.md`。

> 去AI化是「改味不改内容」的风格级操作；引用保真与四铁律优先级高于一切去AI改写。

## 七、Recommendation 校准

| 最严重问题级别 | 结论 | 说明 |
|--------------|------|------|
| 核心贡献成立，仅极小格式 / 语言问题 | Accept | 无需返回作者 |
| 核心贡献成立，局部补充即可 | Minor Revision | 1 个月内 |
| 有潜力，需实质修改 | Major Revision | 2–3 个月 |
| 致命缺陷 / 需全新研究 | Reject | 不建议修稿重投 |

**Reject 触发条件**（任一即建议 Reject；含数量式兜底 ≥5 个「必须修改」级问题，判据唯一真源见 `review_criteria.md`「评审结论校准·论文评审」）：研究问题不成立 / 方法无法检验核心假设 / 核心结论无证据支撑 / 严重伦理问题 / 与期刊定位严重不符。

## 八、六项评价总结（Emerald 标准，6 项，每项 1–3 句）

在 Recommendation 之后、结语之前，用总结性语言逐项作答（不机械复制诊断全文，不逐条罗列八维结论）。六项严格采用 Emerald 评审六问：

1. **Originality（原创性）**：论文是否包含足以支持发表的重要且新颖的信息？
2. **Relationship to Literature（文献关系）**：论文是否展现出对领域相关文献的充分理解，引用范围是否恰当；是否有重要文献被忽略？
3. **Methodology（方法论）**：论文的论证是否建立在适当的理论、概念或其他思想基础之上；研究所基于的研究设计或同等智力工作是否良好；所采用的方法是否恰当？
4. **Results（结果）**：结果是否清晰呈现并得到了恰当分析；结论是否充分地将论文其他要素联结在一起？
5. **Implications for research, practice and/or society（对研究、实践及/或社会的启示）**：论文是否清晰指出对研究、实践和/或社会的启示；是否架起了理论与实践之间的桥梁；研究如何用于实践（经济与商业影响）、教学、影响公共政策、研究（贡献知识体系），以及对社会的影響（影响公众态度、改善生活质量）；这些启示是否与论文的发现与结论一致？
6. **Quality of Communication（沟通质量）**：论文是否对照领域技术语言与期刊读者预期知识水平清晰表达了其论点；是否在表达清晰性与可读性（如句子结构、术语使用、缩略语等）上给予了关注？

> **注意**：此处六项对应 `six_criteria` 字段（恰好 6 项字符串），脚本强校验数量与类型。
> 八维的选题质量/图表呈现/逻辑连接等内部信息已在上文 8 节点正文中体现，**不要**为凑内容把六项改成八项。
> 若确需向用户呈现八维内部评分（团队内部自评用），放在聊天简要的附注里，不进 Word 正文。

## 九、Word 生成

使用套件 `../../scripts/generate_review_docx.py`：
- 入参：`--report 诊断结果.json --output 审稿报告.docx`（JSON 结构见该脚本与 `../../../peer-review/SKILL.md` C8 评分块）。
- **硬校验（默认开启）**：脚本校验 `issues` 必须为 8 节点规范键（中文 8 键或英文 8 键全集）、`six_criteria` 必须为恰好 6 个字符串；任一不满足 → **报错拒绝输出**。仅当显式传 `--no-strict-dims` 时才宽容处理（用于内部调试，不用于交付）。
- 自动：中文宋体 + 英文 TNR、两端对齐、标题加粗、先中文后英文分页（双语时）。
- **保密声明（confidential_notice）默认开启**；封面（cover）可选。
- 若经 Markdown 中转（如对比稿 / 内部自评），可用等价 Markdown→docx 转换器，保持上述字体 / 对齐 / 分页 / 保密声明规则。
- **路径说明**：`--output` 传绝对路径时视为用户显式授权目标，直接规范化使用（不再以 cwd 为 containment 基准）；相对路径仍强制落在 cwd 内防 `..` 逃逸。从任意目录运行均可输出到 workspace / Desktop。

## 九·五、提交版红线（可提交性 · 匿名性 · 无内部信息）

> **新增（实测教训）**：用户评审实测反馈——「语言并不衔接，要提交的话，怎么能出现『本报告以中英双语输出』」。审稿意见最终要**提交给期刊编辑部**，本质是一份正式 Reviewer Report，而非内部工作文档。C4 成稿（Word / Markdown / 聊天摘要）在提交前必须清除一切内部痕迹：

### 1. 必须删除的内部信息（提交版红线清单）

| 类别 | 示例 | 处理 |
|---|---|---|
| 元描述/自指说明 | "本报告以中英双语输出（先中文后英文）"、"This report is provided bilingually..."、MD 镜像说明块 | 直接删除 |
| 内部协作痕迹 | "三套独立交叉复算（本审稿人、数据分析专家、主理人）" | 改为中性表述"本文所有关键数值均经独立复算核验"，数值本身保留 |
| 内部术语 | Trust Boundary、C0–C10 路径编号、八维诊断、DEF-Rxx | 改为审稿通用语（如"审稿惯例""标准评审实践"）或删除 |
| 内部身份 | 评审人署名（秦子谦）、成员花名、obhrm-peer-review、OBHRM 研究协作团 | 删除（审稿匿名惯例）或匿名化 |
| 内部版本/流程 | 版本号、契约说明、镜像说明、评审路径声明 | 删除 |

### 2. 保留的（红线不覆盖）

- **复算数值与证据**：Egger 3.559、t(21)=4.44、预测区间 [−0.07,1.64] 等——全部保留，只改表述外壳。
- **R2 文献加注**："审稿人独立检索，请作者核实"——保留（学术诚信要求）。
- **保密声明**：结语可保留"本报告为保密审稿文件，仅供编辑部与作者修稿使用"（期刊惯例）。

### 3. 检查方法

交付前 grep 自查：`双语输出|Trust Boundary|主理人|数据分析专家|本审稿人|obhrm-peer-review|秦子谦|OBHRM 研究协作团|八维诊断|审稿路径|镜像|契约|v1\.[0-9]` —— 任一命中即打回 C4 重写。英文版同理（`bilingually|Trust Boundary|lead reviewer|data-analysis specialist|review path|mirror|contract|v1\.[0-9]`）。

### 4. 段落与部分衔接（实测反馈：语言不衔接）

- 总体评价 3 段间必须有逻辑过渡（铺垫 → 然而/但是 → 决议），不得硬切。
- 每个 8 节点可加一句节内导语（如"本节先讨论研究设计与方法层面的问题。"），导语为**非编号文本**，置于该节点 issues 数组首元素，不计入编号条数，编号仍从 1. 开始。
- 每条意见的判断/理由/建议段之间用衔接词串联（"其直接后果是…""事实上…""需要说明的是…"），避免三块拼贴；各节点/各节间不得雷同模板。
- 大结构过渡：总体评价末段预告结构 → 8 节点前导语 → 推荐前"综合以上八个节点的意见…" → 六项总结前"按 Emerald 评审标准…" → 结语自然衔接。

### 5. 术语统一（审稿交付术语规范）

全文（中英双语）统一以下术语，杜绝混用（实测沉淀）：
- 调节变量（moderator）／效应量（effect size）／发表偏倚（publication bias）／预测区间（prediction interval）／置信区间（confidence interval）
- 偏倚风险（risk of bias）／单组前后测（single-group pre–post）／依赖效应量（dependent effect sizes）
- 三水平模型（three-level model）／稳健方差估计（RVE）／留一法（leave-one-out）／亚组（subgroup）
- 随机效应模型（random-effects model）／固定效应模型（fixed-effect model）／异质性（heterogeneity）／测量工具类型（assessment tool type，SQ/AT/PT/AG 首现给全称）
- 缩写统一：VBP 不得出现 VPB；中文正文夹带的统计符号（Q_between、τ²、I²、p、d、SE、CI、n、k）保留，但叙述性中文不得夹英文词。
