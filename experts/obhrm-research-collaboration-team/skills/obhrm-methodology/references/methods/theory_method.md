## 用途
在建模、机制解释、假设发展、理论选择时触发。不要机械罗列理论，应按研究问题类型匹配。

| 问题类型 | 常用理论 | 适合解释的问题 | 注意事项 |
|---|---|---|---|
| 交换/互惠/支持 | 社会交换理论、组织支持理论、心理契约 | 支持、承诺、互惠、领导—员工关系 | 避免把所有正向关系都塞进交换逻辑 |
| 资源/压力/耗竭 | 资源保存理论、工作要求-资源模型、压力认知评价 | 倦怠、压力、资源损失、恢复 | 区分资源损失、资源获得与挑战/阻碍压力 |
| 动机/自主/目标 | 自我决定理论、目标设定理论、期望理论 | 自主性、动机、目标承诺 | 说明心理需求或目标机制 |
| 认知/判断/归因 | 归因理论、社会认知理论、意义建构 | 认知评价、归因、判断偏差 | 明确认知对象与过程 |
| 身份/认同/归属 | 社会认同理论、身份理论、角色理论 | 组织认同、职业认同、身份威胁 | 区分身份来源、变化和冲突 |
| 情绪/事件/体验 | 情感事件理论、情绪调节理论 | 情绪反应、体验波动、事件冲击 | 适合动态或事件型解释 |
| 公平/信任/伦理 | 组织公平理论、信任理论、伦理决策理论 | 公平感、信任、伦理领导 | 明确公平维度或信任对象 |
| 领导/团队/关系 | LMX、共享领导、团队过程理论 | 领导行为、团队氛围、协作、冲突 | 区分个体、团队和跨层机制 |
| 制度/战略/组织层 | 制度理论、战略HRM、动态能力 | 组织制度、HRM系统、战略变革 | 注意层级匹配 |
| 技术/数字化/AI情境 | 技术接受、算法控制、社会技术系统、自动化信任 | AI监控、算法管理、人机协作 | 技术情境应进入机制或边界条件 |

## 使用原则
先判断研究问题的核心解释对象；通常以 1 个主理论为核心；假设必须有机制链条；中国情境研究需说明情境如何改变机制或边界。

## 理论数量限制（强制）
- **以 1 个主理论为核心，最多加 1 个辅助理论**。不得堆砌 3 个以上理论。
- 每增加一个理论，必须在文中说明"为什么不用已有理论解释，而需要引入新理论"。
- 多理论时必须明确分工：哪个理论解释哪条路径/哪个变量。禁止多理论各自解释同一关系。

## 大理论慎用原则
资源保存理论（COR）、社会认知理论（SCT）、自我决定理论（SDT）等"大理论"解释力过宽，容易导致机制模糊。使用规则：
1. **优先选用机制更聚焦的中层理论**（如社会交换理论、情绪事件理论、身份理论、心理契约理论等）。
2. 若必须使用大理论，必须在文中给出**排除替代理论的理由**："为何不选用更聚焦的 X 理论，而需要 COR/SDT 的宽解释力？"
3. 大理论作为辅助理论时，必须明确其解释范围限定（"仅用于解释资源损耗路径，不涉及其他路径"）。
4. 大理论不得同时解释中介和调节两条路径（否则等于没理论边界）。

## 理论选择检查清单
在 A3 阶段完成后，逐项检查：
- [ ] 主理论是否能解释核心机制（X 为什么通过 M 影响 Y）？
- [ ] 辅助理论（如有）是否补充了主理论无法解释的部分？
- [ ] 是否排除了更简洁的单理论解释方案？
- [ ] 每条假设是否有明确的理论推导（至少 3 句话：触发条件、心理过程、结果表现）？

## 实证问卷论文
流程：选题与变量 → 理论模型 → 量表选择/开发 → 样本与时间设计 → 数据质量 → 信效度 → 假设检验 → 稳健性。
关键控制：共同方法偏差（Harman单因素、多时点、不同来源）、信效度（Cronbach α、CFA、AVE、区分效度）、中介/调节检验方法选择（逐步法、Bootstrap、Monte Carlo）。
交叉引用：信效度检查可参考 `review_criteria.md` 的质量检查清单。

## 实验研究论文
流程：理论机制 → 操纵设计 → 随机分配 → 操纵检验 → 因变量测量 → 伦理与 debriefing → 结果解释。
关键控制：操纵强度、操纵检验成功率、随机化质量、样本功效（power analysis）、效应量报告、替代解释排除。

## 元分析论文
流程：研究问题 → 检索策略 → 纳入/排除标准 → 编码手册 → 效应量转换 → 异质性 → 调节分析 → 发表偏倚 → 结果解释。
关键控制：检索可复现、纳入标准透明、重复样本处理、发表偏倚检测（漏斗图、Egger、剪补法）、异质性来源解释。
交叉引用：检索策略设计可参考 `evidence_retrieval_protocol.md`。

## 综述 / 理论论文
流程：概念边界 → 文献流派 → 理论张力 → 整合框架 → 命题/议程 → 理论贡献。
关键控制：不是文献罗列而是对话整合；理论框架有边界条件；命题可检验或可推演。
交叉引用：文献流派梳理可参考 `evidence_retrieval_protocol.md`。

## 案例研究论文
流程：研究问题 → 案例选择 → 数据来源矩阵 → 证据链 → 案例内分析 → 跨案例比较 → 理论命题。
关键控制：案例选择有理论依据（理论抽样而非方便抽样）、证据链透明、三角验证、反例处理。

## 质性研究论文
流程：理论抽样 → 访谈/文本资料 → 开放编码 → 轴心/聚合编码 → 数据结构图 → 机制模型/理论命题。
关键控制：编码过程透明、理论饱和判断、研究者立场说明、引文支撑充分、数据结构图与机制模型对应。

## QCA（定性比较分析）

### QCA流程
研究问题 → 条件变量选择 → 校准标准设定 → 真值表构建 → 必要性分析 → 充分性分析 → 结果解释与稳健性检验。

### QCA关键控制
- **结果变量**：必须是集合关系（高/低绩效、离职/留任等）。
- **条件来源**：理论驱动，不是数据驱动凑条件。
- **校准**：有明确校准标准（直接法、间接法、分位数法），并说明理由。
- **必要性**：先检验必要条件，再检验充分条件组合。
- **充分性**：报告一致性阈值、PRI、覆盖率、简约解/中间解/复杂解的选择依据。
- **稳健性**：改变一致性阈值、排除案例、改变校准标准后结果是否稳定。
- **后续承接**：QCA 结果如何与定量或质性方法衔接（如 QCA+SEM、QCA+案例）。

## ESM（经验取样法 / 日记法）

### ESM流程
研究问题 → 事件/信号设计 → 问卷条目精简 → 依从性策略 → 多层数据分析 → 结果解释。

### ESM关键控制
- **层级结构**：明确个体层（L2）和个体内/时刻层（L1）的变量分配。
- **时间设计**：信号间隔、天数、每日次数、固定 vs 随机信号。
- **条目精简**：ESM 条目必须简短（通常每题 10 秒内完成），避免长量表直接照搬。
- **依从性**：报告完成率、缺失模式、依从性激励策略。
- **分析策略**：MLM/HLM、动态结构方程（DSEM）、时间序列、多水平中介。
- **共同方法偏差**：ESM 天然降低 CMB，但仍需说明测量时点设计。

## 追踪 / 纵向研究

### 追踪纵向研究流程
研究问题 → 时间间隔设计 → 测量波次选择 → 样本保持策略 → 纵向数据分析 → 因果推断。

### 追踪纵向研究关键控制
- **时间间隔**：根据理论机制的时间尺度设定（如情绪效应几天、职业发展几年）。
- **波次数量**：至少 3 波才能检验因果方向；2 波只能检验变化。
- **样本保持**： attrition 分析和缺失处理（FIML、多重插补）。
- **分析策略**：交叉滞后模型（CLPM）、随机截距 CLPM（RI-CLPM）、潜变量增长模型（LGM）、潜转变分析（LTA）。
- **因果推断**：明确说明纵向设计如何增强因果推断，但仍需说明替代解释（反向因果、遗漏变量）。
- **与截面研究的区别**：必须说明为什么选择纵向设计，以及纵向设计解决了什么问题。

## 方法选择决策树（简要）

| 你的核心问题 | 推荐方法 | 关键考量 |
|---|---|---|
| 变量 A 是否影响变量 B？ | 截面问卷 + SEM/回归 | CMB 处理、信效度、样本量 |
| 机制是什么（A→M→B）？ | 问卷 + 中介分析/Bootstrap | 中介必要性、替代机制 |
| 边界条件是什么（W 调节 A→B）？ | 问卷 + 调节分析/简单斜率 | 调节假设的理论依据 |
| 因果关系是否成立？ | 实验 / 纵向追踪 | 操纵/时间设计、功效分析 |
| 多因素组合如何导致高绩效？ | QCA | 条件选择、校准、稳健性 |
| 动态过程如何展开？ | ESM / 日记法 / 纵向 | 时间尺度、层级分析 |
| 现象如何发生？ | 案例 / 质性 | 理论抽样、证据链、编码透明 |
| 效应量有多大？ | 元分析 | 检索可复现、异质性、发表偏倚 |
| 理论如何整合？ | 综述 / 理论论文 | 对话整合、框架边界、可检验性 |

## 图表规范用途
用于 OBHRM/管理学项目书、博士论文方案、研究设计、理论模型、技术路线、假设体系、年度计划和用户明确要求“画图/图示/流程图/模型图”的任务。目标是避免图表丑陋、只用文字描述模型、图文脱节或只保留不可读源文件。

## 强制触发场景
出现以下任一情况必须触发：
- 用户要求画图、模型图、机制图、技术路线图、流程图、路线图、变量矩阵、假设矩阵、年度安排。
- 正式项目书、博士论文方案、完整研究设计、开题报告。
- 文本中出现“理论模型”“技术路线”“研究内容递进”“变量关系”“假设体系”“年度安排”。

## 最低交付要求

### 1. 正式 Word/项目书/博士方案
必须同时交付：
1. **可编辑源文件**：`.mmd` 或 `.json` 配置文件。
2. **高清图片**：优先生成 `.png`，宽度不低于 1800 px，分辨率不低于 220 dpi；复杂图建议 2400–3200 px。
3. **Word嵌入**：图片必须插入对应正文附近，不能集中堆在文末；图片标题置于图片下方。
4. **图文一致性说明**：正文需解释图中节点、箭头、路径、边界条件如何对应假设或研究内容。

若因环境限制暂不能转 PNG/SVG，必须在最终回复中明确说明，并保留 `.mmd` 源码、Markdown预览和替代节点表；不得声称“图片已呈现”。

### 2. 项目书/课题申报
至少生成：
- 理论模型图：前因—机制—结果—边界条件。
- 研究内容递进图：研究一/二/三/四如何承接。
- 技术路线图：资料来源、方法、分析、产出。
- 变量与假设矩阵：变量、角色、理论依据、假设编号、检验方法。

### 3. 博士论文方案/开题
至少生成：
- 总体理论模型图。
- 分研究承接矩阵。
- 技术路线图。
- 论文结构图或章节逻辑图。

### 4. 局部研究设计
按需生成理论模型图、流程图、访谈/问卷/实验流程图、QCA 条件—结果矩阵。若用户反馈“图不好看/图很丑/图片没有呈现”，必须升级为高清 PNG/SVG 版本并嵌入 Word。

## 学术图表美观标准

### 版式
- 使用 A4 横向或 16:9 横向比例；复杂技术路线图优先 16:9 或 A4 横向。
- 图中节点不超过 12 个主节点；超出时拆成“主模型图 + 子路径图”。
- 箭头方向保持一致：理论模型优先从左到右，技术路线优先从上到下或左到右，不要混乱折返。
- 分组使用浅色背景块区分“前因层—机制层—结果层—边界层/情境层”。

### 字体与字号
- 中文优先使用系统可用的宋体/黑体/苹方/思源黑体等；英文使用 Times New Roman 或 Arial。
- 节点文字字号不小于 18 pt；标题不小于 22 pt；Word中缩放后仍应清晰。
- 节点内文字尽量 8–16 字；必要时用换行而非挤压。

### 色彩
- 全图控制在 3–4 种主色：深蓝/墨绿/紫灰作为主色，浅蓝/浅绿/浅灰作为填充。
- 使用低饱和学术配色，避免彩虹色、荧光色、强红强黄。
- 同一语义层级使用同一颜色：前因一种色、中介一种色、结果一种色、调节/情境一种色。

### 线条与标注
- 主路径用实线箭头，调节路径用虚线箭头，反馈/补充路径用点线或细线。
- 箭头标签必须短而准，如"互惠规范激活""信任转化""H2/H3"。
- 不要让线条穿过节点；避免文字重叠。

### 调节路径箭头指向规范（关键）

调节变量的箭头**不得随意指向变量节点**。必须按以下模型类型确定指向：

| 模型类型 | 含义 | 调节箭头指向 | 示例 |
|---------|------|------------|------|
| **被调节的中介（第一阶段）** | 调节变量影响 X→元分析路径的强度 | 指向 X→M 的关系线 | W 调节 X 对 M 的影响：箭头指向 X→M 连线 |
| **被调节的中介（第二阶段）** | 调节变量影响 M→Y 路径的强度 | 指向 M→Y 的关系线 | W 调节 M 对 Y 的影响：箭头指向 M→Y 连线 |
| **被中介的调节** | 调节效应(X×W)通过中介 M 影响 Y | 从 X×W 交互项指向 M | 先画 X×W→M，再画 M→Y |
| **两阶段被调节的中介** | 调节变量同时影响 X→M 和 M→Y | 分别指向 X→M 和 M→Y 的关系线 | W 同时调节两条路径 |

**常见错误（禁止）**：
- 调节箭头直接指向中介变量 M 的节点（"调节 M"语义不明确）
- 调节箭头直接指向因变量 Y 的节点（"调节 Y"不是标准调节模型）
- 调节箭头不区分第一阶段和第二阶段（必须明确调节哪条路径）

**实现要求**：生成模型图时，JSON config 中 moderator 的 target 应指定为路径（如 `target_path: "X-M"`, `stage: "first"`），而非简单指向节点；渲染时应据此将调节箭头指向关系线中点。

### 图题与编号
- 正文内以"图1……"格式编号；**图题必须放在图片下方**（禁止图题在上）。
- 图题应说明图的学术功能，而不是只写"模型图"。例如："图1 向上管理驱动反向师徒关系形成的互惠规范机制"。

### 图片说明文字格式
- 图片下方的说明/注释文字（小字）必须**两端对齐**（CSS: text-align: justify）。
- Word 文档中：选中说明文字 → 段落设置 → 对齐方式选"两端对齐"。
- 说明文字内容应涵盖：图中符号含义（实线/虚线/颜色）、变量简称对照、数据处理说明等。
- 说明文字字号建议比正文小一号（如正文小四则说明用五号）。

### Word 文档图表整体格式要求
- 图题在图片正下方，居中，与图片间距 0.5 行。
- 表题在表格正上方，居中，与表格间距 0.5 行。
- 图表与正文之间上下各空一行。
- 图片宽度不超过版心宽度（通常 15cm 以内），居中放置。
- 图中文字在 Word 中缩放至 100% 时应清晰可读（不小于 9pt）。

## 推荐生成方式
模型图建议使用 Mermaid 编写 `.mmd` 源文件并渲染为 PNG 嵌入 Word（注意：捆绑的 `chart_engine.py` 覆盖统计类图表，不含路径模型图）。JSON config 中 `moderator.target` 指定为路径（如 `target_path: "X-M"`、`stage: "first"`），渲染时调节箭头指向关系线中点。

## 输出前图表质量闸门
正式回复前必须检查：
- 是否生成了图片文件，而不只是 `.mmd`；
- 图片是否已嵌入 Word 对应章节；
- 图中变量名称、假设编号与正文一致；
- 节点文字是否清晰，无重叠、无截断；
- 图表是否有解释段，不是装饰性图片；
- 图片大小是否适中，Word中不超过页面宽度，图题在图片下；
- 源文件是否随交付包保存，便于用户后续修改。

## 禁止事项
- 禁止只说“见技术路线图”但不生成图表。
- 禁止只有 Mermaid 源码却回复“图片已呈现”。
- 禁止图表与正文变量/研究内容不一致。
- 禁止把复杂机制压成无意义的单线箭头。
- 禁止使用花哨但不可读的颜色、重叠线条或过小字体。
- 禁止为了美观编造变量、阶段或方法。
