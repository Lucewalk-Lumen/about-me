## 用途
用于 OBHRM/管理学项目书、论文方案、选题诊断、文献 gap、理论建构、综述、投稿返修和用户明确要求“搜索文献/政策/现实情境”的任务。目标是避免无检索写作、只引用陈旧经典、把搜索摘要当正式文献、参考文献与正文不匹配、文献述评只罗列不形成理论缺口。

## 强制触发场景
出现以下任一情况必须触发本协议：
- 自科/社科/教育部/省部级项目书、课题申报、完整研究方案、博士论文方案、开题报告。
- 用户要求“完整流程、详细版、文献充分、覆盖大部分文献、搜索政策、搜索文献、最新研究、近五年文献、前沿”。
- 需要写立项依据、国内外研究现状、文献 gap、理论贡献、参考文献、政策背景。
- 主题涉及实时政策、基金指南、期刊偏好、国家战略、行业实践、数字技术、平台经济、AI、人口/就业/劳动政策等动态事实。

## 核心原则
1. **经典文献用于理论根基，最新文献用于研究缺口**。不能只引用 10 年前的经典文献来支撑“前沿问题”。
2. **先检索，后写作**。复杂交付进入正文生成前，必须形成检索记录、证据分级、文献链和证据矩阵。
3. **先核验，后引用**。无法确认题名、作者、年份、期刊/出版社、DOI 或来源 URL 的文献，只能作为“待核验线索”，不得写入正式参考文献。
4. **从文献到论证，而不是从摘要到堆砌**。每条文献链必须转化为“已有研究—不足—本研究推进”的论证。
5. **检索是迭代过程，不是一次搜索**。必须经历“关键词扩展—初筛—精筛—滚雪球—证据矩阵—写作嵌入”的闭环。

## 强制执行规则

> **以下规则在所有涉及文献检索的任务中具有最高优先级，违反任何一条均视为执行失败。**

### 规则 REF-REAL：真实检索，禁止凭内部知识编造
1. **必须调用工具执行真实检索**：文献检索必须使用 `search` 工具（type=academic）或 `browser` SKILL 在真实学术数据库执行。禁止仅凭 agent 内部知识列出文献。
2. **检索过程必须有记录**：每次检索必须记录数据库/网站、检索式、时间范围、命中数量，并在阶段输出中呈现检索记录（格式见下方"检索记录输出格式"）。
3. **区分已检索和未检索**：
 - 通过工具实际检索到的文献 → 标注为"已检索"，可列为 A/B 级证据
 - agent 内部知识中的文献（未经工具检索核验） → 仅可列为"C 级待核验线索"，且必须标注"未经在线检索核验"
4. **禁止行为**：
 - 禁止在没有调用 search/browser 工具的情况下声称"已执行文献检索"
 - 禁止把 agent 内部知识中的文献当作 A 级已核验证据
 - 禁止在没有检索记录的情况下声称"文献已充分覆盖"
5. **最低检索要求**：每次文献检索任务必须至少执行 3 轮不同关键词/不同数据库的检索。仅一轮检索视为未完成。

### 规则 REF-STRUCT：结构化输出，禁止非格式化文献罗列
1. **证据矩阵必须为 Markdown 表格**：文献证据矩阵必须使用 `../../scripts/evidence_matrix_builder.py` 的 `build_evidence_matrix()` 生成或按其字段标准手动生成 Markdown 表格。禁止以纯文本段落罗列文献。
2. **文献链必须按模板输出**：每条文献链必须包含"已有研究→近五年推进→仍然不足→本研究推进→可引用证据→待核验线索"六个要素。禁止只列出文献作者和年份而不写推进逻辑。
3. **构念词表必须为 Markdown 表格**：关键词矩阵必须使用 `../../scripts/evidence_matrix_builder.py` 的 `build_keyword_matrix()` 生成。禁止以纯文本列出关键词。
4. **检索式矩阵必须为 Markdown 表格**：检索式矩阵必须使用 `../../scripts/evidence_matrix_builder.py` 的 `build_search_matrix()` 生成，每类检索式须列出具体关键词组合和结果数量。禁止只写"已构造检索式"而不展示内容。
5. **B3 述评必须为结构化论证**：项目书 B3 的国内外研究现状述评禁止采用罗列式（逐条罗列"某研究发现……；另一研究认为……"）。必须按文献链组织为"已有共识→近五年推进→仍然不足→本项目推进"的论证段落。

### 规则 REF-PDF：PDF 逐篇读取规则
1. **用户提供了 N 篇 PDF 文献时，必须逐篇读取全部文献**，不得跳过任何一篇。
2. **分批读取**：每次批量读取 10-15 篇（避免上下文溢出），每篇提取以下字段：
 - 作者年份、完整题名、来源期刊/出版社
 - 摘要全文
 - 研究对象/样本（国家、行业、样本量）
 - 研究方法（问卷/实验/元分析/质性等）
 - 核心构念（与本研究的哪些变量相关）
 - 关键发现（与本研究的哪个假设/gap 相关）
 - 不足或边界条件
3. **读取工具**：使用 `../../scripts/clean_pdf_text.py` 清理水印后提取文本。纯扫描版 PDF（无法提取文本）需注明"扫描版，无法自动提取"并基于文件名和元数据补充。
4. **PDF 读取后必须进入证据矩阵**：每篇已读取 PDF 的提取结果必须填入文献证据矩阵，不得只读不记录。
5. **PDF 读取后必须执行网络补充检索**：完成本地 PDF 读取后，必须使用 search 工具（type=academic）补充检索近 3 年（2023 年至今）在线文献，至少补充 5-8 篇，形成"本地文献 + 网络文献"双源证据链。
6. **全部 PDF 必须在述评中体现**：最终述评正文中，用户提供的每篇 PDF 文献至少被引用一次。禁止只读取部分文献。

## 快速执行版：八步文献检索法
复杂任务按以下顺序执行，除非用户明确只要简略思路：

| 步骤 | 动作 | 产出 |
|---|---|---|
| 1. 拆构念 | 把用户主题拆成核心构念、情境、对象、方法、结果变量 | 构念词表 |
| 2. 中英扩词 | 为每个构念生成中英文同义词、近义词、上位词、下位词 | 检索词矩阵 |
| 3. 分层检索 | 分别检索理论根基、近五年前沿、方法测量、政策实践 | 分层检索记录 |
| 4. 初筛 | 按题名、摘要、期刊、年份、相关性剔除低质结果 | 纳入/排除清单 |
| 5. 核验 | 打开来源页或用户文献，确认题录、摘要、方法、结论 | 已核验/待核验分级 |
| 6. 滚雪球 | 对核心文献做向后追溯参考文献、向前追踪引用文献 | 补充核心文献 |
| 7. 证据矩阵 | 按研究链条整理研究对象、理论、方法、发现、不足 | 文献证据矩阵 |
| 8. 写作嵌入 | 把证据转为研究现状、gap、理论模型、假设和方法依据 | 文献链与正文段落 |

## 构念拆解与关键词扩展

### 1. 构念拆解维度
每个主题至少拆成 5 类词：

| 类别 | 说明 | 示例 |
|---|---|---|
| 核心现象词 | 研究对象或现象本身 | reverse mentoring, upward management |
| 理论机制词 | 中介、心理机制、社会机制 | reciprocity norm, psychological safety |
| 边界条件词 | 调节变量、情境变量 | power distance, interpersonal trust |
| 结果变量词 | 绩效、关系、创新、行为结果 | mentoring relationship quality, role transition |
| 方法测量词 | 量表、方法、识别策略 | scale, measure, PROCESS, fsQCA |

### 2. 中英文同义词矩阵
中文研究必须同时使用中文词与英文词。每个核心构念至少列出：
- 英文标准术语；
- 英文同义或近义术语；
- 中文标准术语；
- 中文替代表述；
- 可能的相邻研究领域术语。

示例：

| 构念 | 英文标准术语 | 英文扩展词 | 中文标准术语 | 中文扩展词 |
|---|---|---|---|---|
| 反向师徒关系 | reverse mentoring | reciprocal mentoring, peer mentoring, upward mentoring | 反向师徒关系 | 逆向导师制、反向导师制、代际学习 |
| 向上管理 | upward management | managing up, upward influence, proactive influence | 向上管理 | 向上影响、主动向上沟通、管理上级 |
| 师徒关系质量 | mentoring relationship quality | mentor-protege relationship, mentoring functions | 师徒关系质量 | 导师关系质量、师徒功能、导师支持 |

## 分层检索要求
复杂研究任务至少形成以下三层文献证据：

| 层级 | 作用 | 最低要求 | 典型用途 |
|---|---|---:|---|
| 理论根基文献 | 支撑核心理论、构念定义、机制逻辑 | 5–8 篇 | 概念界定、理论框架、假设逻辑 |
| 近五年前沿文献 | 说明研究进展、争议与缺口 | 8–15 篇 | 文献述评、研究缺口、创新点 |
| 方法与测量文献 | 支撑量表、样本、模型、识别策略 | 4–8 篇 | 研究设计、变量测量、数据分析 |

若用户明确要求“最新文献”或“SSCI/CSSCI前沿”，应优先检索最近 3–5 年发表于管理学、组织行为、人力资源、心理学与社会学主流期刊的论文。

## 推荐检索源与优先级
优先级从高到低：
1. **用户提供的 PDF/Word/参考文献库**：先读取并提取题录、关键词、研究结论。
2. **权威数据库/出版平台**：Web of Science、Scopus、Google Scholar、CNKI、CSSCI、EBSCO、ScienceDirect、Springer、Wiley、SAGE、Taylor & Francis、Emerald、APA PsycNet、Academy of Management、INFORMS、JSTOR。
3. **期刊与机构官网**：AMJ、AMR、ASQ、JAP、Personnel Psychology、JOB、HRMJ、HRM、LQ、MOR、OS、JMS、JOM、JOOP、JVB 等。
4. **搜索引擎摘要**：只能用于发现线索，不能直接当作已核验证据。使用搜索结果后，应尽量访问来源页核验题录和摘要。

如果当前环境无法直接访问数据库，应使用可用搜索工具进行题名、作者、期刊与摘要核验，并在交付中标注“已核验/待核验”
### 中国大陆可用检索工具推荐
在中国大陆环境下，部分国际数据库可能无法直接访问。推荐以下可用检索工具：

| 工具 | 适用场景 | 访问方式 |
|------|---------|---------|
| 中国知网（CNKI） | 中文期刊、学位论文、会议论文、CSSCI来源 | cnki.net（部分功能需机构账号） |
| 万方数据 | 中文期刊、学位论文、会议论文 | wanfangdata.com.cn |
| 维普期刊 | 中文期刊全文 | cqvip.com |
| 百度学术 | 中英文文献综合搜索 | xueshu.baidu.com |
| Web of Science | 英文SSCI/SCI文献 | 需校园网VPN或机构代理 |
| Scopus | 英文多学科文献 | 需校园网VPN或机构代理 |
| Google Scholar | 英文文献综合搜索 | 中国大陆可能无法直接访问，需VPN |

> **注意**：Google Scholar 在中国大陆通常无法直接访问。若目标为SSCI/国际期刊发表，建议通过校园网VPN使用 Web of Science 和 Scopus。

## 反爬虫与访问限制处理
学术数据库普遍设有反爬虫机制。执行在线检索时，按以下规则处理：

### 访问前准备
1. 在进入检索阶段前，提醒用户准备好本地参考文献（PDF文件夹或题录文件），以备在线检索失败时切换到离线分析。
2. 确认用户是否有校园网VPN或机构代理，可访问 Web of Science/Scopus。

### 遇到限制时的处理流程
1. **验证码/登录墙**：使用 browser SKILL 检索时，若遇到验证码或登录要求，立即弹窗提醒用户接管浏览器手动完成验证，验证通过后继续自动检索。
2. **IP封锁/频率限制**：若同一数据库被限制访问，切换到备选检索源（如 CNKI -> 万方 -> 百度学术），每个数据库检索间隔不少于10秒。
3. **完全无法在线检索**：若所有在线检索源均不可用，向用户请求：
 - 指定本地文献文件夹路径（批量读取PDF/Word）
 - 提供文献题录文件（EndNote .enw / RIS / BibTeX / Excel）
 - 直接提供文献列表（文本格式）
 基于用户提供的材料进行离线文献分析。

### 离线文献分析规则
当使用用户提供的本地文献时：
- 批量读取PDF/Word文件，提取标题、作者、年份、期刊、摘要、关键词、方法、结论
- 按相同的分层检索和证据矩阵标准整理
- 标注“基于用户提供的离线文献”，并在交付中列出已分析的文件清单
- 离线分析同样需要形成文献链和 gap 诊断，不得降低质量标准

## 检索式矩阵
复杂任务不得只用一个关键词检索。至少构造 6 类检索式：

| 检索式类型 | 示例 | 目的 |
|---|---|---|
| 直接主题式 | reverse mentoring older workers | 找直接研究 |
| 构念组合式 | upward management reciprocity norm | 找变量关系 |
| 理论机制式 | mentoring social exchange theory reciprocity | 找理论依据 |
| 情境边界式 | mentoring power distance China digital transformation | 找中国/数字化/代际情境 |
| 方法测量式 | interpersonal trust scale mentoring psychological safety scale | 找量表与方法 |
| 近五年前沿式 | reverse mentoring workplace 2020 2021 2022 2023 2024 2025 | 找最新研究 |

中文研究同时使用中英文关键词：如“反向师徒关系/逆向导师制/reverse mentoring”“向上管理/upward management/managing up”“师徒关系质量/mentoring relationship quality”“心理安全感/psychological safety”。

## 初筛与精筛标准

### 初筛纳入标准
- 与核心构念、机制、边界、结果或方法至少一项直接相关；
- 来源为正式期刊、学术出版社、权威机构报告或用户提供材料；
- 题名、作者、年份和来源可确认；
- 近五年前沿文献优先，但理论根基文献不受年份限制。

### 初筛排除标准
- 主题仅弱相关，无法支撑研究问题；
- 非学术博客、营销稿、无来源白皮书；
- 无法确认作者、年份、来源；
- 重复记录、撤稿、疑似掠夺性期刊；
- 只有泛泛概念介绍，不能支撑理论、方法或缺口。

### 精筛优先级
优先保留：
1. 高质量期刊/出版社来源；
2. 直接研究核心构念或相邻机制的文献；
3. 近五年综述、元分析、理论文章和高被引实证文章；
4. 能提供量表、方法或识别策略的文献；
5. 中国情境或可迁移到中国情境的研究。

## 核验与证据等级

### A级：可正式引用
同时满足：
- 题名、作者、年份、期刊/出版社、卷期页码或 DOI/URL 可确认；
- 已读取摘要，最好读取引言、理论、方法或结论中的关键内容；
- 与研究问题直接相关；
- 能明确支撑某个定义、假设、方法或 gap。

### B级：可作为辅助证据
满足题录可确认，但仅读取摘要或二手数据库信息；可用于背景和研究现状，但关键理论判断需谨慎。

### C级：待核验线索
仅来自搜索结果 snippet、ResearchGate、预印本、二手转述或无法确认卷期页码/DOI；可在显著标记「来源未经确证」后引用（本库不保证其真实性，严禁编造出处），或先列入“待核验线索”待后续核实。

## 滚雪球检索
对 A级核心文献必须做滚雪球：
- **向后追溯**：查看其参考文献，找到理论源头、量表源头、经典争议。
- **向前追踪**：查看引用该文献的近五年研究，找到最新拓展。
- **作者追踪**：检索核心作者近五年相关论文。
- **期刊追踪**：检索核心期刊近五年同主题文章。

滚雪球结果必须更新到证据矩阵中，不能停留在聊天框临时判断。

## 文献证据矩阵
复杂交付必须沉淀证据矩阵。最少字段如下：

| 字段 | 说明 |
|---|---|
| 编号 | E1、E2、E3 等唯一编号 |
| 证据等级 | A/B/C |
| 文献类型 | 理论根基 / 近五年前沿 / 方法测量 / 政策实践 |
| 作者年份 | 如 作者甲 & 作者乙, 年份 |
| 题名 | 完整题名 |
| 来源 | 期刊/出版社/机构 |
| 核心构念 | 对应哪个变量或理论 |
| 研究对象/样本 | 样本、行业、国家或研究对象 |
| 方法 | 实证、实验、综述、元分析、QCA、质性等 |
| 关键发现 | 与本研究相关的发现 |
| 不足或边界 | 该文献未解决的问题 |
| 本研究嵌入位置 | 背景/文献述评/假设/方法/贡献 |
| DOI/URL | 可核验链接 |

## 文献链写作模板
每条文献链必须按以下结构输出，而不是只列文献：

```markdown
### 文献链X：主题名称
- 已有研究已经解释：……（列 3–5 篇代表文献）
- 近五年推进：……（说明新变量、新情境、新方法或新争议）
- 仍然不足：……（机制、边界、时序、测量、样本或方法不足）
- 本研究推进：……（本研究如何补足该不足）
- 可进入参考文献的A级/B级证据：……
- 待核验C级线索：……
```

## 政策/现实情境检索
当任务涉及中国情境、政策价值、基金申报、组织实践变化时，至少检索：
- 国家层面权威来源：gov.cn、部委官网、国家统计局、最高法/最高检、人社部、教育部、卫健委等。
- 如有必要，再补地方政策作为落实趋势，不得用地方政策替代国家政策。
- 输出政策证据时必须记录：政策名称、发布主体、发布时间、来源 URL、与研究问题的关系。

- 精筛纳入：

## 从证据到 gap 的转换规则
不得只写“研究较少”。必须写成以下链条：
1. 已有研究解释了什么：对象、理论、方法、结论。
2. 尚未解释什么：边界、机制、时间过程、情境、方法或结果变量。
3. 为什么这个不足重要：理论上阻碍了什么，现实中解释不了什么。
4. 本研究如何推进：新对象、新机制、新时距、新方法、新情境或新干预。

## 交付前文献质量闸门
正式输出前逐项检查：
- 是否保存了检索记录和证据矩阵；
- 是否有近五年文献链，而不是只用经典文献；
- 是否区分“理论根基文献”“前沿文献”“方法测量文献”；
- 每个核心变量是否有定义文献和测量文献；
- 每条核心假设是否至少有 1–2 篇可核验文献支撑；
- 是否至少有 3 条“已有研究—不足—本研究推进”的文献链；
- 参考文献是否与正文引用一致；
- 是否明确哪些文献仍待用户后续精读核验。

## 工具不可用时的补救
- 若联网工具不可用，必须明确说明“当前无法完成实时检索”，并仅基于用户提供材料和已知文献提出检索计划，不得声称已完成检索。
- 若用户提供 PDF/Word 文献，优先读取用户材料，再决定是否需要联网补充。
- 若只能获取摘要，必须标注为 B级或 C级，不能写成“已精读原文”。
- 若用户未提供本地文献且在线检索不可用，明确告知用户需要准备参考文献才能继续，并列出推荐准备方式（文献文件夹路径 / EndNote导出的RIS文件 / 手动文献列表）。

## PDF 批量读取操作流程

> 当用户提供了本地 PDF 文献时，按以下流程执行。本流程是 REF-PDF 规则的操作化展开。

### 步骤 1：文献清点与分批计划
1. 列出用户提供的全部 PDF 文件名，统计总篇数 N。
2. 按 10-15 篇一批制定分批读取计划（避免上下文溢出）。
3. 向用户确认："共 N 篇 PDF，将分 X 批逐篇读取。第一批先读取前 Y 篇。"

### 步骤 2：逐篇提取（每批 10-15 篇）
对每篇 PDF 执行：
1. 使用 `../../scripts/clean_pdf_text.py` 的 `clean_pdf_file()` 提取文本。
2. 从提取文本中识别并记录以下字段：
 - 作者年份（从标题页或首页提取）
 - 完整题名
 - 来源期刊/出版社（从页眉/页脚/元数据提取）
 - 研究对象/样本
 - 研究方法
 - 核心构念
 - 关键发现
 - 不足/边界
3. 纯扫描版处理：若提取文本为空或不足 100 字，标注"扫描版"并基于文件名（通常含作者+年份+题名）补充可用信息。

### 步骤 3：每批汇总
每批读取完成后：
1. 将提取结果填入文献证据矩阵（使用 `build_evidence_matrix()` 生成表格）。
2. 按核心构念归类已提取文献。
3. 向用户展示本批提取摘要，询问是否继续下一批。

### 步骤 4：网络补充检索
全部 PDF 读取完成后：
1. 使用 `search` 工具（type=academic）以核心构念为关键词补充检索近 3 年在线文献。
2. 至少补充 5-8 篇，记录检索来源和检索式。
3. 补充文献同样进入证据矩阵。

### 步骤 5：整合输出
1. 生成完整的文献证据矩阵（本地 + 网络双源）。
2. 构建至少 3 条文献链（每条包含本地和网络证据）。
3. 生成文献对话对象表。

## B3 述评结构化写作规则

> 项目书 B3 阶段的国内外研究现状述评必须按以下结构组织。本规则是 REF-STRUCT 规则第 5 条的操作化展开。

### 禁止的罗列式写法
```
[不通过] 研究一以XX为研究对象，发现A对B有正向影响。
[不通过] 研究二基于社会交换理论，探讨了C在A与B之间的中介作用。
[不通过] 研究三发现D对上述关系有调节作用。
```
这种写法本质上是文献摘要堆砌，不构成"述评"，无法体现研究脉络和 gap 定位。

### 要求的结构化写法
述评必须按文献链组织，每条链内部按"共识→推进→不足→本项目推进"展开：

```markdown
### [文献链主题名称]

**已有共识**：围绕[构念/关系]，已有研究（研究一、研究二、研究三）基本形成了以下共识：[具体共识内容，2-3句]。这些研究共同表明[核心结论]。

**近五年推进**：近五年来，该领域出现了若干重要推进。一方面，研究四引入[新变量/新情境/新方法]，发现[具体推进]。另一方面，研究五基于[新理论视角]，揭示了[新机制]。然而，这些推进也暴露出若干不足。

**仍然不足**：首先，已有研究在[机制/边界/时序/测量/样本]方面存在明显缺口。具体而言，[缺口1：哪篇文献在什么条件下未解决什么问题]。其次，[缺口2：方法论层面未解决的问题]。最后，[缺口3：情境/中国情境层面的空白]。

**本项目推进**：本研究拟从[角度/机制/方法/情境]切入，通过[具体研究设计]，回应上述不足。具体而言：[本项目如何推进缺口1、缺口2、缺口3，每项1-2句]。
```

### 述评组织原则
1. 述评按 3-4 条文献链组织，每条链对应一个核心构念或研究主线，不按作者/年份顺序罗列。
2. 每条链内部先写共识（引用多篇文章），再写推进（聚焦 3-5 篇最新文献），再写不足，最后引出本项目推进。
3. 最后一段总结全部文献链，凝练为 1-2 个核心研究 gap，引出本项目的科学/学术问题。
4. 述评中引用的每篇文献必须来自证据矩阵中的 A/B 级证据。
5. 叙述中必须使用"已有共识""近五年推进""仍然不足"等结构化标志词，让评审一目了然。

## 禁止事项
- 禁止编造文献、卷期页码、DOI、政策名称或统计结果。
- 禁止把搜索结果摘要直接写成“已有研究证明”。
- 禁止在没有检索记录时写“文献已充分覆盖”。
- 禁止只罗列文献，不提炼共识、争议、不足和本研究推进。
- 禁止参考文献列表中出现正文未使用、无法核验或与主题无关的文献。
- 禁止在没有调用 search/browser 工具的情况下声称“已执行文献检索”（见 REF-REAL 规则）。
- 禁止把 agent 内部知识中的文献当作 A 级已核验证据（内部知识文献只能标为 C 级待核验线索）。
- 禁止跳过用户提供的任何一篇 PDF 文献不读取（见 REF-PDF 规则）。
- 禁止在 B3 述评中使用罗列式写法（逐条罗列"某研究发现……；另一研究认为……"），必须按文献链结构化组织（见 B3 述评结构化写作规则）。
- 禁止文献证据矩阵、构念词表、检索式矩阵使用纯文本格式，必须为 Markdown 表格（见 REF-STRUCT 规则）。
- 禁止在文献链中只列出作者年份而不写推进逻辑和具体发现。
- 禁止在 PDF 读取完成后不执行网络补充检索（必须形成本地+网络双源证据链）。
- 禁止检索式矩阵中检索式为空或只写检索类型不写具体关键词组合。
