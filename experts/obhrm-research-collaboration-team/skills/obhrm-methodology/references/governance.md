## 发布质量闸门

以下为交付前必须满足的不变量，机器可读判据见 `../quality_gates.json`（交付前 0 violations 才放行）：

- **引用保真 + 四铁律**（定义见 `skill_rules.md`「引用保真 + 四铁律」，机器判据见 `quality_gates.json` gate `citation_fidelity`/`four_iron_rules`），交付前 0 violations。
- **方法论唯一真源**：包内 `references/` 为唯一真源。
- **Trust Boundary** 硬约束；**蒸馏可回滚**（方法论层进 `governance/method_accumulation.md`，操作层进对应 reference，写前版本备份到 `references/governance/versions/` 下按版本号递增的子目录）。
- **连贯性闸门**：图表必嵌入 + 交叉引用 + 论证连接（Toulmin Warrant）合为一，子项仍查。
- **进度可见性 + 确认点**：论文路径（A0/A1/A5/A6）/ 基金路径（B1/B2/B8/B9）/ 综述路径（G1+/G2/G3/G5）/ 审稿路径（C5/C8/C9）/ 数据分析·定量（D4 / M5 终报告）/ 数据分析·定性（Q1/Q3/Q5）/ 问卷生成（A4 题项确认）/ 选刊路径双模式推荐结果 / distillation 路径 DI-4 及三大方法论关卡须等用户回复。
- **审稿路径为评审唯一真源**（定义见 `skill_rules.md`「评审唯一真源：审稿路径」，机器判据见 `quality_gates.json` gate `review_single_source`）。
- **无角色人设**：功能路由分发，不以研究者人设/帽子驱动交互。
- **全局 P0/P1/P2 严重度分级 + 可追溯账本（稳定 ID）闸门**：交付前按 P0/P1/P2 排序（P0 阻断确认点）；跨路径产物用稳定 ID 与统一状态机标记完成度与就绪度，把既有可追溯矩阵落成可执行机制。机器可读判据见 `quality_gates.json` 的 `severity_p0_p1_p2` / `traceability_ids`。
- **交付前自测**：`../scripts/obhrm_preflight.py`（交付文本预检）全部通过。

## 版本策略

版本号采用 SemVer（`MAJOR.MINOR.PATCH`）：
- **PATCH**：修复 / 文档 / 依赖变更，向后兼容。
- **MINOR**：向后兼容的能力新增（新增域 / 新增脚本 / 新增参考）。
- **MAJOR**：改坏对外契约（删除路径 / 改 spec 接口 / 破坏现有调用），须用户在场确认并写迁移说明。

当前版本以 `plugin.json` 的 `version` 字段为唯一真源（严格 SemVer）。**CHANGELOG 维护规则**：只保留最近 2 个大版本详细记录，每次升级（MINOR/MAJOR）时把更早大版本压缩为「历史版本一览」简洁表（PATCH=修复/文档/依赖，MINOR=能力新增，MAJOR=破坏契约）。

版本历史详见 `../../../CHANGELOG.md`（本文件不复刻计数，以 CHANGELOG.md 为唯一权威）。

## 根 config.json 字段语义（哪些空值是有意为之）

zip 根的 `config.json` 中若干字段留空**属设计决定，不是漏填**。此处逐项说明，供审阅者区分
「有意留空」与「忘了填」：

| 字段 | 取值 | 语义 |
|------|------|------|
| `model` | 空串 | **有意留空 = 不锁定模型**。本技能不绑定特定模型，由安装方按自身可用模型与预算选择；写死会造成安装环境不可用。 |
| `role` | 空串 | **有意留空**。见发布质量闸门第 7 条「无角色人设」——套件按研究推进阶段做功能路由，不以研究者人设驱动交互。填入人设即违反该闸门。 |
| `soul` | 空串 | 同 `role`，理由一致。 |
| `skills` | 空数组 | **有意留空 = 避免双真源**。技能声明的唯一真源是 `.codebuddy-plugin/plugin.json` 的 `skills`；在此复刻会形成第二处真源，违反「方法论唯一真源」闸门。 |
| `prompts` | 空数组 | **有意留空**。提示词内容以 `SKILL.md` 及 `domains/` 下各路径文档为准，不在配置层复刻。 |

`name` / `description` 与包内技能清单同名目保持一致（同名字段同语义），
不另行改写措辞。`testCases` 为平台侧对话冒烟用例，覆盖六条业务路径
（论文 A / 基金 B / 审稿 C / 数据分析 D 与 M / 综述 L / 选刊 J），
每条含 `name`（用例名）、`input`（自然语言输入）、`expect`（期望路由结果）。

## 图表必嵌入 + 交叉引用 + 论证连接

强制规则（所有含数据/论证路径适用）：
1. 图表必须进正文，连续编号、配 ≥80 字 APA 图注、被正文显式引用
2. 全局维护图表登记表
3. 可追溯链：贡献-假设-结果-图表矩阵
4. 论证连接四件强制动作：Warrant / 主张-证据-文献三元 / 文献链闭环 / 逻辑断裂检查
5. 评分兜底：JSON 评分含图表嵌入 / 交叉引用 / 论证连接三维度
6. 执行脚手架：直接复制 `templates/template_guide.md` 空白模板
7. 主动优化建议：收尾通过后再输出 2-4 条优先级优化建议
