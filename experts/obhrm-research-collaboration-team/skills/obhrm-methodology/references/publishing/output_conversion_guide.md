# 成果转化与交付包指南（Paper→PPT / 汇报）

> 场景触发：用户要求「论文转组会 PPT / 开题答辩 / 毕业答辩 / 成果转化」。
> 定位：论文成稿后的**下游转化**——把一份定稿复用为汇报、答辩、传播等多形态产物。

## 一、转化场景与入口

| 场景 | 产出 | 入口/脚本 | 说明 |
|------|------|----------|------|
| 论文 → 组会 PPT | PPTX + 逐页讲稿 | `generate_deliverable_pack.py` + 版式见 `pptx-generation-guide.md` | 按「研究问题→已有证据→设计→样本→结果→局限→下一步」结构 |
| 论文 → 开题/中期/毕业答辩 | 答辩 PPT + 讲稿 | 同上（选答辩模板）+ `pptx-generation-guide.md` | 每页只表达一个主要判断，结果页优先用已有图表 |
| 论文 → 基金申报书素材 | 立项依据/技术路线初稿 | grant-writing B 路径 | 从论文结论反哺基金 B1-B3 |
| 论文 → 学术传播（公众号/科普） | 通俗版摘要 + 图表 | `humanize` + 本指南 | 降复杂度保留证据，避免夸大 |

## 二、通用转化五步（无论何种产物）

1. **定载体**：确认目标形态（PPT/科普），不同载体信息密度不同；
2. **抽骨架**：从定稿中抽取核心论证链（问题→方法→结果→贡献），不重新论证；
3. **换语言**：按受众调整（评审看严谨、答辩看逻辑、科普看可读）；
4. **保证据**：所有数字、统计量、图表、引用与原文一致（结果页优先复用已有图表，**不重算数据**）；
5. **登记留痕**：转化产物登记到交付包清单，注明源稿件版本（防多版本混淆）。

## 三、与交付包脚本的关系

- `generate_deliverable_pack.py` 负责**打包与目录生成**（Word/PDF/审稿报告/交付包）；
- 本指南负责**内容形态转化**（从论文正文→PPT/科普的改写规则）；
- 两者配合：先按本指南改写内容，再用脚本组织交付包结构。
