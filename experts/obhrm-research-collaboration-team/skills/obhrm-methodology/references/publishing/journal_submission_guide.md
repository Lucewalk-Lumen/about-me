## 一、投稿前检查清单

### 1. 期刊选择标准
- [ ] 范围匹配：该期刊是否发表与你主题相关的论文？
- [ ] 受众匹配：该期刊的读者是否会关注你的发现？
- [ ] 影响力：该期刊在你所在领域是否被认可？
- [ ] 掠夺性期刊排查：通过 Beall's List、DOAJ 或 Cabells 核实
- [ ] 开放获取：是否提供 OA 选项？APC 费用多少？
- [ ] 审稿周期：典型审稿周期多长？
- [ ] 拒稿率：相对于你的论文质量是否现实？

> **OBHRM 期刊目录参考**：`field_journal_catalog.md`（18 英文 + 11 中文核心期刊）

### 2. 稿件准备
- [ ] 严格遵循期刊的作者指南（Author Guidelines）
- [ ] 字数/页数在限制范围内
- [ ] 引用格式正确（可能与你的偏好格式不同）
- [ ] 图表符合分辨率和格式要求
- [ ] 双盲审稿已匿名化（如要求）
- [ ] 作者信息页与正文分离
- [ ] 页眉/页脚（如要求）
- [ ] 行号（如要求）

### 3. 投稿所需材料

| 材料 | 通常必需 | 说明 |
|------|:--------:|------|
| Cover Letter | 是 | 致主编 |
| 标题页 | 是 | 标题、作者、单位、通讯作者 |
| 摘要 | 是 | 注意字数限制（通常 150–250 词） |
| 关键词 | 是 | 通常 4–7 个 |
| 正文 | 是 | 遵循期刊结构要求 |
| 参考文献 | 是 | 按期刊要求格式 |
| 表格 | 常需 | 单独文件或嵌入正文 |
| 图表 | 常需 | 高分辨率，特定格式 |
| 补充材料 | 有时需 | 数据、代码、扩展分析 |
| 作者贡献声明（CRediT） | 越来越多期刊要求 | 谁做了什么 |
| 利益冲突声明 | 是 | 即使无冲突也需声明 |
| 数据可用性声明 | 越来越多期刊要求 | 数据可从何处获取 |
| 基金声明 | 是 | 基金编号和资助机构 |
| 伦理声明 | 如适用 | 伦理委员会批准、知情同意 |
| AI 披露声明 | 越来越多期刊要求 | Nature、Science 等已要求 |

## 三、Cover Letter 模板

```
[日期]

[主编姓名，如已知]
主编
[期刊名称]

尊敬的[主编姓名/主编]：

RE: 原创稿件投稿 — "[论文标题]"

我们写信提交题为"[论文标题]"的稿件，拟在[期刊名称]
作为[研究论文/综述论文/短篇通讯]发表。

**研究问题**：
[1–2 句话描述研究问题及其重要性]

**核心发现**：
[1–2 句话突出最重要的结果]

**投稿理由**：
[1 句话说明为何本文适合该期刊的范围和读者群]

**确认事项**：
- 本稿件此前未发表，且未在别处投稿审理中。
- 所有作者均已阅读并批准最终稿件。
- [如适用：本研究已获[伦理委员会]批准（批准号：XXX）。]
- [如适用：本稿件在准备过程中使用了 AI 辅助工具，已在文中披露。]

**建议审稿人**（可选）：
1. [姓名, 单位, 邮箱] — [领域]专家
2. [姓名, 单位, 邮箱] — [领域]专家

**回避审稿人**（可选）：
1. [姓名] — [简述理由，如"近期合作者"]

感谢您审阅我们的投稿。

此致，

[通讯作者姓名]
[职称, 院系]
[单位]
[邮箱]
[ORCID: xxxx-xxxx-xxxx-xxxx]
```

## 四、CRediT 作者贡献声明

| 角色 | 描述 |
|------|------|
| Conceptualization（概念化） | 提出研究构想，确定研究目标 |
| Data curation（数据管理） | 研究数据的管理活动 |
| Formal analysis（正式分析） | 应用统计或计算技术进行分析 |
| Funding acquisition（经费获取） | 为项目获取资金支持 |
| Investigation（调查研究） | 开展研究和数据收集 |
| Methodology（方法论） | 开发或设计研究方法 |
| Project administration（项目管理） | 项目管理与协调 |
| Resources（资源提供） | 提供研究材料或工具 |
| Software（软件开发） | 编程、软件开发 |
| Supervision（监督指导） | 研究 oversight 与领导 |
| Validation（验证） | 结果的验证与核实 |
| Visualization（可视化） | 数据展示准备 |
| Writing – original draft（初稿撰写） | 首次撰写稿件 |
| Writing – review & editing（审阅编辑） | 审阅与修订 |

> **署名规范详细指南**：参见 `../writing/authorship_spec.md`

## 五、数据可用性声明模板

### 开放数据
```
支持本研究发现的数据已在 [数据库名称] 开放获取：[URL/DOI]。
```

### 受限数据
```
支持本研究发现的数据可从 [来源] 获取，但受数据使用许可限制，
不对外公开。合理请求并经 [来源] 许可后，可向作者获取数据。
```

### 无需共享数据
```
本研究未创建或分析新的数据，因此数据共享声明不适用。
```

## 六、AI 披露声明模板

### 简要披露
```
AI 披露：本稿件在准备过程中使用了 AI 辅助工具。作者已审阅
并对全部内容承担完全责任。
```

### 详细披露
```
AI 披露：作者在准备本稿件时使用了 [工具名称]。具体而言，
[工具名称] 被用于 [具体任务：如文献检索辅助、语言编辑、
数据可视化]。使用该工具后，作者进行了必要的审阅和编辑，
并对发表文章的全部内容承担完全责任。
```

## 七、投稿后：回复审稿意见

### 返修回应信结构
```
致编辑和审稿人：

感谢您对我们稿件"[标题]"（稿件编号：XXX）的建设性反馈。
我们已认真处理了所有意见并相应修订了稿件。以下是逐条回应。

--- 审稿人 1 ---

意见 1：[引用审稿人原文]
回应：[说明你做了什么]
修改：[描述具体修改，标注页码/行号]

意见 2：[...]
回应：[...]
修改：[...]

--- 审稿人 2 ---

[同上格式]

---

我们相信这些修订已大幅提升了稿件质量，希望现在适合发表。

此致，
[作者]
```

### 回应最佳实践
1. **回应每一条意见**（即使你不同意）
2. 保持**尊重和感激**的语气
3. 如不同意，用**证据**说明理由
4. 标注具体的**页码/行号**对应修改
5. 修改稿使用**修订模式**（或高亮标记）
6. 同时提交**清洁版本**和**修订标记版本**
