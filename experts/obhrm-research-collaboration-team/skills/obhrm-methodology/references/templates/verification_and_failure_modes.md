## 一、核心原则

**声称完成而没有验证，是不诚实的表现。**

```
没有验证证据，就不能声称完成
```

---

## 二、验证门控流程

在声称任何状态或表达满意之前：

1. **确认**：什么命令/操作能证明这个声称？
2. **执行**：运行完整的验证操作
3. **读取**：完整输出，检查结果
4. **验证**：输出是否确认声称？
   - 如果否：说明实际状态和证据
   - 如果是：说明声称和证据
5. **然后才能**：做出声称

跳过任何步骤 = 撒谎，不是验证。

此流程与 SKILL.md 的「五步法」（明确产出 → 完整写出 → 自检质量 → 标记完成 → 确认下一步）互补：五步法管"产出完整性"，验证门控管"声称真实性"。

## 三、Red Flags — 停止并检查

出现以下想法时，必须先验证再继续。

### 流程类 Red Flags

| AI 的想法 | 正确做法 |
|----------|---------|
| "用户说得很清楚了，直接开始写" | 必须先完成 A0 头脑风暴 |
| "这只是修改一小段" | 检查是否影响证据矩阵/文献链 |
| "先写一段看看效果" | 必须先确认选题和章节结构 |
| "用户很着急，跳过讨论" | 流程可以加速，但不能跳过关键确认（确认点不可跳） |
| "这章内容很简单，不用确认" | 每章写完都必须让用户确认 |
| "先把内容写完再说格式" | 格式在 A0 阶段确定 |

### 文献类 Red Flags

| AI 的想法 | 正确做法 |
|----------|---------|
| "文献我可以补充一些" | 绝不编造文献，必须可追溯 |
| "我记得这个领域的经典文献" | 记忆不可靠，必须验证 DOI/来源 |
| "这个引用看起来很合理" | 没有来源的引用一律不写 |
| "用户应该知道这个领域" | 不假设用户知识，问清楚再写 |

### 验证类 Red Flags

| AI 的想法 | 正确做法 |
|----------|---------|
| "应该写完了" | 运行验证命令确认 |
| "章节看起来完整" | 执行字数统计和结构检查 |
| "引用应该是真的" | 调用 CrossRef API 或搜索验证 |
| "格式应该没问题" | 运行格式检查脚本 |
| "搜索完成" | 检查结果数量和 DOI 列表 |
| "我很确信" | 确信 != 证据，运行验证 |
| "就这一次跳过验证" | 没有例外 |

### 不充分借口清单

| 借口 | 事实 |
|------|------|
| "应该行了" | 运行验证命令 |
| "我很确信" | 确信 != 证据 |
| "就这一次" | 没有例外 |
| "格式检查过了" | 格式检查 != 内容正确 |
| "代理说成功了" | 独立验证 |
| "我累了" | 疲劳不是借口 |
| "部分检查够了" | 部分证明不了什么 |

## 四、AI 研究失败模式库

### 1. 引用幻觉（Citation Hallucination） — 致命 [不通过]
**表现**：AI 生成了不存在的文献引用（作者、年份、期刊均虚构）

**识别方法**：
- 逐一核对 AI 生成的所有引用
- 使用 Google Scholar / 知网验证每篇文献
- 检查 DOI 是否真实有效

**预防措施**：
- [通过] 要求 AI 仅基于真实检索的文献生成内容
- [通过] 禁止 AI "补充"未实际读取的文献
- [通过] 所有引用必须标注来源（A/B/C 级证据）

### 2. 方法论造假（Methodological Fabrication） — 致命 [不通过]
**表现**：AI 生成了不合理或无法执行的研究设计

**常见错误**：
- 样本量不切实际（如"调查 10000 人"但无合理抽样框架）
- 统计方法使用错误（如用回归分析分类变量但不检验假设）
- 实验设计逻辑漏洞（如缺少控制组、操纵检验缺失）

**识别方法**：
- 检查样本量是否与目标总体匹配
- 验证统计方法是否适合数据类型
- 确认实验设计是否可操作

### 3. 理论框架锁定（Theoretical Framework Lock-in） — 警告 [注意]
**表现**：AI 过度依赖某个理论，忽视替代解释

**常见错误**：
- 所有机制都用同一个理论解释
- 不考虑竞争性理论解释
- 理论与研究问题不匹配

**识别方法**：
- 检查是否考虑了至少 2-3 个替代理论
- 评估理论选择是否有充分理由
- 确认理论机制是否过于宽泛

### 4. 统计报告不完整（Incomplete Statistical Reporting） — 警告 [注意]
**表现**：AI 生成了统计结果但缺少关键信息

**常见错误**：
- 只报告 p 值，不报告效应量
- 缺少置信区间
- 不报告模型拟合指标（CFA/SEM）
- 假设检验结果不完整

**识别方法**：
- 对照 `statistical_report_standard.md` 检查
- 确认所有假设都有完整的检验结果
- 验证效应量和置信区间是否报告

### 5. 文献综述空洞化（Shallow Literature Review） — 提示 [提示]
**表现**：AI 生成的文献综述缺乏深度和具体性

**常见错误**：
- 使用"相关研究表明""现有文献较少"等空泛表述
- 缺少具体的作者、年份、发现
- 文献链断裂，缺少"已有→推进→不足→本研究"的逻辑

**识别方法**：
- 检查每一条文献述评是否标注了具体文献
- 确认每个 gap 都有文献支撑
- 评估文献链是否完整

### 6. 假设推导逻辑跳跃（Logical Leap in Hypothesis Derivation） — 警告 [注意]
**表现**：AI 生成的假设推导缺少中间逻辑步骤

**常见错误**：
- 从理论直接跳到假设，缺少机制解释
- 假设间缺少逻辑递进关系
- 调节变量选择无理论依据

**识别方法**：
- 检查每条假设是否有至少 3 句话的机制推演
- 确认假设间是否有过渡说明
- 评估调节变量是否有理论依据

### 7. 语言质量低（Poor Language Quality） — 提示 [提示]
**表现**：AI 生成内容充满机器语言和空泛套话

**常见错误**：
- 使用"值得注意的是""综上所述"等 AI 痕迹词
- 句子长度过于均匀
- 段落结构雷同

**识别方法**：
- 运行 `quality_check.py --risk-words` 检测
- 对照 `writing_self_check.md` 检查
- 人工阅读检查语言自然度

## 五、关键验证模式

### 章节完成验证
```
[通过] [JSON评分块] [看到：8维度均有分值] "阶段评分完成"
[通过] [字数统计] [看到：≥300字] "字数达标"
[通过] [产出文件] [确认存在] "文件已创建"
[不通过] "应该写完了" / "看起来完整"
```

### 引用验证（A6）
```
[通过] [citation_audit.md] [逐一核对作者/卷/页码/DOI] "引用验证完成"
[通过] [CrossRef API] [DOI 可访问] "DOI 验证通过"
[不通过] "引用看起来正确"
```

### 论证连接验证
```
[通过] [Warrant检查] [每个假设有机制解释] "Warrant 完整"
[通过] [文献链检查] [已有→推进→缺口→本研究闭环] "文献链闭环"
[通过] [证据矩阵] [嵌入位非空] "嵌入位完整"
[通过] [Discussion] [回应≥2替代解释] "竞争解释覆盖"
[不通过] "论证应该没问题"
```

## 六、防范策略

### 研究者端
1. **全程参与**：AI 是辅助工具，研究者必须全程参与并负责
2. **逐段验证**：每生成一个部分，立即验证内容和引用
3. **保持批判**：对 AI 生成的内容保持怀疑态度
4. **人工重写**：AI 生成的内容必须人工重写和优化

### AI 使用端
1. **真实检索**：要求 AI 先检索再生成，不得凭记忆生成文献
2. **分步执行**：将大任务拆解为小步骤，逐步验证
3. **引用标注**：所有引用必须标注来源和证据等级
4. **自我检查**：要求 AI 在生成后自我检查常见问题

### 检查清单

在使用 AI 辅助研究时，逐项确认：

- [ ] 所有文献引用已核实（作者、年份、期刊、DOI）
- [ ] 研究设计可执行（样本、方法、分析）
- [ ] 理论选择有充分理由（考虑了替代理论）
- [ ] 统计报告完整（效应量、置信区间、拟合指标）
- [ ] 文献综述具体（标注了具体文献和发现）
- [ ] 假设推导完整（机制推演不少于 3 句）
- [ ] 语言质量高（无 AI 痕迹词，自然流畅）
- [ ] 伦理合规（无造假、篡改、抄袭）
