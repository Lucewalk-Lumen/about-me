# 章节契约模板（Section Contract）

> A1 选题确认后、A2 文献检索前，为论文每个章节立"契约"：明确该章要回答什么问题、覆盖哪些要点、需要什么证据、如何与前后章衔接、何时算完成。前层契约未达标，不得用润色伪装完成。与 `../governance/stable_id_system.md` 配合：契约要点用 S-编号标注，证据用 E/F-编号。

## 模板

### 第 X 章：[章节名]

**核心问题**：本章回答什么研究问题？（1 句，对应 A1 研究问题卡的某一条）

**必覆盖要点**（逐项落实，不可遗漏）：
1. …
2. …
3. …

**证据要求**：
- 需引用文献：≥ N 篇（赋 L-编号）
- 需呈现图表：≥ N 个（赋 F-编号）
- 需报告统计：≥ N 项（赋 E-编号）

**与前后章衔接**：
- 承接：上一章的 ______ 结论 / 上一章输出的 ______
- 输出：为下一章 ______ 提供 ______（如：为 Discussion 提供待解释的实证发现）

**验收标准**（全部满足方可放行进入下一章）：
- [ ] 核心问题有明确回答
- [ ] 必覆盖要点逐项落实（无遗漏、无空话）
- [ ] 证据要求达标（文献/图表/统计数量与编号齐全）
- [ ] 衔接关系成立（承接有据、输出可被下章消费）
- [ ] 稳定 ID（S/E/L/F）已标注并登记入可追溯矩阵

## 使用规则

1. **A1 后立契**：A1 研究问题卡确认后，立即为全部章节起草契约；A2 文献检索按契约要点执行，不跑题。
2. **契约可迭代**：A2/A3 发现新证据或缺口时，更新契约要点并记录变更理由（不静默改）。
3. **A5 收尾核对**：A5 写作完成后，逐章对照契约验收标准自检；未达标补写，不得靠润色掩盖。
4. **审稿联动**：C3 审稿意见若指向某章契约未落实，建 V-修订任务回到该章补齐。

## 与既有产物的关系

- **研究问题卡**（A1）：契约的"核心问题"从研究问题卡派生
- **可追溯矩阵**（A5）：契约的"证据要求"对应矩阵的列
- **obhrm_preflight.py**：占位符检测会拦截契约未落实的 [待作者输入] 标记
- **稳定 ID 体系**：契约要点是 S-编号的来源
