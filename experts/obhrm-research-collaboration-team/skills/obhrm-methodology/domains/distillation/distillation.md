# 蒸馏域（distillation · 方法论沉淀）

> 本文件是套件内「跨路径能力沉淀」独立顶层域的入口与路由。把任意路径（A/B/D/M/C/L/J/Q + visualization / humanize / quality_assurance）工作流中冒出的可复用教训，按层写回（方法论层 / 操作层 / 路径内层）。
>
> **本域在 11 顶层域中的位置**：与 8 条业务路径 + visualization / humanize / quality_assurance 三条通用/质量域并列。覆盖「方法论怎么演进」这一跨路径问题。
>
> **不写回的内容**：用户个人风格偏好 / 个人记忆（属 `~/.workbuddy/` 私域）；本稿特有问题；直觉/临场判断（快照谬误）；公开讨论非亲历真相；不替作者/领域做价值观背书、不美化。

---

## 一、定位与边界

**做什么**：把任意路径工作流中产生的可复用教训，按"研究怎么判断 / 套件怎么操作 / 某条路径内部约定"三层落点。

**不做什么**：

- 不直接产出研究内容
- 不替代 peer_review 做质量判定
- 不替代 quality_assurance 做每阶段评分
- 不管用户个人表达习惯与个人记忆（属 `~/.workbuddy/` 私域，不进本技能）

**与质量域的边界**：

- **quality_assurance**：每阶段末的**评分块**（10 维 1-5 分），关注单次交付的当下质量
- **distillation**：跨阶段的**经验沉淀**，关注能力随时间演进的方向

## 二、四阶段流程

### Phase 1 · 采集候选

来源：任一路径产出的「交接块 →D蒸馏」（字段见 `../../references/templates/handoff-protocol.md` §链路六）。调度者先标记候选。

**必带字段**：

- 形态：`correction | insight | question`
- source：可追溯来源（会话上下文 / 稿件位置 / 审稿意见编号 / 交接块编号）
- source_quote：≤100 字原文
- summary：自己的话一句
- 纠正类附加：`{scene, wrong, correct}`

### Phase 2 · 三重验证提炼（入口门槛）

一条候选要被认定为「可升格的方法/操作规则」而非「一次性备注」，必须过三重验证（RIA-TV++）：

- **V1 跨域复现**：在 ≥ 2 类不同研究场景都成立（单稿特有问题 → 0 过，不蒸馏）
- **V2 有生成力**：能推断一个源任务未直接讨论的新情境如何处理
- **V3 有独特性**：抹掉上下文后不是聪明人都知的常识

判定：**3 过 = 升格写入落点；1 过 = 降级为启发式备注；0 过 = 不蒸馏**。

### Phase 3 · 判层 + 三落点写回

**先判层，再落点**（判层错位是蒸馏最常见的失败模式）：

| 层 | 判定信号 | 落点 | 写回流程 |
|----|---------|------|---------|
| **方法论层**（研究怎么判断） | 涉及缺口类型 / 理论视角选用 / 贡献类型 / 论证链标准 / 综述方法 / 质量闸门 / PPT 叙事线——**换个执行工具仍成立** | `../../references/governance/method_accumulation.md`（包内自包含唯一落点） | 写前备份（版本块追加）→ 与现有 [通过] 规则比对（冲突双留）→ 写回 → 压力自测 → 文件内记 CHANGELOG 一行 |
| **套件操作层**（具体怎么操作） | 涉及套件执行工艺：清单缺项 / 模板字段 / 图表参数 / 脚本环境 / 阶段衔接摩擦——**换执行工具就不成立** | 套件对应 `references/*.md` 或域文件 | 定位最小落点文件 → Edit 写入 → 在 SKILL.md「版本」节追加一行留痕（日期+改了什么+为何） |
| **路径内专有层**（某条路径内部） | 某条路径内部约定（如 论文路径的某阶段纪律） | 对应 `domains/<path>/<path>.md` 路径内章节 | 同操作层 |

**落点边界**：

- 一条教训可能多层都沾（如"假设推导必须给 Warrant，模板里加一栏"）→ 拆成两条分别落点，各自留痕
- 判层拿不准 → 默认方法论层（真源机制更严、可回滚），并在 CHANGELOG 注明"层级存疑"
- **无人值守自动化场景只写方法论层**；操作层 / 路径内层落点仅在有用户在场的会话内蒸馏中执行

### Phase 4 · 写前自检（8 条勾选）

- [ ] 真跨域？非单稿特有问题？
- [ ] 与现有规则冲突时已双留，未私改？
- [ ] 未把作者个人风格误当普适方法？
- [ ] 写回前已备份 + 用户确认（或审计记录留痕）？
- [ ] 每条带可溯源 source？
- [ ] 删掉具体文稿后，这条教训还能独立成立？
- [ ] 含矛盾的内容已按「矛盾不修复」保留张力，未强行调和？
- [ ] 信息不足处已标置信度（推测/据来源/并列），未编造？

## 三、必须坚守的三条原则

**① 诚实边界——明确写「不蒸馏什么」**

- 本稿特有问题（已在我边界）
- 直觉/临场判断无法沉淀为规则（快照谬误：今天的判断 ≠ 可复用规则）
- 单次快照无法捕捉方法演化（写回须标注时效，明天可能迭代）
- 公开讨论 ≠ 亲历真相（不把「某文献说」当「公理」）
- 不替作者/领域做价值观背书、不美化

**② 矛盾不修复**

文献/方法间冲突是领域真实特征，不是要修的 Bug。三类矛盾如实保留：

- **时间性**（观点演化）：标「早期/近期」，以近期为主但提及演化
- **领域性**（不同场景不同规则）：分领域记录，不强求统一
- **本质性**（价值观内在张力）：明确记为「核心张力」

错误做法：选一边忽略 / 编调和解释 / 假装不存在。

**③ 信息不足标注**（与四铁律「标注无支撑」对齐）

| 情况 | 处理 |
|------|------|
| 某维度证据少 | 标「推测」 |
| 仅二手/单一来源 | 降置信度，标「据〔来源〕」 |
| 信息相互矛盾无法判断 | 并列呈现，不替用户下结论 |

## 四、版本与校准机制（写回前自检 + 可回滚）

- **写前必做**：方法论层落点先备份到 `../../references/governance/versions/` 下按版本号递增的子目录，保留近 10 版（超过 10 版压缩归档）
- **纠正层**（用户提"这条不对/要改"时）：
  - **类型 A（用户推翻方法论）**：旧块保留不动，新块以「〔v(N+1).纠正〕」标记追加；CHANGELOG 写明推翻原因
  - **类型 B（用户补操作细节）**：操作层落到对应 reference，本文件只增「操作层配套」指针
  - **类型 C（用户推翻后又撤回）**：保留推翻块 + 撤回块，CHANGELOG 写明「已撤回」
- **冲突双留**：新旧并陈，§2 冲突记录一栏
- **压力自测 3 条**：
  1. 拟写回规则在 ≥ 3 个不同 OBHRM 研究场景下成立才入方法论层
  2. 规则表述不能含"如果用户提到 X 才用"这类语境依赖（语境依赖的归操作层）
  3. 规则不能仅适用于 OBHRM 单一子域（仅适用单一子域的归操作层 `domains/<path>/<path>.md`）
- **可追溯**：每条沉淀必须含：日期 / 教训 / 三重验证证据 / 来源
- **回滚** = 把最近一次 `../../references/governance/versions/` 下的 `method_accumulation.md` 备份拷回 `../../references/governance/method_accumulation.md`
