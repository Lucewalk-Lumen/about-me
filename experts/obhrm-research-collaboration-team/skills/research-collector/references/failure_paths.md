# 失败场景与降级策略

> 完全去除第三方在线文档交付，本地 Markdown 报告文件（对话中告知路径）是唯一交付方式。

## 搜索阶段

| 失败场景 | 触发条件 | 处理方式 |
|----------|---------|---------|
| 某平台搜索无结果 | WebSearch 返回 0 条 | 尝试替代关键词；仍无结果则跳过该平台 |
| 全部平台搜索无结果 | 所有来源均无结果 | 提示用户放宽范围或更换关键词 |
| 搜索结果过少（< 3 条） | 总条目少于 3 | 提示用户信息不足，建议换关键词 |
| WebFetch 被反爬拦截 | HTTP 403/429 或返回空内容 | 尝试其他来源；记录失败原因在输出中注明 |

## 信息提取阶段

| 失败场景 | 处理方式 |
|----------|---------|
| 无法确定发布时间 | 标记为 "未知" |
| 无法确定作者/机构 | 标记为 "未知" |
| 无法提取核心技术 | 用文章摘要前 50 字作为替代 |
| 无法确定局限性 | 标记为 "未提及"（该字段允许较低填充率） |

## 交付阶段

| 失败场景 | 处理方式 |
|----------|---------|
| 报告写入失败 | 改为直接输出到对话 + 提示用户手动复制 |
| 模板字段渲染异常 | 保留原始采集数据，不做模板化处理 |

## 交付清单

正常路径：
1. **本地文件**：报告保存到 `audit/research-collector/<topic>-<YYYY-MM-DD>.md`
2. **文件交付**：在对话中告知用户报告文件路径（WorkBuddy 结果面板会自动呈现生成的交付文件）
3. **下游消费**：用户可选择将报告喂入 literature-review L1 / paper-writing A2 / data-analysis
