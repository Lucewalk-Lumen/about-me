# 数据兜底策略

> 跨平台：文中命令统一 `python3`，Windows 上解释器名通常为 `python`。

## 兜底顺序

1. 用户粘贴 CSV：用户明确提供 CSV 或要求不要联网时，直接解析用户数据，不访问外部数据源。
2. 本地缓存：如果已经有同一标的、周期、复权、区间和根数的缓存，实时数据失败时优先使用缓存，并在报告中标注缓存时间。
3. 东方财富实时数据：默认数据源，串行请求，失败时返回结构化失败 JSON。
4. 数据补充模板：无实时数据、无缓存、无 CSV 时，不生成伪复盘，只要求用户按模板补充数据。
5. 离线 fixture：仅用于 smoke 和评测，不可当作真实行情。

## 缓存使用建议

脚本支持：

```bash
python3 fetch_eastmoney_kline.py 510300 --limit 120 --cache-dir .cache/kline
python3 fetch_eastmoney_kline.py 510300 --limit 120 --cache-dir .cache/kline --prefer-cache
python3 fetch_eastmoney_kline.py 510300 --limit 120 --cache-dir .cache/kline --allow-stale-cache
```

缓存命中时，报告必须说明：

- 来源为 `eastmoney-cache`。
- 缓存大约生成于多久前。
- 缓存行情可能滞后，关键价位和均线需要在最新数据恢复后复核。

## CSV 补充模板

用户可以粘贴以下格式：

```csv
日期,开盘,收盘,最高,最低,成交量,成交额,涨跌幅,换手率
2026-06-24,10.00,10.20,10.30,9.95,1200000,12200000,1.49,1.20
2026-06-25,10.22,10.10,10.35,10.02,980000,9980000,-0.98,0.97
```

最少建议 20 根 K 线；如果要看 MA60 或中期结构，建议至少 60 根。

## 禁止行为

- 不用离线 fixture 冒充真实行情。
- 不在实时数据失败时编造价格、成交量、涨跌幅或关键价位。
- 不隐藏缓存时效；缓存越旧，风险提示越显著。
- 不为了规避限流而并发轰炸东方财富。
