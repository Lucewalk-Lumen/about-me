# 版本更新播报流程（首条消息必做）

> 本流程对应主理人「版本更新播报」职责：确保**线上版本更新、用户再次召唤时能知道更新了什么**，
> 且**同一版本读过一次后不再重复打扰**。本文件是 `agents/teaching-helper-team-lead.md` 版本播报指针的子流程，
> 执行前先 Read 本文件，未读不得操作。

## 触发时机
每次新会话被召唤、收到首条用户消息时执行（在各项强制初始化门禁之前、受理教学类诉求之前）。

## 步骤
1. 读本包 `.codebuddy-plugin/plugin.json` 取 `version`（记为 **V**）；读包根 `UPGRADE.md` 提取与 V 对应的「## v{V}」段落要点。
2. 读状态文件 `~/.workbuddy/teaching-helper-team/seen_upgrade.txt`（记录上次已播报版本；不存在视为从未播报）。
3. **若 V 与已记录版本不同**（或文件缺失 / 读取失败），向用户输出一段**独立区块**：
   ```
   【教学帮帮团 · v{V} 更新提示】
   本次主要更新：…（取自 UPGRADE.md 该版本要点，精简 2–4 条）
   ```
   随后把 V 写回 `~/.workbuddy/teaching-helper-team/seen_upgrade.txt`（目录不存在先 `mkdir -p`；写失败不阻塞，下次仍会播报）。
4. **若 V 相同**，则**跳过**此提示，不打扰。

## 边界
- 本流程只读取包内清单与更新说明、只写一个状态文件，**不启动任何成员 Agent、不执行任何技能、不产出任何交付物**。
- 播报是纯文本告知，不得打断用户原本的诉求；他若已在提需求，先受理需求再顺带告知。
- 本流程**不替代**本包既有的各项强制门禁（装包后初始化、用户输入路由门禁、爬虫验证确认门禁），那些仍按各自章节独立触发。

## 降级
若 `UPGRADE.md` 无法读取，则改为提示「本版本已更新，更新要点见包内 UPGRADE.md」，**不得静默省略**。

## 状态文件约定
- 路径：`~/.workbuddy/teaching-helper-team/seen_upgrade.txt`（仅存一行版本号文本，如 `1.1.1`）。
- 写权限受限时不阻塞：写失败则下次会话仍会播报，属安全兜底。
