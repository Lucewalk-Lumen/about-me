# 论文文献速览与蒸馏助手 (Literature Distiller Pro)
> **归属**：内置扩展——随 thesis-mentor 交付

本 Skill 专注于**学术论文的快速浏览与内容蒸馏**，通过 **"4+2 深度蒸馏模型"** 将学术论文转化为结构化的本地 Markdown 报告。**仅支持用户上传的 PDF 文件**，离线处理，无外部依赖。

## 触发条件

当用户提出以下需求时激活本技能：
- "帮我速览这个PDF"
- "蒸馏这篇论文的核心内容"
- "快速提取这篇文献的关键信息"
- "分析这个PDF的研究方法和结论"
- 用户上传单个 PDF 文件或指定本地 PDF 路径

## 核心架构：4+2 深度蒸馏模型

| 层级 | 模块 | 核心内容 |
| :--- | :--- | :--- |
| **基础层** | **M1: 结构化元数据** | 标题、作者、机构、来源、年份、DOI。**快速标签**：学科分类、研究方法、核心技术。 |
| | **M2: 逻辑骨架还原** | **论证链条**（问题→理论→方法→结论）、**精简摘要**、**关键图表说明**。 |
| | **M3: 引用文献网络** | 核心参考文献列表（Top 10），为后续深入阅读提供指引。 |
| **洞察层** | **M4: 批判性思考** | **研究缺口**、局限性分析、可能的改进方向。 |
| | **M5: 知识图谱关联** | 前置知识提示、同类方法对比、领域定位。 |

## 执行流程

### 步骤 0: 用户目的确认（首要步骤）

在处理任何输入之前，**必须首先询问用户的分析目的**：

**询问方式**：使用 `AskUserQuestion` 工具向用户提问，提供三个选项：
1. **深度蒸馏**：完整的 4+2 模型分析，包含 M1-M5 全部模块，适合深入研究
2. **快速阅读**：仅生成 M1（元数据）+ M2（精简摘要 + 论证链条），跳过 M3-M5，适合快速浏览
3. **简单了解**：仅提取标题、作者、摘要和核心结论，适合初步筛选

**默认建议**：若用户未明确指定，默认为"快速阅读"模式。

### 步骤 1: PDF 文件处理

**仅支持本地 PDF 文件**（扩展名 `.pdf`），离线处理，无外部依赖。

1. **文件接收与验证**：
   - 检查扩展名是否为 `.pdf`
   - 检查文件头是否以 `%PDF` 开头
   - 检查文件大小 > 1000 bytes

2. **内容提取**：使用 WorkBuddy 内置 `pdf` 技能或 `Read` 工具深度解析 PDF 内容（`Read` 工具支持直接读取 PDF 文件并提取文本；对图片型 PDF 可用多模态 `Read` 读取）

3. **根据用户目的执行相应蒸馏级别**：
   - **深度蒸馏**：执行完整的 4+2 模型（M1-M5）
   - **快速阅读**：仅执行 M1 + M2
   - **简单了解**：仅提取标题、作者、摘要、核心结论

4. **生成本地 Markdown 报告**，落 `data/pipeline/outgoing/literature-distiller/` 目录

>  注意：本 skill **不支持在线链接、外部数据库抓取、云端知识库归档**。所有输入必须是本地可访问的 PDF 文件。如需分析在线文献，请先下载到本地后再提交。

### 步骤 2: 4+2 模块化蒸馏

#### M1: 结构化元数据提取

从解析内容中提取基础信息：

```markdown
| 字段 | 提取策略 |
|------|---------|
| 标题 | PDF 首页大字号文本或元数据中的 Title 字段 |
| 作者 | 标题下方的作者列表，逗号或换行分隔 |
| 机构 | 作者姓名后的上标或括号内机构名称 |
| 来源 | 期刊/会议名称（通常在页眉页脚或首页底部） |
| 年份 | 出版年份（从来源或 DOI 中提取） |
| DOI | 若有则提取，否则标注"未找到" |
| 页数 | PDF 总页数 |
| 语言 | 检测主要语言（中文/英文） |
```

**自动生成快速标签**：
- 学科分类：根据标题和摘要关键词判断（如 #NLP #计算机视觉 #强化学习）
- 研究方法：识别研究类型（如 #实证研究 #理论分析 #综述 #案例研究）
- 核心技术：提取关键技术术语（如 #Transformer #注意力机制 #深度学习）

#### M2: 逻辑骨架还原

**论证链条重构**（用简洁语言概括）：

```
 研究问题 →  理论基础 →  方法论 →  实验设计 →  主要发现 →  结论
```

**精简摘要生成**（150-200字）：
- 用通俗语言总结研究核心
- 突出创新点和关键结论
- 避免过多技术细节

**关键图表说明**：
- 提取重要图表的标题和简要说明
- 标注图表所在页码（便于用户回查原文）

#### M3: 引用文献网络（仅深度蒸馏模式）

提取参考文献列表中的**核心10条**：

```markdown
### 核心参考文献（Top 10）

1. 作者. 标题. 期刊/会议, 年份.
2. ...
```

- 优先选择被多次引用的经典文献
- 标注近3年的最新研究
- 若原文有"Related Work"章节，优先提取其中提到的关键文献

#### M4: 批判性思考（仅深度蒸馏模式）

基于内容进行快速分析：

**研究缺口识别**：
- 该方法未覆盖的场景或限制条件
- 实验设计的不足之处（如数据集规模、评估指标单一）
- 未讨论的潜在问题

**局限性分析**：
- 计算复杂度或资源需求
- 泛化能力限制（特定领域/数据集）
- 理论假设的合理性

**可能的改进方向**：
- 方法层面的优化建议
- 实验设计的扩展思路
- 跨领域应用的潜力

#### M5: 知识图谱关联（仅深度蒸馏模式）

**前置知识提示**：
- 理解本文需要的基础概念（2-3个关键点）
- 相关技术或理论的简要说明

**同类方法对比**（若文中提到基线方法）：

| 方法 | 核心思路 | 优势 | 劣势 |
|------|---------|------|------|
| 本文方法 | ... | ... | ... |
| 基线方法1 | ... | ... | ... |

**领域定位**：
- 用1-2句话说明该研究在领域中的位置
- 例如："这是将 Transformer 应用于时间序列预测的最新尝试，继 Informer 和 Autoformer 之后的又一重要进展"

### 步骤 3: 生成本地 Markdown 报告

根据用户选择的蒸馏级别，生成相应内容的本地 Markdown 报告，落 `data/pipeline/outgoing/literature-distiller/`：

**深度蒸馏模式**：包含 M1-M5 全部内容
**快速阅读模式**：仅包含 M1 + M2
**简单了解模式**：仅包含标题、作者、摘要、核心结论

```markdown
# 论文速览：{论文标题}

>  蒸馏日期：{YYYY-MM-DD HH:MM}  
>  原始文件：`{本地 PDF 文件路径}`  
>  文件大小：{XX MB} | {XX 页}  
>  DOI：{doi_if_available}
>  分析模式：{深度蒸馏/快速阅读/简单了解}
```

### 步骤 4: 输出与交付（本地 Markdown）

**交付流程**：
1. 将步骤 3 生成的完整 Markdown 内容作为文档正文
2. 写入 `data/pipeline/outgoing/literature-distiller/distilled_{paper_id}.md`
3. 同目录下生成 `distilled_metadata.json` 索引文件
4. 在对话中返回文件路径，供用户复制或进一步处理
5. **交付前确定性门禁（必跑）**：成稿交付前运行 `python skills/deai-rules/scripts/deai_preflight.py <成稿路径>`，须 PASS；与 `deai-rules` 五维自评（≥45）共同构成 quality 门禁，未 PASS 不得标记为交付物（规则见 `skills/deai-rules/SKILL.md`）。

### 步骤 5：归档到知识库（可选）

- 若用户的团队知识库已初始化（即 `~/.workbuddy/wiki-knowledge/` 目录存在且含 `WIKI-SCHEMA.md`），可将本结构化报告经 `knowledge-wiki` 技能的 Ingest 流程沉淀为 wiki 页面，便于后续跨任务复用。
- 若知识库未初始化，跳过本步骤，并在交付物说明中注明「未沉淀至知识库」。
- 本步骤不强制：无论是否归档，蒸馏报告均已落 `data/pipeline/outgoing/literature-distiller/`，主流程不受影响。

## 输出规范

### 交付物形式

- **主要产物**：本地 Markdown 文件
- **文件命名**：`distilled_{paper_id}.md`
- **文件位置**：`data/pipeline/outgoing/literature-distiller/`
- **配套文件**：`distilled_metadata.json`（含来源 PDF 路径、蒸馏级别、生成时间等元信息）

### 质量标准

1. **速度优先**：单篇文献处理时间控制在 1-2 分钟内
2. **核心准确**：M1 元数据和 M2 论证链条必须准确
3. **简洁可读**：避免冗长描述，用列表和表格呈现
4. **可追溯性**：明确标注原始 PDF 文件路径和页码引用
5. **实用导向**：M4/M5 提供 actionable 的洞察和建议
6. **透明标注**：必须明确标注数据来源（仅本地 PDF，无外部补充）

### 关键约束

-  **仅支持本地 PDF 输入**：拒绝在线链接、URL、URL 列表等任何外部来源
-  **用户目的确认**：处理前必须询问用户分析目的
-  **输出本地 Markdown 报告**：落 `data/pipeline/outgoing/literature-distiller/`，禁止依赖任何外部协作平台
-  **不虚构信息**：缺失字段明确标注"未找到"
-  **区分事实与推断**：M4/M5 标注为分析观点
-  **保留原文引用**：关键结论使用原文表述并加引号
-  **不处理加密 PDF**：提示用户先解密
-  **不处理损坏文件**：记录错误并告知用户
-  **不做深度学术评审**：仅提供快速浏览和初步洞察

## 常见问题处理

| 场景 | 处理方式 |
|------|----------|
| PDF 为扫描版（图片型） | 提示用户："检测到扫描版 PDF，文本提取效果可能不佳，建议使用 OCR 工具预处理" |
| 某字段提取失败 | 在报告中标注"未找到"，继续处理其他字段 |
| 参考文献格式混乱 | 尽力标准化，无法标准化的保留原样 |
| 文件过大（>50MB） | 提示用户："文件较大，解析可能需要较长时间，是否继续？" |
| 用户需要批量处理 | 支持指定文件夹，逐个处理并生成汇总清单 |
| 文件读取权限不足 | 提示用户检查文件权限或重新拷贝到可访问目录 |
| 蒸馏过程中字段提取不全 | 在报告中对应字段标注"未找到"，继续处理其他字段 |

## 使用示例

### 示例 1：PDF 文件 + 深度蒸馏

用户上传 `paper.pdf` 并说：
> "帮我深度蒸馏这篇论文"

助手响应：
1. 确认用户目的为"深度蒸馏"
2. 验证文件有效性
3. 执行完整的 4+2 蒸馏（M1-M5）
4. 生成本地 Markdown 报告，落 `data/pipeline/outgoing/literature-distiller/`
5. 在对话中返回文件路径

### 示例 2：批量处理多篇 PDF

用户上传多份 PDF 到 `~/Papers/batch1/` 并说：
> "把这批论文快速过一下，提取标题和核心结论"

助手响应：
1. 确认用户目的为"快速阅读"
2. 遍历目录，校验每个文件
3. 逐个执行 M1 + M2 蒸馏
4. 每个文件生成独立报告
5. 在 `data/pipeline/outgoing/literature-distiller/` 下生成清单索引

### 示例 3：简单了解模式

用户上传 `paper.pdf` 并说：
> "简单了解一下这篇论文的核心内容"

助手响应：
1. 确认用户目的为"简单了解"
2. 仅提取标题、作者、摘要、核心结论
3. 生成精简版本地 Markdown 报告
4. 在对话中返回文件路径
5. 处理时间控制在 30 秒内

**注意事项**：
- 本 Skill 定位为**快速浏览工具**，适合初步筛选文献
- 如需深度学术分析，建议选择"深度蒸馏"模式并结合专业文献管理软件
- 生成的报告为本地 Markdown 文件，存储在 `data/pipeline/outgoing/literature-distiller/` 目录
- 处理敏感文献时，注意本地文件的访问权限
- 蒸馏结果仅基于用户提供的 PDF 内容，不联网检索任何补充信息
