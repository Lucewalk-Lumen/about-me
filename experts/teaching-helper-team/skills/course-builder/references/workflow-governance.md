## 多智能体角色定义与写入边界


课程建设全流程涉及多类工作，可按角色分工协作。每个角色有明确的职责边界和写入权限。

### 角色定义

| 角色 | 职责 | 核心产出 |
|------|------|---------|
| **协调员** (Team Lead) | 全流程编排、阶段推进、用户交互、任务分发与仲裁 | 阶段决策、任务分配、进度看板 |
| **研究员** (Researcher) | 学科调研、资料收集、来源验证、素材整理 | 调研报告、素材索引、来源验证记录 |
| **设计员** (Designer) | 教学设计、大纲规划、知识框架梳理、教案设计 | 课程大纲、知识框架图、教案方案 |
| **写作员** (Writer) | 教材正文编写、课件内容撰写、迭代修订 | 章节草稿、课件文本、修订记录 |
| **审查员** (Reviewer) | 分层质检、AI痕迹检测、风格一致性检查 | 质检报告、修改建议、复检记录 |

### 写入边界

每个角色对文件系统有明确的写入权限，防止冲突：

| 角色 | 允许写入 | 禁止写入 |
|------|---------|---------|
| **协调员** | 进度看板、任务状态、阶段决策记录 | 章节正文、质检报告内容 |
| **研究员** | 调研笔记、素材索引、来源验证记录 | 章节正文、教案设计文件 |
| **设计员** | 课程大纲、知识框架、教案方案、课件结构 | 章节正文（仅提结构建议） |
| **写作员** | 分配到自己负责的章节草稿、写作笔记 | 其他写作员的章节、质检报告 |
| **审查员** | 质检报告、修改建议清单、复检记录 | 章节正文（仅标注建议） |

### 多智能体协作适用场景

> **重要原则**：多智能体正文写作默认不推荐，除非用户明确要求。

| 适合多智能体的任务 | 不适合多智能体的任务 |
|------------------|-------------------|
| 策划（大纲拆解、课程定位） | 正文写作（风格不一致风险） |
| 校对（术语核查、格式审计） | 连续叙事章节（衔接边界难对齐） |
| 审核（质量门禁、一致性检测） | 需要统一语气的整篇文稿 |
| 调研（多来源并行检索） | — |

**正文写作建议**：优先使用单会话串行模式；仅当章节间依赖关系已明确且用户知悉风险后，才启用多写作员并行。

### 任务依赖管理

任务可设置依赖关系，当依赖任务未完成时自动阻塞：

```
任务A（调研） → 任务B（大纲设计） → 任务C（第一章写作） → 任务D（第一章质检）
```

- 尝试启动有未完成依赖的任务 → 自动转为"受阻"状态
- 标注阻塞原因：依赖任务ID列表
- 依赖完成后，受阻任务恢复为"待开始"

## 横向协同磁盘协议


多角色协作时，以**磁盘文件为唯一可合并真值**，不以对话为信息来源。

### 真值原则

1. **磁盘优先**：所有角色的产出物落盘为文件，其他角色读取文件而非依赖对话记忆
2. **追加不覆盖**：检索日志、质检记录等审计类文件只追加新行，不原地篡改历史
3. **写入边界**：每个角色只写自己权限范围内的文件，禁止覆盖他人产出

### 冲突处理

| 冲突类型 | 处理方式 |
|---------|---------|
| **内容冲突**（两角色对同一知识点有不同表述） | 上升至协调员仲裁，输出决议摘要落盘后再改正文 |
| **术语冲突**（不同章节使用不同术语） | 由协调员或单一"术语管理员"合并，写作员只追加"建议" |
| **进度冲突**（任务状态不一致） | 以磁盘上的进度看板为准，口头"已写完"不采信 |

### 最小同步清单

每轮并行协作前，确认以下事项：

1. 进度看板已更新（当前各任务状态）
2. 章节ID和文件命名一致（避免跨章节引用错位）
3. 术语表当前版本无异议
4. 引用格式与数据源约定统一（避免合稿时双轨脚注）

## 会话恢复与上下文管理


跨会话恢复课程建设项目时，执行三级检测：

### 三级恢复检测

| 检测顺序 | 检测目标 | 命中后输出 |
|---------|---------|-----------|
| 1 | 会话恢复简报（48小时内） | 上次决策、未决问题、用户偏好提示 |
| 2 | 当前阶段状态文件 | 当前所处阶段、已完成节点 |
| 3 | 项目摘要（如有） | 项目名称、课程信息、进度概要 |

命中后输出恢复卡（4行）：

```
━━ 课程建设进度 ━━
课程：{课程名称}
当前阶段：{Phase X}
上次完成：{节点}
建议下一步：A / B / C（最多3个选项）
━━━━━━━━━━━━━━━━
```

### 记忆分层

| 层级 | 内容 | 写入时机 | 权威性 |
|------|------|---------|--------|
| **L1 项目真值** | 阶段状态、章节台账、进度看板 | 每轮阶段切换时落盘 | 最高，以磁盘为准 |
| **L2 工作笔记** | 术语锁定、待办清单、用户约束 | 每轮讨论中追加 | 次之，L1冲突时以L1为准 |
| **L3 用户全局** | 教师偏好、课程信息 | 教师主动告知时 | 跨项目复用，但本轮以L1为准 |

### 冲突仲裁规则

1. **用户最新明确陈述** 覆盖旧摘要与旧记忆
2. **项目落盘文件** 优先于未落盘的闲聊推断
3. 工作笔记与项目真值冲突时，以项目真值为准，再修正工作笔记

## 长会话上下文压缩策略


长会话（如多轮章节修订）中，优先使用磁盘真值而非重复注入全文。

### 压缩原则

| 原则 | 说明 |
|------|------|
| **不重复读取** | 单轮内不重复读取 SKILL.md 或大型参考文件 |
| **优先读摘要** | 优先读取会话恢复简报、阶段状态文件，而非全文 |
| **跨轮落盘** | 超长讨论前，将"术语锁定、待办、用户约束"写入工作笔记 |
| **临时不入长期** | 临时事实（如某次调试的错误信息）不写入长期记忆 |

### 长会话结构化摘要

超长对话（30分钟以上或多轮迭代）时，在关键节点将决策写入结构化摘要：

```json
{
  "sessionRef": "会话标识",
  "decisions": [
    "确认课程名：《数据结构与算法》",
    "大纲从15章调整为12章"
  ],
  "openIssues": [
    "第3章实验设计待确认"
  ],
  "userPreferencesHint": {
    "batchConfirm": true,
    "stylePreference": "正式学术风格"
  }
}
```

### 双轨语境

| 层级 | 对应行为 | 目的 |
|------|---------|------|
| **首响层** | 快速响应、截断冗余信息 | 防止首响过慢，保持交互性 |
| **写作层** | 长回合讨论、结构化落盘 | 保证内容质量和可追溯性 |

## UX优化规范

>
> **详细规范**：本节为通用策略概要。详细的防卡顿时间阈值（15s/30s分层）、进度条设计、决策节点规则见 [textbook-visual/ux-design.md](textbook-visual/ux-design.md)；防卡顿执行指南见 [textbook-ops/anti-stall-guide.md](textbook-ops/anti-stall-guide.md)。

### 主动会话恢复

每次新会话首轮触达时，自动执行三级检测（见上文"会话恢复"），命中后输出恢复卡。

### 渐进式引导

- 只推荐"最近可达的下一步"，每次最多3个动作
- 首次用户只问"你要做什么课程"，不直接抛内部术语
- 每次阶段完成后更新下一步建议

### 成就式反馈

从"考试式阻断"改为"成就式反馈"：

| 传统方式 | 成就式方式 |
|---------|-----------|
| 质检失败，请修复后继续 | 本章已完成，当前 87/100；2处已自动优化，1处待你确认 |
| 有3个错误 | 已检查完毕，大部分很好；3处建议优化，你可以选择现在处理或稍后 |

失败项统一提供三个选项：`[现在修] [稍后修] [跳过]`

### 进度可视化

在以下时机自动展示进度：
- 阶段切换时
- 每章完成时
- 用户主动询问进度时

进度仪表盘格式：

```
━━━━━━ 课程建设进度 ━━━━━━
课程：数据结构与算法  阶段：Phase 3 教材编写
章节：4/12 完成  |  质检：3/4 通过
预计剩余：8 章  |  总字数：~12,350
━━━━━━━━━━━━━━━━━━━━
```

### 行为学习（半透明）

学习用户偏好时须可解释，应用偏好时须提示：

> 根据你之前的偏好，我先用 {风格} 输出；如果你想改，我马上切。

临时事实不进长期记忆，长期只保留"策略经验"。

## 信息优先级与仲裁规则


把"用户话/磁盘真值/系统策略"三类信息分开，避免混淆。

### 三类信息产权

| 类别 | 典型来源 | 处理原则 |
|------|---------|---------|
| **用户主权** | 当前对话中的明确指令、当轮确认 | 最高优先级；摘要与记忆不得覆盖 |
| **项目状态** | 落盘文件、章节台账、进度看板 | 以磁盘为准；变更需写入文件或经用户确认 |
| **系统策略** | SKILL.md流程、质检规则、参考文件 | 只读引用；不冒充用户命令 |

### 仲裁规则（冲突时听谁）

1. **用户最新明确陈述** 覆盖旧摘要与旧记忆条目
2. **项目落盘文件** 优先于未落盘的闲聊推断
3. **系统策略** 仅为参照，不覆盖用户指令和项目状态
