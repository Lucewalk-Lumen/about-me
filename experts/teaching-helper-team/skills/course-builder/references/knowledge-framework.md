## 三档深度体系

### 档位定义

| 档位 | 触发条件 | 输出内容 | 适用场景 |
|------|---------|---------|---------|
| **框架档（skim）** | 仅提供课程主题 | 3-5层知识框架树 + 3条延伸学习建议 | 快速了解课程知识体系 |
| **重点讲解档（guided）** | 课程主题 + 重点话题/教学目标/材料文件 | 框架档内容 + 5-10个重点节点200-500字讲解 + 核心知识点提炼 + 概念依赖关系图 | 备课参考、复习框架 |
| **全节点档（deep）** | 用户明确要求全讲 | 重点讲解档内容 + 所有叶子节点讲解（分批，每批≤15） + 可选练习题 | 自学辅导、教材编写基础 |

### 自动切换规则

```
if 用户未指定深度:
    if 仅有课程主题 → skim
    if 有重点话题 OR 有教学目标 OR 有材料文件 → skim + guided
    if 用户明确要求"全部讲解""每个都讲" → skim + guided + deep
else:
    按用户指定执行（force_skim / force_guided / force_deep）
```

### 讲解写作要求

每个重点节点讲解200-500字，按用户水平调整：

| 用户水平 | 讲解风格 | 示例 |
|---------|---------|------|
| 初学者 | 多用比喻 + 例子 + 类比生活 | "就像图书馆的索引卡片一样，哈希表通过..." |
| 中级（默认） | 平衡术语和解释 | "哈希表通过哈希函数将键映射到存储位置..." |
| 高级 | 直接用术语 + 强调难点和易混点 | "哈希冲突的解决：开放寻址法vs链地址法..." |

每个讲解末尾必须附"核心要点"总结块（1-3条具体要点，不空泛）。

## 节点数指引

不同课程类型和深度档位的合理节点数范围：

| 课程类型 | 框架档 | 重点讲解档 | 全节点档 | 说明 |
|---------|--------|-----------|---------|------|
| 单学期课程（2-3学分） | 30-60节点 | +5-10重点 | ≤100 | 最常见类型 |
| 双学期课程（4-6学分） | 50-80节点 | +8-12重点 | 拆分处理 | 建议按学期拆分 |
| 实验实践课 | 15-30节点 | +3-5重点 | ≤50 | 节点较少，重实操 |
| 公共基础课 | 40-60节点 | +5-8重点 | ≤80 | 知识面广但深度有限 |

**单次处理上限**：1门课/次，节点数>100时拒绝并建议分课处理或按一级分支拆分。

## 输入解析规则

不同格式资料的解析方式：

| 资料格式 | 解析方式 | 降级方案 |
|---------|---------|----------|
| Markdown | 提取ATX标题(#)+Setext标题(===) | 无需降级 |
| DOCX | zipfile+xml.etree解析Heading 1-5样式 | 无样式时用字号推断层级 |
| TXT/纯文本 | 7套启发式回退：章节编号/数字序号/§符号/中文序号（一二三）/字母序号/缩进层级/空行分段 | 识别率低时提示用户转Markdown |
| PDF（文本层）| 提取文本后解析 | 文本层缺失时转OCR |
| 图片/截图 | OCR识别后解析 | 识别率<80%时提示用户确认 |
| URL网页 | 抓取正文后解析 | 正文无法获取时提示用户粘贴内容 |
| 视频/音频 | 拒绝，提示用户先转为文字 | — |

**OCR低质量处理**：
- 乱码率>20%时暂停，展示识别样本，让用户确认是否继续
- 识别结果标注为`ocr_extracted`，提醒用户核对

## 概念依赖关系分类体系

### 6类依赖关系

| 关系类型 | 定义 | 示例（数据结构课程） |
|---------|------|---------------------|
| **前置条件** | 学B之前必须先掌握A | 数组 → 排序算法（排序算法依赖数组概念） |
| **归纳关系** | B是A的抽象/推广 | 栈和队列 → 线性表（都是线性表的特例） |
| **细化关系** | B是A的具体实现/子类型 | 树 → 二叉树 → 二叉搜索树 |
| **对比关系** | A和B互为对照/可替换 | 数组 vs 链表（同为线性结构但实现方式对比） |
| **应用关系** | B是A的应用场景/使用案例 | 哈希表 → 数据库索引 |
| **工具关系** | B是理解/操作A所需的工具 | 指针 → 链表（链表的实现依赖指针概念） |

### 依赖关系输出格式

每条依赖必须包含：

```markdown
| 关系类型 | 知识点A | 知识点B | 关联说明 | 置信度 |
|---------|---------|---------|---------|--------|
| 前置条件 | 数组 | 排序算法 | 排序算法以数组为操作对象，不理解数组无法理解排序过程 | 高 |
```

### 挖掘约束

- **条数限制**：≤ 总节点数 × 0.3（防止过度连线）
- **保守策略**（默认）：只输出高置信度
- **激进策略**：输出中置信度及以上
- **每条必须给出具体依赖原因**，禁止"A和B有关系"这种空话

### 反模式

```
[不通过] Bad:   { from: "前馈网络", to: "反向传播", reason: "两者有关系" }
[通过] Good:  { from: "前馈网络", to: "反向传播", type: "前置条件",
           confidence: "高",
           reason: "反向传播是前馈网络训练算法的具体实现——前向计算输出→损失→反向链式法则求梯度" }
```

## 防幻觉溯源规范

### 两种模式

| 模式 | 条件 | 溯源规则 |
|------|------|---------|
| **纯主题模式** | 仅有课程主题，无材料 | 所有节点标注为AI推断；顶部加警示banner |
| **材料优先模式** | 有材料文件 | 每节点对材料做校验，匹配成功标注来源，失败标注AI推断 |

### 校验方法

对含数字/专名/公式/名词的节点，用ngram匹配（连续词组校验）：

```
匹配成功 → 标注来源文件 + 章节 + 原文片段
匹配失败 → 标注AI推断 + [注意]标记
```

推断字段（如"难点提示""易混点""考点分布"）必须单独标注为AI推断。

### 警示banner（纯主题模式）

```
[注意] 本框架由AI根据课程主题推断生成，建议核对教材后使用
```

### 失配处理

当材料模式下失配率>30%时，暂停并展示失配节点Top 10，让用户选择：
1. 补充材料
2. 接受当前AI推断标注
3. 重新选材料范围

## 工作流程

### Step 1：输入解析与模式判定

- 课程主题 与 材料文件 至少有其一
- 无材料 → 纯主题模式（高幻觉风险，加banner）
- 有材料 → 材料优先模式
- 两者都有 → 混合模式（材料优先 + 主题作为补全提示）

### Step 2：深度档位确认

按自动切换规则或用户指定确定深度档位。

### Step 3：框架生成（skim，必出）

- 纯主题模式：LLM生成3-5层框架
- 材料优先模式：以材料大纲为准 + AI补全缺失子节点
- 混合模式：以材料为准 + 主题作为"是否漏了什么"的反向核对
- 生成3条延伸学习建议，每条附说明

### Step 4：重点节点选择与讲解（guided档）

- 按重要度策略挑5-10个重点节点
- 每个写200-500字讲解，含核心要点总结
- 严禁产出无具体内容的空泛节点

### Step 5：概念依赖关系挖掘

- 跨分支挖掘6类依赖
- 限制≤总节点数×0.3
- 每条带具体原因+置信度

### Step 6：全节点讲解（deep档，可选）

- 所有叶子节点生成200-500字讲解
- 分批约束：单批≤15，超出时标注截断并询问用户"继续下一批？"
- 可选附加：关联指针（易混点）+ 练习题

### Step 7：溯源审计（内部执行）

- 材料模式：逐节点校验
- 纯主题模式：全部标注AI推断

### Step 8：输出

- 默认输出 Markdown 框架文档
- 按需生成 Mindmap / Mermaid / OPML 等格式

## 重点知识讲解

### 1. 数组
位置：线性结构 > 数组

数组是一种线性数据结构，它在连续的内存空间中存储相同类型的元素。每个元素通过索引（下标）访问，索引从0开始。数组的最大优势是随机访问——可以在O(1)时间内访问任意位置的元素。但这也意味着在中间插入或删除元素时需要移动后续所有元素，时间复杂度为O(n)。

在大学课程中，数组不仅是编程基础，更是理解其他数据结构（如堆、哈希表）的基础。需要注意的是，Python的list与C/Java的数组在底层实现上有本质区别——Python list是动态数组，支持自动扩容。

核心要点：
- 数组支持O(1)随机访问，但插入/删除为O(n)
- 内存连续分配是数组的核心特征
- 动态数组（如ArrayList）通过扩容机制解决固定容量问题

### 2. 二叉搜索树（BST）
位置：树形结构 > 二叉搜索树

二叉搜索树是一种特殊的二叉树，满足“左子树所有节点值 < 根节点值 < 右子树所有节点值”的性质。这一性质使得BST在查找、插入、删除操作上平均时间复杂度为O(log n)，远优于数组的O(n)。BST的中序遍历会得到一个有序序列，这是它的一个重要性质。

BST的关键问题是退化——当插入序列已排序时，BST退化为链表，所有操作变为O(n)。这引出了平衡二叉树（AVL树、红黑树）的学习动机。在教学中，BST是“从线性到非线性”思维转变的关键节点。

核心要点：
- BST的查找/插入/删除平均O(log n)，最坏O(n)
- 中序遍历BST得到有序序列
- BST退化问题是引入平衡树的动机

## 知识增量管理


当对同一知识领域进行多轮检索调研时，只提炼知识的变化部分（增量），而非整页吸收已有知识。

### 增量识别原理

对每条检索结果生成指纹（`标题 + 来源 + 发布日期` 的哈希），与上一轮的调研结果比对：

| 变化类型 | 判定条件 | 处理方式 |
|---------|---------|---------|
| **新增 (added)** | 当前轮有、上一轮无 | 提炼为新知识，纳入知识库 |
| **更新 (updated)** | 指纹相同但摘要内容或日期变化 | 对比前后差异，更新对应知识点 |
| **移除 (removed)** | 上一轮有、当前轮无 | 标注为"可能过时"，提示核实是否仍有效 |

### 增量提取流程

```
1. 收集当前轮检索结果，逐条生成指纹
2. 加载上一轮的领域知识库（sourceResults）
3. 比对指纹集合，分类为 added / updated / removed
4. 生成增量报告：
   - stats: 上一轮数量、当前轮数量、新增数、更新数、移除数
   - added: 新增条目列表（标题、来源、日期、摘要、方法论、最佳实践）
   - updated: 变更前后对比
   - removed: 移除条目列表
5. 增量摘要：Top-5 新方法、Top-5 更新信号、Top-5 过时信号
```

### 知识库更新规则

| 增量类型 | 知识库操作 | 标注 |
|---------|-----------|------|
| added | 新增知识点节点，标注来源和首次发现日期 | `[新增: YYYY-MM-DD]` |
| updated | 更新已有知识点的摘要/方法论字段，保留变更记录 | `[更新: YYYY-MM-DD]` |
| removed | 保留节点但标注"可能过时"，不直接删除 | `[过时: YYYY-MM-DD]` |

### 应用场景

- **课程大纲迭代**：对比上一版和当前版学科进展，只更新变化部分
- **教材修订**：对比新旧版参考资料，精准定位需要修订的章节
- **课件更新**：学年更替时，只更新有变化的案例和数据

### 防止整页吸收

增量管理的核心原则是"只提炼变化，不整页吸收"：
- 已存在于知识库中的知识，不重复录入
- 仅当知识点的摘要内容或方法论发生实质变化时，才标记为 updated
- 移除的知识不立即删除，保留历史记录以备追溯
