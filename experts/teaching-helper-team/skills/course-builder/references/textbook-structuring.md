## 阶段化工作流

从零散资料整理为系统化教材/讲义，按以下阶段执行，每阶段设推进门禁：

```
S0 资料分析 → S1 体系规划 → S2 内容组织 → S3 教学要素补充 → S4 质检 → S5 终稿交付
```

### 阶段门禁

| 阶段 | 做什么 | 推进条件 | 不满足时 |
|------|--------|---------|---------|
| **S0 资料分析** | 盘点资料、提取知识点、生成覆盖度报告 | 核心知识点覆盖度≥60% | 提示用户补充资料 |
| **S1 体系规划** | 设计章节结构、知识递进逻辑 | 用户确认章节目录 | 修改后重新确认 |
| **S2 内容组织** | 按章节填充内容、标注来源与缺口 | 各章具备标题+核心内容 | 继续填充至达标 |
| **S3 教学要素** | 添加学习目标、导读、小结、习题 | 每章含目标+小结+习题 | 补充缺失要素 |
| **S4 质检** | 分层质量检查（详见quality-review.md） | S层+P层检查通过 | 修复问题后重新检查 |
| **S5 终稿** | 格式规范化、统一术语编号 | 通过洁净检查（无过程标注残留） | 清理后重新检查 |

### 串行写作约束

- **每轮最多修改2个文件**：完成1个→汇报结果→再进行下一个
- **修改前说明**："接下来修改哪个文件、改哪几处、大概需要多久"
- **防卡顿**：单文件操作超30秒无输出时，输出一行进度提示
- **可见性**：所有修改落地到文件，不仅存在于对话描述中

### 各阶段产出

| 阶段 | 输入 | 产出 |
|------|------|------|
| S0 资料分析 | 用户提供的讲义/笔记/论文/扫描件等 | 知识点清单、资料覆盖度报告 |
| S1 体系规划 | 知识点清单 + 课程目标 | 章节目录结构 |
| S2 内容组织 | 各章节知识点 + 原始资料 | 教材正文初稿 |
| S3 教学要素补充 | 正文初稿 | 含学习目标/导读/小结/习题的完整稿 |
| S4 质检 | 完整稿 | 质检报告 + 修订建议 |
| S5 终稿 | 修订后完整稿 | 格式统一、可交付的终稿 |

## 资料分析方法

### 第一步：资料盘点

对用户提供的所有资料进行分类整理：

| 资料类型 | 处理方式 | 注意事项 |
|----------|---------|---------|
| 教材/参考书 | 提取章节结构与核心知识点 | 注意版本时效性 |
| 讲义/课件 | 提取教学要点与案例 | 可能存在不完整或口语化内容 |
| 学术论文 | 提取前沿观点与案例 | 适合作为拓展阅读或前沿章节 |
| 笔记/手稿 | 提取知识框架与个人见解 | 需甄别准确性与完整性 |
| 扫描件/图片 | OCR识别后提取文字 | 检查识别准确性，校正专业术语 |
| 视频/音频 | 转录后提取要点 | 适合补充案例与实例 |

### 第二步：知识点提取

从每份资料中提取知识点，建立知识点清单：

```
知识点编号 | 知识点名称 | 所属领域 | 重要程度(H/M/L) | 资料来源 | 完整度(完整/部分/缺失)
```

- **重要程度判定**：核心概念为H，支撑性知识为M，拓展性知识为L
- **完整度判定**：资料中有充分讲解为"完整"，仅有提及为"部分"，完全未覆盖为"缺失"
- **缺失知识点标注**：对于课程目标要求但资料中缺失的知识点，明确标注，提示需补充

### 第三步：覆盖度报告

生成资料覆盖度报告，向用户说明：

- 已覆盖的章节与知识点
- 部分覆盖、需补充的内容
- 完全缺失、需从头编写的内容
- 资料间存在矛盾或过时的内容

> **卡点**：资料覆盖度不足
> **自救**：标注缺口，先完成已覆盖部分，缺口部分标注"待补充"并提示用户。

## 章节体系规划

### 规划原则

1. **知识递进**——从基础到高级，从简单到复杂，遵循认知规律
2. **逻辑自洽**——章节间有清晰的逻辑关系（并列/递进/总分）
3. **学时匹配**——内容量与学时分配合理，重点章节分配更多篇幅
4. **模块化设计**——每章相对独立，便于灵活调整教学顺序
5. **实践导向**——理论章节后紧跟实践/案例章节

### 常见章节结构模式

**模式一：线性递进式**（适合理工科）

```
第1章 基础概念与理论框架
  → 第2章 基本原理与方法
    → 第3章 核心技术/方法
      → 第4章 进阶应用
        → 第5章 前沿与拓展
```

**模式二：模块并列式**（适合文社科）

```
第1章 导论（学科总览）
  第2章 主题A（理论与案例）
  第3章 主题B（理论与案例）
  第4章 主题C（理论与案例）
第5章 综合分析与展望
```

**模式三：问题驱动式**（适合应用型课程）

```
第1章 问题导入与背景
  → 第2章 分析框架
    → 第3章 方法与工具
      → 第4章 案例实践（多个案例）
        → 第5章 综合项目
```

### 章节规划表

完成章节设计后，生成规划表供用户确认：

| 章 | 标题 | 主要知识点 | 学时 | 对应课程目标 | 资料覆盖度 |
|----|------|-----------|------|-------------|-----------|
| 1 | [标题] | [要点列表] | [X] | 目标1 | 完整 |
| 2 | [标题] | [要点列表] | [X] | 目标1、2 | 部分（需补充X） |
| ... | ... | ... | ... | ... | ... |

## 内容组织与写作

### 每章标准结构

每章应包含以下组成部分：

1. **章首导语**（200-300字）——本章学习意义、核心问题、与前后章节的关系
2. **学习目标**（3-5条）——使用布鲁姆动词，标注认知层次
3. **正文**——按节组织，每节聚焦一个子主题
4. **案例/实例**——每节至少1个实际案例或应用实例
5. **本章小结**——用要点列表归纳核心内容
6. **思考与练习**——分层次习题（见习题生成策略）
7. **拓展阅读**——推荐文献与资源

### 正文写作要求

- **学术准确性**：概念定义准确，理论表述严谨，引用规范
- **可读性**：避免纯理论堆砌，善用类比、图示、实例辅助理解
- **适度性**：内容深度与教学对象匹配，不过浅也不过深
- **启发性**：关键知识点后设置"思考"小框，引导深入思考
- **前沿性**：融入学科最新进展与行业动态

### 图表使用建议

| 图表类型 | 适用场景 | 设计要点 |
|----------|---------|---------|
| 概念图/思维导图 | 展示知识体系结构 | 层级清晰，关系标注 |
| 流程图 | 展示过程/算法/方法步骤 | 步骤完整，决策分支明确 |
| 对比表 | 比较不同概念/方法 | 对比维度合理，重点突出 |
| 示意图 | 解释抽象概念 | 简洁直观，标注清晰 |
| 数据图表 | 呈现实验/统计数据 | 坐标轴规范，注明来源 |

## 教学要素补充

### 学习目标编写

每章学习目标3-5条，遵循 SMART 原则（具体、可测、可达、相关、有时限）：

```
示例：
学完本章后，学生能够：
1. [记忆] 列举[核心概念]的三个基本特征
2. [理解] 解释[核心原理]的物理含义
3. [应用] 运用[方法/工具]解决[类型]问题
4. [分析] 比较不同[方法/方案]的优缺点及适用条件
```

### 导语写作要点

- 点明本章在课程中的定位（承上启下）
- 提出本章核心问题（激发思考）
- 联系实际应用（增强学习动机）
- 控制在200-300字

### 小结写作要点

- 用要点列表（5-8条）归纳核心知识
- 不重复正文原文，用精炼语言概括
- 可用知识结构图替代或补充文字小结

## 习题生成策略

### 习题分层设计

| 层次 | 题型 | 对应布鲁姆层次 | 占比 | 示例 |
|------|------|---------------|------|------|
| 基础题 | 选择、填空、判断、简答 | 记忆/理解 | 40% | 简述XX的基本概念 |
| 应用题 | 计算、分析、设计 | 应用/分析 | 40% | 运用XX方法求解给定问题 |
| 拓展题 | 综合分析、开放论述、项目设计 | 评价/创造 | 20% | 针对XX实际场景，设计完整解决方案 |

### 习题生成原则

1. **覆盖性**——习题应覆盖本章所有重要知识点
2. **梯度性**——从易到难排列，基础题→应用题→拓展题
3. **真实性**——应用题和拓展题尽量基于真实场景
4. **原创性**——避免直接照搬教材原题，可改编
5. **参考答案**——每题附参考答案或评分要点

### 题量建议

| 章节学时 | 基础题 | 应用题 | 拓展题 | 合计 |
|----------|--------|--------|--------|------|
| 2学时 | 5-8题 | 3-5题 | 1-2题 | 9-15题 |
| 4学时 | 8-12题 | 5-8题 | 2-3题 | 15-23题 |
| 6学时 | 12-18题 | 8-12题 | 3-5题 | 23-35题 |

## 格式规范

### 术语规范

- 首次出现的专业术语标注英文原词：如"机器学习（Machine Learning）"
- 全书同一术语保持一致，不混用近义词
- 缩写首次出现时写全称：如"自然语言处理（Natural Language Processing, NLP）"

### 编号规范

| 对象 | 编号格式 | 示例 |
|------|---------|------|
| 章 | 第X章 | 第3章 |
| 节 | X.X | 3.1 |
| 小节 | X.X.X | 3.1.1 |
| 图 | 图X-X | 图3-1 |
| 表 | 表X-X | 表3-1 |
| 公式 | 式(X-X) | 式(3-1) |
| 例 | 例X-X | 例3-1 |

### 参考文献格式

采用 GB/T 7714 格式：

```
[序号] 作者. 题名[文献类型标志]. 出版地: 出版者, 出版年.
[序号] 作者. 题名[J]. 刊名, 年, 卷(期): 起止页码.
[序号] 作者. 题名[D]. 保存地: 保存单位, 年份.
[序号] 作者. 题名[EB/OL]. (发布日期)[引用日期]. URL.
```

### 排版建议

- 正文：宋体小四号（12pt），行距1.5倍
- 标题：章标题三号黑体，节标题四号黑体，小节标题小四号黑体
- 图表标题：五号宋体，居中
- 公式：居中，编号右对齐
- 页边距：上下2.54cm，左右3.18cm

### 字数指引

不同课程类型和学时的教材建议字数范围：

| 课程学时 | 建议总字数 | 每章字数 | 每节字数 | 说明 |
|----------|----------|---------|---------|------|
| 32学时（2学分） | 8-12万字 | 8千-1.2万字 | 2千-4千字 | 精简型教材 |
| 48学时（3学分） | 12-18万字 | 1-1.5万字 | 3千-5千字 | 标准型教材 |
| 64学时（4学分） | 18-25万字 | 1.5-2.5万字 | 4千-6千字 | 完整型教材 |
| 实践为主课程 | 6-10万字 | 5千-8千字 | 1千-3千字 | 讲义型，重案例和实验 |
| 研究生课程 | 15-20万字 | 1.2-2万字 | 3千-5千字 | 含文献综述和前沿讨论 |

**单章字数调整原则**：
- 重点章节（核心知识）可超20%上限
- 过渡章节（背景/导论）可低于20%下限
- 每章字数差异不超过2倍（最长章/最短章）

### 资料冲突处理

当多份资料间出现内容矛盾时，按以下优先级裁决：

| 优先级 | 来源 | 说明 |
|--------|------|------|
| 1 | 用户提供的指定主教材 | 以用户明确指定的教材为准 |
| 2 | 最新版权威教材 | 选择出版时间最新的权威教材 |
| 3 | 学科标准/规范 | 如国标、行标、学科教学指导委员会标准 |
| 4 | 学术共识 | 多数教材一致表述 |

**冲突处理流程**：
```
1. 标注冲突：在某知识点旁标注"【冲突】来源A说X，来源B说Y"
2. 按优先级裁决：选择优先级更高的来源
3. 提示用户：将冲突点和裁决结果列入"待确认事项"，交付时提示用户审核
4. 记录裁决理由：简要说明为何选择此来源而非彼
```

**常见冲突类型与处理**：

| 冲突类型 | 示例 | 处理方式 |
|---------|------|----------|
| 定义表述不同 | "数据结构是数据的组织方式" vs "数据结构是相互存在特定关系的数据元素集合" | 取权威教材表述，标注另一说法为"另一种表述" |
| 版本差异 | 某标准2019版vs2023版 | 取最新版，标注"旧版为X" |
| 方法争议 | 快速排序选基准的不同策略 | 列出主要方法，标注各自适用场景，不强行取舍 |
| 术语冲突 | "散列表" vs "哈希表" | 选主教材用法，标注另一术语为同义词 |

### 版本管理建议

教材/讲义在多轮修订过程中应做好版本管理：

**版本编号规则**：
```
v0.X — 草稿阶段（内部修订，未交付）
v1.0 — 首个交付版本（用户确认）
v1.X — 交付后修订（小改：改错、补充）
v2.0 — 重大修订（结构调整、章节增减）
```

**修订追踪**：
- 每次修订在文件首部更新版本号、修订日期、修订摘要
- 修订摘要格式：`[v1.1] 2026-08-06 | 修正第3章术语不一致；补充第5章习题答案`
- 重大修订前备份上一版本

**修订记录表**：

| 版本 | 日期 | 修订内容 | 修订人 |
|------|------|---------|------------|
| v0.1 | YYYY-MM-DD | 初稿完成 | |
| v0.2 | YYYY-MM-DD | 根据质检报告修订S层问题 | |
| v1.0 | YYYY-MM-DD | 用户确认，交付 | |
| v1.1 | YYYY-MM-DD | 修正P层问题 | |

### 终稿洁净检查

交付前必须通过以下检查（S5门禁）：

- [ ] 无过程标注残留（如"待核实""待补充""[DISCARDED]"等）
- [ ] 无AI写作痕迹（见quality-review.md的AI痕迹检测）
- [ ] 术语全书一致
- [ ] 编号连续无跳号
- [ ] 参考文献格式统一
- [ ] 图表均有编号和标题

## 附录A：资料质量评估标准

>
> **知识框架关联**：检索到的资料纳入知识框架时的防幻觉溯源与增量管理详见 [knowledge-framework.md](knowledge-framework.md)。（JUDGE 评分器）方法论。

教材编写中检索到的参考资料，按以下五维度评分后决定取用策略：

| 评分维度 | 权重 | 评分依据 | 分值范围 |
|---------|------|---------|---------|
| **相关性 (relevance)** | 25% | 资料标题/摘要与章节关键词的命中率 | 0-1 |
| **时效性 (freshness)** | 20% | 发布日期距当前的天数衰减 | 0-1 |
| **权威性 (authority)** | 25% | 来源域名/机构的可信度 | 0-1 |
| **可获取性 (accessibility)** | 15% | 全文是否可访问、是否需付费/登录 | 0-1 |
| **可操作性 (actionability)** | 15% | 资料中是否含步骤/清单/方法/数据 | 0-1 |

### 时效性评分衰减表

| 发布距今天数 | 分值 | 说明 |
|------------|------|------|
| ≤30 天 | 1.0 | 最新资料 |
| ≤90 天 | 0.85 | 较新 |
| ≤180 天 | 0.7 | 可用 |
| ≤365 天 | 0.55 | 需核实是否过时 |
| >365 天 | 0.35 | 仅作历史参考 |

### 权威性评分参考

| 来源类型 | 分值 | 示例 |
|---------|------|------|
| 官方权威 | 0.95 | gov.cn、people.com.cn、xinhuanet.com、cctv.com |
| 技术权威 | 0.88 | github.com、developers.weixin、cloud.tencent.com、alibabacloud |
| 专业媒体 | 0.78 | 36kr、huxiu、acm.org、ieee.org、arxiv.org |
| 社区UGC | 0.62 | zhihu、xiaohongshu、douban、bilibili |
| 其他 | 0.5 | 未分类来源 |

### 批量评估决策

对一批检索结果统一评分后，按平均分决策：

| 平均分 | 决策 | 说明 |
|-------|------|------|
| ≥0.7 | keep_and_extract_delta | 保留结果，提取知识增量 |
| 0.55-0.7 | add_site_scoped_queries | 补充定向检索，提高覆盖 |
| <0.55 | rewrite_query_and_switch_source | 改写检索词，更换来源 |

### 可操作性检测信号

资料摘要中含以下关键词时，可操作性评分提升：

- **方法信号**：步骤、清单、方法、流程、策略、框架、最佳实践 → +0.25
- **数据信号**：含具体数值 → +0.2
- **意图命中**：摘要内容与章节意图匹配 → +0.1

## 附录B：文件规模守卫


教材编写过程中监控产出文件规模，防止单文件过大导致可维护性下降。

### 文件规模阈值

| 阈值类型 | 单文件上限 | 追踪总量上限 | 说明 |
|---------|-----------|-------------|------|
| **硬阈值** | 8 MB | 64 MB | 超过则阻断交付（enforce模式） |
| **软阈值** | 5 MB | 40 MB | 超过则告警提示，不阻断 |
| **建议上限** | 3 MB | 30 MB | 超过则建议拆分 |

### 单文件过大处理

| 文件大小 | 处理方式 |
|---------|---------|
| >8 MB | 阻断交付，必须拆分为多个文件 |
| 5-8 MB | 告警，建议拆分章节为独立文件 |
| 3-5 MB | 正常，但注意控制后续增长 |

### 总量过大处理

当追踪文件总量超过阈值时：
- **硬阈值（64 MB）**：阻断交付，必须清理冗余文件或拆分项目
- **软阈值（40 MB）**：告警提示，建议清理临时文件、中间产物
- **建议上限（30 MB）**：正常，保持关注

### 追踪范围

以下文件纳入规模监控：
- 教材正文文件（.md / .docx）
- 交付物目录下的所有文件
- 发布版本目录下的所有文件

排除范围：node_modules、.git、审计日志（.jsonl）

## 附录C：结构瓶颈检测


监控教材编写过程中的结构瓶颈，防止项目因局部膨胀而卡顿。

### 文件级瓶颈阈值

| 检测项 | 告警阈值 | 阻断阈值 | 说明 |
|-------|---------|---------|------|
| 单文件体积 | ≥120 KB / 1200 行 | ≥320 KB / 3200 行 | 超标文件需拆分 |
| 任务队列 | 接近阈值的 70% | 超过阈值 | 待处理任务过多时需优先清理积压 |
| 检查点数量 | ≥56 个（阈值的70%） | ≥80 个 | 过多检查点表示反复回退，需审视流程 |
| 检索日志体积 | 接近阈值的 70% | ≥30 MB | 日志过大需清理或归档 |
| 运行态保留天数 | >21 天 | >30 天 | 超过保留期的中间态需清理 |

### 瓶颈处理流程

```
1. 扫描所有受监控文件
2. 按文件体积和行数分类：ok / warn / fail
3. 检查运行态指标（任务队列、检查点、日志）
4. 生成瓶颈报告：
   - fail 级问题 → 阻断交付，必须解决
   - warn 级问题 → 告警，建议在下一轮迭代中处理
5. 如检测到 workflow-full 文件已配套拆分（≥8个分卷 + 精简入口），可豁免该文件的 fail 级判定
```

### 拆分策略

当文件超过阈值需要拆分时：

| 原文件特征 | 推荐拆分方式 |
|-----------|-------------|
| 单章超长（>320 KB） | 按节拆分为独立 .md 文件，主文件保留索引 |
| 多章合一（>320 KB） | 按章拆分为独立文件 |
| 参考资料堆积 | 将附录、参考文献拆出为独立文件 |
| 代码示例过多 | 代码移入独立代码文件，正文保留引用 |

## 附录D：教材改写模式


当需要基于已有教材进行升级改写时，按以下模式执行。

### 三种改写模式

| 模式 | 适用场景 | 核心策略 |
|------|---------|---------|
| **自有旧书升级** (self-upgrade) | 教师对自有旧版教材进行内容更新 | 保留原有框架，更新过时内容，补充新进展 |
| **海外内容本地化** (global-localization) | 将国外优秀教材内容本地化适配 | 替换文化背景案例，适配国内教学标准，保留核心理论 |
| **爆款结构重构** (bestseller-reframe) | 参考畅销教材的结构重新组织内容 | 借鉴结构框架，替换全部内容为原创表述 |

### 改写最小清单

改写前必须明确以下三类清单（每类 3-5 条）：

**保留项**（原书中有价值、应保留的内容）：
- [ ] 核心理论框架是否仍然有效
- [ ] 哪些案例具有长期参考价值
- [ ] 哪些方法论已被验证可靠

**替换项**（需要更新或替换的内容）：
- [ ] 哪些数据已过时需要更新
- [ ] 哪些方法已被新方法取代
- [ ] 哪些表述需要现代化

**新增项**（需要补充的新内容）：
- [ ] 学科最新进展（≥3年内）
- [ ] 新增的实践案例
- [ ] 新技术的教学适配

### 改写合规边界

| 合规项 | 要求 |
|-------|------|
| 来源范围 | 明确标注改写来源的章节/素材边界 |
| 改写边界 | 允许重写表述，不做直接复制粘贴 |
| 价值保留 | 明确标注需保留的原有价值点（3-5条） |

### 改写执行节奏

```
1. 每轮最多修改 2 个文件，串行推进
2. 每轮完成后执行质检（参见 quality-review.md）
3. 终稿交付前必须通过全部门禁检查
```

## 附录E：教材编制看板模板

>
> **多角色协作**：看板中协调员/写作员/审查员等角色的详细职责与写入边界详见 [workflow-governance.md](workflow-governance.md) §多智能体角色定义与写入边界。

教材编写过程使用任务看板管理进度，确保有序推进。

### 任务类型

| 类型 | 说明 | 示例 |
|------|------|------|
| **调研** (research) | 前期资料收集与学科调研 | 检索最新学科进展、收集行业案例 |
| **大纲** (outline) | 教材大纲设计与评审 | 章节结构设计、知识体系梳理 |
| **章节** (chapter) | 单章内容编写 | 编写第3章"栈与队列"正文 |
| **审校** (review) | 质检与修订 | S/P/C层质检、AI痕迹检测 |
| **交付** (delivery) | 终稿交付与发布 | 终稿洁净检查、格式统一、打包交付 |

### 任务状态流转

```
pending（待开始）→ in_progress（进行中）→ done（已完成）
                          ↓
                    blocked（受阻）
```

**状态优先级**（看板排序）：in_progress → blocked → pending → done → skipped

### 任务依赖管理

任务可设置依赖关系（`dependsOn`），当依赖任务未完成时：
- 尝试将任务设为 in_progress → 自动转为 blocked
- 标注阻塞原因："依赖未完成: [依赖任务ID列表]"
- 依赖任务完成后，blocked 任务可恢复为 pending

### 看板视图格式

```markdown
## 教材编制看板

### 进行中
| 任务ID | 标题 | 类型 | 章节 | 开始时间 |
|--------|------|------|------|---------|
| cha-ch3-xxx | 编写第3章正文 | chapter | 3 | 2025-01-15 |

### 受阻
| 任务ID | 标题 | 阻塞原因 |
|--------|------|---------|
| rev-ch3-xxx | 第3章质检 | 依赖未完成: cha-ch3-xxx |

### 待开始
| 任务ID | 标题 | 类型 | 优先级 | 依赖 |
|--------|------|------|--------|------|
| cha-ch4-xxx | 编写第4章正文 | chapter | 50 | cha-ch3-xxx |

### 已完成
| 任务ID | 标题 | 完成时间 |
|--------|------|---------|
| res-xxx | 学科进展调研 | 2025-01-10 |
```

### 看板使用规则

1. **每轮只推进 1-2 个 in_progress 任务**，避免并行分散注意力
2. **blocked 任务优先处理**，解除阻塞后才能继续后续工作
3. **每轮完成后更新看板**，记录完成时间和下一步任务
4. **skipped 状态需标注原因**，不可随意跳过任务

## 附录F：大纲冻结与变更管理


### 冻结含义

大纲在 S2 阶段完成后执行冻结：
- 章节标题、章数规划、各章核心问题与学生学习收获点已确认

### 变更单模板

大纲冻结后如需调整结构，须填写变更单：

| 变更前 | 章数 / 标题摘要 |

- 变更前的状态须可追溯（保留变更记录）

## 附录G：终稿版本状态机


### 四态状态机

教材/讲义终稿采用固定四态管理：

| 状态 | 含义 | 允许操作 |
|------|------|---------|
| **draft**（草稿） | 可持续改写 | → candidate |
| **candidate**（候选终稿） | 进入收口与验收 | → draft（回退修订）/ → release |
| **release**（发布版） | 已确认交付，固定哈希与变更说明 | → candidate（回退修订）/ → archived |
| **archived**（归档版） | 不再作为当前交付基线 | 终态 |

### 状态迁移规则

```
draft ──→ candidate ──→ release ──→ archived
  ↑           │             │
  └───────────┘             │
              └─────────────┘
```

- 默认不允许跨级跳转（如 draft → release）
- 确需越级时须标注原因
- 每次 release 须绑定交付文件哈希，便于后续版本对齐和回归定位

### 回退策略

| 场景 | 操作 |
|------|------|
| 发布后发现问题 | release → candidate，修复后再回到 release |
| 版本不再维护 | release → archived |
| 候选终稿需大改 | candidate → draft |

**禁止**直接覆盖旧终稿文件而不记录状态迁移。

## 附录H：培训教材场景质量规则


面向培训教材/员工手册的专用质量规则，在通用S/P/C/B规则基础上增加培训场景专项检查。

### S0 初始化收集要素

编写培训教材前须收集：

| # | 要素 | 必须 |
|---|------|------|
| 1 | 培训主题与目标能力 | [关键] |
| 2 | 目标学员画像（岗位/经验水平/团队规模） | [关键] |
| 3 | 输出类型（课程教案/员工手册/知识库文档） | [关键] |
| 4 | 培训时长（半天/全天/系列课） | |
| 5 | 是否需要配套练习题和工具模板 | |
| 6 | 企业内部案例是否可用 | |

### S2 大纲结构

| 模块 | 字数范围 | 必须包含 |
|------|---------|---------|
| 课程目标 | 500-1000字 | 学习目标（SMART原则）、适用人群、课程导览 |
| 知识篇 | 每节1000-2000字 | 概念定义、原理说明、要点提炼 |
| 案例分析 | 每章1-2个，每案例500-1500字 | 真实企业场景、情境还原、分析框架 |
| 练习篇 | 每章3-10题 | 题目+参考答案+评分说明 |
| 工具模板 | 按需 | 可直接使用的表格/检查清单/流程图 |
| 延伸阅读 | 可选 | 推荐书单/参考资料 |

### 培训场景专项质量规则

**S层（结构层）**：
- 每章开头明确列出2-5条学习目标（用"学完本章，你将能够..."句式）
- 案例须来自真实企业场景（可脱敏处理，但情境必须真实可信）
- 练习题须提供参考答案，选择题须标注正确选项理由
- 全书知识点前后不出现矛盾

**P层（专业层）**：
- 每个知识点段落结构：定义→原理→例子→小结
- 案例分析须包含：背景→问题→解决方案→结果→启示
- 避免"众所周知""显而易见"等表达

**C层（表达层）**：
- 专业术语首次出现时附括号解释（面向非专业学员时）
- 练习题指令清晰，不产生歧义
- 标题层级清晰（H1章→H2模块→H3知识点）

**B层（一致性层）**：
- 全书使用同一套术语体系
- 各章学习目标与章末练习题考察内容对应
- 课程难度循序渐进，从基础到应用有合理梯度
