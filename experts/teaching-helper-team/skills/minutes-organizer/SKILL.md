WorkBuddy 已内置并启用官方办公技能，`.docx` 交付**优先委托 `tencent-docx` 技能**出片；

# 学术会议纪要与综述报告智能生成
> **归属**：领域技能层——纪要整理专家（minutes-organizer）


> 从本地文件夹到 Word 文档的完整流水线：信息收集 → OCR识别 → 内容归类 → 撰写 → 去AI化 → TEEL段落逻辑 → Markdown预览 → Word输出。产出两类文档：**会议纪要**（按主题-汇报人复述）与**学术综述报告**（按议题重组、三层评述、证据分级）。核心能力：综述报告体裁、按议题重组、证据分级、四类去AI化高频病灶速查。

## 路由中枢

根据用户输入判断路径与**产物类型**：

| 场景 | 路径 | 说明 |
|------|------|------|
| 完整会议纪要 | **标准路径** | 扫描文件夹 → OCR → 撰写 → 去AI → TEEL → Word |
| 学术综述报告 | **综述路径** | 标准路径产出内容底稿 → 按议题重组升格 → 三层评述 → 证据分级 → Word（详见 `references/review-report-guide.md`） |
| 仅 .md 预览 | 快速路径 | 跳过 Word 输出 |
| 增量更新 | 增量路径 | 只处理新增文件，追加到已有文档 |
| 仅 OCR | OCR 路径 | 只做 OCR 输出文本 |
| 行动项/决策/待办 | **行动项路径** | 用户直接粘贴零散会议文本 → 提取行动项/决策/待办清单，归档 `YYYY-MM-DD_topic.md`（详见 `references/action-items-tracking.md`）；不走 Word 流水线 |

**产物判别（纪要 vs 综述报告）：**

- 默认产物是**会议纪要**（忠实复述每位报告人讲了什么，按主题-汇报人组织）。
- 当用户出现以下信号时，走**综述路径**产出**学术综述报告**：提到"综述报告""主题综述""学术报告""按主题/议题重组""详尽版/上万字""放回研究脉络/学理定位""要有评述和判断"等。
- 两者不是替代关系：综述报告**以纪要内容为素材底稿**，在其上做议题重组与三层升格。拿不准时先问用户要"纪要"还是"综述报告"。

## 标准路径（完整流程）

### 阶段 1：信息收集与分类

扫描用户指定的会议文件夹，自动识别和分类文件：

- **录音转录稿**：`.txt` 文件，按文件大小判断完整版 vs 摘要版（完整版通常 >50KB）
- **官方议程**：`.pdf` 或 `.docx`
- **PPT 照片**：`.heic`、`.jpg`、`.jpeg`、`.png`：**强制同时匹配大小写**（`.JPG`/`.JPEG`/`.PNG`/`.HEIC`），使用 `ls` 两次（`ls *.{jpg,JPG,png,PNG,heic,HEIC,jpeg,JPEG}`），确保零遗漏
- **其他文档**：`.docx`、`.xlsx`

**文件收集强制检查：**

完成文件清单后，查看每类文件数量。若用户在后续反馈中暗示有照片未计入（如"我忘记还有照片没有添加""现在已更新"），说明第一步扫描遗漏了，必须重扫全量文件夹，确认是否遗漏了特定扩展名（尤其 `.JPG` 大写后缀的照片文件）。

输出：文件清单 + 分类摘要。**ASR 转录中的演讲人姓名必须用官方议程 PDF 校正**（如"林辉→李育辉""唐桂瑶→唐贵瑶"）。

### 阶段 2：OCR 识别

对 PPT 照片做 OCR。使用本地 RapidOCR（`rapidocr-onnxruntime` + `onnxruntime` + `opencv-python`），脚本直接读图片文件、写文本到磁盘，零上下文污染。

**运行方式：** 照片数量 >20 张时，OCR 必须后台运行（`run_in_background: true`），避免超时中断。

**环境准备顺序（按此执行，不可跳过）：**
1. 先创建 isolated venv，再 pip install。不能在全局 python 环境安装。
2. 依赖清单以本团 `setup` 技能的 `PY_DEPS["minutes-organizer"]`（OCR + 图片预处理）为唯一真源；首次会话由 `setup` 技能自动装入托管 venv，正常无需手动安装。如需手动补齐，按该清单在 isolated venv 内安装（[注意] venv 的 pip 路径因系统而异，务必用 `-m pip` 而非裸 `pip`，否则 Windows 下 `<venv-dir>/bin/pip` 不存在会直接失败）：
   - macOS / Linux：`<managed-python> -m venv <venv-dir> && <venv-dir>/bin/python -m pip install rapidocr-onnxruntime onnxruntime opencv-python pillow-heif`
   - Windows（PowerShell / cmd）：`<managed-python> -m venv <venv-dir> && <venv-dir>\Scripts\python.exe -m pip install rapidocr-onnxruntime onnxruntime opencv-python pillow-heif`
3. 若 pip install 中退出码 137（OOM），降低并发重试（设置 `--no-cache-dir` 且逐包安装，不用一口气装全部）
4. 安装成功后跑 `python -c "from rapidocr_onnxruntime import RapidOCR; print('OK')"` 验证

**HEIC 转换（跨平台）：** 原指令的 `sips` 仅 macOS 自带，Windows / Linux 无此命令会失败。统一改用 Python（`pillow-heif` 跨平台）转 JPG：
   `python -c "import pillow_heif, PIL; pillow_heif.register_heif_opener(); im=PIL.Image.open('<in>.HEIC'); im.thumbnail((2048,2048)); im.save('<out>.jpg', quality=90)"`
   首次使用先 `<venv-dir>/bin/python -m pip install pillow-heif`（Windows 用 `<venv-dir>\Scripts\python.exe -m pip install pillow-heif`）；也可改用 ImageMagick 跨平台命令：`magick '<in>.HEIC' -resize 2048 '<out>.jpg'`。转换后用 `ls`（Windows 用 `dir`）确认输出存在再删原 HEIC。

**OCR 脚本要求：**
- 断点续跑：检查 `ocr_text/<filename>.txt` 是否存在，已存在跳过
- 异常容错：单张失败不终止整批，记录失败文件列表到 `ocr_errors.log`
- 每处理 10 张输出进度 `[10/166]`

**批量完成通知（强制）：**

OCR 任务结束后，必须在对话中明确告知用户：
- "OCR 完成：共 X 张，成功 Y 张，失败 Z 张（已记录到 ocr_errors.log）"
- 若 Z>0，列出失败的照片文件名，请用户手动检查这些照片是否损坏
- 输出合并文件路径 `ocr_all.txt` 及其文件大小

**增量补充：** 若用户在 OCR 完成后说"还有照片漏加了"，执行增量流程：
1. 新照片复制到同一 photos/ 目录（统一转为小写 .jpg 扩展名）
2. 跑 OCR 只处理新增照片（断点续跑机制自动跳过已处理）
3. **重新全量重建** `ocr_all.txt`（从所有 `ocr_text/*.txt` 合并，而非仅追加新照片），确保 `ocr_all.txt` 原子一致
4. 完成后通知用户新的总数和新增内容概览

### 阶段 3：内容归类与主题划分

从议程 PDF 提取会议结构（主题、分场、汇报人），将 OCR 文本和转录稿按主题归类。分场命名使用议程原文。没有议程时从内容自动推断。

### 阶段 4：按"主题—汇报人"撰写纪要

核心结构要求：

- 一级标题（`#`）：会议主题/分场标题
- 二级标题（`##`）：汇报人姓名 + 演讲标题
- 不使用三级及以上标题做"一/二/三"编号，每位汇报人的内容用自然段落展开

**关键要求：**

1. **不做概括压缩**。基于录音原文与PPT内容，写出演讲人所讲的**所有**内容，不是概括大意。
2. **姓名必须校正**。用官方议程纠正 ASR 错误。
3. **PPT 内容标注**。幻灯片来源的独有内容用"幻灯片显示"等自然语句融入正文，不使用"（PPT）"机械标签。
4. **不编造内容**。录音缺失的部分注明"所收录录音未包含该段内容"，不补写。
5. **ASR 乱码段标注**。语音识别严重乱码的部分注明"录音中后段乱码，以下为可还原部分，细节存疑"。

### 阶段 5：去AI化语言规范（强制）

> 去AI化不等于压缩。研究对象、数据口径、样本量、方法条件、结论边界、专有名词一律保留。

**AI高频词警告（遇到即替换或删除）：**

删除/替换以下词汇：值得注意的是、综上所述、不难发现、不可否认、旨在、为...提供了重要启示、深入探讨、与此同时、显著改善、发挥着重要作用、众所周知、极其重要、近年来、随着社会的发展、越来越受到关注、引起了广泛关注、具有重要的理论意义和实践价值、填补了...空白、有待进一步研究、由于上述原因、基于此、总的来说

**标点控制（强制）：**

- 破折号（——）：全篇 0 处
- 分号（；）：每 1000 字 ≤ 2 个
- 避免连续 2 段以上以冒号+列表开头

**结构模式警告：**

- 三点法强迫症：不要每段恰好 3 个子论点
- 段落长度均一化：变化段落长度，短段落强调，长段落展开
- 镜像结构：不要让每位讲者的内部结构完全一致
- 二元对比 "不是 X 而是 Y" 全篇 ≤ 2 次

**自然行文原则：**

- 结论前置：段首给核心判断
- 先交代对象、资料范围、问题背景，再说明处理、结果、判断边界
- 句子可略长，段落中可以有必要的承接、限定和少量重复
- 主语明确、关系清楚、读者能顺着过程理解即可

### 阶段 6：TEEL 段落逻辑（强制）

> 仅有去AI化词句不够，必须构建段落内部的因果、递进、转折链条。

每个段落按 **TEEL** 四要素成段：**T**opic（主题句，段首给出该段核心判断）→ **E**vidence（证据，数据 / 案例 / 引述支撑主题）→ **E**xplanation（解释，说明证据含义并建立因果或递进）→ **L**ink（衔接，连到下一段或回归核心论点）。四要素的定义、正反例与检查清单见 `references/teel-structure.md`（本技能唯一真源）。

**句间连接词（必须自然融入）：**

- 因果：因此、由此、进而、从而、基于此
- 递进：进一步地、更重要的是、更关键的是、顺着这个思路
- 转折：然而、不过、尽管如此
- 让步：尽管、虽然、诚然

**禁止的写法：** "事实 A。事实 B。事实 C。" 这种平行罗列必须改写为 "事实 A → 解释 → 引出事实 B → 再解释" 的因果链。

**禁止的写法：** 每位演讲人的结构完全一致（都是"开场→一二三"），破除镜像结构，让每位的结构跟随其演讲内容自然展开。

### 阶段 7：Markdown 预览 + 用户确认

输出 .md 文件供用户确认。**不要去AI化之前就先出 Word**。

### 阶段 8：Word 输出

用户确认 .md 后，用 `scripts/generate_docx.js` 生成 .docx。脚本内建两套排版档，**默认自动判别档位**（综述型内容自动套档 B），也可用 `--profile` 手动覆盖（脚本细节见 `references/word-output-guide.md`）：

- **档 A（会议纪要）**：`node scripts/generate_docx.js <in.md> [out.docx]`。A4，Arial 字体；主标题 18pt 深蓝，H1 16pt 深蓝，H2 13pt，H3 12pt，正文 11pt；引用块蓝色竖线；行距 1.5。
- **档 B（学术综述报告）**：内容包含"摘要/关键词/编号章节/附录/首行标题含综述或报告"等信号时**自动套用**；无需手动传参。A4，中文正文宋体、标题黑体，西文 Times New Roman；正文 12pt，H1 15pt、H2 13pt，主标题 18pt；**正文首行缩进 2 字符（480 DXA）**；行距 1.5；摘要/附录可小一号字。

> **自动判档**：脚本按内容命中信号打分（≥2 判综述），命中时打印 `Auto-detected profile: review`；判别失误可用 `--profile minutes|review` 手动指定（显式传入优先，打印 `Using profile: X (user-specified)`）。
> **依赖健壮化**：脚本按 `require("docx")`（本地/NODE_PATH）→ 全局 `npm root -g` → WorkBuddy 运行时 node_modules 三级备选加载 `docx` 库，三处都找不到时给出中文安装提示并退出。Node 依赖以 **`package.json`** 为清单（`docx` 锁定版本）：在技能目录执行 `npm install` 即可安装到本地 `node_modules`。

## 综述路径（学术综述报告）

当产物是**学术综述报告**时，在标准路径的阶段 1-3（信息收集、OCR、内容归类）之后**不走**阶段 4 的"主题-汇报人复述"，改走以下升格流程。完整体裁规范见 `references/review-report-guide.md`，此处为流程锚点。

### 升格阶段 A：素材底稿

先按标准路径阶段 1-4 产出一份忠实的内容底稿（或复用已有纪要）。综述报告以此为素材，不凭空写作。

### 升格阶段 B：按议题重组

通读全部内容，提炼 5-8 个贯穿性议题（如"AI 对职能的重构""变与不变的实证""服务国家战略的路径"），为每个议题建章，把分属不同报告人的相关观点编织进同一章讨论。同一报告人的内容可拆入多章。章间用承上启下过渡句衔接。

### 升格阶段 C：每议题三层展开（强制）

每章不能停在"某某说了什么"，须三层递进：

1. **观点梳理**：客观呈现核心主张、概念、数据、案例，保留样本量/数据口径/专有名词。
2. **学理定位**：把观点放回既有研究脉络，说明它接续/呼应/挑战了哪个理论传统。
3. **缺口评述**：指出证据基础与边界——系统实证 vs 理论构想 vs 趋势判断，适用范围如何。

### 升格阶段 D：学术骨架与证据分级

按标准结构成文：标题（主+副）/ 摘要（250-400字）+ 关键词 / 编号章节 / 结论与讨论 / 三附录（报告人索引、数据来源说明、待核实事项）。结论处**必须做证据分级**（证据扎实 / 理论构想 / 趋势判断），提醒读者审慎引用。诚信边界沿用纪要规范并更严格：数据转引标注"未独立核验"，引用文献待补全，录音乱码段明确标注。

> 综述报告全程同样受阶段 5（去AI化，含四类高频病灶）与阶段 6（TEEL）约束。篇幅长、议论密度高，尤其防"段段升华""章节镜像结构""学理定位处空转动词"。

### 升格阶段 E：Markdown 预览 → Word

同标准路径阶段 7-8，先出 .md 供确认，再生成 Word。

## 行动项路径（行动项 / 决策 / 待办跟踪）

当用户直接粘贴零散会议文本、只想要结构化行动项、决策与待办清单（不生成正式 Word 纪要）时，走本路径。完整方法论见 `references/action-items-tracking.md`，此处为流程锚点。

### 行动项阶段 A：识别与提炼
- 判断输入是原始笔记 / 转写 / 字幕 / 邮件 / 聊天，据此调整提炼策略
- 抽取：会议标题、日期、摘要（2–3 句）、全部行动项（含负责人与截止日期）、决策、开放问题、下一步、参会人

### 行动项阶段 B：格式化输出
- 行动项统一为 `- [ ] @Owner: Task — Deadline`，无负责人标 `@Team`，无截止日期标 `TBD`，捕捉隐含与明确任务
- 待办清单按 逾期 / 今日 / 本周 / 无截止日期 / 已完成 五分区，编号不复用
- 关键决策单独列出；始终使用正确 Unicode 字符（`—`/`[通过]`/`[注意]`/`[日期]`），禁止 ASCII 近似替代

### 行动项阶段 C：归档与联动
- 首次使用时创建 `meeting-notes/`，按 `YYYY-MM-DD_topic.md` 命名保存完整记录（含原始笔记折叠保留）
- 同一条消息内完成展示、文件保存与待办提示；按用户回复（`all` / `1,2,4` / `none`）将行动项写入待办清单
- 支持按负责人、日期范围回溯历史会议，检索归档并附来源引用

> 本路径与「标准路径 / 综述路径」互补：正式纪要 / 综述 Word 仍走路由中枢的对应路径；本路径只做轻量结构化与待办联动。

## 质量自检关卡

在交付 Word 前逐条检查：

**通用（纪要与综述报告均适用）：**

- [ ] 已运行 `python skills/deai-rules/scripts/deai_preflight.py <成稿路径>` 并 PASS（与五维自评 ≥45 共同构成 quality 门禁，见 `skills/deai-rules/SKILL.md`）
- [ ] 发言人姓名已按官方议程校正
- [ ] 无 AI 高频词（值得注意的是/综上所述/不难发现/旨在/与此同时等）
- [ ] 无四类高频病灶（镜像对仗句/段段升华收尾/空转动词/万能指代开头，详见 `skills/deai-rules/SKILL.md`）
- [ ] 破折号全篇零处
- [ ] 无"（PPT）"机械标注（已融入正文）
- [ ] 无连续 3 段以编号列表开头
- [ ] 二元对比 "不是X而是Y" 全篇 ≤ 2 次

## 常见陷阱（每条来自实战经验）

### 陷阱 1：照片扩展名大小写遗漏
`*.jpg` 不会匹配 `.JPG`（bash glob 区分大小写）。每次扫描必须同时跑 `ls *.{jpg,JPG,jpeg,JPEG,png,PNG,heic,HEIC}`。用户说"忘记还有照片"时，第一反应检查大写后缀文件。

### 陷阱 2：OCR 批量完成后未通知
长任务后台跑完后若未通知用户，用户会反复催"好了吗/继续"。OCR 完成、文件生成、任何耗时 >30s 的批量操作，完成后必须发消息说明结果和下一步。

### 陷阱 3：pip install OOM（退出码 137）
低内存环境 pip install 多包时可能被 OOM-killer 杀掉。拆开逐个装，设 `--no-cache-dir`，先装最小的。

### 陷阱 4：增量照片合并不原子
用户补加照片后，只把新 OCR 追加到 `ocr_all.txt` 会导致遗漏。必须从所有 ocr_text/ 文件全量重建（`cat ocr_text/*.txt > ocr_all.txt`）。

### 陷阱 5：会议录音不全但未标注
若转录稿从中间开始（无开场致辞），必须在对应汇报人处注明"所收录录音未包含该段内容"，不能编造也不能空着。

### 陷阱 6：综述报告写成了纪要的"换皮"
用户要综述报告，却仍按发言顺序逐人复述、只加了个摘要，这不是综述。综述的核心是**按议题重组 + 三层评述（学理定位、缺口评述）**。若只做了观点梳理没有学理定位和缺口评述，等于没升格。结论处**必须做证据分级**，否则读者无法判断哪些结论可直接引用。
