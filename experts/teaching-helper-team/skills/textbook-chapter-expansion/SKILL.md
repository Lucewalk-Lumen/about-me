# 教材薄弱章节批量扩充
> **归属**：内置扩展——随 course-builder 交付

适用于：教材/书籍/长文档中大量章节内容过薄、需要大规模加厚；有独立素材库需要回填正文；补充完成后需导出 docx。

## 适用场景与前置条件

触发条件（满足其一）：
- 用户说"教材/书某章太薄、像提纲，需要补齐/扩充/加厚"
- 多章节需要批量补充内容（预计新增 1 万字以上）
- 有独立素材库需要回填进正文
- 补充完成后需输出 md + docx

开始前用 AskUserQuestion 与用户对齐：
- 目标 md 文件路径（可能分上下册/多文件）
- 素材库目录路径（如存在）
- 每章字数目标（如 8,000 字）
- 输出格式（md / md+docx）
- 补充方向（原稿回填 / 素材库回填 / 薄弱章节加厚 / 指定内容）

## 阶段0 备份

编辑任何用户文件前先备份：

```bash
cp "<目标.md>" "<目标.v{版本}.bak>"
```

## 阶段1 三路并行扫描

并行启动 3 个后台 Agent（run_in_background=true），各输出一份独立报告文件：

1. **原稿对比**（scan-original）：对比原始稿/历史版本与当前版，用 MAPPING/变更清单找仍丢失的内容
2. **素材库扫描**（scan-materials）：遍历素材库全部文件，识别未被引用的高价值内容，按价值分梯队（第一/第二梯队），估算可新增字数
3. **章节厚度分析**（scan-chapters）：逐章统计字数，列出未达标章节，标注极薄/偏薄，指出缺实训、缺拓展案例的章节

提示词模板见 [references/agent-prompts.md](references/agent-prompts.md)。

等待策略：不要频繁轮询；用输出文件大小变化或完成通知判断。若需确认进度，间隔 30–60 秒检查一次报告文件是否已生成。

## 阶段2 差距汇总与方案确认

汇总三份报告，输出补齐方案：原稿缺失点（位置+预估字数）、素材库可回填内容（梯队+预估字数+目标章节）、极薄章节清单（当前字数 vs 目标字数）。用 AskUserQuestion 与用户确认执行策略（推荐"先补极薄章节"）。

## 阶段3 多 Agent 并行章节扩充

每个待扩充章节启动一个独立 Agent（后台并行），**输出到独立文件**（如 ch6_expanded.md），不直接修改正文。

Agent 提示词必须包含（模板见 references/agent-prompts.md）：
- 当前章节字数、行号范围、现有小节结构（含各小节字数）
- 明确的扩充字数目标（如 +7,000 字）
- 内容方向：实训场景（完整操作步骤/提示词模板/评价观测点）、拓展案例、代码示例、思政融入等
- 输出要求：写入指定独立文件，风格与正文一致

## 阶段4 脚本锚点注入

用 [scripts/inject_by_anchor.py](scripts/inject_by_anchor.py) 把扩充内容注入正文：

```bash
# 批量注入（推荐）：JSON 描述所有注入点
python3 scripts/inject_by_anchor.py batch "<目标.md>" injections.json
```

- 锚点：章节标题、`## 思政融入`、`---` 分隔线等稳定标记
- 锚点可能多处出现（如多个章节都有"思政融入"），用 line_before/line_after 限定行号范围使其唯一
- **多处注入时脚本自动从下往上执行**（按行号降序），避免行号偏移
- 注入后抽查章节边界，确认未破坏原有结构

## 阶段5 素材分层回填

- 素材按梯队注入：先第一梯队（高价值），再第二梯队；每批内同样从下往上
- 注入内容保留来源标注（〔来源：...〕）

## 阶段6 一致性验证

- 章节标题完整性：注入前后 `grep -n "^## 第.*章"` 数量一致
- 术语统一：如教材指定工具名，全文替换 Agent 可能用错的名称（先 grep 计数，再批量替换）
- 字数达标：目标章节字数 ≥ 目标值
- 记录行数/文件大小对比

## 阶段7 导出 docx

调用 **docx 技能**（Skill: docx）执行 md→docx。若无 pandoc/LibreOffice，可用 [scripts/md2docx.py](scripts/md2docx.py)（python-docx，含图片嵌入）。

**图片嵌入关键坑**：md 中图片引用可能是原作者本地路径（当前机器不存在）。处理步骤：
1. 提取 md 全部图片引用（`!\[alt\]\(path\)`）
2. 在素材库/图片资源目录按文件名（basename）搜索真实文件
3. 建立映射后嵌入；找不到的用占位提示
4. 验证：docx 图片嵌入数 == md 引用数；文件大小应显著大于纯文本（参考案例：224KB → 16MB）

## 阶段8 总结报告

输出补齐总结报告（md）：补齐前状态、三路扫描发现、各章节补齐内容、素材注入清单、验证结果、docx 导出记录。

## 关键陷阱

1. **注入顺序**：同一文件多处注入必须从下往上，否则行号偏移导致锚点错位（脚本 batch 模式已内置该逻辑）
2. **Agent 输出独立文件**：不要让扩充 Agent 直接改正文，统一由注入脚本写入，便于审查与回溯
3. **锚点唯一性**：`## 思政融入` 等多处重复的锚点必须用行号范围限定
4. **图片路径**：md 内图片路径常为他人机器路径，必须 basename 匹配重建映射
5. **术语一致性**：并行 Agent 可能用错教材指定术语（如工具名），注入后统一检查替换
6. **备份先行**：所有编辑前备份原文件

## 验证

- [ ] 章节标题 grep 数量与注入前一致
- [ ] 目标章节字数 ≥ 字数目标
- [ ] docx 图片嵌入数 = md 引用数
- [ ] docx 文件大小合理（含图应明显增大）
- [ ] 抽查 docx 中表格/代码块/图片渲染正常
