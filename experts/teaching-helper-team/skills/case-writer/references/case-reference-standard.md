# 案例参考文献与著录统一标准（case-reference-standard）

> **定位**：case-writer 引用与著录的 **L1 统一标准**，合并路径 A（教学案例）、B（课程思政）、D（工商管理案例）三套模板的 references 规范，消除差异、确保跨模板一致可复用。

> **路径口径**：本包写作层为**四路径**（A 教学案例 / B 课程思政 / C 融入思政 / D 工商管理案例）；其中 C 为轻量模式，复用 A/B 模板与规约、**不建独立 spec**，故**模板层只有 A/B/D 三条模板路径**。后文凡称「A/B/D 三条模板路径」，均指模板 / spec 层；**写作层始终为四条路径，两层口径不可混同**。

> **单一事实来源（SSOT）**：`skills/citation-integrity/SKILL.md`（全团 L0 权威层）。本文件只做**增量**约束（更严 / 更具体），**不得放宽** L0；与 L0 冲突时一律以 L0 为准。
> **采集层**：来源检索与桌面知识库取用细则见同目录 `references/source-integrity.md`（采集层，不重复定义标记格式）。

## 0. 为什么需要本文件

A/B/D 三条模板路径的引用写法统一如下：

| 路径 | 旧写法 | 问题 |
|------|--------|------|
| A 教学案例 | 正文 `〔来源：…〕` 文内标记，无参考文献节 | 缺 consolidated 来源列表，跨模板不可比 |
| B 课程思政 | 正文 `〔来源：…〕` 文内标记，无参考文献节 | 同上 |
| D 工商管理案例 | 正文 `¹²³` 上标脚注 + `来源：作者，"篇名"，媒体/机构，日期，URL，访问日期 YYYY-MM-DD` | **与 L0 `〔来源：…〕` SSOT 冲突**，格式自成一套 |
| 配置层 | `case-config.json` `ref_format` 用 GB/T 7714 `[N] 作者. 题名[文献类型/OL]…` | **与案例教学场景的 `〔来源：…〕` 标记不一致** |

本文件将上述差异统一为**一套**文内标记 + **一套**参考文献著录格式，A/B/D 三条模板路径共用，且兼容 `md_to_docx.py` 转换器。

## 1. 文内标记（A/B/D 三条模板路径统一，强制）

正文凡出现政策条文、行业数据、获奖记录、外部标杆、任何带出处的数字，一律用统一 `〔来源：…〕` 标记。**路径 D 不再使用 `¹²³` 脚注样式**。

| 类型 | 文内标记格式 |
|------|--------------|
| 政策 / 文件 | `〔来源：《文件全称》，发布机构，年份〕` |
| 数据 / 统计 | `〔来源：机构 / 报告名，年份；检索日期 YYYY-MM-DD〕` |
| 网络 / 新闻 / 机构报告 | `〔来源：作者 / 机构，"篇名 / 报告名"，媒体 / 发布机构，日期，URL，访问日期 YYYY-MM-DD〕` |
| 桌面案例知识库 | `〔来源：桌面案例知识库 / 某类资料（如"获奖案例全文"）〕` |
| 教师主观经验 | `基于笔者教学实践观察`（不套用来源标记） |
| 无可靠来源 | `〔无可靠来源，待核实〕`（交付前必须清零，不得带此标记交付） |

> 标记语法（`〔…〕` 全角方头括号）与 L0 `citation-integrity` 完全一致，不新造符号。

## 2. 参考文献节（A/B/D 三条模板路径统一，推荐必含）

每个案例正文末尾可（推荐）附一个 **`## 参考文献`** 节，集中列出来源。

- **标题固定为 `## 参考文献`**：与 `md_to_docx.py` 转换器的 `ref_trigger_heading` 对齐，触发悬挂缩进排版。
- **条目编号 `[N]`**：从 `[1]` 起顺序编号，与正文 `〔来源：…〕` 出现的顺序对应；可去重合并同一来源。
- **条目格式见第 3 节统一著录格式**。
- 教师主观经验（`基于笔者教学实践观察`）与待核实标记（`〔无可靠来源，待核实〕`）**不列入**参考文献表。

> A/B/D 三条模板路径一致约定：无论 A / B / D，参考文献节标题、编号方式、著录格式**完全相同**，保证跨模板可比对、可复用。

## 3. 著录格式（统一，按来源类型）

参考文献表内每条用下述统一著录格式（与第 1 节文内标记同源，仅展开为书目条目形态）：

| 类型 | 统一著录格式（`[N]` 条目） |
|------|---------------------------|
| 政策 / 文件 | `[N] 《文件全称》〔发布机构，年份〕` |
| 数据 / 统计 | `[N] 机构 / 报告名〔年份；检索日期 YYYY-MM-DD〕` |
| 网络 / 新闻 / 机构报告 | `[N] 作者 / 机构. 篇名 / 报告名. 媒体 / 发布机构, YYYY-MM-DD. URL（访问日期 YYYY-MM-DD）` |
| 桌面案例知识库 | `[N] 桌面案例知识库 / 某类资料` |

**示例**：
```
## 参考文献

[1] 《关于深化新时代学校思想政治理论课改革创新的若干意见》〔中共中央办公厅、国务院办公厅，2019〕
[2] 教育部. 2023 年全国教育事业发展统计公报〔2024；检索日期 2025-03-10〕
[3] 中国企业家杂志. 某集团组织变革实录. 中国企业家, 2024-06-15. https://example.com/xxx（访问日期 2025-03-12）
[4] 桌面案例知识库 / 获奖案例全文
```

> 著录条目**不要**以 `- ` / `* ` 开头（否则 `md_to_docx.py` 会误判为项目符号、破坏 `[N]` 悬挂缩进），直接从 `[N]` 起写。

## 4. 跨模板一致性规则

1. **文内标记统一**：A / B / D 正文一律 `〔来源：…〕`，不再出现 `¹²³` 脚注、`来源：作者，"篇名"…` 等私有格式。
2. **参考文献节统一**：A/B/D 三条模板路径均可用 `## 参考文献` + `[N]` 编号 + 第 3 节著录格式；占位、顺序、去重规则一致。
3. **配置对齐**：`config/case-config.json` 的 `citation` 块 `ref_format` 与 `in_text_mark` 已改为本文件口径，不再使用 GB/T 7714 `[文献类型/OL]` 写法。
4. **转换器兼容**：`md_to_docx.py` 仅识别 `[N]`→上标、`参考文献`→悬挂缩进；`〔来源：…〕` 作为文内字面标注原样呈现。两者并存不冲突。

## 5. 与 L0 / md_to_docx 的关系

- **L0 `citation-integrity`**：管"这条引用是不是真的存在、是不是真说过你写的那句话"（四铁律、核验四问、三态标注、交付门槛）。本文件只管"标记长什么样、著录怎么写"，**不替代** L0 的核验。
- **`md_to_docx.py`**：排版工具，不校验引用真伪。`〔来源：…〕` 在正文为字面文本；`## 参考文献` 节下 `[N]` 条目进入悬挂缩进；正文若用 `[N]` 指针则转上标（保留字面子）。
- **执行次序**：先过 L0 引用保真（真伪），再按本文件统一标记与著录（格式），最后由 `deai-rules` 做去 AI 味（风格）。次序不可反。

## 6. 红线（沿用 L0 四铁律，违反即退回）

- 不编引用：不虚构政策文件名、发文字号、行业数据、获奖记录、企业公开数字、文献出处。
- 不归观点：不把行业观点安到具体企业或专家名下；教师自身判断注明"基于笔者教学实践观察"。
- 标注无支撑：查不到的显式标 `〔无可靠来源，待核实〕`，不许静默留着，也不许临时编一个支撑；交付前清零。
- 不超范围：AI 不替教师担保政策时效与准确性，不替教师作案例可申报 / 可入库判断；超出材料范围的发挥须主动报告。
- 禁止模糊断言顶替：出现"大量 / 显著 / 普遍 / 据研究表明 / 相关数据显示"而无具体出处的，一律按无支撑处理。
