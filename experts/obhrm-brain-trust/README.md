# OBHRM 智囊团 · 程亦楠（Vivian）

> 花名 **程亦楠（Vivian）** — 把教材、理论、量表、方法四路知识汇聚于一处的 OBHRM 智囊团。

谈及任一组织行为学概念，直接呈现该概念的**教材定位、理论依据、成熟量表与可行的分析路径**。
核心能力全部由**纯标准库 Python 脚本**提供，离线运行、零第三方依赖（唯一例外见 §七）。

## 一、名称怎么理解

| 项 | 值 | 含义 |
|---|---|---|
| **卡面名称** | **OBHRM 智囊团** | 对外的专家团名。官方校验器要求 Team 型的 `profession` 与 `displayName` 取值一致，平台实际展示的是 `profession`，因此两者统一为「OBHRM 智囊团」。检索与呈现由四位专家分工完成，知识资产与回答方式不随名称改变 |
| **名称** | `obhrm-brain-trust` | **枢纽**。不新增知识源，而是把教材、理论、量表、方法四路资产接到同一个中枢上——四路进来，一处出去 |
| **花名** | **程亦楠（Vivian）** | **汇聚四库之知**。「汇」点出 hub 的中枢角色，「知」点出服务对象要的是知识本身，而非一个替他下判断的权威。主理人卡位显示此花名 |
| **职业定位** | 知识检索与呈现 | 做的是**检索、关联与呈现**：把库里真实存在的教材原文、理论四段正文、量表条目、方法门控准确取出并组织成连贯回答，把材料给全，判断留给人 |
| **头像** | 四位专家各一张统一漫画/插画风格半身人物头像 | 藏青/板岩蓝背景，以手持道具区分领域——程亦楠（连接枢纽徽章）/ 顾铭泽（天平）/ 江语桐（书卷）/ 陆奕辰（数据平板）；团队卡位 `avatars/team.jpg` 为四人协作场景，主理人卡位 `avatars/team-lead.jpg` |

**当前版本**：1.0.3（包内各处版本号一致：`plugin.json`、4 个 `SKILL.md`、4 个知识库 `_meta.version`）

**为什么是「团队」**：四位专家分工协作——主理人程亦楠负责建团、路由与汇编，顾铭泽、江语桐、陆奕辰分别坐测量、理论、方法三个知识域；理论、量表、方法的条目细节一律由对应专家检索回传，主理人不代写专业产出。全团做的是**检索、关联与呈现**——把库里真实存在的教材原文、理论四段正文、量表条目、方法门控准确取出并组织成连贯回答，不下诊断、不替人拍板，也不假装有库外的知识。

## 二、服务对象与呈现方式

**服务对象**：本科生、研究生、学者 —— 三类读者**均在服务范围内**。

**呈现方式**：检索到的内容**直接在回答中完整呈现**。

- 不反问、不追问、不用"你觉得呢？""先想想看"这类引导式话术代替回答。
- 一次提问换一次完整回答：教材定位、理论依据、测量工具、分析路径，该给的一次给全。
- 同一份回答覆盖三层深度，**各取所需**：

| 读者 | 从回答中取用 |
|------|--------------|
| 本科生 | 概念含义、教材定义与出处、典型例子 |
| 研究生 | 理论四段正文（内容/作用机制/结构/应用）**（覆盖率见脚注）**、量表维度与计分、变量操作化 |
| 学者 | 方法族选择与适用条件、效应量与检验路径、原始文献出处 |

- 答案末尾可附**可选的**延伸方向（如"要看完整量表条目，我可以展开 S015"）。这是补充而非反问——用户不问就不展开。

### 四项功能

| 功能 | 说明 | 知识来源 |
|------|------|--------|
| 知识检索与介绍 | 查概念、讲定义、定位教材章节与出处 | 教材《组织行为学精要》12 章 / 52 节 / 335 个编号节点 |
| 量表检索与介绍 | 找测量工具、查维度/条目/计分/出处 | 601 个量表 |
| 理论方法检索与介绍 | 查理论内容/结构/适用场景，查方法族与用法 | 145 个理论、108 个 R 方法 |
| 数据分析指导 | 分析路径建议、方法适用条件、R 脚本用法与门控 | 108 个 R 脚本 / 19 个方法族 |

> **脚注 · 理论库质量口径**：**条目状态**为 27 条 `verified`（来源已确证）/ 118 条 `draft`（正文可用、但来源尚未确证到可查证的公开文献，资料本身真实、可引用出结果，但输出须显著标记「来源未确证」，严禁编造，见条目 `note`）。**四段覆盖**：内容（`what`）127/145、作用机制（`processes`）36/145、结构（`structure`）58/145、应用（`application`）135/145；四段齐备 23/145。任一段正文缺失的条目，输出时标注该段（原文未覆盖），不补写。**D1 内源补足 25 条**：含 11 条为消除桥接虚关联而新补录的教材侧条目（古典科学管理理论、人际关系学说、认知失调理论、平衡理论、MBTI、从众、社会惰化、群体思维、虚拟团队、约哈利之窗、职业倦怠三维模型），均已降为 `draft` 并附【出处：D1,§…】锚点与二次来源边界声明，引用前须核对原始出处。
>
> **内源补足披露**：另有 25 条理论在上游数据准备阶段依据资产包内置教材 D1（《组织行为学精要：核心理论与管理应用》）做过二次补全（以【出处：D1,§…】锚点标示）；该教材为内部教学二次来源、非原始同行评议文献。这 25 条的状态已据补足事实统一降为 `draft`，检索输出（含 `query_theories.py` 与 `query_concept.py`）会对命中条目显式给出【内源补足警示】，请勿将其补足部分作为经核验的权威内容引用，引用前请核对【出处：D1,§…】所指原始出处。

> **存储口径（v1.0.3 变更）**：理论库与量表库的条目正文存放于**合并存储**（`skills/theory/knowledge/theories/entities.json`、`skills/scale/knowledge/scales/entities.json`），各自是「以 id 为键」的单一 JSON 文件，是条目的**唯一来源**；本包**不再随附逐条单文件**（`Txxx.json` / `Sxxx.json`）。这样做的直接原因是逐条单文件会把包内文件数从 157 推到 900+，超出平台审核对包内文件数的上限；内容无损——合并存储与原逐条文件已做过全字段逐条比对（理论 144/144、量表 601/601，零漂移）。检索脚本与四位专家均自合并存储按 id 取正文。

### 教材怎么用

- **先查索引，再取原文**：`skills/bridge/references/chapter-index.md` 给出章级概览与 12 章的**节号树（两级：`X.Y` 节 / `X.Y.Z` 小节，共 193 个节点）**。先在索引里定位到节或小节，再按编号读取对应章节文件的原文；更细的 `X.Y.Z.W` 条一级**不在索引内**，直接在章节原文里按编号定位。
- **编号体例**：编号照原书层级（`X.Y` 节 / `X.Y.Z` 小节 / `X.Y.Z.W` 条），Markdown 标题层级与编号深度一致（`##` = 节，`###` = 小节，`####` = 条）。教材全书的编号节点（三级合计）为 335 个。
- **引用格式**：引用教材时锚点固定写作【出处：D1,§X.Y】。
- **内容为纯文字**：教材以文字呈现，不含插图；涉及图形示意的内容已转为文字表述。
- **保留的非正文块**：【内容概要】（11 处）、【本章小结】（12 处）、引例、**实践专栏**（22 处企业真实案例）、知识链接（5 处）、**资料来源**（32 处出处标注）均可查用。

## 四、四库如何联动

教材、理论、量表、方法四路知识**各自独立编制**，因此以「概念」为枢纽把它们串成一张可联动的网：谈任何一个组织行为学概念，都能同时给出"教材怎么讲 / 理论怎么解释 / 量表怎么测 / 数据怎么验"四重视角。

```
                 ┌───────────────────────────┐
   用户概念词 ──▶ │  obhrm-bridge 概念桥接层   │
   （如「情感」）  │  109 概念 × 中英双语关键词  │
                 └─────────────┬─────────────┘
        ┌──────────────┬───────┴────────┬──────────────┐
        ▼              ▼                ▼              ▼
 教材（本 skill 内）  theory-library    scale-library    r-analysis
 skills/bridge/references/textbook/ch01.md…ch12.md  145 理论  601 量表  108 R 脚本
   ch05 情绪与压力    T033 情感事件理论   S015 情感承诺     13.x ESM
   【D1,§5.x】        T034 情感信息理论   S109 情绪耗竭     15.x 多层
```

> 上图为**示意**。四库联动的分级行为、匹配规则与协同关系，以 `skills/bridge/SKILL.md`（§三 / §四 / §五）为准。

- **概念词表单源**：概念词表以 `_bridge.json` 为唯一来源——收录 109 个概念、锚定教材 12 章骨架、含中英双语关键词及其到四库的映射，检索脚本读取此文件。
- **桥接索引给出映射**：`_bridge.json` 记录每个概念到教材章节、理论、量表、R 方法的映射，所有 ID 均取自各库真实节点。
- **不臆造**：匹配不到的概念如实报告"库内无匹配"，绝不凭记忆补写。

### 匹配口径（摘要）

- **中文**：`name_zh` / `variable_zh` 关键词子串匹配；**英文**：`name_en` / `variable_en` / `construct_id` 关键词子串匹配（**不做词首边界限定**，下划线不与空格等价）。
- **R 方法**：先取指定方法族内标题命中者，不足再补该族代表脚本。
- **排序**：命中关键词数多者优先；同分时名称短者优先（短名通常为核心构念）。

> 本节仅作摘要。完整匹配规则（`construct_id` 参与匹配、方法域整族纳入、边界判定示例等）见 **`skills/bridge/SKILL.md` §四**，该文件为权威依据。

> **桥接覆盖口径说明**：88/88 指「教材有章节锚点的内容域概念均能在三库中找到挂载」，属教材骨架内的桥接覆盖率。此外，理论库另有 79 条、量表库另有 222 条**教材外扩展条目**（如 CNI 模型、SOR 理论、双过程理论等）——它们的构念在教材 D1 中无对应章节篇幅，因此不挂任何概念节点，**这是教材边界使然、而非挂载缺口**。这些条目同样完整可查：经全库回退检索按名称、关键词或构念直达，输出与已挂载条目一致（维度题数、核验状态、原文路径俱全）。

## 七、运行环境

- **纯标准库 Python 3.6+**，零第三方依赖，无 `pip install` 步骤
- **检索层完全离线**：4 个 Python 检索脚本不含任何联网能力，不发起任何网络请求
- **路径自解析**（基于 `__file__`），不依赖当前工作目录、不依赖环境变量
- **R 执行需本机安装 R**：108 个 R 脚本以文本与门控指导形式提供，需你在本机 R 环境运行；缺包时只提示 `install.packages()`，**绝不自动安装**
- **一个脚本可选联网**：`skills/ranalysis/scripts/19-llm/19.1.R`（本地大语言模型分析）默认离线、加载与运行都不发起任何网络请求；仅当你显式加 `--online` 时，才连接**本机** Ollama 服务（`http://localhost:11434`），用于在你自己的机器上运行本地模型。请求不离开本机，其余 107 个脚本始终无联网行为

### 隐私与数据

- **数据不外传**：检索层不发起任何网络请求；`skills/ranalysis/scripts/19-llm/19.1.R` 默认离线，仅在显式启用 `--online` 时与本机 Ollama 通信，不向任何外部服务器发送数据
- **无凭据**：不需要任何 API Key、令牌或账号，资产内不含任何密钥
- **只读**：检索与介绍为只读操作，不运行 R、不读取你的外部数据文件、不产出统计结果
- **不采集身份信息**：不采集学生或受访者个人身份信息

## 九、能力边界

- **理论库规模**：理论库共 145 条，部分概念（如"绩效""满意度"等方法域概念）可对应的理论条数较少。未命中时如实标注"库内无匹配"，不硬凑。
- **理论草稿与截断提示**：145 条中 118 条为 `draft`（来源尚未确证），另有 **75 条判定为【内容不完整】**（其中 65 条作者显式标记「截断」、10 条经高精度检测确认为续写符号/英文碎句截断，含部分 `verified` 条目；个别极短中文短语截断可能漏报，建议人工抽检）。`draft` 条目资料本身真实、可引用出结果，但输出须显著标记「来源未确证」，严禁编造；条目级状态以检索输出中的 `status` 字段与条目 `note` 为准。
- **内源补足披露**：25 条理论在上游数据准备阶段依据资产包内置教材 D1 做过二次补全（以【出处：D1,§…】锚点标示；教材为内部教学二次来源，非原始同行评议文献）。这 25 条状态已据补足事实统一降为 `draft`，检索输出（`query_theories.py` / `query_concept.py`）会对命中条目显式给出【内源补足警示】，请勿将补足部分作为经核验的权威内容引用。
- **不含 R 运行时**：本资产不随附 R 或任何 R 包，运行环境须由使用者自备；缺包只提示不代装（详见 §七）。
- **教材为文字版**：教材不含插图，回答时不引用图片、不使用"如下图所示"一类表述，一律用文字重述要点。
