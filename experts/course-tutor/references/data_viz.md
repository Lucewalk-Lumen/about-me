# 学情可视化看板（实时数据分析 / 获取 / 可视化）

> 本文件是 `agents/course-tutor.md` §2.3 主菜单第 14 项的细则（**先 Read 再操作**，未读不得动手）。
> 目标：把数据中枢里的学情**实时取出 → 按方法学分析 → 渲染成美观看板**，全程直连腾讯文档、无服务端。

## 零、先看边界：看板与相邻能力怎么分工

教师说的每句话对应哪个产物，先判清楚再动手，避免重复劳动或答非所问：

| 教师诉求 | 走哪个能力 | 产物 |
|---|---|---|
| 「看看整体学得怎么样 / 出个看板」 | **本文件** | 自包含 HTML 看板（KPI + 分布 + 趋势 + 积分榜） |
| 「出周报 / 月报」 | `teacher_reports.md` §6 | Markdown 周报（叙事结论为主） |
| 「学情洞察 / 谁掉队 / 补练路径」 | `course_mastery.py insight`（菜单 13） | 掌握画像 + 异常名单 + 补练建议 |
| 「积分 / 排行榜」 | `points.md` + `course_points.py` | 积分明细与排名（看板可内嵌其榜） |
| 「预警 / 谁很久没学」 | `course_warn.py`（学生端开场自检） | 预警名单 |

> 看板**不是**周报的替代品：看板回答「现在是什么样」，周报回答「这周发生了什么、下周做什么」。
> 教师只要结论 → 周报；教师要看全局 → 看板；两者可以同一批数据各出一份。

## 一、对话交互铁律（优先于一切）

1. **先自检、再取数**：走 §2.0 启动自检；未连通道 / 未建库时按主文件规则处理，**不臆造看板**。
2. **取数方式统一**：经 §1.1 定位 + 数据通道封装 `course_tdoc.py` 读取该课 Usage 文件的
 `usage` / `summaries` 子表，**绝不硬编码**定位 ID。
3. **定位 ID 不进看板、不进对话**：看板只含聚合后的统计数字与学生姓名（名册里的真实姓名）；
 任何 `file_id` / `sheet_id` 不出现在 HTML 与对话中（§1.3）。
4. **不编造**：缺失字段 / 缺失课程在聚合时即显式标注，看板留空或标「无数据」，不补零、不插值。
5. **先问清看板要回答什么**（§三 阶段 1）：教师没说就**先问一句**「想看整体掌握、某教学周变化，
 还是某几个学生？」——目标不同，取数范围与图表完全不同，别默认全量硬出。

## 二、实时数据获取（复用既有口径）

- 按 §4.1–4.3 的**逐课**三段式读取（该课 Usage `usage` 子表全量 → 逐生归并 → 合并）；
 **名册只用于取真实姓名**（`roster` 表按学号匹配），**不存在「学情文件」列**，不要按该列取数
 （该列是历史设计、线上无此列，按它取数必然读空）；
- 先过 §4.2 **聚合前过滤**：教师端行 / 空学号 / 测试号 `0000` 一律剔除；
- 按 `teach_week`（教学周）归集趋势，无校历回退 ISO 周并在看板标注「未对齐校历」；
- **要做多维分析，这些列必须一并取出**（缺了对应维度就不出图）：`环节`（环节分布）、
 `err_type`（错因分布）、`知识点`（知识点掌握排行）、`时间`（活跃度 / 学时）、`学号`（去重人数）；
 课程知识点总数取自 `config.json` 的 KP 清单（覆盖率分母）；
- 读全表注意**分页**：`list_records` 单页上限 100 条，返回 `has_more=true` 时必须带 `offset`
 逐次 +100 继续读，直到 `has_more=false`（与学生端同一条分页铁律）——只读首页会让看板少算一大半学生；
- **数据体检（可选但推荐）**：导出 CSV 后跑
 `python3 "${CODEBUDDY_PLUGIN_ROOT}/course_datakit.py" profile 学情.csv --json`，
 看每列缺失率 / 类型 / 异常值；工具有 7 个子命令：`profile`（体检）、`clean`（清洗）、
 `funnel`（漏斗）、`cohort`（同期群）、`rfm`（学生分层）、`abc`（贡献度分层）、`sig`（显著性）。

## 三、分析方法学（八阶段流程）

把取出的原始学情按以下**八个阶段**推进，**第 7 阶段（交付前复核）不过，不得出图**：

1. **需求澄清**：确认本次看板要回答什么（整体掌握？某教学周异常？某批学生掉队？），并确认口径
 （是否含测试号、是否按教学周还是自然周）；
2. **数据体检**：`course_datakit.py profile` 看缺失 / 异常；数据等级 D（缺失重 / 行数过少）
 先向教师说明再降级出图，**不静默出图**；
3. **EDA（探索）**：分布 / 趋势 / 分组对比，**只产假设不产结论**；
4. **深度分析**：按场景选方法——环节转化用漏斗、留存 / 连续跟进用同期群、学生分层用
 RFM 或 ABC、两组差异用显著性检验；
5. **洞察提炼**：每条按「发现 → 结论 → 所以呢 → 建议」四段写，并标**证据强度**：
 **强**（多指标一致、样本充足）/ **中**（单指标或样本偏少）/ **弱**（仅趋势、需复核）；
6. **可视化映射**：按 §四 的图表选择矩阵把结论映射成图表，一图一结论，不为好看堆图；
7. **交付前复核（必过门禁）**：逐项自查——替代解释是否排除、口径前后是否一致、
 因果链是否经得起追问、数据质量是否回查过；挑不出毛病才进看板；
8. **叙事与建议**：给看板配一段「怎么看这张板」的说明 + 1-3 条可执行建议（谁、做什么、何时做），
 建议要能落到人或知识点，不要只说「加强练习」。

> **置信度不是装饰**：标「弱」的洞察要写清弱在哪（样本量、口径、时间窗），
> 教师按它做教学决策时才知道该不该采信。

## 四、可视化（图表选择 + 自包含 HTML 看板）

### 4.1 图表选择矩阵（不要凭喜好选图）

| 要表达什么 | 用什么图 | 理由 |
|---|---|---|
| 随时间的变化（教学周趋势） | 折线 | 连续时间轴看走势与拐点 |
| 个体之间对比（学生掌握分布） | 堆叠柱 | 同时看总量与结构（收敛 / 部分 / 卡住） |
| 占比结构（整体掌握构成） | 环图 / 饼图 | 看份额，类别 ≤ 5 个才用 |
| 环节转化（预习→复习→题目生成） | 漏斗 / 堆叠柱 | 看每一环的流失 |
| 两个量的关系（学时 vs 收敛数） | 散点 | 看相关与离群点 |
| 排名（积分榜） | 表格 | 精确值优先，别用图表达排名 |

**配色纪律**：收敛用绿、部分用橙（警示）、卡住用红（异常）；同一含义全板配色一致，
**不要**为了美观把「卡住」配成暖色系。

### 4.2 出图命令

```bash
python3 "${CODEBUDDY_PLUGIN_ROOT}/course_viz.py" <聚合json> \
 --course "<课程名>" --out "<输出 html 路径>" [--max-students <人数>]
```

- `--max-students` 默认 **40**：学生更多时只画前 N 人，**页面与 stdout 都会标注截断**
 （要全量显式调大，脚本不会静默丢人）；
- `--max-kp` 默认 **12**：知识点排行按「卡住」降序只取前 N 个（同样会标注截断）；
- 聚合 JSON 缺字段时，脚本在 stdout 报 `[WARN] 聚合 JSON 缺失字段（按 0 / 空计，不编造）`——
 看到就回 §二 补取，**不要**当噪音忽略；
- 看板为**自包含静态页**（数据内联，不需要后端即可打开 / 分享）；
 图表库 Chart.js 走 CDN **首次需联网**，加载失败会**自动降级为数据表格**
 （页面顶部出现「离线模式」提示条，数值与图表口径一致），不会出现空白图。

### 4.3 看板结构（脚本产出，教师看到什么 —— 九块，不止三个面）

| # | 模块 | 图形 | 回答什么问题 |
|---|---|---|---|
| 1 | 总览 KPI | 数字卡 | 规模：在学 / 有记录 / 会话 / 覆盖 / 收敛率 / 覆盖率 / 人均 / 卡住 |
| 2 | 学生掌握分布 | 堆叠柱（人多自动横向） | 谁学得好、谁在掉队 |
| 3 | 整体掌握结构 | 环图 | 全班健康度 |
| 4 | 教学周趋势 | 折线 | 走势与拐点（有没有突然变差的一周） |
| 5 | 学习环节分布 | 横向条 | 学生在**赶进度**（首学多）还是**在巩固**（复习多） |
| 6 | 知识点掌握排行 | 横向堆叠条（按卡住降序） | **下节课最该讲评哪个知识点** |
| 7 | 错因分布 | 环图 | 学生卡在概念、审题还是计算 |
| 8 | 学习活跃度 | 柱 + 折线双轴 | 投入是否稳定（会话数 + 学时） |
| 9 | 学生分层 | 环图 | 领先 / 跟进 / 掉队 / **沉默**（谁需要被点名关心） |
| 10 | 未收敛知识点 | 横向条 | 整班**无人收敛**的知识点，优先复盘讲授方式 |
| 11 | 积分排行榜 | 表格（前 10） | 谁领先 |

> 第 5–10 块**有数据才渲染**，没有就不留空卡片；数据不足时看板会退化为「总览 + 学生分布 +
> 结构 + 趋势」，此时脚本会在 stdout 提示缺了哪些维度字段。
>
> **分层与沉默由已有数据派生，不需要新增字段**（口径公开，便于教师对照自己的判断）：
> - 个人收敛率 = 本人 `converged / (converged + partial + stuck)`；
> - **领先** ≥60%｜**跟进** 30–60%｜**掉队** <30%｜**沉默** = 无任何伴学记录；
> - **未收敛知识点** = `kp_mastery` 中 `converged == 0` 的知识点（整班无人收敛）。
>
> 人数多的课程（如百人级名册）最该看的是**沉默人数**与**掉队占比**——
> 这两个数字比平均分更能说明真实覆盖情况。

## 五、聚合 JSON 口径（脚本契约）

`course_viz.py` 与 `course_points.py` 共用同一份聚合 JSON。字段契约：

| 字段 | 类型 | 含义 | 缺失时 |
|---|---|---|---|
| `course_name` | 字符串 | 课程名（看板标题） | 回落 `--course` 参数，都无则显示「(未命名课程)」 |
| `students[].sid` | 字符串 | 学号 | 显示 `?` |
| `students[].name` | 字符串 | 真实姓名（取自名册） | 回落显示学号 |
| `students[].sessions` | 整数 | 会话数 | 按 0 计，并报缺失 |
| `students[].kp_records` | 整数 | 学情行数 | 按 0 计，并报缺失 |
| `students[].converged` / `partial` / `stuck` | 整数 | 三类结果计数 | 按 0 计 |
| `students[].kp_distinct` | 整数 | 去重知识点数 | 按 0 计 |
| `weeks[].teach_week` | 字符串 | 教学周标签 `2026-秋-W7` | 该周不进趋势图 |
| `weeks[].converged` / `partial` / `stuck` | 整数 | 该周三类计数 | 按 0 计 |
| `leaderboard[].sid` / `name` / `points` | 字符串 / 整数 | 积分榜 | 无榜则不渲染该区块 |
| `stages[]` | 数组 | 环节（**学习阶段**）分布：`{"stage":"首学","count":52}`；**不要写「苏格拉底引导」**（那是引导方式） | 无则不出「学习环节分布」图 |
| `kp_mastery[]` | 数组 | 知识点掌握：`{"kp_id":"…","converged":n,"partial":n,"stuck":n}` | 无则不出「知识点掌握排行」 |
| `err_types[]` | 数组 | 错因分布：`{"err_type":"概念","count":9}` | 无则不出「错因分布」图 |
| `activity[]` | 数组 | 活跃度：`{"teach_week":"…","sessions":n,"hours":f}` | 无则不出「学习活跃度」图 |
| `coverage` | 对象 | 覆盖率：`{"total_kp":241,"covered_kp":18,"rate":7.5}` | 无则 KPI 显示「—」 |

示例：

```json
{
 "course_name": "心理学与生活",
 "students": [
 {"sid":"2024001","name":"张三","sessions":12,"kp_records":30,
 "converged":20,"partial":6,"stuck":4,"kp_distinct":18,"bonus":0}
 ],
 "weeks": [
 {"teach_week":"2026-秋-W7","converged":40,"partial":10,"stuck":5}
 ],
 "leaderboard": [ {"sid":"2024001","name":"张三","points":320} ]
}
```

**出图前自检（5 条，逐条过）**：
1. 过滤做全了吗（教师端行 / 空学号 / 测试号 0000 已剔除）；
2. 分页读全了吗（`has_more` 已翻到底）；
3. 姓名来自名册吗（不是学号、不是花名）；
4. 有没有 `file_id` / `sheet_id` 混进 JSON；
5. 交付前复核（§三 阶段 7）过了吗。

## 六、常见故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| 看板 KPI 有数但图全空 | 离线 / 内网，Chart.js 从 CDN 加载失败 | 属**预期降级**：页面会自动显示数据表格并提示「离线模式」；要图表请联网后重新打开 |
| 学生数明显偏少 | 只读了首页（`has_more` 未翻页） | 按 §二 翻页读全后重新聚合 |
| 趋势图不显示 | 聚合 JSON 无 `weeks`（未取 `teach_week` 或校历未对齐） | 补 `teach_week` 聚合；确实无校历就按 ISO 周并在看板标注 |
| 收敛率 0% 或 100% | 多半是字段错位（结果列取错）或过滤把有效行滤光了 | 回查 §4.2 过滤与列映射，**不要**直接对外下结论 |
| 只显示前 40 人 | 默认 `--max-students 40` 截断 | 页面已标注；要全量显式加大该参数 |
| 排行榜区块缺失 | JSON 没传 `leaderboard`（没先跑积分） | 先按 `points.md` 算积分再出板 |
| 只出了 4 张图，环节 / 知识点 / 错因都没有 | 聚合 JSON 没传 `stages` / `kp_mastery` / `err_types` | 脚本 stdout 会提示；回 §二 把 `环节` / `知识点` / `err_type` 列一并取出再聚合 |
| 学生名字挤成一团看不清 | 学生多时脚本会自动转**横向条形**；若仍挤，调小 `--max-students` | 横向条形下标签竖直排列，不会重叠 |
| 学号显示为姓名 | `name` 缺失，回落学号 | 用名册按学号补真实姓名 |

## 七、回写（可选）

- 看板路径可写入 `report` 子表「学情报告」存址（同 §6.2 周报回写纪律）；
- 积分榜可写入 `usage_sheet.points`（若已建）；
- 看板**不要**写回学生可见空间——它含全班聚合数据，只面向教师。
