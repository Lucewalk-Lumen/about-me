# 课程伴学专家 · 参考细则（teacher_setup.md）

> 本文件由 `agents/course-tutor.md` 按无损分片拆出，**内容与原 SKILL 逐字一致**。
> 引用方式：`${CODEBUDDY_PLUGIN_ROOT}/references/teacher_setup.md`。

### 2.0.1 首次设置向导（首次使用，主动引导搭建教师自己的教学库）

**触发**：
- **首次**：§2.0 第 1 步判定「尚未建立数据中枢」，或教师说「带我完成首次设置」/「帮我建数据中枢」；
- **增量（新增课程）**：已建立数据中枢的教师说「新增课程」/「再开一门课」→ 从第 2 步进入
 （第 1 步身份确认静默跳过），仅处理新增课程，后续注册 / 建库 / 播种 / 收尾与首次向导同构。

**核心原则：默认流程不依赖示例课。** 云端 Hub `course_versions` 表中的示例条目《组织学习理论》（`sample-course`，`is_template=true`）
只是**结构示范**——多数教师不理解它的含义，因此向导**永远以教师的真实课程为起点**，
示例课仅在教师明确说「先用示例课试试」时才被纳入建库。

向导步骤（逐步交互，每步等教师确认后再进入下一步）：

0. **通道前置探测（先于一切交互）**：按 §2.0 第 2 步 A / B 探测数据通道——不可用 → 直接输出
 「未连接到数据中枢」停止提示并停在待连接状态，**不进入任何向导问答**
 （避免教师聊完身份 / 课程 / 资料方式后，到建库一步才发现连不上）；
0b. **开场白先给功能导览（必做，兑现引导语承诺）**：进入向导问答**之前**，先按 §0 引导语模板
 列出全部功能菜单（含校历 / 学习预警 / 学情洞察），并明确标注「以下为建库完成后可用的功能」——
 不让教师只见门槛不见能力（这是引导语「介绍你能帮我做什么」承诺的组成部分）；
1. **确认身份**：按 §2.1 读写 `~/.workbuddy/profile.json`（已确认则静默跳过）；
2. **询问课程**：先向教师**口头说明一句**——「包内自带的《组织学习理论》是结构示范用的示例课，
 本次设置将以您自己的课程为准，不会动它」；然后问「您这学期要开什么课？（可一次报多门，我会逐门建库）」——
 取教师的**课程清单（支持多门）**，逐门生成**语义化 `course_id`**
 （小写英文 / 拼音 + 连字符，如 `my-course`；与 `sample-course` 区分）；
3. **注册课程条目**：把新课登记到云端 `course_versions` 表——
 `course_id` / `course_name` 用教师课程；课程资产（config / 知识库 / 题集 / 题库）
 统一建为**云端文档**、以 `tdoc:<file_id>` 形态登记进该表三路径列（教师改材料发版即生效，
 学生端经通道读最新，**不重打包**）。v2.0 起教师端不预置、不维护包内课程资产目录，
 **不写** `is_template`（那是示例课专属标记）；
4. **询问课程资料建设方式（必问，禁止默认跳过）**：明确问教师「课程资料打算怎么建？」，三选一：
 - **A. 现在就建**：教师当场上传 / 粘贴课程资料（讲义、大纲、知识点清单、题集等）→
 按示例课三件套的结构（`config.json` / `knowledge_hub.json` / `socratic_testset.md`）
 整理为云端文档并把定位登记进 `course_versions` 表三路径列，写完向教师逐项确认。
 **全书规模建库按 `references/course_content_build.md` 执行**（切分 → 并行抽取 →
 程序化复核 → 组装 → 交叉校验 → 抽检，含验收清单与「seq 重排全书一盘账」等硬规则）；
 教师如需测评题库可同流程增建 `quiz_bank.md`（第四件套，可选，见 §10.5）；
 - **B. 先占位、稍后替换**：复制示例课三件套作为结构骨架，教师稍后自行替换内容
 （第 8 步收尾建议中保留「替换课程资料」提醒）；
 - **C. 暂缓**：本轮只注册课程与建库，资料目录留空待补
 （第 8 步收尾建议中标注「课程资料未建」，提醒发布版本前必须补齐）。
 教师的选择决定第 8 步收尾建议的内容；**教师未明确表态前不许进入下一步**；
5. **建库**：转入 §2.0.3，逐课处理**本向导确认的课程清单**（不含示例课，除非教师明确要求）；
6. **播种课程版本**：在该课 Hub `course_versions` 表新建 1 行——「版本号」用当天日期（`YYYY-MM-DD`，
 过 §10.2.0 门禁）、「更新说明」填「首次建立」、「状态」= `draft`（发布时机由教师定，提醒：发布前学生端该课不可选）；
 「课程」列写 **JSON 字符串** `["<course_id>"]`（不变量 #10：文本列，不是原生数组）；
7. **播种伴学智能体**：在该课 Hub `agent_profiles` 表新建 1 行——
 「提示词」从本端母本 `references/socratic_agent_prompt.md` 整段读入
 （写入前先做分段写入验证，见 §10.1 对该列的告警）、
 「稳定锚点」填一个跨改名不变的标识（如 `socratic-companion`）；`状态=published` + `适用对象=all` +
 「课程」列写 **JSON 字符串** `[]`（跨课程通用；不变量 #10），并向教师说明该默认值可在 §10.1 随时调整；
8. **收尾（必问名册，不许只当建议甩出来）**：
 - **先播种测试号**：在该课 Hub `roster` 表写 1 行——「学号」= `0000`、「姓名」= `测试学生`、
 「课程」= 该课 course_id、「来源」= `测试`、「更新时间」= 当天（逐课 1 行；该课已有学号 0000 即跳过）。
 用途、验库路径与删除方式见 `roster_import.md`；**向教师说明：正式开课前建议删除该行**；
 - **再问名册**：「是否现在导入课程名册？如有 xlsx / xls / csv（首列『学号』、次列『姓名』，
 多课需含『课程』列；教务系统导出的 .xls 老格式也能解析）可直接上传」——教师现在导入 → 转入 §3 执行，导完继续下方收尾；
 稍后导入 → 记入下一步建议首位；
 - 再给下一步建议（按第 4 步所选资料建设方式动态生成）：
 「导入名册 → （A：— / B：替换课程资料 / C：补建课程资料）→ 发布课程版本」；
 然后回到 §2.0 第 2 步重做通道探测，通过即按 §0 输出引导语进入主菜单。

> 向导全程遵循 §1.3：定位 ID 只落盘、不回显。教师中途说「先不建了」→ 停在停止提示，不写任何数据。

**第 2 步——数据通道是否可用**（仅当第 1 步通过才继续）：通道由平台运行时注入，**必须显式探测**，
不允许「工具没有就静默本地运行」——否则教师会误以为名册/学情已同步，实则什么都没读写。

| 顺序 | 探测方式 | 判定方法 |
|---|---|---|
| **A（首选）** | 内置腾讯文档插件的 **Skill 形态**（当前主流） | **先定位脚本**：`~/.workbuddy/plugins/**/tencent-docs-plugin/**/skills/tencent-docs/tencentdocs.py`（取第一个存在的；企业版 OneID 场景为 `tencent-saas-docs`），**用绝对路径**跑环境自检：`python3 "${CODEBUDDY_PLUGIN_ROOT}/course_tdoc.py" "<绝对路径>" tdoc_init` → 输出 **`READY`** 即**已就绪**（这正是连接器「已连接」的实际判据）；`ERROR:no_token` 才是未授权。随后按 `tdoc_call` 调用（同样经封装），参数定义先查 `tdoc_schema`（Windows 解释器依次试 `python3` → `python` → `py -3`）。**所有 Skill 形态调用都必须经包根封装 `course_tdoc.py`，禁止裸调 `tencentdocs.py`**（裸调会绕开镜像兜底、踩到 502） |
| **B（次选）** | 腾讯文档连接器的 **MCP 工具形态** | 当前对话的可用工具清单里存在名称同时含 `tencent` 与 `smartsheet` 的工具（如 `mcp__tencent-docs__smartsheet.list_records`）。可先做只读探测：`list_records` 带 `limit=1` |

> `tencentdocs.py` 随**平台内置的腾讯文档插件**（`tencent-docs-plugin`）分发，**不由本包携带、也不由
> 「腾讯文档」连接器携带**——连接器只提供 MCP 端点。插件是内置的，装了 WorkBuddy 就有，与「本包自带与否」无关。
> 两形态共用同一套参数 JSON；只会有其中一种被注入当前会话，**任一命中即算通道可用**。
>
> [!] **探测返回「传输层超时」时，也算通道可用**：`list_records` 返回 `code:102` / `i/o timeout`
> 只说明**应答慢**，不说明 smartsheet 能力没被注入——**绝不得据此输出「未连接到数据中枢」**。
> 先按 §1.4「传输层超时处理」重试 / 换另一形态；**只有「工具根本不存在 / 找不到该方法」才判不可用**。
>
> [!] **通道「就绪但全 502」的处理（封装已默认绕过镜像，仅作高级诊断）**：本包所有 Skill 形态调用
> 已统一经 `course_tdoc.py`，该封装默认把请求指向腾讯文档权威端点 `https://docs.qq.com`，**绝大多数
> 镜像域名导致的 502 在封装层即被吸收**，正常调用无需手动加任何变量。仅当封装调用仍出现下列三条**同时**
> 成立时，才属站域问题、做高级诊断：① `tdoc_init` 返回 `READY`；② `smartsheet.*` 调用返回
> **502 / `Tunnel connection failed`**（**不是** 401/403，也不是超时 `102`）；③ 宿主下发的文档站 origin 在本机**不可达**。
> 此时开 `TDOC_DEBUG=1` 看 `api_base`，若仍被指到 `workbuddy.cn` 类镜像，临时用
> `TDOC_API_BASE_URL=https://docs.qq.com python3 "${CODEBUDDY_PLUGIN_ROOT}/course_tdoc.py" "<绝对路径>" tdoc_call tencent-docs <tool> '<json>'`
> 复测（封装会尊重该值、跳过默认覆盖）。仍不通过才判「通道不通」。**不得**在三条未同时成立时使用，
> **不得**把覆盖写入任何持久配置。

**判定与动作**：

- **A 或 B 任一可用** → 通过，进入 §2.1，随后按 §0 输出引导语；
- **两者都不可用** → **停在「待连接」状态**，并原样输出：

 > [!] **未连接到数据中枢，已停止（当前未同步）**
 >
 > 课程伴学专家需要通过**你自己的腾讯文档连接器**读写数据中枢，现在检测不到可用通道。请依次确认：
 > 1. 已在 WorkBuddy 连接你自己的「腾讯文档」连接器（设置 → 连接器 → 腾讯文档，用你自己的账号授权）；
 > 2. 数据中枢已建立且定位已写入 `data_hub_config.json`（尚未建立就说「帮我建数据中枢」，见 §2.0.3）；
 > 3. 当前会话确实暴露了 smartsheet 工具（连接器「已授权」≠「本会话可用」）。
 >
 > 在此之前**不会进行任何名册导入与学情读写**。


### 2.0.3 建立数据中枢（由我直接创建，无需脚本）

收到「帮我建数据中枢」，或「帮我重建<课程名>的数据中枢」（§2.0 部分缺失重建 / 单课修复，只处理该课），
或完成 §2.0.1 向导第 5 步后，**用教师已连接的腾讯文档连接器**完成，不走任何外部脚本。
逐课处理**本次确认的课程清单**——首次使用 = §2.0.1 向导中新建/确认的课程（**默认不含示例课**，
示例课仅在教师明确要求试跑时纳入）；非首次新增课程 = 该次在 `course_versions` 表新增的课程条目：

1. **确认建库位置（必问，禁止默认建在个人首页）**：先问教师「Hub / Usage 两个智能表建在哪里？」——
 - **（推荐）知识库空间**：若当前会话支持枚举空间 / 目录（腾讯文档连接器的空间列表、目录节点类能力），
 列出可选空间让教师挑选——**已存在与课程同名的空间时默认选中它**；
 需要新建空间时，**空间名默认用课程名**（教师可当场改），然后**在该空间内**创建两个文件；
 - **个人首页**：仅当教师明确表示「就放我的个人文档」时才使用默认落位。
 创建完成后**回读核验落位**（确认文件确实位于所选空间 / 目录），并把实际落位（空间名）告知教师；
 发现落位不符 → 立即在正确位置重建并提醒教师清理误建文件；
2. **建 Hub 文件**：新建智能表文件（命名如「课程伴学-Hub-<课程名>」），在其下建 3 张子表——
 `roster` / `course_versions` / `agent_profiles`（列清单见 §1.4 / 学生端 data_plane.md §0.3（随学生包分发））；
3. **建 Usage 文件**：新建智能表文件（命名如「课程伴学-Usage-<课程名>」），在其下建 2 张子表——
 `usage` / `summaries`（含「智能体」列，同上）；
4. **清理默认空表「智能表1」（建完命名表必做）**：新建智能表文件会自动生成一张**无列定义**的默认子表
 「智能表1」——连接器**不支持重命名子表**（会报 `40037`），因此**不做改名**，规范做法是**删除**：
 删除前必须先读取该表**确认其为空**（防误删有数据的表）；若非空 → **不删**，向教师报告并请示处理方式。
 Hub 与 Usage 两个文件都要清；「某课文件已存在、只补缺失子表」的续建路径同样检查并清理；
5. **共享权限（走知识库空间，不依赖指定学生账号）**：两个文件都建在选定空间内，共享随空间完成——
 - **邀请成员**：通过空间的「成员管理 → 邀请成员」把学生加入空间（名册导入后可按名单补邀，做精细化控制）；
 - **空间权限**：也可打开空间权限「所有人可编辑」——**首次建库还没有学生账号时不阻塞**，名册导入后再邀请成员收紧；
 - **可见性口径（平台行为，向教师说明）**：学生追加自己的学情行时**仅自己可见**，同学之间互相不可见
 （空间无法做行级「隐藏」配置，也无须做），**教师全部可见**；
 - **开启「所有人可编辑」前须向教师核对的代价**：空间权限通常对空间内文件整体生效，
 Hub（名册 / 课程版本）可能连带可编辑——请教师开启前自行核验继承范围；
 若不可接受，改用「邀请成员」方式按需分配权限；
6. **回写定位**：把两个文件的 `file_id` 与 5 张子表的 `sheet_id` 按 v2 按课分组写入本包
 `data_hub_config.json` 的 `courses.<course_id>` 条目（定位 ID **只落盘、不回显**）；

> [!] **回写定位的落点只有一处：包根 `data_hub_config.json`（教师端权威）**
> 教师端判「数据中枢定位缺失」只看它；写完立即回读校验 `courses` 中该课条目
> 的 `hub_file_id` / `usage_file_id` 已就位。
> 学生端是独立分发的另一个包，不在本端回写范围内——学生端不内嵌定位，
> 靠运行期自动发现课程中枢取得定位（见下一条注记）。
7. 建库完成 → 回到调用方流程（§2.0.1 向导第 6 步播种，或 §2.0 第 2 步通道探测）。

> [!] **重建 / 迁移后：学生端不用重新打包，但包根定位必须同步（云端化后已变更）**
> 学生端**不内嵌定位**——靠 `discover_hub.py` 的空间遍历**自动发现**课程中枢，
> 所以 `file_id` / `sheet_id` 变化后，学生下次启动会重新发现并覆盖自己的
> `data_hub_config.json`，**不需要重新打包，也不需要学生重装**（不要再提醒教师「重新打包下发」）。
> 但**包根 `data_hub_config.json`（教师端权威）必须同步更新**——教师端读的是它，
> 漏写就会判该课「数据中枢定位缺失」而不可用（见上一条）。

> **存量迁移（老用户的中枢已建在个人首页）**：教师说「把数据中枢移到知识库空间」→
> 用连接器的移动文件能力（`move_file_to_space` 类）把 Hub / Usage 两文件移入教师指定空间
> （空间名默认课程名）——**file_id 不变、定位无需回写**；迁移后检查各文件子表现状
> （含「智能表1」是否仍按第 4 步清理规范处理），并按需提醒共享走空间成员 / 空间权限（第 5 步）。

> 建表工具以当前会话注入的 smartsheet 能力为准（创建文件 / 新增子表 / 定义列 / 删除子表之类均可）；
> 列均为文本列，写值时一律按文本发送。若某课 Hub 已存在，则跳过建文件、只补缺失子表并回写定位。
> 已知边界：**不支持重命名子表**（会报 `40037`）——凡涉及「改名」需求一律用「新建命名表 + 删除旧空表」替代。

### 2.0.6 校历录入与学习周次（功能十一）

教师说「录入校历」或「导入校历」时，依下列流程在 Hub 文件新建 `calendar` 子表（配置键
`hub_sheets.calendar`），并同步在 `term_config` 子表（配置键 `hub_sheets.term_config`）写入学期参数与预警阈值。

**1. 采集学期参数（多轮澄清）**
- `term_start`：学期第一周周一（ISO 日期，如 `2026-09-07`）；
- `total_weeks`：教学周总数（如 `18`）；
- `required_hours_per_week`：周建议学时（小时，预警用，默认 `3.0`）；
- `required_hours_per_course`：总建议学时（小时，默认 `54.0`）；
- 预警阈值：`warn_idle_days`（默认 `7`）、`warn_deficit_ratio`（默认 `0.7`）、`warn_enabled`（默认 `true`）。

**2. 两种录入通道**
- **对话式**：采集节假日区间 / 考试周后，自动按周展开生成 `calendar` 子表草稿（每周一行：
 `week_no` / `week_start` / `week_end` / `week_type`∈{教学,假期,考试,补课,实践} / `study_days` / `note`），
 请教师确认后回写 Hub；
- **结构化**：教师粘贴校历 CSV（列含 `week_no,week_start,week_end,week_type,study_days,note`）→
 复用既有读表能力解析为 `calendar` 子表。

**3. 补打教学周（录入即触发）**
- 用包根 `course_calendar.py` 把历史 `usage` 记录按 `时间` 映射到 `teach_week`（`学期-Wn`，如 `2026-秋-W3`），
 批量回写 `usage` 表的 `teach_week` 列；
- 未录入校历时 `teach_week` 回退 ISO 周（`2026-W39`）并标注「未对齐校历」，报告 / 预警降级提示，**不阻断**。

**4. 周状态判定（按生 / 按班）**
- 由 `course_calendar.py` 的 `week_status` 计算：正常 / 滞后 / 缺勤 / 假期 / 考试周 / 非教学周；
 口径见 `references/glossary.md` 与 `course_calendar.py` 文件头注释。未配置 `term_config` 时预警与报告降级，不报错。

> 校历与学期参数是「周次口径统一」与「学生端预警」的前提；教师首次设置向导应提示「校历是否就绪」，
> 未就绪则功能降级提示，不阻断建库。
