# 任务积分与游戏化

> 本文件是 `agents/course-tutor.md` 中「§4.7 任务积分与游戏化」的**外置细则**。
> 执行 §4.7 任何操作前，必须先 Read 本文件；未读不得动手（不得凭记忆算分 / 写表）。
> 聚合 JSON 口径与 `references/data_viz.md` 的「聚合 JSON 口径」一节**共用同一份**，先读那里再回来看本文件。

## 1. 设计原则

- **正向激励、与平时分解耦**：积分是游戏化激励层，平时分（§5）是学业评价层，两套口径互不污染。
- **不惩罚**：任何「卡住 / 未收敛」都不扣分，只在预警与看板中单列，引导补练。
- **学生端可见自身积分**：学生本地会话摘要即可算分（与 `course_warn.py` 同口径），不依赖中枢写权限。

## 2. 积分口径

```
points = 10 × 收敛KP数
 + 4 × 部分KP数
 + 2 × 伴学会话数
 + 1 × 覆盖知识点数（kp_distinct）
 + 奖励加分（bonus，由教师酌情发放，如主动讲解、答疑问）
```

- 卡住（stuck）计 0 分，不进入积分公式，只在看板/预警单列。
- 字段名（聚合 JSON 内每个学生的对象）：
 - `converged` 收敛KP数、`partial` 部分KP数、`sessions` 伴学会话数、
 `kp_distinct`/`kp_records` 覆盖知识点数、`bonus` 奖励加分（缺省 0）。
- 公式由 `course_points.py` 的 `compute` 实现，单一事实来源，**不要自写公式**。

## 3. 期末排名与奖励

### 3.0 教师端取数（学情本来就在腾讯文档里，直接算）

**不需要任何手工准备**——学情一直写在数据中枢的 Usage 表里，按§4.3 三段式读出来直接喂脚本：

1. 按 §1.1 定位 → 选定 `course_id` → 取 `usage_file_id` + `usage_sheet.usage`；
2. 经数据通道（`course_tdoc.py` 走 Skill 形态，或 MCP `smartsheet` 工具形态）读该课学情全部记录；
3. 先过 §4.2 **聚合前过滤**（测试号 `0000` / 空学号 / 教师端行剔除）；
4. 把读到的记录原样存为 CSV（列：`学号,姓名,时间,知识点,结果,环节`——**环节列必带**，
 缺它时题目生成记录会被按 KP 收敛证据计（旧口径），积分虚高）或直接构造 JSON；
5. 调下列命令出排行榜。

> 学生端只要写过学情，这里立刻就能算出**历史累积积分**——不需要学生重新做任何事。

### 3.1 方式一（推荐）：直接读取 Usage 导出的原始 CSV

**不需要手工拼 JSON**——把该课 Usage 表的学情（`usage`）导出为 CSV 后直接算：

```bash
python3 "${CODEBUDDY_PLUGIN_ROOT}/course_points.py" --from-csv <学情.csv> --course "<课程>"
```

- 期望列（中文或英文表头均可，缺列则该指标按 0 计并**打印提示**，**不编造**）：
 `学号 / 姓名 / 时间 / 知识点 / 结果`；
- 自动按 §4.1 口径聚合：`sessions`=去重(学号,时间)、`converged/partial/stuck`=按「结果」列计数、
 `kp_distinct`=去重知识点数；
- **测试号 `0000` 默认剔除**（与 §4.2 聚合前过滤一致），要保留加 `--include-test`；
- 无可用数据时**明确提示**「学生可能尚未写入记录，或全部行被过滤剔除」——**不静默返回空榜**。

### 3.2 方式二：已聚合好的 JSON

```bash
python3 "${CODEBUDDY_PLUGIN_ROOT}/course_points.py" <聚合json> --course "<课程>"
```

### 3.3 通用参数

- `--top-n 3`：只输出前三名奖励名单（发奖 / 公示用）；
- `--out <路径>`：写出排行榜 JSON；
- 输出含排名、积分、前三名「🏆 奖励」标注；
- 看板（`course_viz.py`）可叠加排行榜表，与学生收敛分布同屏展示。

## 4. 回写（可选）

- 排行榜可写入 `usage_sheet.points` 子表（前提是 §2.0.1 已建该子表）。
- **未建则不写**，仅本地展示，不影响排名与奖励判定。
- 写前遵守 §1.5 写纪律（写前读现状· 写前留档 · 恢复先确认）。

## 5. 学生端积分可见性（已实现， 学生侧）

- 学生端会按**同一口径**自行计算并在会话收尾展示本人积分（教师端只需保证本文档口径，不必关心学生端实现）；
- 展示只含**本人**积分明细与排名，**绝不**显示他人明细；
- **班级排名的来源**：① 教师排行榜写回 `usage_sheet.points` 子表后，学生**只读自己那一行**；
 ② 未写回时显示「班级排名由教师统计或期末发布」——**两种情形都不编造**；
- 学生端的展示细则不随教师端分发；**两端口径以本文档为准**——口径不一致会导致学生看到的分数
 与教师端统计对不上，改本文档即同步两侧。
