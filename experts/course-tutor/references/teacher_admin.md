# 课程伴学专家 · 参考细则（teacher_admin.md）

> 本文件由 `agents/course-tutor.md` 按无损分片拆出，**内容与原 SKILL 逐字一致**。
> 引用方式：`${CODEBUDDY_PLUGIN_ROOT}/references/teacher_admin.md`。

### 10.1 维护伴学智能体属性（名称 / 头像 / 花名）

**数据源**：Hub 文件的 `agent_profiles` 表（配置键 `hub_sheets.agent_profile`）。

| 列标题（逻辑字段） | 含义 | 学生端表现 |
|---|---|---|
| 名称（`name`） | 智能体**名称** | 选型列表展示为「{{名称}}（{{花名}}）」 |
| 头像（`avatar`） | 智能体**头像**（emoji 等） | 同上；**本列不在学生端展示（不显示 emoji）**——选型与对话只用名称+花名标识。周报如启用智能体统计仍可取用，但建议留空或避免 emoji，以免跨客户端显示不一致 |
| 花名（`nickname`） | 智能体**花名** | 同上 |
| 简介（`description`） | 智能体简介 | 选型时的说明文案 |
| 提示词（`system_prompt`） | 伴学规则（即 `socratic_agent_prompt.md` 的线上版） | 学生端选型后直接以此开启伴学 |
| 状态（`status`） | `draft` / `published` / `gray` | `published` 或（合规的）`gray` 才对学生可见 |
| 课程（`courses`） | 限定课程的 course_id 数组（JSON 字符串） | 空数组 `[]` = **跨课程通用**；含某 course_id = 该课专用 |

> [!] **口径铁律**：`name` / `avatar` / `nickname` 是「伴学智能体」的属性，**不是教师或学生自己的身份**。
> 教师在本表改的是「某个智能体叫什么、长什么样」，不是给自己或学生换头像。学生端只读展示、不修改。
>
> **默认跨课程人设（播种基准）**：本包默认一个跨课程通用人设——`agent-companion-default`（名称 课程伴学精灵，花名 耘知），`课程=[]`、对所有课程可见。可选人设功能已取消，不再播种第二人设；增删改都在中心端 `agent_profiles` 完成，无注册表播种。

**定位要改的那一行**（`list_records` 读回后在本地匹配，禁止凭 `id` 猜）：
1. 首选**稳定锚点**列（`source_key`——跨改名不变的标识，播种时按 §2.0.1 第 7 步填入）；
2. 都命中不了 → 把读到的智能体列表展示给教师，由教师**指认**要改哪一个，**不猜**。

**一次调用改多个属性**（把要改的字段都列进 `field_values`）：

```json
// smartsheet.update_records —— 例：改名「思辨向导」、头像 、花名「南舟」，并限定到 sample-course
{
 "file_id": "<当前课程条目 hub_file_id>",
 "sheet_id": "<当前课程条目 hub_sheets.agent_profile>",
 "records": [
 {
 "record_id": "<record_id>",
 "field_values": [
 { "field": "名称", "text_value": { "items": [ { "text": "思辨向导", "type": "text" } ] } },
 { "field": "头像", "text_value": { "items": [ { "text": "", "type": "text" } ] } },
 { "field": "花名", "text_value": { "items": [ { "text": "南舟", "type": "text" } ] } },
 { "field": "简介", "text_value": { "items": [ { "text": "苏格拉底式提问，先问后引", "type": "text" } ] } },
 { "field": "课程", "text_value": { "items": [ { "text": "[\"sample-course\"]", "type": "text" } ] } },
 { "field": "状态", "text_value": { "items": [ { "text": "published", "type": "text" } ] } },
 { "field": "适用对象", "text_value": { "items": [ { "text": "all", "type": "text" } ] } }
 ]
 }
 ]
}
```

**权威源划分**——重跑建库脚本时哪些改动会被覆盖，以此为准：

- `name` / `avatar` / `nickname` / `description` 属**教师个性化配置**，权威源是**本表**——
 脚本只在**首次建行**时播种，此后**不再回写**（教师的编辑不会被脚本冲掉）；
- `system_prompt` 属**版本化资产**，权威源是本包随附的课程资产，脚本**每次运行都会推上线**——
 改提示词请改 `references/socratic_agent_prompt.md` 后重跑脚本，不要只在线上表改；
- `status` / `target_audience` / `courses` 属**教师运营态**，脚本无权回写，仅新建行写默认值；
 脚本的补发布分支**只补 `draft` 状态的行**、且不覆盖 `target_audience`——按本节设好的灰度状态，
 重跑脚本不会被清空。

> [!] **改 `system_prompt` 要格外谨慎**：它是智能体的「大脑」，**写空会让伴学行为静默失效且不报错**。
> 改前先读回原值留档，改后提醒教师让学生端重启一次会话验证。它是长文本列，
> **写入一律分段验证**：先写一小段确认可写，再整体覆盖——不假设单次能写满。
>
> 表内还有 `角色` / `默认头像` / `默认花名` / `可选头像` / `可选花名` 等列，**本包不使用，一律留空**——
> 不要向教师承诺「可选的头像/花名池」等本包未实现的功能。

> [!] **要让某个智能体对学生不可见，用 `gray` + `target_audience=gray_list` + 空名单，不要用 `draft`**：
> - `draft` 在建库脚本眼里是「上次发布失败的残留」，重跑脚本时会被**补发布为 `published`**；
> - `gray` 才是教师主动设置的灰度态，属教师运营态，脚本无权覆盖；
> - 「对全体隐藏」的正确写法是三字段一起写：`状态=gray` + `适用对象=gray_list` + `灰度名单=[]`（空名单恒无人命中）；
> - **只写 `状态=gray` 而 `适用对象` 仍是 `all` 的话，结果是全体可见，不是隐藏**；
> - **用之前先知道学生会看到什么**：被排除的学生会看到「该课程暂无已发布智能体，请联系老师」并无法进入伴学——
> 这句话对他是**假的**（智能体存在且已发布，只是没覆盖他），且会把矛头指向教师。
> 因此此技巧**只适合「暂不开放、且已告知学生」的场景**，不要当作无声的隐藏手段。
> - 学生反馈「暂无已发布智能体」但教师确认已发布时，**先查灰度**：大概率是该生不在名单内。


### 10.2 发布 / 灰度课程版本

**数据源**：Hub 文件的 `course_versions` 表（配置键 `hub_sheets.course_ver`）。

#### 10.2.0 写入前校验：版本号必填且须为 `YYYY-MM-DD`

**这是写入前的硬门禁**——新建版本行、发布、灰度**之前都要先过**。不满足就**停下来向教师指出
具体哪里不合规，请其修正后重试，不要写表**。

**格式**：四位年-两位月-两位日，连字符分隔（`^\d{4}-\d{2}-\d{2}$`），且必须是**真实存在的日期**。

| | 示例 | 判定 |
|---|---|---|
| [OK] 正确 | `2026-08-29` | 标准格式（与 Hub `course_versions` 表「版本号」列同口径） |
| [X] 错误 | `v1.2` | 带前缀，不是日期 |
| [X] 错误 | `2026.08.29` | 分隔符不是连字符 |
| [X] 错误 | `2026-8-9` | 月 / 日未补零 |
| [X] 错误 | `2026-02-30` | 日期不存在 |
| [X] 错误 | `final` / `latest` / **留空** | 非日期 / 必填项为空 |

> **为什么必须卡格式**：「版本号」是文本列，版本新旧靠**字符串比较**判定——学生端按
> 「线上版本号 > 包内版本号」决定是否提示切换。格式不统一，比较结果就不可预期。
> **版本号必填**：教师没提供时主动询问（建议用当天日期），**不要**自行填默认值蒙混写表。
> **已知边界**：腾讯文档为文本列，**服务端不校验**任何格式；本门禁是**唯一防线**，由写入侧（本端）守护。
> **同日重复发布的坑**：版本号 = 日期，同一天修订内容后再发布，版本号不变——学生端
> 「线上版本号 > 包内版本号」比较**不触发**更新提示。同日修订请**在「更新说明」里写清改动**，学生端仍会在开场播报该版本更新说明。
> 另注：若建库 / 播种动作绕过本端直接写表，则不经过本门禁——
> 直接改 `course_versions` 表「版本号」列时，格式由改的人自己保证。

#### 10.2.1 发布 = 成对写 `状态` + `适用对象`

`状态` 取值：`draft` / `published` / `gray`（`draft` 为建库默认值）。

> [!] 约定口径：`状态 = "published" if 适用对象 in ("all", "force_update") else "gray"`。
> 因此「正式发布」应**同时**写 `状态=published` + `适用对象=all`；只改一个会留下自相矛盾的行。

```json
// smartsheet.update_records —— 例：发布某课程版本
{
 "file_id": "<当前课程条目 hub_file_id>",
 "sheet_id": "<当前课程条目 hub_sheets.course_ver>",
 "records": [
 {
 "record_id": "<record_id>",
 "field_values": [
 { "field": "状态", "text_value": { "items": [ { "text": "published", "type": "text" } ] } },
 { "field": "适用对象", "text_value": { "items": [ { "text": "all", "type": "text" } ] } }
 ]
 }
 ]
}
```

> [!] **课程版本未发布 → 学生端该课不可选**。发布课程版本是学生能用这门课的前提，不是可选项。
>
> **发布后必须回读验证**：`update_records` 成功后**再 `list_records` 回读该行**，确认
> `状态=published` 且 `适用对象=all` 已实际落表——「写入返回成功」≠「表里已是对的」，回读通过才算发布完成。

#### 10.2.2 灰度 = 写 `适用对象` + `灰度名单`

| `适用对象` | 含义 |
|---|---|
| `all` | 全体可见（正式发布） |
| `gray_list` | 仅名单内 sid 可见—— **课程版本上当前不生效，见下方说明** |
| `force_update` | 全体可见且强制（绕过灰度） |

`灰度名单` 是 **sid 列表的 JSON 字符串**（如 `["2024001", "2024002"]`），空串/缺失按 `[]` 处理。

> **课程版本的灰度名单当前不生效——不要用它做教学隔离**：
> 学生端判定课程版本可见性时**只校验 `状态 ∈ {"published", "gray"}`**，**不读 `适用对象`、也不读 `灰度名单`**。
> 设好名单后，名单外的学生**照样能看到并使用该课程版本**，没有任何报错。
> （对比：**智能体**的灰度是完整生效的，见 §10.1。）修复前，课程版本灰度只能当「标记」用，不能当「隔离」用。
>
> **现在不要随手把 `适用对象` 设成 `gray_list`**——它当前不产生任何效果，但一旦学生端开始消费，
> `灰度名单` 会**静默转活**：测试名单、上一届名单都会当场变成真实的隔离名单；
> **若名单恰好为空，则全体学生都看不到该版本**。教师暂不需要灰度时，让 **`适用对象` 保持 `all`**——
> 此时名单无论空或非空都不产生任何效果；**不要**在 `适用对象=gray_list` 的状态下留空名单。
>
> **要让某个课程版本对学生不可见，唯一手段是 `状态=draft`**——课程版本上 `gray` **一律不限制可见性**
> （与学生端选课判定完全不读灰度字段，两者不可类比，勿套用 §10.1 的结论）。`draft` 的可靠边界：
> - **教师自建课程**（registry 中 `is_template` 不为 true 的条目）：建库脚本**不会接管**这些版本行，`draft` 稳定保持；
> - **示例课 `sample-course`**（`is_template=true`）：其版本行会被脚本按 `(课程, 版本号)` 幂等键收养
> （不过滤创建者），且 `draft` 状态的行会被**补发布为 `published`** 并推给全体学生。
> 对策：想让课程版本保持隐藏，不要让它的 `(课程, 版本号)` 与 `course_versions` 表中的示例课条目撞车；
> 或重跑建库脚本后复查该行的状态。
>
> **灰度属教师运营态**：`状态` / `适用对象` / `灰度名单` 的权威源是**线上表**，建库脚本无权回写——
> 仅在**新建行**时写默认值（`all` / `[]`）。按本节设好的灰度，重跑脚本不会被清空。

```json
// smartsheet.update_records —— 例：按约定口径写「灰度」三字段
// [!] 灰度名单当前不被学生端消费，名单不会产生隔离效果（见上方）
{
 "file_id": "<当前课程条目 hub_file_id>",
 "sheet_id": "<当前课程条目 hub_sheets.course_ver>",
 "records": [
 {
 "record_id": "<record_id>",
 "field_values": [
 { "field": "状态", "text_value": { "items": [ { "text": "gray", "type": "text" } ] } },
 { "field": "适用对象", "text_value": { "items": [ { "text": "gray_list", "type": "text" } ] } },
 { "field": "灰度名单", "text_value": { "items": [ { "text": "[\"2024001\", \"2024002\"]", "type": "text" } ] } }
 ]
 }
 ]
}
```

#### 10.2.3 联网补充开关 = 写 `运行开关` 列

`运行开关` 是**开关容器**，值为单行 JSON 字符串，键 `allow_web_supplement`，取值 `false` / `ask` / `true`
（**默认 `false`**，建库脚本写入的默认值即 `{"allow_web_supplement": "false"}`）。

| 取值 | 学生端行为 |
|---|---|
| `false`（**默认**；含缺失 / 空值 / 非法值） | **禁止**联网补充 |
| `ask` | 允许，但**每次**触发前都要学生确认 |
| `true` | 允许，每会话首次触发前确认一次 |

```json
// smartsheet.update_records —— 例：把联网补充改为「每次询问」
{
 "file_id": "<当前课程条目 hub_file_id>",
 "sheet_id": "<当前课程条目 hub_sheets.course_ver>",
 "records": [
 {
 "record_id": "<record_id>",
 "field_values": [
 { "field": "运行开关", "text_value": { "items": [ { "text": "{\"allow_web_supplement\": \"ask\"}", "type": "text" } ] } }
 ]
 }
 ]
}
```

> [!] **值必须是完整 JSON 容器，不能写 `on` / `true` 这类裸值**。裸值属**非法值** →
> 学生端按 `false` 处理，教师以为「已经打开联网检索」，实际一直是关闭的。
> 写入前请对照本节 JSON 写法，键名恒为 `allow_web_supplement`。
>
> [!] `运行开关` 是**整列覆盖**（不是按 JSON 键 merge）。改写时必须带上原有其他键，
> 否则会静默抹掉教师此前配置的其他开关——**改前先读回原值**。
> 配置缺失或为空的旧版中枢，学生端会回退读 `agent_profiles` 表该智能体 `提示词` 顶部指令块的
> `allow_web_supplement`；两者并存时**取更严格者**（false > ask > true）。
> `运行开关` 同属教师运营态：建库脚本重跑**不回退**已存在行的该列，仅**新建行**写默认值。


### 10.3b 课程资产上云（让教师改材料不必重打包）

> **为什么需要**：在资产上云之前，每门课的材料（`config.json` / `knowledge_hub.json` /
> `socratic_testset.md` / `quiz_bank.md`）**只存在于内嵌定位学生包里**，教师改一次材料就得重打一次学生包。
> 上云后材料放腾讯文档，教师改完发版即可，**学生下次会话自动拿到最新**——彻底免去打包分发。

**前置**：该课已建库（§2.0.3），Hub `course_versions` 表可写。

**步骤**（按课逐个迁移，互不影响）：

1. **上传资产到腾讯文档**：把该课 4 个资产文件传为腾讯文档（建议放同一**知识库空间**，
 便于统一共享给学生只读）。取每份的文档定位（`file_id` 或文档链接）。
2. **登记到 `course_versions`**：把「配置路径 / 知识库路径 / 题集路径」三列改写为**云端定位**，
 统一写成 `tdoc:<file_id>` 形态（`quiz_bank.md` 若原来无路径列，可新增一列「题库路径」登记）。
3. **发布课程版本**：走 §10.2，把新版本置为 `published`（`status`）。
4. **验证**：让学生端重开会话（或教师端自查），确认读到的是云端新内容。

**读取端行为**（学生端 `course_assets.md` §8.1 已实现双判别）：
- 路径是 `tdoc:<file_id>` / 文档链接 → **走腾讯文档通道读云端最新版**；
- 路径是包内相对路径 → 仍读包内（**旧行为，向后兼容**，未迁移的课不受影响）；
- 云端读不到 → 回退包内相对路径形态再读（学生端旧行为，向后兼容）→ 再读不到 → **如实回报该资产缺失，不静默跳过**——不另设注册表兜底，缺失即如实回报。

**迁移注意**：
- **逐课迁移**，不要一次全改——混合形态期间两套读取都工作，不影响任何一课；
- 迁移后仍可**保留包内资产做兜底**（不删），云端临时不可达时学生仍能学；
- 真实 `file_id` 只写入 Hub 的 `course_versions` 表（教师侧），**不要**写进学生包配置；
- 云端定位按 §1.3 铁律**不进对话、不进日志**。

> **迁移完成后的收尾（本期不做）**：全部课程都上云后，可摘掉 `course_assets.md` §8.1 的
> 包内路径兜底分支与 `registry` 兜底。当前保留，保证任何迁移比例下都不崩。


### 10.5 出题 / 组卷（细目表驱动 + 热点情境）

**细则见 `references/exam_generation.md`**（细目表解析规范、程序化校验清单、热点纪律）。简版：

- **触发**：教师说「出题 / 组卷 / 按细目表出卷」并附**命题双向细目表**（docx / xlsx / 口述均可）；
- **细目表解析**：矩阵行 = 知识章节、列 = 能力层次（认识 / 理解 / 应用 / 分析 / 综合）、
 格 = 题型 + 题量 + 分值（docx 合并单元格先规范化再读，规范见细则文档 §1）；
- **素材**：优先复用该课 `quiz_bank.md` 已有题；不足再新编——新编题的考点必须在
 `config.json` KP 清单内（**超纲知识点不进卷**），难度对齐细目表能力层次
 （认识/理解 → 选择/判断/名词解释，应用/分析 → 简答/情境判定，综合 → 案例/论述）；
- **热点情境协同（新编情境题必做）**：用网络搜索引入**近 6-12 个月**真实热点 / 企业案例做题干
 情境，让卷子考「应用」而不是「背诵」；纪律：①热点必须与考点 KP 挂钩，不能为热点而热点；
 ②事实保真——引用的数字 / 时间 / 主体一律经搜索核实（如灯塔工厂中国占比「接近六成」即失实，
 实为约 42%，截至 2025-09 全球 201 座中中国 85 座，来源：世界经济论坛 / 麦肯锡「全球灯塔网络」名单【实测】），核实不到的数字不写；③题干末尾标注来源（同学生端 §2.1 固定模板格式）；
 ④搜索结果不入学生库、不写任何智能表；
- **程序化校验（交付前必过）**：逐格核对题量、题型与细目表一致；分值合计 = 细目表合计（通常 100 分）；
 考点全部可追溯至 KP；附答案与评分要点；校验不过 → 修复后重出，**不得交付未过校验的卷**；
- **产出**：试卷（含答案与评分要点）本地生成 docx / markdown 交付教师；细目表对照表一并列出
 （每格：要求 vs 实际）；试卷**不写入**任何智能表、不进学生端（除非教师明确要求把部分题并入 `quiz_bank.md`，
 那属题库更新 → 更新后发版即生效，学生端自动同步）。

> **与「学生自己出题」的关系**：学生说「出几道题考考我」时，学生端**从同一份 `quiz_bank.md` 抽题**，
> **出题即附全部答案**（复习材料，学生先作答不是必须的，见本包 `references/socratic_agent_prompt.md` §3.2）。
> 所以**你录入题库的题，就是学生能抽到的题**——题库决定学生的复习面。
> 组卷新编的题若要进学生抽题池，必须先并入 `quiz_bank.md`（已上云的课程发版即生效，学生端自动同步）。

### 10.6 整库数据导出备份（本地存档，防误删 / 误改）

**用途**：把每门课在腾讯文档里的**全部子表导出到本机本地备份**——云端误删 / 误改 / 账号异常时可回装。导出分「连接器读取 + 本地归档」两步；本脚本**不直接持有任何凭据、也不调用连接器**，读取由主理人经 `smartsheet.list_records` 完成。

**导出（教师说「备份 / 导出备份 / 整库备份」即触发）**：

1. 按 §1.1 取本包根 `data_hub_config.json`（真实定位）。对**每门课、每张子表**读出记录：
 - Hub 文件 5 张：`roster` / `course_versions` / `agent_profile` / `calendar` / `term_config`
 - Usage 文件 3 张：`usage` / `summaries` / `report`
 - 用 `smartsheet.list_records` 分页（`limit` / `offset` 拉全），各存为临时文件 `<课程>__<子表>.json`
 （课程 id 用连字符、不含下划线，`__` 为切分符；如 `sample-course__roster.json`）。
2. 调用包根归档器（自动产出时间戳备份目录：每课每表 `json` + `csv`、`manifest.json`、配置快照，并打印 `BACKUP_DIR=...` 与表数 / 行数）：
 ```bash
 python3 "${CODEBUDDY_PLUGIN_ROOT}/scripts/backup_data_hub.py" assemble \
 --src <临时目录> \
 --dest <备份根，默认 ~/.workbuddy/course-tutor/backups> \
 --config "${CODEBUDDY_PLUGIN_ROOT}/data_hub_config.json" \
 --label <可选，如 期中前>
 ```
3. 把 `BACKUP_DIR` 与摘要转述给教师。列出历史备份：`... backup_data_hub.py list`。

**回装（谨慎，非幂等）**：教师明确要恢复某备份时——
- 先 `restore --plan <备份目录>` 产出回装载荷（按配置快照把 `(课程,子表)` 映射到 `file_id` + `sheet_id`）；
- 按 §1.5「恢复先确认」**逐表向教师确认**，再经 `smartsheet.add_records` 写回；
- **切勿盲目覆盖线上数据**，也不读包内任何脚本执行。

> **隐私**：备份落在本机教师自己目录，仅含该教师自己课程数据；不向外传输、不写任何智能表。

### 10.6b 课程结课归档（学期结束一键打包：材料 + 学情 + 分析结果）

> **与 §10.6 的分工**：§10.6 是「**防误删**」的整库备份（用于**回装**）；
> 本节是「**学期留档**」的按课程归档（用于**存档 / 交接 / 分析 / 论文引用**）——**目的不同，别混用**。
>教师说「学期结束了 / 结课 / 归档这门课 / 把材料和学生数据打包下载」即触发本节。

**产出**：一个按课程命名的 zip，含 `materials/`（课程材料）+ `tables/`（学情/名册，json+csv）+
`analysis/`（积分榜/看板数据/周报）+ `manifest.json`（清单与统计）+ 可选 `pending_close.json`（结课待写回）。

**步骤**（读取由主理人经连接器完成，脚本只负责归档与打包）：

1. **读该课材料**：按 `course_versions` 三路径列解析——**云端定位**（`tdoc:<file_id>`，见 §10.3b）
 经通道读最新内容；**包内路径**形态只出现在学生端运行语境，教师端不涉及——教师端材料一律云端定位。
 把读到的内容存成 `materials__<course_id>/**`（保留原相对结构）。
2. **读该课子表**：按 §1.1 取 `usage_file_id` / `hub_file_id`，读该课
 `roster` / `usage` / `summaries`（以及有则读 `course_versions`），
 各存为 `<course_id>__<子表>.json`。
3. **产出分析结果**（可选但推荐）：
 - 积分榜：`course_points.py --from-csv <usage.csv> --out analysis__<course_id>__points.json`；
 - 看板/周报：把 §4/§6 生成的 markdown、CSV 一并存为 `analysis__<course_id>__<名称>`。
4. **打包**：
 ```bash
 python3 "${CODEBUDDY_PLUGIN_ROOT}/scripts/course_archive.py" \
 --course "<课程名>" --course-id "<course_id>" --src <临时目录> \
 [--close-course --close-note "<结课说明>"]
 ```
 先用 `--dry-run` 让教师确认将打包什么，再正式执行；产出目录与 zip 路径打印 `ARCHIVE_DIR` / `ARCHIVE_ZIP`。
5. **结课状态写回**（`--close-course`）：脚本**不碰云端**，只产出 `pending_close.json`；
 主理人**向教师确认后**经连接器把 `course_versions` 该课 `状态` 改为 `closed`。

> **注意**：结课只是把课程版本置为 `closed` 使其**不再对学生可见**（§8 铁律：
> 隐藏课程版本的唯一手段是 `状态=draft`，`closed` 语义为「已结课归档」）。
> **不要**用 `closed` 代替 `draft` 做隐藏，也**不要**承诺灰度名单外的可见性。

**结果转述**：把 zip 路径、清单统计（材料数/子表数/总行数/分析结果数）告诉教师，
并提醒「材料已上云的课程，归档的是**云端最新版**；未上云的是包内版本」。

> **隐私**：归档落在本机教师自己目录（`~/.workbuddy/course-tutor/archives/`），
> 含**学生姓名与学号**——提醒教师妥善保管、勿外发；定位 ID 不进包（§1.3）。
