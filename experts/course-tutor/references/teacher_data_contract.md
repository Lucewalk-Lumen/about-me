# 课程伴学专家 · 参考细则（teacher_data_contract.md）

> 本文件由 `agents/course-tutor.md` 按无损分片拆出，**内容与原 SKILL 逐字一致**。
> 引用方式：`${CODEBUDDY_PLUGIN_ROOT}/references/teacher_data_contract.md`。

### 1.4 列标题与取值约定

直连 `smartsheet.*` 读写时，`field` 一律用**中文列标题**：

| 表 | 列标题（写作 field 的值） |
|---|---|
| roster | 学号 / 姓名 / 课程 / 来源 / 更新时间 / 学情文件 |
| course_versions | 版本ID / 课程 / 版本号 / 更新说明 / 配置路径 / 知识库路径 / 题集路径 / 状态 / 适用对象 / 灰度名单 / 创建时间 / 创建者 / 运行开关 |
| 另：`course_versions` 的「配置路径 / 知识库路径 / 题集路径」三列支持**两种形态**（见下方注）；上云后可另加「题库路径」列登记 `quiz_bank.md` |
| agent_profiles | 智能体ID / 名称 / 头像 / 花名 / 简介 / 提示词 / 课程 / 版本号 / 状态 / 适用对象 / 灰度名单 / 创建时间 / 更新时间 / 创建者 / 角色 / 默认头像 / 默认花名 / 可选头像 / 可选花名 / 稳定锚点 |
| usage | 时间 / 学号 / 知识点 / 收敛轮数 / 结果 / 周次 / teach_week / 来源 / 智能体 / 环节 / err_type / 幂等键 |
| summaries | 时间 / 学号 / 知识点 / 摘要 / 时长 / 来源 / 智能体 / 环节 / 幂等键 |

> 只有**列标题**是中文；`status` / `target_audience` 的**取值**仍是英文枚举
> （`draft` / `published` / `gray`；`all` / `gray_list` / `force_update`）。
> **`course_versions` 三路径列的两种形态（v2.0.1 起支持）**：
> - **云端定位**（推荐）：`tdoc:<file_id>` / `tdoc://<file_id>` / `docs.qq.com` 开头的文档链接
> → 学生端**经腾讯文档通道读云端最新版**，教师改材料发版即生效，**不必重打包**；
> - **包内相对路径**（旧，向后兼容）：`references/courses/<course_id>/config.json`
> → 从学生包内读，**教师改材料需重打包**。
>
> 读取端按文件逐个判别，两种可混用；教师端按本表口径执行即可（资产读取只认 `course_versions` 表给出的路径）；
> 教师端上云步骤见 `references/teacher_admin.md` §10.3b。真实 `file_id` 只写在 Hub 表里，不进学生包配置。
> 学情相关取值已中文化：结果 ∈ {已收敛, 部分收敛, 卡住}；来源 ∈ {学生端, 教师端, 测试}；名册来源 ∈ {导入, 测试}；环节 ∈ {预习, 首学, 复习, 题目生成}（学生端写入时随行带上；环节取值定义见 `references/socratic_agent_prompt.md`「3.0 环节」）。**「苏格拉底引导」是引导方式、不是环节**，不写入本列。

> [!] **2.0.1 口径变更的历史数据连带影响（迁移须知）**
> 2.0.1 把「首次学习」正式定为独立阶段 `首学`。在此之前首学没有合法值，只能记成「预习」，
> 于是历史行里有一批「实际是首学、却记为预习」的记录（实测：心理学课 KP-1.5、KP-2.1 即如此）。
> 另有若干行按当时的临时口径记为「苏格拉底引导」——**这些行按 `首学` 解读**（当时就是在
> 首学场景下写入的，语义等价）。Usage 表仅追加、不修改，学生端无法更正，处理建议：
> ① 导出学情 CSV，在**本地报表**里把上述两类行按 `首学` 权重重算（不动云端原始数据）；
> ② 确需订正时由教师在数据中枢手工调整「环节」列（**不要用学生端补写**，会产生重复行）；
> ③ 跨版本对比的报表须注明该映射，避免口径差异被误读为学生表现变化。
> 另两条**易越界的取值约定**：`周次` 为 ISO 周 `YYYY-Www`（如 `2026-W39`，**不是**周序号 `1`）；
> `知识点` 必须逐字取自该课 `references/courses/<course_id>/config.json` 的 `kp_id`（**不是**章节名，
> 也**不是**「KP 号 + 中文标题」的拼接写法）。
> 本期新增列（向后兼容，见 `references/glossary.md` 数据模型术语）：
> - `usage.teach_week`（教学周，固化标签，如 `2026-秋-W3`）：由 `course_calendar.py` 依据
> Hub `calendar` 子表对每条学情的 `时间` 计算并随行写入；**报告 / 预警一律以 `teach_week` 为准**。
> 未录入校历时回退为 ISO 周并标注「未对齐校历」，不阻断统计。
> - `usage.err_type`（错因，可选）：学生对「卡住」题标注的错因类型（概念 / 计算 / 审题），
> 教师端可在周报异常模块看分布。
> - `summaries.时长`（duration_min，单位分钟）：每次会话的累计学时，供学生端学习预警
> （`course_warn.py`）计算「本周需补学时」与教师端报告使用。

|---|---|---|---|

> 「录入校历」时在 Hub 文件新建 `calendar` / `term_config` 子表（见 `teacher_setup.md` §2.0.6），
> 首次生成周/月报时在 Usage 文件新建 `report` 子表（见 `teacher_reports.md`）；建表后把定位写回对应配置键。
> 分发占位模板已预置这 3 个扩展键（占位符），未用到时保持占位即可，不强制。
> 未录入校历 / 未配置学期参数时，`teach_week` 回退 ISO 周、预警与报告降级提示，**不阻断**任何读写。
> 上述任一列取越界值的影响**按消费方分两类，不要混为一谈**（2.0.1 实测校正）：
> - **平时分（§5 权重表，教师/主智能体计算）**：按「环节 × 结果」查表，越界值**不命中任何权重**
> ——这一次学情在平时分里等于未记录；
> - **积分（`course_points.py`）**：只按「结果」聚类去重，**不校验环节白名单**（仅特判「题目生成」
> 转 bonus）——越界环节行的**积分照常计入**（实测：环节取未知值仍计入收敛数）。
>
> 两条口径不一致本身就是缺陷来源，**根本解法是别写出越界值**。学生端已在 SKILL 顶部与 §3
> 各放一道「写入前逐行自检」（取值合法集见本表上方「学情相关取值」一行）；
> 教师侧汇总时如发现越界行，按本约定归位或剔除，并在面板标注。
> 本文档行文用英文字段名指代逻辑字段（如 `status`），实际写表时按上表换中文标题。
>
> [!] **同步注**：本表与学生端 data_plane.md §0.3（随学生包分发）的同名表**重复维护**——改任一侧列标题时，另一侧**必须同步改**，
> 两端列标题不一致会导致读写错列。

**常见错误码**（调用返回时**先分类再处理**——传输层超时可重试，鉴权 / 权限 / 业务错误一律停止并原样提示）：

| 错误码 | 含义 | 处理 |
|---|---|---|
| `400006` | Token 鉴权失败 | 提示重新授权腾讯文档连接器：**Token 获取路径**——打开 `https://docs.qq.com/open/auth/mcp.html` 复制个人 Token（官方现行入口；旧路径：`docs.qq.com` 登录后右上角「更多操作 → 开放平台」→ 龙虾专用入口）。**header 的 key 必须是 `Authorization`**（用 `token` / `auth` / `X-Token` 等任何别名都会鉴权失败）。**不要**教教师去改 header 前缀——`Authorization: Bearer <token>` 由连接器插件自己拼装，教师手上没有、也不需要这个开关 |
| `400007` | VIP 权限不足 | 提示当前腾讯文档账号权限不足，需升级 VIP（<https://docs.qq.com/vip?immediate_buy=1>）后才能读写——**不要**反复重试 |
| `22001` | sub sheet not found（子表不存在） | **先核对再动手**：列出该文件全部子表现状——表可能已被教师手动删除；按现场重建缺失子表 → **回写两处定位**（包根 + 学生端模块，见 `teacher_setup.md` §2.0.3 的铁律；学生端会自行重新发现，**无需重新打包**）。**不要按时间邻近性归因于自己上一步操作** |
| `102` / `i/o timeout` / `ReadFrame` | **传输层超时**（服务端应答慢，非鉴权、非权限、非子表丢失、**非文件损坏**） | **可重试**——见下方「传输层超时处理」。**不得**据此判定「未连接到数据中枢」，**更不得**新建 / 重建数据中枢 |

> [!] **通道事实卡（与腾讯文档官方《skill 配置说明》对齐；排错时以此为准）**
>
> | 项 | 权威事实 |
> |---|---|
> | MCP 服务地址 | `https://docs.qq.com/openapi/mcp`（另有 `slide-mcp` / `doc-mcp` / `sheet-mcp` 三个子端点） |
> | 鉴权 header | **必须是 `Authorization`**——用 `token` / `auth` / `X-Token` 等别名一律鉴权失败 |
> | 取值形态 | 由插件自行拼 `Bearer <token>`，**无需手动干预**；「去掉 Bearer 前缀」不是排错手段 |
> | 票据环境变量 | 宿主机注入 `TDOC_OAUTH_ACCESS_TOKEN`（个人版 C 端 OAuth，透传 `Authorization: Bearer`）；企业版另有 `TDOC_ONEID_ACCESS_TOKEN`（透传 `X-Oneid-Access-Token`）+ `tencent-saas-docs` 技能 |
> | Token 获取 | 打开 `https://docs.qq.com/open/auth/mcp.html` 复制个人 Token（官方现行入口）；旧路径：`docs.qq.com` → 右上角「更多操作 → 开放平台」→ 龙虾专用入口 → 复制个人指令与 Token |
> | 客户端超时 | 技能通道默认 **120 秒**（`TDOC_HTTP_TIMEOUT`，或命令行 `--timeout <秒>` 覆盖）；连接器 MCP 侧是**平台托管**配置 |
> | 频率控制 | 免费用户 2000 次/天、超级会员 20000 次/天、超级会员 Plus 40000 次/天（官方《MCP 概述》）——高频批量读写时留意该上限 |
> | 已有配置 | 官方明确：**已在 IDE / 客户端配好 MCP 就无需重复配置**——所以「工具清单里没看到 smartsheet」不等于没连通（见 §2.0） |
> | 版本错配 | 401 / 403 且提示票据被拒 → 可能是把**企业版 OneID 票据打到了个人版端点**，应改用 `tencent-saas-docs`；**反复解绑 / 重连连接器不会改变结果** |
> | 站域端点 | Skill 形态调用**统一经包根封装 `course_tdoc.py`**：它默认把 `api_base` 强制指向权威端点 `https://docs.qq.com`，绕开平台 V2 MCP Gateway 偶发将 `api_base` 覆盖到失效镜像（`www-docs.workbuddy.cn` 等）导致的 502。**不要**直接裸调 `tencentdocs.py`、也不要在包内持久写死任何 `api_base` 覆盖 |
>
> [!] **写格式铁律（实测教训：表面成功、实际空数据）**
>
> `smartsheet.add_records` 的行**必须**用 `field_values` 规范格式——直接写 `{fields:{列:值}}`
> 会返回成功但 `list_records` 读出 `field_values: []`（数据根本没进去）。文本字段固定格式：
>
> ```json
> {"field_values": [{"field": "列名", "text_value": {"items": [{"text": "内容", "type": "text"}]}}]}
> ```
>
> **不要手拼**——用包根封装自带的转换子命令（纯本地、不联网）：
>
> ```bash
> python3 "${CODEBUDDY_PLUGIN_ROOT}/course_tdoc.py" make_records <rows.json>
> ```
>
> 入参 `rows.json` = `[{列名: 值}, ...]` 简单行列表，输出即上面规范格式（可直接喂 `add_records`）。
> 空值 / 空串自动跳过。**所有写路径**（播种 / 名册导入 / 学情落库 / 会话摘要）一律经此转换。
>
> [!] **tencentdocs.py 定位（改进：免手填）**
>
> `course_tdoc.py` 现支持三级定位：① 首个实参绝对路径；② `TDOC_PY` 环境变量；
> ③ **自动发现**（默认）——扫插件缓存取最新版 `tencent-docs-plugin/*/skills/tencent-docs/tencentdocs.py`。
> 插件升级后**无需**重新手填路径；仅当三级都失败才报「未定位」。

> [!] **传输层超时处理（服务端偶发，按此执行）**
>
> 症状形如 `type:framework, code:102, msg:tcp client transport ReadFrame, caused by read tcp ...: i/o timeout`。
> 这是**服务端应答超时**——同一个文件可能这一次超时、下一次就通。
> **它不是「连不上」，不是「文件坏了」。**
>
> 1. **先重试，再下结论**：同一调用**最多重试 5 次**。
> - 读操作（`list_records` / `list_views` / `list_fields`）：直接重试即可；
> - **幂等写**（把某列改成同一个值，如 `update_records` 改「运行开关」）：可安全重试；
> - **非幂等写**（`add_records` 新增行）：超时后**不得盲目重试**——必须先读取确认是否已写入，避免重复行
> （名册重复靠 `(学号, 课程)` 去重兜底，学情重复靠「幂等键」兜底，但仍是先查后写更稳）；
> 2. **两种形态互为兜底**：MCP 工具形态连续 2 次超时 → 立刻改用 Skill 形态
> （`python3 "${CODEBUDDY_PLUGIN_ROOT}/course_tdoc.py" "<tencentdocs.py 绝对路径>" --timeout 180 tdoc_call tencent-docs <tool> '<参数 JSON 对象>'`，
> 绝对路径按 §1.1 说明定位）重试；反过来同理。Skill 形态**一律经包根封装 `course_tdoc.py` 调用**，
> 它会默认把请求指向权威端点、绕开网关偶发指到失效镜像的 502。
> **MCP 超时 ≠ 通道不可用**，绝不得据此输出「未连接到数据中枢」停止话术；
> 3. **优先定向读取，别整表拉**：`list_records` 传 `record_ids`（或 `limit=1`）比全表扫描**快得多也稳得多**。
> 要取某几行时：先 `list_views` 拿该视图 `config` 里的 `recordIds`，再按 id 定向取；
> `list_fields` / `list_views` 这类元数据接口通常最稳，可用来先确认表还在不在；
> 4. **「调大超时」不是解法**：腾讯文档连接器的超时是**平台托管配置**，
> 包侧既不需要、也无法调整——重试 + 换形态才是解法；
> 5. 重试仍全部失败 → 才按停止处理，提示「该文件一时响应超时，可能拥堵，请稍后重试」。
> **不要因此重建数据中枢**：重建会改变定位 ID，逼全体学生重装包，代价远大于等待重试。

## 关键不变量（外置自 SKILL §8，唯一真源）

| # | 不变量 |
|---|---|
| 1 | **教师身份**存 `~/.workbuddy/profile.json`（`{"role": "teacher"}`）；学生身份 = 名册的「学号 + 姓名」（每次实时读取），学生本地仅缓存 |
| 2 | 名册导入按 `(学号, 课程)` 维度去重 |
| 3 | **学情聚合过滤**：「来源」=教师端、「学号」为空、「来源」=测试（仅平时分）、「学号」=测试号 `0000` 的行不参与统计（见 §4.2 / §5） |
| 4 | **周报锚定数据周**：默认取最新有记录的周次，无记录不输出空报（见 §6.1） |
| 5 | **教师使用记录**：「来源」只填 `教师端`；学号留空；不计入平时分（细则见 `references/teacher_reports.md` 的「6.3 教师使用记录」） |
| 6 | 定位 ID 按 §1.1 顺序读取（配置 → .env 分键 → 首课扁平键），皆无则停止；**禁止硬编码**；**不得在对话中展示真实 ID**（§1.3） |
| 7 | **学情聚合口径**：学生端写入粒度为「每会话 × 每 KP 一行」（多 KP 同一次会话「时间」相同）；`sessions` = 去重 `(学号, 时间)` 数，`kp_records` = 记录条数 |
| 8 | **改表前必须回读确认**：`update_records` / `delete_records` 前须先 `list_records` 读回真实 `record_id`；禁止凭业务 `id` 列猜测定位键，禁止凭模糊描述批量改表 |
| 9 | **改表前向教师复述**：「要改哪一行、改成什么」先复述一遍再执行；候选行不唯一时由教师**指认**，不猜 |
| 10 | **结构化列按 JSON 字符串写入**：`课程` / `灰度名单` / `运行开关` 的值是 **JSON 字符串**（如 `["sample-course"]`），不是原生数组 / 对象；列均为文本列，写值一律按文本发送 |
| 11 | **发布与灰度联动**：`状态` 与 `适用对象` 必须**成对**写——正式发布 = `published` + `all`；只改一个会留下自相矛盾的行（见 §10.2） |
| 12 | **`运行开关` 整列覆盖**：不支持按 JSON 键 merge，改写前必须先读回原 JSON 并带上原有其他键（见 §10.2） |
