# 课程资料授权与自动同步（教师职责与同步）

> 本文件是 `agents/course-tutor.md` §2.3 主菜单第 16 项的细则（**先 Read 再操作**）。
> **分工（v2.1 修订）**：教师端与学生端均从平台安装。教师的工作只有两件事：
> **在腾讯文档建好资料 → 把课程中枢空间授权/邀请给学生**。资料更新由学生端自动同步，教师无需发送任何文件。

## 一、模型（授权）

| 角色 | 职责 | 不做什么 |
|---|---|---|
| **教师** | 在腾讯文档建好全部课程文档（课程资料 / 名册 / 学情表）；建好**中枢文档并授予可编辑权限**，通过小程序 / 二维码 / 链接**邀请学生加入** | 不打包、不发布、不维护任何 zip |
| **学生** | 从平台安装学生端（一次）→ 在 WorkBuddy **连接腾讯文档 MCP** → **自动发现教师课程中枢空间** → 直接开始学习 | 不需要重装：资料更新**自动同步到本地** |

**中枢（hub）的本质**：教师建的一个**对外共享、并邀请学生加入的知识库空间**，内容是「学生所需的最小信息集合」——
课程清单、材料清单、Hub/Usage 的定位、版本戳。学生端**自动发现该空间**（`discover_hub.py` 遍历学生侧可见空间），
运行时自己找到全部内容。教师更新资料 → 版本戳变化 → 学生端自动拉取存本地。

## 二、教师侧操作（菜单 16 · 课程资料授权）

1. **建资料**（首次设置 §2.0.1 已完成数据中枢者跳过）：课程材料、名册、学情表都在腾讯文档；
2. **建课程中枢**（每门课一次）：由教师端建课流程（学生端经 `discover_hub.py` 自动发现）在知识库空间落地该课的 Hub 文件（3 表：`roster` / `course_versions` / `agent_profiles`）与 Usage 文件（2 表：`usage` / `summaries`；表名两种写法均可），并把定位写入学生端本地 `data_hub_config.json` 的 `courses.<course_id>`（键：`hub_file_id` / `hub_sheets` / `usage_file_id` / `usage_sheet`）——**脚本只落盘、不回显，教师无需手工记录任何定位 ID**；
3. **邀请学生**：通过小程序 / 二维码 / 链接把学生加入该空间（已授予可编辑）；学生在 WorkBuddy 中**连接腾讯文档 MCP** 即可使用；
4. **告知学生**：自己的学号 + 姓名（学生端首聊按 §1 身份校验（学号 + 姓名））；
5. **日常更新**：直接改腾讯文档里的资料并更新版本戳——学生端开场自动比对并同步，**无需教师做任何分发动作**。

> 教师侧**不出产任何 zip**。若教师提出「发布课程新版本给学生」之类的诉求，如实说明：
> 学生端会自动同步最新资料，教师无需发布任何文件；若学生端长时间未同步，请检查中枢空间的共享状态与学生端的腾讯文档连接。

## 三、学生侧逻辑（学生端 · 平台通用版）

学生端（`course-companion`，**零预置课程信息**，`courses` 初始为空）运行时：

1. **首次**：在 WorkBuddy **连接腾讯文档 MCP** → `discover_hub.py` 遍历学生侧可见的知识库空间、自动发现教师课程中枢 → 读到课程清单 → 选课 → 双因子（学号 + 姓名）校验身份（形态 A，无兜底形态）；
2. **每次开场**：比对中枢「材料版本戳」vs 本地缓存 → 有更新才拉取（幂等）；
3. **更新落地**：学生端把新资料保存到本地缓存，取不到就回退上一版；
 只解析 `*.json` / `*.md`，**绝不私自执行**包内脚本（仅按文档明示的 `discover_hub.py` / `fetch_assets.py` 入口按需调用）——这就是「有更新，保存在本地，无需再次安装」；
4. **伴学**：与通用学生端同一套逻辑（苏格拉底引导 / 学情回流 / 会话收尾自动呈现「我的积分」）。

> 「包版本」与「课程内容版本戳」是两个独立记录：包版本随教师端统一发布；
> 版本戳（course_versions / agent_profiles 表）由教师发布节奏决定，互不代表对方。
