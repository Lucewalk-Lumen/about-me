# Changelog 规范（Changelog Convention）

> 本团 CHANGELOG.md 必须严格遵循 [codebuddy.cn 官方更新日志](https://www.codebuddy.cn/docs/workbuddy/Changelog) 的体例。本文件是规范说明 + 本团模板 + 首版（1.0.0）示例（格式已于 2026-10-07 对照官方核对修正）。

## 一、官方格式要点（对齐官方）

1. **标题**：`## X.Y.Z 版本发布 🚀(YYYY-MM-DD)`
   - 版本号用语义化 `MAJOR.MINOR.PATCH`；括号为**半角** `( )`，含 🚀 装饰符，与官方一致。
2. **正文条目**：**扁平无序列表**，每条以 `新增` / `优化` / `修复` 动词开头；**句尾不加句号**；不设 `### 新增` 等子标题，标题下**不写导语段落**。
3. **只写智能体功能**：条目描述专家团对用户可见的能力与行为，不写开发过程、元信息或内部编号。
4. **版本号语义**：MAJOR 不兼容变更 / MINOR 向下兼容新增 / PATCH 向下兼容修复。

## 二、硬要求

- **版本号真源为 `plugin.json.version`**：CHANGELOG 仅做记录，不得把 CHANGELOG 当作版本依据，二者必须一致。
- **禁止悬空引用**：日志中引用的文件/目录必须真实存在，避免写"新增 xxx.md"但文件未落地。
- **计数类数字须与实物一致**：如参考库文件数、依赖登记项数，落笔前先清点实物。
- 日期格式固定 `YYYY-MM-DD`，与标题括号内一致。
- 条目顺序建议：新增 → 优化 → 修复（某类无内容时不写该类条目，不写"无"占位）。

## 三、本团 CHANGELOG 模板

```markdown
# 更新日志 · 校园演示帮手团（campus-ppt-helper）

## X.Y.Z 版本发布 🚀(YYYY-MM-DD)

- 新增：（真实落地的能力，用户可感知、可验证，句尾不加句号）
- 优化：（无则不写该条）
- 修复：（无则不写该条）
```

## 四、首版（1.0.0）写法示例

> 以下为本团 CHANGELOG 首版**示意（简版）**；实际以包内 `CHANGELOG.md` 为准。

```markdown
## 1.0.0 版本发布 🚀(2026-10-06)

- 新增校园演示帮手团专家团：主理人带五位专业成员端到端协作，从资料采集到成品演示文稿

- 新增广财品牌模板 10 套、党政模板 5 套（共 15 套），托管于腾讯文档「演示模板库」，经连接器在线获取后套用
- 新增四维质检与"不通过→精修→复验"闭环
```

## 五、与 standards-watch.md 的衔接

- 标准自更新机制发现文档变动并升版本时，必须按本规范更新 CHANGELOG。
- 升版后核对：标题版本 = plugin.json.version；动词前缀条目完整；句尾无句号；无悬空路径引用。
