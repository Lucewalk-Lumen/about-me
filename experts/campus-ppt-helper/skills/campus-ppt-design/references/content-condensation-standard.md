# 内容凝练标准（Content Condensation Standard）

> 面向内容架构师（campus-ppt-content-architect）+ 采集检索员 + 制作员（campus-ppt-maker）。
> **本文件解决一个已实际发生的系统性缺陷**：正文页字数被"扩写"上来，但封面 / 目录 / 章节过渡页也被同一条"越多越丰满"的指标推着塞满了正文——页面失去了页型，读者拿到手的是一份"每页都在说话、但没有一页在干自己该干的事"的稿子。
> 本标准的纪律移植自外部技能 **`ai-writing` 1.0.1**（登记见 `external-dependency-registry.md` §一 #19）。

## 〇、为什么引入 ai-writing

### 0.1 引入的不是"又一个写作技能"，是它的一条门禁

`ai-writing`（罗斯蒙德智能写作与文档交付）的业务流 C 有一条硬门禁——**「动笔前必确认两项（缺一不动笔）」**：

1. **写作风格**：体裁 / 语气 / 视角 / 发布渠道；给不出明确风格时列 2–3 个候选让用户选，**不得自行默认**；
2. **字数限制**：明确目标字数**区间**；用户未给时给出建议区间并经确认，**不得自行默认篇幅**。

以及第 8 条质量护栏：**「风格与字数未经用户确认不动笔」**。

这条门禁的价值不在于"确认两种参数"，而在于它**把"写多少"从写作过程中拎出来、提前钉死**。本团此前的失败恰好是它的反面：没有页型与预算的约束，写作阶段就只剩一个动作——**往能塞的地方塞**。

### 0.2 移植到课件的等价物

| ai-writing 的概念 | 课件管线的等价物 | 落点 |
|---|---|---|
| 写作风格确认 | **页型契约**（这页是封面 / 目录 / 章节过渡 / 正文） | `page-content-contract.md §二` |
| 字数限制确认 | **每页字数上限**（不是下限） | `page-content-contract.md §三` |
| 素材索引 `M-01…Mn`（每个事实句可指回素材） | **资料登记表 + `S-x` 溯源编号** | `source-hygiene.md`、页面清单表 |
| 「骨架仅作确认后的可选参考」（不按类型自动套模板） | **先定页型骨架与版式，再写文案**；不得"先堆字后套版式" | `layout-selection.md §五` |
| 交付前跑 `check_doc.py` / `check_report.py`，**退出码非 0 禁止交付** | 交付前跑三关：几何门 / 字数门 / **内容类型门** | 本文件 §五 |
| 「核验未通过不交付，且不得通过放宽阈值刷绿」 | 同上 | `quality-evaluation-standard.md` |

> **一句话**：本团缺的从来不是"写得多"，而是**"这页该写什么、写多少"在动笔前就被钉死**。

## 一、五步法（课件版）

原文五步法：`写作意图 → 风格与字数确认 → 素材检索 → 草稿/大纲 → 格式标准化 → 指定格式交付`。
课件版把"风格"换成"页型"，把"格式标准化"换成"版式与视觉"，其余同构：

```
① 定页型     逐页确定页型（封面 / 目录 / 章节过渡 / 正文-案例 / 正文-证据 / 正文-并列 / 结尾）
      ↓
② 定预算     逐页查 page-content-contract.md §三，取该页型的**字数上限**与**必填元信息**
      ↓
③ 索引素材   把采回的资料登记为 M-xx / S-x（来源 + 原文摘录 + 支撑页），**指不回素材的句子不得写入**
      ↓
④ 凝练成句   对每页做「一句主张 + ≤N 个支撑点」的压缩，**先压缩到骨架、再展开成文案**
      ↓
⑤ 版式与交付 按页型选版式（遵守七条轮换规则）→ 出片 → 三关验收
```

> **①②必须先于③④**。跳过①②直接进入"把资料写进页面"，就是本次缺陷的成因，主管应在阶段门上拦截并退回。

## 二、凝练的四条操作定义（可执行）

"凝练"不是一个形容词，是四个可核对的动作：

| # | 动作 | 判据（不通过即未凝练） |
|---|---|---|
| 1 | **压成一句主张** | 每页能写出**一句话**主结论；写不出来 = 这页还没有观点，不许动笔 |
| 2 | **支撑点封顶** | 支撑点 ≤ 契约上限（正文页一般 3–5 个）；第 6 个支撑点必须替换、合并或删 |
| 3 | **同质去重** | 同一组数字 / 同一个案例 / 同一句结论**在全片只出现一次**；重复出现即删后出现的那次（除非是封面与目录的**索引式**复述） |
| 4 | **长句拆成结论句** | 每个支撑点的首句必须是结论句（可独立读懂），后句才是依据；"一段话从头讲到尾"判不合格 |

**反例（本次缺陷的原文）**：

> 目录页左栏：「先讲课程定位与学习目标，再用可溯源案例示范迁移路径，然后拆四类题型的答题结构，最后用公开数据与自检清单收口。每一步先给结论句，再补支撑句。」

这段本身写得没错——**但它不该出现在目录页**。它的正确归宿是「本讲说明」页或演讲者备注。判断依据不是"写得好不好"，而是**"这页的页型允不允许"。**

## 三、与"内容太少"的关系（为什么凝练不是"写少点"）

**凝练 ≠ 缩短全片字数。** 本团此前收到的两次"内容太少"反馈仍然有效——只是当时开错了药方：

| | 错误做法（已发生） | 正确做法（本标准） |
|---|---|---|
| 目标 | 让**每一页**字数都上去 | 让**每一页**都干自己该干的事 |
| 手段 | 找空白带 → 塞正文 | 定页型 → 定预算 → 凝练 |
| 结果 | 封面出现"主线"、目录出现教学说明、章节页出现学习产出 | 封面是封面、目录是目录、正文学得住 |
| 正文页 | 93 → 248 字/页（**这部分是对的，保留**） | 保持 200–250 字/页的**凝练后**信息量 |
| 索引页 | 一并被塞满（**这部分是错的**） | 回到"少字页"，只承载索引 / 标题 |

> **结论**：正文页的扩充成果**保留**；封面 / 目录 / 章节过渡页的"扩充"**全部撤销**。
> 全片总字数可能下降，但**信息密度与可读性上升**——这才是"丰满"的正解。

## 四、每页必须回答的三个问题（架构师自检）

动笔前，逐页回答；答不上来就不许进入第 ④ 步：

1. **这页是什么页型？**（七个之一，见 `page-content-contract.md §一`）
2. **这页读完，读者要记住哪一句话？**（唯一主张）
3. **这页承载元信息还是内容？**（封面/目录/章节页承载元信息与索引；正文页承载内容）

> 第 3 问是最容易答错的一问。**封面不承载内容**——读者在封面只会看"这是什么课、谁讲、怎么找他"；把课程主线、时长、方式放上去，是把封面的注意力预算花在了错误的地方。

## 五、验收（三关，缺一不可）

| 关 | 脚本 | 通过判据 | 管什么 |
|---|---|---|---|
| 几何门 | `check_geom.py` | 退出码 0（无重叠 / 无出界 / 不贴边） | 形状有没有打架 |
| 字数门 | `measure.py` | 正文页 ≥ 200 字/页 | 内容够不够 |
| **内容类型门** | `check_content_scope.py` | 退出码 0 | **每页是不是在做自己该做的事** |

> **三关的分工必须讲清楚**：几何门与字数门此前**全部通过**，用户仍然退回——因为这两关**结构上无法**发现"目录页出现了正文段落"。缺的正是第三关。任何一关退出码非 0 即禁止交付，**不得放宽阈值刷绿**（`ai-writing` 质量护栏第 5 条）。

## 六、与外部技能的关系（诚实标注）

- `ai-writing` 是**方法论来源**，本团引用的是它的**门禁设计**（风格与字数确认门、五步法、核验退出码），**并不调用它的脚本**——它的 `check_doc.py` / `check_report.py` 面向 docx 与日报周报，与 pptx 管线不同构。
- 因此本团**不得声称"已调用 ai-writing 技能生成课件"**。正确表述是：**"内容凝练纪律参照 `ai-writing` 1.0.1 业务流 C 的确认门"**。
- 它在本团的用途有且仅有**一**处：**给 `page-content-contract.md` 的"动笔前定页型与预算"提供外部依据**。超出这个范围引用它，即属过度引用。
