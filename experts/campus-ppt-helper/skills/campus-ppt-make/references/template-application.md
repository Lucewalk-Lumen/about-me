# 模板真实取色与套用标准（Template Application）

> 面向制作员（campus-ppt-maker）。核心：**先读模板真实设计规范，再写指令**（能否沿用模板取决于 §〇 选路：A 只取规范重绘，B 才保留模板；**B 的保真单位是"页"**——必须深拷贝模板页，新建空页会丢光模板视觉）。禁止"套通用学术蓝 / 凭记忆填色 / 编造示例 hex"。
> 背景：曾发生"演示件写死 `#1E4FA8` 通用蓝、指令示例编造 `#1F4E79`/`#C00000`"的事故——出片**根本没过模板**。本文件把它固化为标准动作。

## 〇、能力边界与"套用模板"的两条路径（先读，先定路线）

**结论**：官方"模板"能力分两条路，**必须显式选路**，不能含糊说"套用模板"。

| 路径 | 用什么 | 能保留什么 | 不能保留什么 |
|---|---|---|---|
| **B. 模板保真（默认 / 重 / 强保真）** | 官方 `tencent-local-office-edit`（editor_sdk）：**`slide_duplicate_slide` 深拷贝模板页** + `slide_set_text*` 改字 | **页层视觉**（logo 图片 / 色块 / 装饰 / 图形）+ 母版 / 版式 / 主题 / 示例页样式 | 需先读懂模板各页设计、规划"哪页当哪页"；改字后要回填字号 / 控制换行 |
| **A. 风格重绘（兜底 / 轻量）** | 官方 `tencent-pptx`：`create-from-material` 读图提风格 → `create-from-scratch` 重画 | 配色、字体层级、版式**结构**（作为设计规范照做） | **不能继承模板母版 / 版式引用**；成品不含模板原生版式 |

**依据（可复核）**：
- `tencent-pptx/references/create-from-material.md` 第 18 行要求"读取并遵循 create-from-scratch.md 的标准流程来创建 PPT"；第 14 行原文要求"学习 pptx 文件的风格……**禁止一成不变，模仿无法复现的风格样式**"。⇒ 该技能只做"学风格 + 重画"，不继承母版。
- `slidep` 只有 `create` / `upsert-dsl` / `validate` / `screenshot` / `lint` 五个子命令，`create` 生成空白稿，**无模板参数**，也无导入 / 套用模板命令。
- `tencent-local-office-edit` 的 `slide_*` 工具含 `slide_get_master_info`（列版式）、**`slide_duplicate_slide`（深拷贝整页，保留全部形状 / 图片 / 装饰 / 样式 —— 路径 B 的主力工具）**、`slide_add_slide`（新建页，**只带母版层**）、`slide_remove_slide`、`slide_set_text*`、`slide_add_image`、`save_file`。⇒ 可做到页面级保真。

**路径 B 最小可执行步骤**（页面级保真，**以"页"为模板单位**）：
1. 复制模板到输出名（模板来自腾讯文档导出缓存，获取见 `tencent-docs-template-source.md`）：`cp ~/campus-ppt-cache/广财-07-绿色极简模板.pptx "<输出>.pptx"`
2. 打开（`wait=true` 等模型就绪）：`python3 edsdk.py call open_file file_path="<输出>.pptx" file_type=slide wait=true` → `file_id`
3. 看结构：`slide_get_info`（页数）、`slide_get_page_info`（每页形状 / 图片 / 文本）、`slide_get_master_info`（版式清单）
4. **建页＝深拷贝**：对设计正确的模板页 `slide_duplicate_slide file_id=<id> page_indexes=[N]`
   （整页深拷贝，保留全部形状 / 图片 / 装饰 / 文本 / 样式）
5. 删多余页：`slide_remove_slide`（**务必从后往前删**，避免索引位移）
6. 写内容：`slide_set_text`（**文本自带 `\n` 换行**，见 §已知限制 2）→ `slide_set_text_property` 回填模板原字号
7. 存盘：`save_file`
8. 复核：`slidep screenshot <file> --page-index <i>` **逐页目视**；无 LibreOffice / Office 可用 `Spire.Presentation` 离线渲染

> **禁止**：删光示例页后用 `slide_add_slide` 新建页来"出片"。该工具只带母版层（浅灰底 + 版式占位符），
> 模板视觉（logo 图片、色块、装饰矩形、图形）**全在"页"层，不会继承**——出片必然"只有文字、没有模板"。

**路径 B 实测结论（复核修正）**：
- **【作废·旧版结论】**：「母版 / 版式 / 主题语义级保真成立（11/11 版式几何签名一致）」。
  该结论**只对了一半**——它证明的是"母版 / 版式 / 主题层"保真，**但模板视觉根本不长在那一层**。
  实测反证：用 `slide_add_slide` 出的片，母版 / 版式 / 主题全部一致，**产出件却是零图片、零装饰、只剩文字**。
  **层选错 ⇒ 结论必错。** 保真判定必须落到**页层**（`ppt/slides/*.xml` 的 `<p:pic>`、`<p:sp>` 数量与几何）。
- **【修正后结论】**：以 **`slide_duplicate_slide` 深拷贝模板页**为建页手段时，产出件**页层视觉完整保留**
  （广财封面：校徽 logo 图片 1 个 + 青色 `227780` 色块 + 装饰细线；内容页：页眉色条 + 三栏三角图形）。
  经**官方 `slidep screenshot`（editor_sdk）与离线 `Spire.Presentation` 两条独立渲染通道**逐页目视确认一致。
- **判定口径（务必按此复核）**：① 产出件解包后 `ppt/media` 或 `ppt/slides/media` 存在图片；
  ② 每页 `<p:pic>` / `<p:sp>` 数量与来源模板页一致；③ **官方渲染器逐页出图目视**。
  仅比对母版 / 版式 / 主题**不足以判定保真**。

**已知限制（实测踩坑，勿踩）**：
1. **`slide_add_slide` 只带母版层**：新建页 `shape_count = 0`（没有版式占位符实例），且**页层视觉（logo 图片 / 色块 / 装饰矩形 / 图形）一律不继承**。⇒ 出片必须用 `slide_duplicate_slide` 深拷贝模板页，**不要用 `slide_add_slide` 建页**。
2. **`slide_set_text` 会重置字符级样式**（字号 / 粗体 / 颜色），且文本框多带 `spAutoFit`——**单行长文本会把框撑宽**（实测 `cx` 由 245pt 被撑到 706pt，横穿版面）。⇒ ① 改写文本**自带 `\n` 换行**，行长控制在框宽内；② 改完用 `slide_set_text_property` **回填模板原字号**（广财-07 实测规格：封面标题 32pt / 副标题 16pt / 学院 14pt；内容页小标题 16pt 粗体 / 正文 14pt / 编号 66pt）。
3. **形状 id 是"会话级"的**：同一文件重新 `open_file` 后 id 会重新分配（实测 `000084` → `00007b`）。⇒ 跨会话**不要复用 id**，每次都先 `slide_get_page_info` 重取。
4. **落盘会重序列化 XML**：母版 / 版式 / 主题的**字节 md5 会全部改变**（`r:id` 重编号、删 `p14:creationId`、形状 id 重编号等）。⇒ 保真判定必须做**语义比对**，**严禁用 md5 判保真**——用 md5 会得出"没保真"的**错误**结论。但语义比对**只比母版 / 版式层同样会误判**，必须落到**页层**（见上"判定口径"）。
5. **删页必须倒序**（索引前移）；`slide_add_slides` 批量只支持**同一 layout**。
6. **内嵌图片落点非标准**：editor_sdk 落盘把图片写到 `ppt/slides/media/`（模板原在 `ppt/media/`），关系目标相应为 `media/…`，两条路径各自自洽、文件合法。注意：若在图片落盘**之前**取渲染，编辑器会话缓存会导致**预览缺图**——`close_file` + 重新 `open_file` 后即正常，**不是**产出件缺陷。
7. **像素级外观可验证，且是必做项**：`slidep screenshot <file> --page-index <i>`（走 editor_sdk，无需 Office）；无渲染环境时用 `Spire.Presentation` 离线渲染。**结构 / 语义层结论不能替代**逐页目视——本次事故正因"只做语义层比对、没做页层目视"而漏检。

**选路规则（默认 B，1.0.3 起）**：**未说明保真度 → 默认走 B**（广财师生 / 党政单位套用内置品牌模板；自备模板同样默认保真）；用户明确不要模板、只要求"配色字体像模板、结构清晰"，或无内置模板可用（中性兜底）→ 走 **A**，但**必须向用户如实说明"未沿用模板母版 / 版式 / 页层视觉"**。

**红线**：任何路径都不许编造色值；hex 一律来自模板提取结果（见下文 §二 / §六）。

> **出片第 0 步（强制）**：动手前先按 `external-dependency-registry.md` 卡 1–4 预检四个外部依赖（`tencent-pptx` 及 7 份设计文件 / `tencent-local-office-edit` / `browser-skill` / 腾讯文档模板库）。**卡 4 未过（鉴权失败 / 枚举不足 15 / 取件四级全败）时禁止继续**，按 `tencent-docs-template-source.md §四` 降级口径处置。

## 一、铁律

1. 选定模板后，**必须先提取该模板真实的色板 / 字体 / 版式**，再动手写指令与 DESIGN.md。
2. 指令、DESIGN.md 里出现的**每一个 hex 都必须来自提取结果**；未提取不得填色。
3. **禁止**用"通用学术蓝 / 通用预设"替代：一旦发现配色与所选模板主题不符，即判"未过模板"，返工。

> 补：判"是否过模板"以**页面显式色 / 字体是否取自模板提取结果**为准；"是否携带模板母版"取决于上面选的是路径 A 还是 B——路径 A 的成品不带模板原生母版属正常，但**必须在交付说明里写明**。

## 二、提取真实母版的两种手段（二选一，优先 B）

| 手段 | 命令 | 依赖 | 适用 |
|---|---|---|---|
| A. 官方渲染取色 | `python <tencent-pptx>/scripts/pptx2image.py "<模板.pptx>" --outdir style_preview --grid 9 --dpi 300`，再用 `read_image` 逐页读取 | **LibreOffice + poppler(pdftoppm) + Pillow** | 有 LibreOffice 的环境；同时能看到版式/母版/品牌图 |
| B. 直读 XML（推荐，零依赖） | 解包 `.pptx`，读 `ppt/theme/theme1.xml` 的 `a:clrScheme` 与 `a:fontScheme`；并扫 `ppt/slideMasters` / `ppt/slideLayouts` / `ppt/slides` 的 `srgbClr` 频次 | 仅需 zip + 文本读取 | 只需精确色板/字体；**无 LibreOffice 时唯一可行** |
| C. 官方逐页出图（保真复核首选） | `slidep screenshot "<file>.pptx" --page-index <i> --out <png>`（走 editor_sdk，**不需要 Office / LibreOffice**） | 仅需官方 `tencent-local-office-edit` 环境 | **路径 B 保真复核必做**：逐页目视页层视觉是否保留 |
| D. 离线兜底渲染 | `Spire.Presentation`（`pip install Spire.Presentation`，纯离线，免费版带 `Evaluation Warning` 水印，**水印不在文件内**） | 仅需 Python | 环境里既无 Office 也无 editor_sdk 时；用于交叉验证 |

> 说明：A 依赖 LibreOffice（本机**未安装**，故 A 实际不可用）；B 直读 XML；**C 是本团保真复核的主用通道**。B/C/D 都只是"读取 / 渲染"，不属于团队红线禁止的"Python/JS 生成脚本"——红线禁止的是"自带脚本生成 .pptx"，不是"读取或渲染模板"。

> **重要**：相当多第三方模板的 `theme1.xml` 是**遗留的 Office 默认主题**（如 `4472C4` / `5B9BD5`），真实品牌色其实在 `slideMaster` / `slideLayouts` / `slides` 里。因此**不能只看 `theme1.xml`**——必须同时扫母版与幻灯片的 `srgbClr`，**以实际出现频次高的色为准**。

## 三、要提取什么（缺一不可）

1. **主题槽位全量（继承包本体）**：`theme1.xml` 的 `dk1` / `dk2` / `lt1` / `lt2` / `accent1..6` 的 `srgbClr` **全量**，以及 `majorFont` / `minorFont` 的 `a:latin` 与 `a:ea` 字体栈（`dk1` / `lt1` 通常为黑 / 白，也须记录真实值，不得假定；CJK 的 `a:ea` 常为"宋体"或空）。
2. **实际用色**：`slideMaster` / `slideLayouts` / `slides` 中 `srgbClr` 的**高频色**（模板真正在用的品牌色，可覆盖第 1 项的默认遗留值）。
3. **字体（run 级实际字族）**：第 1 项已覆盖主题字体栈；此处补页面 / run 级实际 `a:ea` / `a:latin`——模板实际显示字族可能与主题栈不同（内置 13 套实测见 `body-typography-standard.md` 附录 A 中文字族列）。
4. **母版 / 版式结构**：`ppt/slideMasters/*`、`ppt/slideLayouts/*` 的数量与原型页（封面/目录/章节分隔/内容/结尾）。
5. **视觉元素**：logo 位置、色带、图片处理、装饰形状。
6. **主题继承包（换底稿不换风格）**：把第 1 项提取结果写入 DESIGN.md 固定字段（配色表每行 `角色 | hex | 来源` + 字体栈，字段见 §四）。任务中途**换底稿**（重新导出模板 / 更换模板文件）时，**按继承包恢复风格，不重新拍色拍字**——实现"换底稿不换风格"。第 2 项的页面高频色是继承包的**校验旁证**（防遗留默认主题，见 §二 警告），不替代主题槽位本身。

## 四、产出物

1. **`DESIGN.md`（任务产出物，写入本次任务的输出目录，非包内文件）**，固定字段：
   - `## 模板来源`：模板文件名（如 `广财-02-蓝色风景模板.pptx`）
   - `## 配色（取自模板，硬约束）`：主色 / 辅色 / 强调 / 浅底 的真实 hex 表，每行 `角色 | hex | 来源（theme1.xml 或 母版/页面频次）`
   - `## 字体`：CJK 字族（`a:ea` / `majorFont`）、拉丁字族（`a:latin`）
   - `## 版式`：母版 / 版式清单与原型页（封面 / 目录 / 章节分隔 / 内容 / 结尾）
   - 生成时**只允许**使用本文件列出的 hex 与字体。
2. **指令清单的"配色"字段**填真实 hex，并注明来源模板文件名。
