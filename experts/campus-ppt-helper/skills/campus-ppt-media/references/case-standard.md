# 案例标准（Case Standard）

> 面向采集员（campus-ppt-collector）、设计师（campus-ppt-content-architect）、制作员（campus-ppt-maker）与质检员（campus-ppt-qa）。
> 解决**"案例只有半句话"**这类问题：没有结构模板、没有整页/内嵌的选择规则、没有数量篇幅约定、没有出处硬要求。
> **核心铁律：只允许可溯源的真实案例。缺失标「待补充」，绝不编造。**

## 一、铁律

| 规则 | 说明 |
|---|---|
| **不得编造** | 案例的企业名、时间、数据、结果，**任何一个字段**无来源即整条不得使用。禁"某企业""据悉""有研究表明"式模糊来源。 |
| **必须可溯源** | 每条案例带 S 编号（采集报告来源表），级别 **L1 / L2 / L3**（见 `source-hygiene.md §二`）；**L4 一律不得作为案例**。 |
| **缺失就标缺** | 找不到真实案例时，写 `案例：待补充（采集员待核）`，回传主理人；**不得**退而编造或用"虚构示例"填充。 |
| **教学示例的例外** | 教学场景允许使用**教材 / 考纲内的例题**（属 L2 权威），但**必须标注教材名称与章节**，且**不得**包装成"真实企业案例"。 |
| **禁止 AI 生成案例** | 与配图不同，案例**没有 AI 生成兜底档**——AI 生成的"案例"就是编造。 |

## 二、案例结构模板（五要素）

每条完整案例必须能被填入下表；**填不满五要素的，降级为"例证"**（见 §三）。

| 要素 | 内容要求 | 字数参考 |
|---|---|---|
| **① 背景** | 主体（谁）、时点（何时）、处境（在哪、做什么）。**主体须真实可查** | 20–40 字 |
| **② 冲突** | 面临的具体问题 / 瓶颈 / 风险。要有"张力"，不是流水账 | 20–40 字 |
| **③ 做法** | 采取的具体动作（可 2–3 个关键动作）。**避免"加强管理"这类空话** | 30–60 字 |
| **④ 结果** | **必须带数据**（数值 + 单位 + 时点）。无数据的结果不算结果 | 20–40 字 |
| **⑤ 启示** | 对本 deck 论点的支撑 / 可迁移的做法。**必须与本页结论标题呼应** | 20–40 字 |

### §2.1 结构化书写模板（设计师直接抄用）

```markdown
**案例 C1：<主体> 的 <议题>**
- 背景：<主体> 于 <时点> ……
- 冲突：……
- 做法：① …… ② ……
- 结果：<指标> 由 <A> 提升至 <B>（<单位>，<时点>）
- 启示：……
- 出处：[S3] <机构>《<标题>》<版本/日期>（L2 权威）
```

> **写作纪律**：不用形容词堆砌（"取得了显著成效"），用**数值**；不写"业内人士认为"（无主体），写**具体机构与文号**。

## 三、整页案例 vs 内嵌案例（选择规则）

| 形态 | 触发条件 | 版面占比 | 配图 |
|---|---|---|---|
| **整页案例**（案例页） | 案例**五要素完整**且是本页核心论点的主要支撑；或案例需要图表佐证 | 整页 | 建议 1 张（实景/数据图） |
| **内嵌案例框** | 案例作为**论点的举例**存在，页面主体仍是论述 | ≤ 页面 1/3（一侧栏或底部条） | 不配图 |
| **例证**（一句话） | 只有事实性引用、撑不起五要素 | ≤ 2 行 | 不配图 |

### §3.1 判定流程

```
有一条素材，想当案例用
│
├─ 有真实主体 + 可溯源出处？
│   ├─ 否 → 不得使用（回隔离区）
│   └─ 是 ↓
├─ 五要素是否填满？
│   ├─ 否 → 降级为【例证】（一句话，进正文或注释）
│   └─ 是 ↓
├─ 是否为本页主要支撑？
│   ├─ 是 → 【整页案例】（独立成页）
│   └─ 否 → 【内嵌案例框】（≤ 1/3 版面）
```

> **禁止**：把不完整素材硬撑成整页案例（会逼出编造）。**降级比编造安全**。

## 四、数量与篇幅

| 场景 | 案例数量 | 篇幅上限 | 说明 |
|---|---|---|---|
| **教学** | 每个核心知识点 **≥1 个例证**；重难点 **≥1 个完整案例** | 整页案例 ≤ 1 页；例证 ≤ 2 行 | 教学案例优先**教材例题 / 考纲例题**（L2） |
| **答辩** | 支撑研究设计的 **1–2 个**真实案例（如调研对象、数据场景） | 每例 ≤ 1 页 | 答辩案例须与研究口径一致，写明样本来源 |
| **实习** | 同类做法 / 对标案例 **2–3 个**，用于比较 | 每例 ≤ 半页（并排对比） | 优先同业公开数据（L2） |
| **党建党政** | 政策文件中的**典型案例 / 先进做法** 1–2 个 | 每例 ≤ 1 页 | **必须**引官方原文 + 文号（L1） |

### §4.1 密度约束

- 全篇案例（含例证）**不超过总页数的 1/3**，避免"通篇讲故事、不见观点"。
- **相邻两页不得都是整页案例**（版式多样性，见 `deck-gotchas.md §三`）。
- 每个整页案例**必须**有 ⑤ 启示段，且启示必须回收本页结论。

## 五、出处硬要求（写作规范）

| 项 | 要求 |
|---|---|
| 位置 | 案例框 / 案例页**底部**单独一行，字号用 T6（9–11pt） |
| 格式 | `出处：<机构>《<文献/文件标题>》<版本或文号>，<日期>` |
| 交叉验证 | 案例的**结果数据**须满足 C1 交叉（≥2 独立来源，含 ≥1 个 L1/L2）；**单一来源的数据必须标注**"单一来源，待交叉" |
| 时效 | 实习 / 答辩案例优先 **近 3 年**；党建党政案例**以现行有效文件为准**，旧版本须标注已被替代 |
| 匿名 | 涉商业秘密 / 个人隐私的主体，须**匿名化**（如"A 公司""某同学"）并**注明已匿名**；匿名后仍须保出处（"据 XX 年报"） |
| 与配图一致 | 案例配图必须是**该案例本体**的图，不得用无关图冒充 |

### §5.1 与来源卫生的衔接

- 案例素材进入结构前，**必须**过 `source-hygiene.md §三` 的相关性三问（归属 / 新鲜 / 口径）。
- 淘汰的候选案例进**污染隔离区**，写明淘汰理由（如"L4 无署名""已被 2025 版替代"），**不静默丢弃**。
- 用户此前明确否决过的案例，**绝对不得**在后续轮次重新引入（`source-hygiene.md §五`）。

## 六、四场景差异速查

| 维度 | 教学 | 答辩 | 实习 | 党建党政 |
|---|---|---|---|---|
| 案例偏好 | 教材例题、课程实例 | 研究场景、调研对象 | 同业对标、市场案例 | 官方通报的典型 / 先进做法 |
| 来源要求 | L2（教材 / 考纲） | L2（数据 / 文献） | L2（年报 / 行业报告） | **L1（官方原文 + 文号）** |
| 结果数据 | 可为例题答案 | 必须（研究数据） | 必须（经营指标） | 可为定性表述（但须引原话） |
| 语气 | 启发、平实 | 严谨、有据 | 干练、结论先行 | 庄重、规范 |
| 篇幅形态 | 内嵌框为主 | 整页为主 | 并排对比为主 | 整页为主 |
| 常见失误 | 把虚构情境当案例 | 案例与样本口径不一致 | 用软文当行业数据（L4） | 不引文号、用旧版条例 |

> 场景定义与触发词见 `scenario-templates.md §三`。

## 七、质检员检查清单（并入四维·事实辨别性）

- [ ] 每条案例是否有 **S 编号**且级别为 L1/L2/L3？无编号或 L4 = **FAIL**
- [ ] 五要素是否齐全（整页案例）？缺 ④结果数据 = **WARN**；缺 ①②③⑤ = **FAIL**
- [ ] 结果数据是否带**数值 + 单位 + 时点**？空缺 = WARN；编造嫌疑 = FAIL
- [ ] 是否满足 C1 交叉？单源未标注 = WARN
- [ ] 出处行是否齐全、格式合规、字号为 T6？缺失 = **FAIL**（**覆盖条款**：若用户要求"成品可独立使用"，上屏出处行不再强制，改入**演讲者备注**或省略，由门禁 **A12** 逐页 FAIL 上屏来源，不由本项判 FAIL；见 `layout-selection.md` §1.3。注意 **S 编号仍须保留于备注**以便溯源，不可一并删除）
- [ ] 是否出现**编造主体 / 模糊来源**（"某企业""据悉"）？出现 = **FAIL**
- [ ] 教学场景是否把教材例题包装成"真实企业案例"？出现 = **FAIL**
- [ ] 案例数量是否超过总页数 1/3？超出 = WARN
- [ ] 相邻两页是否都是整页案例？是 = WARN（版式多样性）
- [ ] 是否动用了用户已否决的案例？出现 = **FAIL**

## 八、设计师产出增量（页面清单表新增列）

`campus-ppt-content-architect` 的页面清单表由 5 列扩为 **7 列**：

```markdown
| 页 | 章节 | 结论式标题 | 核心要点（≤5） | 资料出处 | 配图 | 案例 |
|----|------|-----------|---------------|----------|------|------|
| 1 | 封面 | …… | — | — | 模板视觉 | — |
| 2 | 总览 | …… | …… | S1 | 图表：模块占比 | — |
| 4 | 模块A | 结论句 | …… | S2,S3 | 示意图 1 张 | 内嵌框 C1 |
| 7 | 案例 | 结论句 | …… | S5 | 实景 1 张 | 整页 C2 |
```

### §8.1 两列的填写规则

| 列 | 允许值 | 说明 |
|---|---|---|
| **配图** | `无` / `图表：<类型>` / `示意图` / `实景` / `模板视觉` / `待补充` | 一旦填了非"无"，采集员必须采回（见 `media-standard.md`） |
| **案例** | `无` / `例证 C_N` / `内嵌框 C_N` / `整页 C_N` / `待补充` | 一旦填了非"无"，采集员必须采回**含出处**的真实案例 |

> **两列必填**（可填"无"）。留空视为未做结构设计，主理人应退回。
> 填了 `待补充` 的条目，制作员**不得**自行填充内容，须回传主理人。
