# 四维质检标准（Quality Evaluation Standard）

> 总目标：保障"资产接入 WorkBuddy 体验"——用户拿到的 PPT 与专家团交付，必须**任务做完、指令照做、事实真实、规则不破**，且安装包干净、官方校验可过。
> 本文件是质检员（campus-ppt-qa）的执行细则；四维任一项 FAIL 不得放行。

## 维度一：任务完成度（Task Completion）

**定义**：交付物是否覆盖用户全部诉求与设计师的页面方案，无缺页、无遗漏要点。

**检查项（每条含 期望 / 判定方法 / 严重度）**：

1. **页面覆盖**
   - 期望：实际页数 = 结构方案页面清单，无缺页、无多余废页。
   - 判定方法：逐页比对结构方案 `页面清单表` 的页号与标题。
   - 严重度：缺核心页 → FAIL；多 1-2 装饰页 → WARN。
2. **要点覆盖**
   - 期望：每页核心要点（≤5）全部落地，无"待补充"残留在终稿。
   - 判定方法：逐页核对要点条目与资料对应关系。
   - 严重度：核心要点缺失 → FAIL；次要要点缺失 → WARN。
3. **用户显性诉求覆盖**
   - 期望：用户在分诊中明确的场景/平台/时长要求均被满足；口径基线 `01-brief.md` 的 `must_have` 全部落地、`must_not` 全部未出现。
   - 判定方法：回看主理人分诊记录与 `01-brief.md`，逐项核对。
   - 严重度：关键诉求未满足（如"要广财模板"却用错）→ FAIL；出现 `must_not` 内容 → FAIL。
4. **讲稿/时长（若要求）**
   - 期望：结构方案中的讲稿要点与秒数被体现或可导出。
   - 判定方法：检查备注页/讲稿是否存在。
   - 严重度：缺失 → WARN。
5. **阶段完整性**
   - 期望：`CAMPUS_PPT_STATE.md` 的 `phase_status` 全部为 `done`；存在 `blocked`/`skipped` 时报告须说明原因。
   - 判定方法：读状态清单，核对 `artifacts` 是否齐备。
   - 严重度：关键阶段 `blocked` 且未说明 → FAIL；`skipped` 未说明 → WARN。
6. **配图覆盖（新增）**
   - 期望：结构方案 `配图` 列标了内容的页面全部落实；`待补充` 条目在终稿中**明确标注**而非无声缺图；每页至少 1 个非文字元素（图表 / 图形 / 图片）。
   - 判定方法：逐页比对 `配图` 列与成品；扫"全字页"。
   - 严重度：标的配图缺失 → **FAIL**；`待补充` 未标注 → FAIL；出现全字页 → WARN。
   - 依据：`media-standard.md` §三/§七。
7. **案例覆盖（新增）**
   - 期望：结构方案 `案例` 列标了内容的页面全部落实；五要素（背景/冲突/做法/结果/启示）齐全；案例总量未超总页数 1/3；相邻两页不同时是整页案例。
   - 判定方法：逐页比对 `案例` 列与成品，核查五要素与占比。
   - 严重度：标了案例却缺失 → **FAIL**；五要素缺 ④结果数据 → WARN；缺 ①②③⑤ → FAIL；占比超限 → WARN。
   - 依据：`case-standard.md` §二/§三/§四/§七。

**验收阈值**：完成度维度 0 FAIL 即通过（WARN 可接受并附提示）。

## 维度二：指令遵从性（Instruction Compliance）

**定义**：交付物是否严格遵循主理人调度指令、结构师方案、模板规范与制作员转译指令。

**检查项**：

1. **模板遵从**
   - 期望：使用约定模板（广财 / 党政默认或用户提供），未私自换模板。
   - 判定方法：核对（a）所用模板是否符合 `scenario-templates.md` 的场景决策；（b）页面显式 `srgbClr` / `typeface` 是否**全部来自该模板的提取结果**。**不要以"是否携带模板母版"作为判定依据**——官方 `tencent-pptx` 路径（A）本就不带模板原生母版（详见 `template-application.md §〇`）。
   - 严重度：错用非约定品牌模板 → FAIL（涉品牌合规）；风格微调 → WARN。
2. **配色取自主题**
   - 期望：配色取自模板主题色，无硬编码新增色。
   - 判定方法：抽查色值是否等于模板主题色板。
   - 严重度：出现无关硬编码色 → WARN；大面积违和 → FAIL。
3. **字号层级**
   - 期望：T1–T7 七级齐全且**单调递减**（T1 > T2 > T3 > T4 ≥ T5 ≥ T6），同层级全篇一致，且**每一级都能追溯到该套模板的实测值**（`body-typography-standard.md` 附录 A）。
   - 判定方法：抽查典型页字号；核对是否等于模板实测值（**不是**"看起来像"）；检查是否出现孤立异常值。
   - 严重度：写了与模板无关的通用值（如"正文 18pt"当模板实为 14pt）→ **FAIL**；同层跳变 / T5–T6 反序 → WARN；层级混乱影响阅读 → FAIL。
   - 依据：`body-typography-standard.md` §二/§八。
4. **正文样式落实（新增）**
   - 期望：中文字族与模板 `a:ea` 一致；已执行换行预算（目标形状 `cx` 未膨胀超模板原值 ×1.05）；已执行 `slide_set_text_property` 字号回填（无字号丢失）；**排版结论附逐页出图**。
   - 判定方法：取 `slide_get_page_info` 比对 `cx` 与字号；跑 `slidep screenshot` 逐页目视。
   - 严重度：`cx` 膨胀 / 字号丢失 → **FAIL**；未附出图却声称"排版无溢出" → **FAIL**（不得默认通过）；字族被改成通用字体 → FAIL。
   - 依据：`body-typography-standard.md` §五/§六/§七。
5. **页面顺序与标题**
   - 期望：页面顺序与结论式标题与方案一致。
   - 判定方法：逐页比对。
   - 严重度：顺序错乱或标题被改回描述句 → WARN；关键信息页错位 → FAIL。

**验收阈值**：遵从性维度 0 FAIL 即通过。

## 维度三：事实辨别性（Fact Discrimination）

**定义**：资料、数据、引用均真实可溯，无编造、无断章取义。

**检查项**：

1. **出处完整**
   - 期望：所有数据/政策/定义类内容均有采集员 `S 编号` 出处（URL+时间戳）。
   - 判定方法：逐条事实回溯采集报告来源表。
   - 严重度：终稿出现无出处关键数据 → FAIL；次要数据无出处 → WARN。
2. **无编造**
   - 期望：无"据传""大概"式虚构数据、无臆造 URL。
   - 判定方法：抽查数据与 URL 可访问性/合理性。
   - 严重度：发现编造 → FAIL。
3. **引用准确**
   - 期望：原文摘录未被断章取义、未改数值。
   - 判定方法：比对摘录与官方原文。
   - 严重度：歪曲原意 → FAIL；轻微省略 → WARN。
4. **交叉验证**
   - 期望：关键事实≥2 独立来源（依采集标准）。
   - 判定方法：看来源表是否多源。
   - 严重度：单一来源关键事实 → WARN（提示补验证）。
5. **来源卫生（新增）**
   - 期望：无 L4 淘汰来源（营销软文/SEO 聚合/无署名搬运）内容进入大纲或成品；未引用用户**已删除/已否决**的内容；过期版本已标注。
   - 判定方法：核对采集报告来源表的「级别」列与「污染隔离区」；比对口径基线 `01-brief.md` 的 `must_not`。
   - 严重度：L4 来源进入成品 → **FAIL**；引用了用户已删除内容 → **FAIL**；违反 `must_not` → **FAIL**。
   - 依据：`source-hygiene.md` §二/§三/§五。
6. **采集方式可核**
   - 期望：采集报告如实声明本次是否使用 browser-skill、是否发生降级、降级原因。
   - 判定方法：看报告"边界声明"与来源表「获取方式」列。
   - 严重度：宣称"已交叉验证"但实为降级产物 → **FAIL**（冒充已核验）。
7. **配图来源可查（新增）**
   - 期望：每张图片有来源级别（P1–P5）与许可；无带水印 / 无署名 L4 图；AI 生成图已标注「AI 生成·非实拍」；图片已落地为本地文件（非远程 URL）。
   - 判定方法：核对采集报告「图像来源表」与成品内 `ppt/media/`；抽查文件是否存在。
   - 严重度：图片无来源级别 → **FAIL**；AI 图未标注 → **FAIL**；使用 L4 水印 / 搬运图 → **FAIL**；交付远程 URL（成品缺图）→ FAIL。
   - 依据：`media-standard.md` §二/§七。
8. **案例可溯源（新增）**
   - 期望：每条案例有 `S 编号` 且级别为 L1–L3；五要素齐全；结果带数值+单位+时点；出处行齐全（T6 字号）；无"某企业""据悉"式模糊来源；未使用用户已否决的案例。
   - 判定方法：核对采集报告「案例候选表」与成品案例页；回溯 S 编号。
   - 严重度：无编号 / L4 来源 / 模糊来源 / 编造主体 → **FAIL**；结果数据无出处或单源未标注 → WARN。
   - 依据：`case-standard.md` §一/§五/§七。

**验收阈值**：事实维度 0 FAIL 即通过（WARN 提示补源）。

## 维度四：规则遵从性（Rule Compliance）

**定义**：交付物与交付过程是否触碰 P0 红线与协作规范。

**检查项**：

1. **P0 视觉红线**
   - 期望：无 emoji 图标装饰、无渐变/发光/毛玻璃套路、无 Lorem ipsum 占位、无硬编码色、无弹跳缓动。
   - 判定方法：逐页目检 + 动画窗格检查。
   - 严重度：任一出现 → FAIL。
2. **备份提醒**
   - 期望：破坏性操作（覆盖原文件/压缩媒体/批量替换）前已提醒备份。
   - 判定方法：看制作说明是否含备份提醒。
   - 严重度：未提醒 → WARN。
3. **干净打包**
   - 期望：安装包仅含 `agents/*.md`、`skills/**/*.md`、`avatars/*.png`、`.codebuddy-plugin/plugin.json`、`settings.json`、`README.md`、`CHANGELOG.md`、`UPGRADE.md`（代码纯净，≤20M）；模板经腾讯文档「演示模板库」在线获取，不随安装包分发；无 `.py/.js/.pyc/__pycache__/测试/构建脚本`。
   - 判定方法：目录扫描。
   - 严重度：出现开发脚本残留 → FAIL。
4. **官方校验可过**
   - 期望：.pptx 能被官方 tencent-pptx / WPS 正常打开与校验，无损坏。
   - 判定方法：用官方 tencent-pptx / WPS / Office 打开并逐页检查（或渲染截图）；无该能力时按 zip 完整性 + 打开测试核验；**无法执行时须在报告中标「待复核」，不得默认通过**。
   - 严重度：无法打开/校验失败 → FAIL；未验证 → WARN（标"待复核"）。

**验收阈值**：规则维度 0 FAIL 即通过。

## 运行时门禁执行时机（四门 SOP）

判据全文与阈值以 `runtime-gate-thresholds.md` 为单一权威，本节只定**执行时机与 FAIL 流转**——四道门不是"质检员一个人的事"，而是按角色与模式档位分工：

| 执行角色 / 时机 | 几何门 | 字数门 | 页型门 | 视觉门 |
|---|---|---|---|---|
| 制作员出片后自检（轻 / 重两模式） | 必跑 | 必跑 | 不跑 | 轻模式在则必跑（建造纪律）；重模式必跑 |
| 质检员 · QA-lite（轻模式） | **必跑（底线）** | **必跑（底线）** | 不跑 | 在则跑，审美类结论判 WARN 不阻塞 |
| 质检员 · 四维全检（重模式） | 必跑 | 必跑 | 必跑 | 必跑 + 逐页 slidep 出图目视 |

- **缺脚本降级**：按 `runtime-gate-thresholds.md` §一 人工核对，只能标「未验证」；
- **模式档位判定**（轻 / 重）见 `interaction-protocol.md` §六；制作员自检口径见 `campus-ppt-make` 使用原则「出片后自跑两道门」。

**门禁 FAIL 与四维判定的衔接**（门禁红 → 报告里落到哪一项）：

| 判红的门 | 回填到 |
|---|---|
| 字数门 | 任务完成度 · 内容信息量判据（正文页 < 200 字 = 内容不足） |
| 几何门 | 指令遵从性 · 正文样式落实 或 出片项（重叠 / 出界 / 贴边） |
| 页型门 | 指令遵从性 · 页型契约（页没做自己该做的事） |
| 视觉门 | 指令遵从性 · 版面可复算合规（A1–A14 + AN） |

**FAIL 流转入口**：门禁非 0 → 按「页 / 断言编号 / 实测值 / 阈值」定位（原样引用断言编号，不得只写"XX 门 FAIL"）→ 精修指令经主理人回传制作员 → 制作员精修后**复跑全部门禁**（含未修的门）→ 四门全 0 回端复检；第 3 轮复验仍 FAIL → BLOCK，升重模式或报用户。完整四步见 `runtime-gate-thresholds.md` §一。

## 总验收规则

- 四维全部 0 FAIL → **通过**（可附 WARN 提示）。
- 任一维度 FAIL → **不通过**，进入下方闭环。
- 仅 WARN（且无 FAIL）→ **通过（附风险提示）**。

## 不通过 → 精修 → 复验 闭环

**触发条件**：任意维度出现 FAIL，或 ≥2 个 WARN 且涉及事实/规则维度。

**精修动作清单**：
1. 定位：精确到"第 X 页 / 第 X 字段 / 第 X 动画"。
2. 派单：质检员将精修指令经主理人回传制作员（campus-ppt-maker）。
3. 精修范围（按维度）：
   - 完成度 FAIL → 补页 / 补要点，并**保持与原页同一路径**（路径 A 沿用原配色 / 字体规范；路径 B 继续**深拷贝模板页**改字），见 `template-application.md §〇`。
   - 遵从性 FAIL → 换回约定模板 / 改回主题色 / 修正标题与顺序。
   - 事实 FAIL → 删除编造内容或补真实出处（回采集员补采）。
   - 规则 FAIL → 移除 emoji/渐变/毛玻璃/弹跳；清理脚本残留；补备份提醒。
   - **运行时门禁 FAIL → 按「运行时门禁执行时机」节的 FAIL 流转入口走**：定位到断言 → 回制作员精修 → 复跑全部门禁。
4. 复验：原 FAIL 项须降至 PASS/WARN，且未引入新问题；复验仍 FAIL 则二次精修，最多 2 轮。

**复验标准**：
- 原 FAIL 项全部解除（PASS 或降级为可接受 WARN）。
- 新增页面/修改未破坏既有遵从性与事实性。
- 打包扫描复检通过。

> 闭环记录写入质检报告"精修指令 + 复验结论"段，确保可追溯，呼应"资产接入 WorkBuddy 体验"总目标。

## 内容信息量判据（v2 指标）

### 为什么废弃"几何覆盖率"作为丰满度指标

曾用「内容包围盒占 B 内容带面积」判断页面饱满度，**该指标会被空大框骗过去**：
一个 220×111 pt 的文本框只放 15 个字，包围盒面积很大，但信息量极低。
实测反例：某示例 7 页几何覆盖率全部落在 83%–96%（判"合理"），
但**正文页平均仅 93 字**，用户仍判"内容太少"。**几何覆盖率与信息量是两件事。**

### 改用：字数 + 要点密度

| 指标 | 定义 | 判据 |
|---|---|---|
| **总字数** | 该页所有 `<a:t>` 文本字数之和（含标点） | 正文页 **200–250 字/页**（教学课件经验区间） |
| **要点密度** | 长度 ≥6 字且非纯数字的文本块数 ÷ 文本块总数 | ≥ 40% |
| **少字页豁免** | 封面页 / 结尾页 / 章节过渡页 | 天然少字，**不追 150 字**，但须有标题 + 导语 + 落款三层 |

### 交付前必测（不可只看渲染图"感觉空"）

```bash
# 逐页统计字数与要点密度，与目标区间比对
$PY measure.py <产出件.pptx>
```

**执行时机**：制作员出片后自跑 + 质检员按档位复跑（QA-lite 为底线门、四维全检必跑），见上方「运行时门禁执行时机」；`measure.py` 退出码 0 = 字数门通过，非 0 按 FAIL 流转入口回流。

**判定**：正文页平均 < 200 字 → 判「内容不足」，须补；
**禁止**用"版面看起来不空"替代字数测量——这是本条标准的设立原因。

### 扩充内容时的红线

1. **不得为凑字数编造**：统计数据、案例、文献、页码一律不得虚构（见 `source-hygiene.md`）。
2. **先量几何再写文案**：每条文案字数 ≤ `框宽 ÷ 字号 × 可用行数`，超出会触发 `spAutoFit` 撑宽并压到相邻元素（见 `deck-gotchas.md` §十）。
3. **落到顶的页要明示**：几何容量用尽的页（如全文已写满框、空白带属禁放区）应如实说明"已到顶"，不得硬塞导致溢出。
