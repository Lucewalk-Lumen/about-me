# 多章出片与批量对账（Batch & Reconciliation）

> 面向主理人 + 制作员 + 质检员。当任务从"单份 deck"升级为"一套教材 / 课程 → 多章、每章一份 deck"时使用。
> 来源：吸收自社区批量课件出片的通用实践（编排与对账）；**引擎仍走官方 tencent-pptx / WPS**，本文件只补"编排 + 对账"的 know-how。

## 一、何时启用

- 输入是一本教材 / 长篇讲义 / 课程大纲，产出是**多个** .pptx（一章一份），共用一套品牌模板。
- 单份 deck 仍走常规单流程；本文件只处理"多份 + 批量"。

## 二、编排（对齐本团铁律）

1. **先锁决策**：章 → 文件映射（一章一份？合并？）、来源优先级、**每章页数与密度目标**、是否先出"样章"。
2. **样章先行**：先做好**第 1 章**作为"保真锚"（走四维质检），经用户确认后再铺开——锚点消除并行偏差。
3. **并行铺开**：按"样章"给每章一份**固定简报**（字段模板见下），由主理人按波次派发（对齐"主理人 TeamCreate → 分诊 → 中转 → 回传 → 门控"，**成员不互连**）。
4. **返工闭环**：样章至少过一轮"密度 + 多样化"返工再铺开；未确认的锚点绝不下发。

### 每章固定简报（波次派发的最小单元，九字段缺一不派）

| 字段 | 内容 | 来源 |
|---|---|---|
| `chapter_id` | 章号 → 文件名映射（如 `ch03 → 第3章-XX.pptx`） | Phase 0 锁决策 |
| `source_refs` | 本章素材出处（S 编号 / 采集报告行号），复述忠实、可回溯 | 采集报告 |
| `template` | 共用模板名 + file_id + 本地缓存路径（全批同一套） | Phase 0 + `tencent-docs-template-source.md` |
| `page_target` | 本章页数与密度目标（页数 ≈ 知识点数；每页 ≤5 要点、≥1 非文字元素） | Phase 0 |
| `anchor_ref` | 样章文件路径 + 三项钉死口径（T1–T7 字号实测表 / 配图落位 / 案例出处行样式） | Phase 1 样章 |
| `layout_rotation` | 版式多样性要求（七条轮换规则） | `layout-selection.md` §五 |
| `must_have` / `must_not` | 本章必须落地 / 不得出现（与 `01-brief.md` 一致） | 口径基线 |
| `gate_plan` | 出片后自跑几何 + 字数门；每章质检按四维全检（批量命中重模式） | `runtime-gate-thresholds.md` §〇 |
| `deliver_path` | 本章输出目录（与最终投递位置同路径，防样章镜像缺口） | Phase 0 |

### 波次派发节奏

1. **波次大小**：默认每波 ≤3 章（主理人中转带宽与质检排队深度所限）；样章确认后的**第 1 波只派 1 章**（试产波）——流程跑通、口径无漂移后再放全量波。
2. **波次门**：每波结束做主理人级抽点（章数 / 命名 / 逐份可打开 / 简报字段回执），通过才开下一波；**波次内任意一章 FAIL → 暂停续派**，精修复验通过后续派。单章失败只标该章 `branch: chNN=blocked`，**不连坐整批**（`task-state-resume.md` §五）。
3. **状态落盘**：每章进度以 `branch: chNN=done/blocked` 登记进 `CAMPUS_PPT_STATE.md`；断点续传从首个非 done 章继续，不整批重来。
4. **串行降级**：无并行派发能力（缺 TeamCreate / Agent）时按同一简报串行执行，**不得宣称并发**（见 §五）。

## 三、逐章质检（四维 + 出片项）

- **批量命中重模式**（Tripwire 触发信号含"一章一份 / 多班级 / 多 deck"），每章按**四维全检**执行：四门全跑 + 逐页 slidep 出图（`runtime-gate-thresholds.md` §〇）。**批量不降低单章门禁**，也不许多章合并跑一门交差——退出码以单章文件为准。
- 每份 deck 都要过四维质检 + `deck-gotchas.md` 的出片项（溢出、占位残留、水印、变形）。
- 明确可接受的残差：封面/结尾模板图、有意出血。

## 四、批量对账（收尾必做）

每波结束先做**波次小对账**（波内章数 / 命名 / 逐份可打开），通过才开下一波；全部波次完成后做**批级对账**：

1. **数量合计**：实际文件数、总页数与计划对账（分支登记以 `CAMPUS_PPT_STATE.md` 的 `branch:` 为准）。
2. **逐份可打开**：每份都能被官方 / Office 正常打开。
3. **产物一致**：同一份 deck 在"输出目录"与"投递位置（资料库 / 网盘）"应一致（可用 md5 比对）——路径一致性靠简报 `deliver_path` 字段保证。
4. **样章镜像缺口（经典坑）**：手工做的样章常**不会**自动随其他 deck 同步到投递位置——收尾时**显式补投样章**并复核。
5. **大文件陷阱**：单个大 deck 云端渲染报"无效文件"时，先确认是路径错或尺寸上限，而非真损坏（见 deck-gotchas.md §五）。

## 五、边界

- 本文件不引入任何自带生成脚本；多章出片仍由官方技能逐份生成。
- **返工以章为单位**：单章 FAIL 只精修该章（保持与该章同一路径），不跨章合并返工，**不得以样章复制改名冒充其他章产出**。
- 若运行环境缺少并行派发能力（无 TeamCreate / Agent），主理人按同一简报**串行**执行，**不得宣称并发**。
