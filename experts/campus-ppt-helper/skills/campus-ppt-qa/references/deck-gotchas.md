# 出片避坑清单（Deck Gotchas）

> 面向制作员 + 质检员。汇总"出片阶段最容易翻车"的通用陷阱，**按类别排查，不绑定具体渲染引擎**。
> 来源：吸收自社区批量课件出片的通用实践，已去除 python-pptx 专有细节，保留可迁移的通用项。

## 一、环境 / 依赖

| 症状 | 根因 | 处理 |
|---|---|---|
| 模板转图 / 预览卡住或超时 | 渲染依赖（LibreOffice / poppler）缺失或网络受限 | 校验依赖；缺渲染器时改用"直读 `theme1.xml`"取色（见 template-application.md），不强行装环境 |
| 预览生成失败却宣称"出片成功" | 未区分"已生成"与"可预览" | 如实标注"已生成，预览依赖未就绪"，不谎称校验通过 |
| 采集阶段"站点全部不可达" | 其实 browser-skill 未就绪（CLI 缺失 / 守护进程未起 / 扩展未连），被误判为站点问题 | 先做预检 `BSK_AUTO_START=0 bsk status --json`；不可用即降级，见 `browser-skill-integration.md` §一/§五 |
| 采集命令反复失败、空转 | 沙箱环境未跨调用保持 `BSK_HOME` / `BSK_AUTO_START` | 每条 `bsk` 命令都带同一 `BSK_HOME` 与 `BSK_AUTO_START=0`，不跨任务复用 session |
| 会话崩溃 / 重连后"从头再来" | 流程状态只在会话内存 | 每阶段落盘 `CAMPUS_PPT_STATE.md`，恢复时先找状态文件续跑，见 `task-state-resume.md` |
| 成品里混进无关 / 过时内容 | 采集未分级、无相关性闸门 | 按 `source-hygiene.md` 分级（L1–L4）并过三问闸门，L4 进污染隔离区 |

## 二、模板沿用（最容易翻车）

| 症状 | 根因 | 处理 |
|---|---|---|
| 整篇像"通用蓝"，不像所选模板 | 未读模板主题，套了通用预设 | 强制走 template-application.md 提取真实色板 |
| 指令里的配色是编造 hex | 把示例色值当"取自模板" | 每个 hex 必须可追溯到提取结果 |
| 母版占位文字残留（如"单击此处编辑标题"） | 套模板未清理占位 | 出片后逐页扫占位残桩 |
| 模板自带装饰被整体删光，成品"素白" | 把模板"页层装饰"误当冗余清理掉 | **模板视觉长在页层，是模板本体，不得删**；出片用 `slide_duplicate_slide` 整页深拷贝 |
| 同一字号在 A 模板正常、在 B 模板显得过大 | 15 套模板**画布不统一** | **广财-07 为 720×405pt，其余 14 套为 960×540pt**（0.75×）。坐标、边距、字号观感与图片尺寸**均须按画布换算**，不可跨模板套用固定值；先读 `ppt/presentation.xml` 的 `<p:sldSz>`（见 `body-typography-standard.md` §5.0） |

- **是否"过模板"的判定**：看页面显式 `srgbClr` / `typeface` 是否全部来自模板提取结果；**不要用"是否带模板母版"来判**——官方 tencent-pptx 路径（A）本就不带模板原生母版，需在交付说明中如实标注；如客户要求模板保真，改走 tencent-local-office-edit 路径（B），见 `template-application.md §〇`。
- **判保真严禁用 md5**：走路径 B（编辑器落盘）时，母版 / 版式 / 主题会被**重序列化**（`r:id` 重编号、删 `p14:creationId`、形状 id 重编号），字节 md5 **必然改变**——用 md5 判会误判为"没保真"。**必须做语义比对**：版式数量与名称、几何签名（形状 name + 占位符 type + x/y/cx/cy）、主题槽位、内嵌字体。
- **【重要】 只比母版 / 版式层会"假保真"（实测真实事故）**：模板视觉（logo 图片、品牌色块、装饰矩形、图形）**挂在"页"层，不在母版 / 版式层**。若出片只验母版 / 版式 / 主题，会得出"11/11 版式几何签名一致 ⇒ 保真成立"的**错误结论**，而产出件其实是**零图片、零装饰、只剩文字**。⇒ **保真判定必须落到页层**：解包数 `ppt/slides/*.xml` 的 `<p:pic>` / `<p:sp>`，且**用 `slidep screenshot` 逐页出图目视**。
- **路径 B 禁用 `slide_add_slide` 建页**：该工具只带母版层（浅灰底 + 版式占位符），`shape_count = 0` 且**页层视觉一律不继承**。出片必须用 `slide_duplicate_slide` 深拷贝设计正确的模板页，再 `slide_set_text` 改字。
- **`slide_set_text` 后必须回填字号 + 控制换行**：该工具会重置字符级样式；文本框多带 `spAutoFit`，**单行长文本会把框撑宽**（实测 `cx` 245pt → 706pt 横穿版面）。⇒ 文本自带 `\n`，随后 `slide_set_text_property` 回填模板原字号。
- **像素级外观是必做项**：`slidep screenshot <file> --page-index <i>`（editor_sdk，不需 Office）；无渲染环境时用 `Spire.Presentation` 离线渲染。**"结构 / 语义保真"不能替代逐页目视**。

## 三、内容密度与版式多样性

| 症状 | 根因 | 处理 |
|---|---|---|
| "每一页没细节" | 密度未锁定 | 一页一个知识点；每页 = 定义 + 解释 + 例/data |
| "排版都一样、很单调" | 只用一种版式 + 每页同一色带 | 轮换版式（图文/两栏/卡片/流程/陈述）与收尾样式 |
| 连续多页等宽卡片横排 | 版式惯性 | 相邻页版式不得重复；视觉重量需有差异 |

## 四、图片

| 症状 | 根因 | 处理 |
|---|---|---|
| 图片带水印（图库站） | 免费图源带水印 | 换干净来源；官方**生成**图水印属正常，**不得**为遮掩而裁掉 |
| 图片被拉伸变形 | 固定 w×h 忽略原图比例 | 等比缩放 + 居中裁剪 |
| 空图占位框 | 图片缺失未兜底 | 用与主题一致的完整无图版式兜底，绝不留空框 |
| **贴图报错 -32603** | `slide_add_image` 的 `image` 传了 **http/https 远程 URL** | 该工具**不取远程字节**，会明确报错 `remote URLs (http/https) are not supported; pass a local absolute path or a data URI instead`（**实测：硬报错，非静默丢图**）。先把图**下载到本地**再传本地绝对路径，见 `media-standard.md` §六 |
| **自检说"媒体全丢"，但文件其实完好** | 保存后媒体**迁移**到 `ppt/slides/media/`（图表在 `ppt/slides/charts/`），仍按 `ppt/media/` 统计 | 统计口径要**同时扫 `ppt/media/` 与 `ppt/slides/media/`**。本次验证初次即踩此坑、误判为"media: 0"（见 `media-standard.md` §6.5） |
| 图片没铺满预留框 / 留白不均 | `slide_add_image` **会按原图比例自动修正宽高**，你给的 `w` 可能不被采纳 | 先把按比例算好的 `w` 与 `h` **一起传**，别只定 `w`；落位后用 `slide_get_page_info` 复核实测几何 |
| 图压住页眉色条 / logo / 装饰 | 未先读模板页层形状包围盒就落位 | 先用 `slide_get_page_info` 取"页层非占位符形状"包围盒作禁入区，**再**算图位置；不要"先放图再看哪被压" |

## 五、渲染 / 预览 / 校验

| 症状 | 根因 | 处理 |
|---|---|---|
| 文字溢出 | 交付前未把溢出降为 0 | 出片后逐页检查溢出；残差只允许出现在封面/结尾模板图与有意出血。**且须主动预防**：按 `body-typography-standard.md` §五 算换行预算（框宽 `cx` 膨胀是已发生过的真实事故） |
| 文本框被撑宽、横穿版面 | 写入长文本前未做容量预算 | 文本自带 `\n` 断行 + 写后复核 `cx` 未超模板原值 ×1.05 + 用 `slide_set_text_property` 回填字号（见 `body-typography-standard.md` §五/§六） |
| 大文件云端报"无效 PPTX" | 多为路径错或渲染尺寸上限，非真损坏 | 先 `zipfile.testzip()` + 能否打开复核，再从正确路径渲染 |
| 页数与计划不符 | 未做合计对账 | 见 batch-qa-reconciliation.md |

## 六、生成指令（DSL）与主题残留

| 症状 | 根因 | 处理 |
|---|---|---|
| 装饰色块盖住下方文字（截图才暴露，lint **不报错**） | DSL 中 `position: 'absolute'` 的装饰层压在未定位的内容 Box 之上 | 装饰层设 `zIndex: 1`、内容层设 `position: 'relative', zIndex: 2`；出片后**必须看截图**校验层级，不能只信 lint |
| 成品 `theme1.xml` 残留 Office 默认主题（`4472C4` 等） | 生成器自建空白稿自带默认主题 | **可接受**：判定标准是"页面是否引用 `schemeClr`"，页面引用数为 0 即不影响观感；**不要**为对齐主题槽位而解包改写 XML（会绕开官方工具链、破坏可复现性） |
| 图表位置/尺寸算错，偏出画布 | **官方 `slide_add_chart` 描述首段写 "pixels at 96 DPI"，参数说明写 "points"** —— 文档自相矛盾 | **已实测定案：单位是 points**（传 x=300 y=250 w=380 h=130 → 落盘 300.0/250.0/380.0/130.0）。描述首段系官方笔误。`slide_add_image` / `slide_add_table` 同为 points。首次调用后仍建议 `slidep screenshot` 出图核对（查遮挡，非查单位），见 `media-standard.md` §6.2 |
| 读图表 / 表格几何读不到 | `p:graphicFrame` 的变换在 **`p:xfrm`**，不是 `a:xfrm` | 解析脚本须区分：`p:pic` / `p:sp` 用 `a:xfrm`，`p:graphicFrame` 用 `p:xfrm` |

> 说明：本清单与具体引擎无关；若运行环境提供官方 `qa_pptx` 之类的逐页校验，优先调用，并把其输出纳入四维质检。

## 九、editor_sdk 契约陷阱（端到端实测，6 条）

| # | 陷阱 | 症状 | 正确做法 |
|---|---|---|---|
| 1 | `slide_remove_slide` 的参数是 `page_index`（**单数**） | 传 `page_indexes` 报 `-32603 requires: page_index` | 用 `page_index`；**倒序删**避免索引位移 |
| 2 | `slide_duplicate_slide` 有 `target_page_index` | 批量复制时插入位置并非"紧跟各源页" | 默认是「插在**最后一个被复制页之后**」；要精确控制**必须显式传 `target_page_index`**。**更正本文件旧记录**"副本默认插在源页之后"——那是单页观察的偶然结果 |
| 3 | `slide_add_chart` 的 `chart_type` 是**白名单** | 传 `column` 报 `-32603 unsupported chart_type` | 用全名：`clusteredColumn` / `stackedColumn` / `line` / `pie` / `doughnut` 等 |
| 4 | `slide_add_image` 的 `h` 是**必填** | 只传 `w` 报 `requires: page_index, x, y, w, h, image` | `w`/`h` 都要给（工具仍按原图比例自动修正，但必填项不能省） |
| 5 | `slidep screenshot` **按文件路径缓存已打开的文档** | 改完 pptx 再用**同一路径**出图，拿到的是**旧版渲染**（实测 3 次：PNG 字节数与旧版完全一致，一度误判为"没生效"） | **每次出图用唯一文件名**（如 `_r_$(date +%s%N).pptx`），或先 `close_file`。**校验法**：出图后比对 PNG 字节数是否随改动变化 |
| 6 | 删页后**新页序号 ≠ 原页序号** | 删掉原第 5、7 页后，新页 5/6 实际来自原 6/8；按新序号查原始形状会取到已删页形状，报 `page not found` | 维护 `SRC = [新页序 → 原页序]` 映射；**优先按原文签名定位形状**，不要硬编码 id（id 也会话级漂移） |

## 十、spAutoFit 撑宽是排版越界的根因（本次再实测确认）

`slide_set_text` 会把文本框**撑到文本宽度**，**不报错、不提示**。端到端实测：

| 形状 | 原始 `cx` | 写入后 `cx` | 撑宽 | 后果 |
|---|---|---|---|---|
| 三卡片左正文 | 220 pt | **397 pt** | 1.8× | 压到相邻形状 |
| 三卡片右正文 | 220 pt | **383 pt** | 1.7× | 出框 |
| 章节页大数字（写 `2018`） | 56 pt | **160 pt** | 2.9× | 与相邻数字**重叠** |
| 章节页大数字（写 `1`） | 56 pt | 160 pt | — | 仍偏大 → **大数字位只宜 1 字符** |

**换算公式**：`可容字数 ≈ 原始 cx ÷ 字号`（中文全角约 1 字 ≈ 1 字号宽）。中英混排文本按**当量**折算（全角 1 / 半角 0.5，见 `body-typography-standard.md` §5.1）。
**写长文案前必须按此反算上限**，而不是看原始宽度"好像装得下"。

> 与 `body-typography-standard.md` 的换行预算互为补充：那份讲**纵向行数**，本条讲**横向撑宽**。

## 十一、新增文本框（`slide_add_text`）也会溢出画布底边

`slide_add_text` 新建的文本框**按 `w` 换行**，一旦文字超出会**向下换行**；若框底已贴近画布底边（405 pt），第二行就**掉出画布**。本次实测两处：

| 位置 | 文字 | w × 字号 | 结果 |
|---|---|---|---|
| 案例页出处行 | 40 字 | 430 ÷ 12 ≈ 35 字 | **换行溢出**，第二行落到 y≈393 pt（画布高 405） |
| 证据页来源行 | 两行各 25 字 | 400 ÷ 12 ≈ 33 字 | **换行溢出** |

**规避**：新增文本框前先算 `单行容纳上限 = w ÷ 字号`，**文字超限就先精简或加宽**，不要指望它自动缩放。
本次修法：出处行与来源行**合并为一行**并把 `w` 提到 690 pt（≈ 57 字），一行容下。

**同时注意色块避让**：封面青色块实测占 y=159–279 pt；把灰字放到 y=232 会**压块且对比度不足**。补内容前先量模板装饰的实际区间。

## 十二、模板正文占位符的 `wrap="none"` + `spAutoFit` 撑爆（QA 实测，唯一真正卡住产出的坑）

**症状**：`slide_set_text` 写入长文案后，文本框 `a:ext.cx` 被改成**文本宽度**，
长文单行冲出画布、大面积压住相邻元素（实测 P4 正文框 220 → **789pt**，右边界到 **1295pt**，画布仅 720pt）。

**关键坑点**：**事后单独设 `wrap="square"` 无效**——因为框已经被撑大了。
必须**三步同做**（顺序不能换）：

```
1) 复位：把 a:ext.cx / cy 改回模板原值
2) 换行：<a:bodyPr wrap="square">
3) 自适应：<a:bodyPr><a:normAutofit/></a:bodyPr>
```

模板的正文占位符**默认是 `wrap="none"`**，这是本轮唯一真正卡住产出的原因——
规格表算容量时若漏了这条，会按"行数"算出合规字数，实际却全部横向溢出。

**容量判据（正确版）**：对 `wrap="none"` 的形状，必须按**横向**判：

```
x + 文案字数 × 字号 ≤ 同排下一元素 x − 15pt
```

而非按行数。只有完成上述三步复位后，才可用"字/行 × 行数"的纵向判据。

> **当量口径（2026-10-14 补）**：容量判据公式中的"字数"按**当量**折算——中英混排文本全角 1 / 半角 0.5，与容量预算、字数门同一把尺（见 `body-typography-standard.md` §5.1 与 `runtime-gate-thresholds.md` §二），消除"字数"与"当量"的口径微差。

## 十三、`slidep screenshot` 在**同一个文件路径上的第一次调用必定失败**

对一个**新路径**的 pptx 执行首次 `slidep screenshot`（无论 `--page-index` 是几）
都会报 `presentation is not open`（HTTP 500）——**与页号无关，是文档尚未打开**。

**正确做法：先渲任意一页当预热（结果可丢弃），再渲目标页**：

```bash
SRC="_r_$(date +%s%N).pptx" && cp "$DECK" "$SRC"   # ① 必须用唯一文件名，避开路径缓存
slidep screenshot "$SRC" --page-index 3 --out /tmp/_warm.png >/dev/null 2>&1   # ② 预热，结果丢弃
for i in 0 1 2 3 4 5 6; do
  slidep screenshot "$SRC" --page-index $i --out "_out/p$((i+1)).png" >/dev/null 2>&1
done
rm -f "$SRC"
```

> **两个坑叠加**：① 路径缓存 → 必须换唯一文件名；② 首次必失败 → 必须先预热。
> 漏掉任一条都会拿到**旧版渲染**或**缺页**，而缺页是静默的（循环里 `>/dev/null` 会吞掉报错）。

**冷加载对照实验（判定"这次的图到底是不是新的"）**：
把**同一份**产出件复制到两个路径分别出图 —— **新路径（冷加载）** 与 **旧路径（缓存）**。
若两张 PNG 的字节数 / md5 **不同**，说明旧路径拿到的是**改前**的渲染。实测：`165578`（旧路径）vs `166246`（新路径），
而两次之间只改了图表文字色 —— 旧路径那张里标签依旧是深色。
> 因此**"渲染图看着没问题"不能作为验收证据**，除非出图路径是本次新建的。
> 更硬的验收依据是**可复算的门禁**（`check_visual.py` 等）——它直接读 OOXML，不经渲染器，不受缓存影响。

## 十四、几何检测必须递归 `grpSp` 且按类型取 xfrm

交付前跑几何门禁（重叠 / 出界 / 贴边）时，两个易错点：

1. **必须递归 `<p:grpSp>`**：目录条目、三角形等藏在 group 内，只扫顶层会**漏检**。
2. **xfrm 必须按形状类型取直接子路径**：`p:sp / p:pic` → `p:spPr/a:xfrm`；`p:graphicFrame` → `p:xfrm`。
   **用 `.//` 递归查找会命中嵌套 group 内部的 xfrm，导致同一形状被重复计入**（实测一次报出 61 处，其中 49 处是误报）。

> 另：`slidep screenshot` 会把出界文字**裁剪掉**，渲染图看着正常但文件几何已坏。
> **目视不能替代几何检测**——换到 PowerPoint / WPS 打开会看到文字冲出页面。

## 十五、视觉门禁的画布无关性（RF / AF 自适配）

视觉门禁 `check_visual.py` 不写死画布尺寸，直接读 `ppt/presentation.xml` 的 `<p:sldSz>`，并以两个因子把"与画布成比例"的阈值自动缩放，使**同一版式在广财-07 的 720×405 与其余 12 套 960×540 下判定一致**：

- `RF = 画布高 / 405`：用于**长度 / 距离**类阈值（死带 A4 的 `MAX_DEAD_BAND`、数字标签距离 `NUM_LABEL_DIST`、标签宽度上限），即"按画布高度比例缩放"。
- `AF = (画布宽 × 画布高) / (720 × 405)`：用于**面积**类阈值（重叠面积 A6 的 `200` 与占比 `0.05`）。

**字号类阈值（A1 / A7 / A11 的 36pt 基准、A2 / A9 的字号拟合）是绝对 pt，不随画布变**——因为字号是绝对单位，×4/3 升画布时字号保持不变。

> **改画布后的注意事项**：把 720×405 线性 ×4/3 升到 960×540（缩放几何、不碰字号）后，只要门禁读到了新的 `sldSz`，阈值即自适配，无需改门限常量。经实测：同一 deck 在两种画布下均退出码 0。

## 十六、大文件操作绕开 editor_sdk 桥，直改 OOXML

editor_sdk 的 `_request` 有**硬编码 30s 超时**：23MB 样片 `open_file` 实测 **4 分钟/次**，走桥必超时。

**分界原则**：

| 操作类型 | 通道 |
|---|---|
| 建页 / 删页 / 深拷贝模板页 / 设文本 / 插图图表 | 走 editor_sdk（`slide_duplicate_slide` 等，结构性操作） |
| 版面微调（`xfrm` 几何 / `bodyPr` 换行自适应 / `pPr` 字号行距） | **直改 `ppt/slides/slideN.xml`** |

**为什么版面走直改**：做版面的最小改动单元是 `xfrm` / `bodyPr` / `pPr`——全部落在 `slideN.xml` 里，直改**确定、瞬时、精确到 0.01pt**，不受 30s 超时约束。

**直改纪律**：改前备份整文件；每次从干净源还原再打补丁（幂等）；改后**必须重跑四道运行时门禁**（见 §十七）；只动 slide 级 XML，不碰母版 / 版式 / 主题（那是路径 B 保真单位，见 §二）。

## 十七、每轮修复必须重跑全部门禁（修 A 可能破 B）

**真实事故链**（样片第 8 版 → 第 9 版）：删金字塔治 A13 竖向空洞 → 连带删掉了承载深底的圆环 → 白字落到 `#EEEEEE` 浅底页面上（对比 **1.16:1**，A8 判红）；而当时的 A8 检出器以「被装饰覆盖」为前提，**装饰一撤就整体跳过**——白字压浅底也判 PASS（反向漏判）。

**纪律**：

1. 单点修复后，**四门（几何 / 字数 / 页型 / 视觉）全绿才算完**——只跑修的那一门，等于默认其他门没被破坏；
2. 每轮修复的**新引入缺陷**要记入补丁日志，与「本轮修了什么」并列；
3. 检出器本身被发现「结构上抓不到某类缺陷」时，**修检出器**，不是把缺陷内容删掉了事。

## 十八、色彩面积统计必须解析 `grpFill`

官方 `design-principle.md` 把「色彩面积分配」列为硬指标（主色 ≤60% / 辅色 ≤30% / 强调色 ≤10%，且至少 2 页比例须显著不同），`DESIGN.md` 必须落具体数值——而**肉眼看图给百分比等于编数**，必须从 OOXML 实算。

**坑**：组内形状的 `fillRef` 会被**组级 `grpFill` 覆盖**——只看子形状 `spPr` 统计，实测把 P2 主色占比从 **26% 误判为 1.7%**。

**处理**：色彩统计须先解析 group 的 `grpFill` 对子形状 `fillRef` 的覆盖关系，再按「实际生效填充」归类主 / 辅 / 强调色面积；统计不到生效填充的块单列「未解析」，不得默认计入任一色。

## 十九、内容只铺半页：A14 填充度断言（1.0.3，治「排版太多空白」）

**症状**：用户反馈「排版太多空白」——一页内容只铺上半页，下半页全空；或双栏一高一低。而当时的四道门禁**全部判绿**：A4 只管标题栏到最高元素的空带、A13 只管块与块之间的空洞、字数门只数字数、「留白 ≤35%」只是 DESIGN.md 里的描述性指标**从未转为断言**。

**根因**：此前没有任何**页面填充度的正向判据**——"块没坏、字数够、页型对、无大洞"四件事都成立，页面照样可以只铺半页。

**修复（A14 双判据，仅 case/evidence/parallel/content 页）**：

- **A14a 页尾留白**：B 区内容**墨迹底边**距 B 区下沿 ≤ **72pt·RF**；
- **A14b 栏内进度**：任一**内容栏**墨迹底边进度 ≥ B 区高 **70%**；
- 全文见 `visual-execution.md` §1.2，阈值速览见 `runtime-gate-thresholds.md` §五。

**实现四条纪律（缺任一则判据不可信）**：

1. **按墨迹算，不按框高**：文本占用高 = 行数 × 行距 × `FONT_LINE` × 字号，图 / 装饰按整框。这是 v1 几何覆盖率被「220×111pt 的框只放 15 字」骗过的同款教训——**空大框会虚报填充度**；
2. **B 区下沿取 C 区边界（画布高 ×495/540），不能沿用 A13 的 CH−14**：页码 / 页脚条（实测 y≈528.5pt）会把尾留白填满，A14a 假性通过；
3. **A13 与 A14 口径分工是有意为之**：A13 按版式框判「块与块之间」（防段末留白误报），A14 按墨迹判「页面填充度」（防空大框虚报）——同页两种口径并存，互为补充；
4. **内容栏定义要收窄**：只有「≥2 行文本块」或「图 / 图表高 ≥ B 区高 25%」的分栏受 A14b 约束——装饰栏、侧边窄栏不受限，否则误报。

**正反两向实测（发布前）**：合规章片 deck_v11 七页全绿（不误报）；违规对照——删 P5 底边元素 → A14a 实测尾留白 **277.5pt**、A14b 四栏进度低至 **36%** 双项判红；删 P4 左栏内容 → A14b 第 1 栏 **67%** 判红，且 A14a 正确沉默（该页底边仍满）。另经 720×405 画布自适配验证（RF 缩放生效）。

> 配套修复：`measure.py` 字数门此前把 `<a:t>` 写死，对 ET 重序列化页面（`ns2:t`）全文漏读、误报 0 字——已改前缀无关正则 + 未登记页型越界保护，修复后该页实测 215 字达标。**检出器自身的缺陷与内容缺陷同罪**（见 §十七）。
