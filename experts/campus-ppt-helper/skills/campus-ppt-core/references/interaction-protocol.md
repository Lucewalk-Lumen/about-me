# 交互协议与需求口径基线（Interaction Protocol & Scope Baseline）

> 面向主理人（lead）。解决**日常使用中最影响体感的三类问题**：
> 提问不显示、反复追问、用户改口径后下游没跟上。核心：**少问、问得出来、问完落盘、变了要追**。

## 一、交互止损三原则

| 原则 | 做法 | 反面（要避免） |
|------|------|---------------|
| **一次问完** | 需要澄清时，把问题**合并成一批**（≤3 个），一次问清 | 问一个→答一个→再问一个，把用户拖成挤牙膏 |
| **问得出来** | 澄清优先用**可点击的选项式提问**（结构化选项，附推荐项），而非大段开放式追问 | 只发一段纯文本反问，用户看不到 / 不想答，交互悬空 |
| **问了就推进** | 用户**不答 / 迟答 / 说"你定"**时，按**默认值推进**并在产物中标注"以下为默认口径，可随时改" | 因等答案而**整条链路停摆** |

> **为何强调"问得出来"**：本团曾出现"提问一直不显示"的反馈（对话第 16 轮）。根因是澄清方式与呈现形态不匹配。**规范**：凡是需要用户在选项间做选择（场景/平台/保真度/是否复用模板），一律给**结构化选项**；只有开放型补充（如"请指个参考链接"）才用纯文本。若一次结构化提问后无响应，**不要重复发问**，改按默认值推进。

## 二、需求口径基线（Scope Baseline）

**在派单之前**，主理人把已确认的口径固化为一份可复读的基线，写入任务工作区 `01-brief.md`（与 `task-state-resume.md` 同目录）：

| 基线字段 | 说明 |
|---------|------|
| `scenario` | 教学 / 答辩 / 实习 / 党建党政（+ 单位） |
| `audience` | 受众（学生 / 评委 / 领导 / 党员…） |
| `platform` | PowerPoint 365/2021/2016 / WPS / Keynote（未说明则默认 365 并标注） |
| `fidelity` | 路径 B 模板保真（深拷贝模板页，**默认**；见 `template-application.md §〇`）/ 路径 A 风格重绘（兜底） |
| `template` | 选定模板路径或"用户自备" |
| `length` | 目标页数与密度 |
| `must_have` | 用户点名的必须内容 |
| `must_not` | 用户明确**不要 / 已删除**的内容（**强约束**） |

> `must_not` 是防回归的关键：把用户历轮"删掉 / 不要 / 否决"的内容集中记录，**下游一律不得引入**（衔接 `source-hygiene.md §五`）。
> **默认值兜底**：未说明的平台 → PowerPoint 365；未说明场景 → 教学（广财师生）；未说明保真度 → **路径 B（模板保真）**——广财师生 / 党政单位默认套用内置品牌模板；仅当用户明确不要模板、或无内置模板可用（非广财且无自备模板的中性兜底）时才路径 A。全部标注"可改"。

## 三、口径变更协议（用户改主意时）

用户中途改口径（换场景 / 换模板 / 否方案）是常态，**不是异常**。处置三步：

1. **落盘**：更新 `01-brief.md` 的对应字段，并在 `CAMPUS_PPT_STATE.md` 记录变更时间与内容。
2. **影响面扫描**：判断哪些下游产物受影响——
   | 变更字段 | 失效的下游 |
   |---------|-----------|
   | `scenario` | 模板、叙事框架、语气、大纲 → 全部回退 |
   | `template` / `fidelity` | 制作、质检 → 回退（大纲可保留） |
   | `length` | 大纲、制作、质检 → 回退 |
   | `must_not` 新增 | 若已进入大纲/成品，须**剔除并回退** |
3. **显式回退**：把受影响阶段状态置回 `pending`（级联规则见 `task-state-resume.md §四`），**只重跑受影响部分**，不整条重来。

> **禁止**：口径变了却继续用旧产物；或悄悄改了口径而不告诉用户改了哪些、影响了什么。变更必须**显式回报**给用户。

## 四、分诊必问 vs 可以不问

| 情形 | 处置 |
|------|------|
| 用户已说清场景 + 平台 + 产出 | **不再追问**，直接派单 |
| 用户只说"做个 PPT"，其余不明 | 一次结构化提问：场景 / 平台 / 是否复用模板（3 问，附默认推荐） |
| **用户已附全部资料且未提模板** | **按轻模式默认推进**（不再提问，直接进大纲确认门，见 §5.1）——Tripwire 分流判轻（判据见 §六）；模板口径按 §5.2：命中内置模板族默认路径 B 保真 |
| 用户要一个快速答案（"这图叫什么""帮我写页标题"） | 直接答，**不拉全团队、不提问** |
| 涉及用户真实演示文稿但**未上传文件** | 给"可在你自己的 PPT 上直接套用"的通用方案，并在说明中标注需按实际情况调整 |
| 用户说"你定 / 随便 / 都行" | 全部取默认值，**标注可改**，直接推进 |

## 五、确认门（大纲确认门 + Skill 路由门）

交互止损三原则（§一）管"少问、问得出来"，本节管"**在三个关键节点把默认值推进切换为显式确认**"。核心：确认门本身仍是"一次问完"（一个问题四个选项），只是把"默认值推进"的适用范围从"所有决策"收窄到"低风险决策"。

### 5.1 大纲确认门（强制）

- **时机**：内容架构师交付页面清单表之后、制作员开工之前。Workflow A/B 强制，Workflow C 复用样章确认门。
- **形式**：页面清单表预览 + 同一条消息内一次结构化提问（A 直接生成 / B 改页 / C 调结构 / D 先看讲稿）。
- **确认口径**：大纲**必须显式确认**——"嗯/好/可以"等模糊应答不算确认；**不适用"不答即按默认推进"**（大纲是需求翻译层，静默推进会把翻译错误烧成成品，返工成本 = 级联失效）。不答 → 不重复发问，落盘 `open_questions` 停摆等待；后续指令未提大纲 → 视为默认确认并显式提示。
- **轻模式豁免**：① 用户自带完整大纲且说"就按这个做"；② 页数 ≤5 快件；③ 用户分诊说"你定/直接做/别问我"（记 `01-brief.md` `confirm_mode: light`）→ 门降级为一句话回读确认，同消息内继续推进不阻塞。

### 5.2 Skill 路由门（生成技能/路径三态判定）

| 三态 | 判据 | 动作 |
|---|---|---|
| 明确走 B（默认） | 只说"做个 PPT"且身份命中内置模板族（广财师生 / 党政单位）；或要"就是单位那套模板"/自备模板要保真 | 直接 `tencent-local-office-edit` 模板保真，不问 |
| 明确走 A | 用户明确不要模板 / 只要"配色字体像模板"；或无内置模板可用（非广财且无自备模板的中性兜底） | 直接 `tencent-pptx` 风格重绘，不问，交付注明"未继承模板母版" |
| 用户自带 skill | 明确指定"用我装的 xx skill" | 确认后路由到指定 skill，不静默用默认 |
| 模糊（触发确认） | 保真度不明 / B 依赖不可用 / 拿不准 | **必须停下来问，禁止默默选默认** |

- 模糊态一次提问附推荐项；推荐项规则：自备模板→荐保真；只说模板无保真字样（含只说"做个 PPT"且命中内置模板族）→**荐保真**；仅无内置模板可用时→荐重绘并如实告知"未含品牌模板"；B 依赖缺失→不荐保真且如实告知。
- 不答兜底：按推荐项推进并显式标注；**B 依赖缺失不可默认推进**（能力缺失须如实降级告知，不可静默走 A 冒充）。
- 路由细则见 `official-skill-routing.md §二`。

### 5.3 默认推进 vs 显式确认（三因子判定）

三因子：①返工成本 ②用户可感知度 ③不可逆性。
- **默认推进**：平台 / 场景归类（触发词明确）/ 页数密度 / 受众 / 叙事框架 / 语气。
- **必须显式确认**：大纲（页面清单）/ skill 路径模糊态 / 模板品牌保真（无模板要品牌）/ 覆盖原文件等破坏性操作。
- 一句话："错了用户能忍、改起来便宜"的默认推；"错了要重跑链路、或用户一眼能看出不对、或不可逆"的必须问。

## 六、轻/重模式分流（Tripwire，派单前必判）

在分诊之后、派单之前，先判定本任务走**轻模式**还是**重模式**。判定结果写入 `01-brief.md` 的 `mode` 字段与 `CAMPUS_PPT_STATE.md` 的 `run_metrics.mode`，并作为后续所有阶段"做不做"的依据。本节是轻/重模式判定的**唯一权威**，各成员文档只引用、不复制判定表。

| 触发信号（任一命中即重模式） | 模式 |
|---|---|
| 输入含外部 URL / 需联网采集外部资料 | 重 |
| 用户**明确要求**模板保真（"就用我们学校/单位那套模板，logo/母版都要在"；自备模板要保真）——内置品牌模板默认套用（未明确要求保真）不触发本行 | 重 |
| 批量任务（一章一份 / 多班级 / 多 deck） | 重 |
| 其余（用户自带全部资料、模板可默认或只要风格一致、单份产出） | **轻（默认）** |

**冲突与升级规则**：

- 信号冲突（如给了 URL 但说"不用参考，随便做"）→ **用户显式意图优先**，判轻模式，冲突处理记入留痕。
- 轻模式执行中发现占位符对不上 / 必须实测模板才能继续 → **自动升级重模式并显式告知用户**，不静默继续产出错版。
- 误判方向设"宁重勿轻"：拿不准时从重，避免轻模式漏做品牌合规项。

**模式的核心差异**：轻模式跳过外部采集、模板实测取色、STORY/DESIGN 双留痕、逐页截图、四维质检全检；重模式全部保留。各成员的分叉执行细则见成员文档（制作员的轻量 / 完整出片路径、质检员的 QA-lite / 四维全检）。

**质检侧门禁的执行时机不随模式含糊**：无论轻重，制作员出片后都自跑几何门 + 字数门；QA-lite 以该两门为底线（审美类判 WARN 不阻塞）；页型门、视觉门与逐页出图归重模式四维全检。完整执行时机矩阵与 FAIL 流转入口以 `campus-ppt-qa` 的 `runtime-gate-thresholds.md` §〇 为单一权威。

## 七、与其它标准的衔接

- 与 `task-state-resume.md`：`01-brief.md` 是断点续传时判断"可否跳过结构阶段"的依据（口径未变才可跳）。
- 与 `source-hygiene.md`：`must_not` 与其"旧产物隔离"同源，二者必须一致。
- 与 `quality-evaluation-standard.md`：质检"指令遵从性"维度须核对成品是否满足 `must_have`、且**未包含** `must_not`。
