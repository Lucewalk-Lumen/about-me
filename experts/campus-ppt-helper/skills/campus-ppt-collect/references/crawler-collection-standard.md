# 爬虫采集标准（Crawler Collection Standard）

> 面向采集员（campus-ppt-collector）。定义"爬虫必备标准"，**明确禁止"仅简单搜索就交付"**，给出采集产物模板。本标准是质检"事实辨别性"的上游依据。
>
> **配套文件**：本文件管"**采什么、标准是什么**"；`browser-skill-integration.md` 管"**用什么调、怎么调通、调不通怎么办**"（可用性预检 / `bsk` 会话契约 / 降级）；`source-hygiene.md` 管"**该不该进来**"（L1–L4 来源分级 / 相关性闸门 / 污染隔离区）。三者配套使用，缺一不可。

## 一、为什么必须爬虫，而非简单搜索

简单搜索（只在搜索引擎结果页看摘要、不进页面、不交叉验证、不标出处）产出的资料：
- 无原文可溯，易断章取义；
- 单一来源，易被 SEO/营销内容带偏；
- 无时间戳，无法判断时效性；
- 无 URL 出处，下游无法复核。

因此，**采集员必须使用 browser-skill 做真实网页爬取**，禁止"仅简单搜索即交付"。

## 二、爬虫必备检查项（交付前逐项打勾）

| 编号 | 检查项 | 具体要求 |
|------|--------|----------|
| C1 | 多源交叉验证 | 关键事实≥2 个独立来源（官方 + 权威媒体/学术库）相互印证 |
| C2 | 页面深链抓取 | 进入详情页/文档页/PDF 原文，非仅列表页或搜索摘要 |
| C3 | 官方原文摘录 | 政策/数据/定义类优先摘录官方原文，标注发布机构与文号/版本 |
| C4 | URL + 时间戳出处 | 每条资料标注 抓取时间(ISO 8601 含时区) + 完整来源 URL |
| C5 | 站点可用性探测 | 采集前先访问目标站点首页确认可达；不可达记录原因 |
| C6 | 失败重试 | 单源失败（超时/403/404/反爬）按重试策略处理并记录结果 |

## 三、标准采集流程

1. **需求拆解**：从主理人任务提取"采什么、采到什么程度、是否有指定来源（官网/广财内网）"。
2. **站点可用性探测（C5）**：browser-skill 打开目标站点首页；不可达→记录并换源/重试。
3. **多源交叉（C1）**：关键事实至少 2 源；优先官方源。
4. **深链抓取（C2）**：进入详情/原文页，提取可引用段落与数据。
5. **官方原文摘录（C3）**：政策/数据附官方原文片段 + 发布机构。
6. **失败重试（C6）**：单源失败按策略（见下）重试；全失败标"未获取"并说明，绝不编造。
7. **结构化产出**：来源表 + 关键摘录 + 待核实清单。

## 四、失败重试与站点探测策略

- **超时/5xx**：指数退避重试，最多 3 次（间隔 2s/4s/8s），仍失败标"站点不可用"。
- **403/反爬**：更换 UA / 尝试官方镜像 / 降级为"记录可达但内容受限"，不强行突破鉴权。
- **404**：确认 URL 是否过期，尝试站点内搜索找新地址；找不到标"原文已下线"。
- **受限页面（校内权限等）**：如实标注"需权限未获取"，列入待核实清单交用户补充。

## 五、禁止"仅简单搜索"的反面案例

| 反面做法 | 问题 | 正确做法 |
|---------|------|----------|
| 只在搜索结果摘要抄一句就当资料 | 无出处、易断章取义 | 进原页面深链抓取并摘录 |
| 单源就下结论"据研究显示…" | 无交叉验证，可能偏颇 | ≥2 独立源交叉 |
| 写"数据约增长 10%"无 URL | 无法复核、可能编造 | 附来源 URL + 抓取时间 + 精确值 |
| 用"百度百科说…"当权威 | 非官方、时效难证 | 优先官方/学术源，百科仅作线索 |
| 不标时间"最近出台" | 时效性不明 | ISO 时间戳精确到采集时刻 |

## 六、采集产物模板（来源表）

```markdown
# 资料采集报告（采集员·采真）

## 一、来源表
| 编号 | 标题 | 来源 URL | 发布机构 | 抓取时间(ISO) | 可信度 | 备注 |
|------|------|----------|----------|---------------|--------|------|
| S1 | 《XX》课程大纲 | https://... | 广财教务处 | 2026-10-06T10:00:00+08:00 | 高（官方） | 原文摘录见下 |
| S2 | XX 行业报告 2025 | https://... | 某研究院 | 2026-10-06T10:05:00+08:00 | 中（第三方） | 与 S3 交叉 |

## 二、关键摘录（可直接引用）
- [S1] 原文："……"（发布机构/文号）
- [S2] 数据：XX 增长 12.3%（来源：XX 2025-03）

## 三、待核实清单
- [ ] 某数据点仅单一来源，建议补交叉验证
- [ ] 某页面需校内权限未获取，待用户补充

## 四、零外部依赖边界声明
本次采集全部通过 browser-skill 在线获取，未使用本地脚本；受限项已在待核实清单标注。
```

## 七、与质检的衔接

- 采集中每条资料带 `S 编号`，供结构师引用、质检员"事实辨别性"回溯。
- 若采集阶段即发现无法获取关键事实，必须在待核实清单标红，下游不得自行编造（否则质检事实维度判 FAIL）。
