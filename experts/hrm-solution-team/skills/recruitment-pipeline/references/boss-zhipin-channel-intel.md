# BOSS直聘招聘渠道情报（招聘市场分析框架）

> 标准定义：基于公开职位/公司页的招聘市场情报采集与结构化分析方法论。引用方：recruitment-pipeline。
>
> 适用场景：薪酬对标 / 技能人才画像 / 竞品公司招聘态势 / 岗位供需热度 / 雇主品牌对标——以公开数据支撑招聘决策，而非自动化投递或抓取。

## 1. 概述

BOSS直聘是国内主流直聘平台，其**公开**职位页与公司页包含可结构化的市场信号：薪资区间、经验/学历门槛、技能标签、公司规模与福利。本笔记提供一套**轻量、合规、人工辅助**的分析框架，把"零散看过的几个 JD"转化为可对比的市场情报，补 `compensation-band.md`（市场对标）与 `recruiting-pipeline.md`（渠道运营）的数据底座。

**核心理念**：渠道情报只是决策的输入，不是结论本身；所有数值必须经 `compensation-band.md` 的 4 级证据层级复核后才能作为定薪/编制依据。

## 2. 边界与合规

- **仅限公开页面**：职位列表、职位详情、公司主页等无需登录即可见的内容。
- **不做**：自动登录、批量抓取、聊天/投递自动化、绕过平台反爬。
- **频率克制**：人工触发式解析，标注采集时间，避免规模化采集。
- **用途限定**：结果仅用于内部分析与对标，不得外传或作商业转售。
- **平台规则优先**：如平台更新 robots/服务条款，以平台最新规则为准。

## 3. 标准数据字段（采集时统一抽取）

| 类别 | 字段 |
|------|------|
| 职位 | 职位名称、薪资范围、城市、经验要求、学历要求、职位类型、发布时间、链接 |
| 职责 | 核心职责描述、任职要求、技能标签（平台算法标注） |
| 公司 | 公司名称、行业、规模、融资阶段、福利亮点、在招职位数 |

## 4. 三类标准分析产物

### 4.1 职位摘要卡（单岗对比）

```
| 维度 | 本公司 JD | 市场中位（N=样本数） |
|------|-----------|----------------------|
| 薪资范围 | X-Y | X'-Y' |
| 经验门槛 | N 年 | N' 年 |
| 学历门槛 | 本科 | 本科/硕士 |
| 高频技能标签 | A/B/C | A/B/D |
```

用途：判断自家 JD 在市场上的竞争力（偏高/持平/偏低）。

### 4.2 技能标签词云（岗位画像）

- 对同岗位 20-50 条公开 JD 的技能标签做频次统计
- 输出「必备技能（>70% 出现）」「加分技能（30-70%）」「新兴技能（<30% 但增长）」
- 对照 `recruiting-pipeline.md` 的 JD 优化章节，刷新自家岗位画像

### 4.3 公司招聘态势（竞品/对标）

- 在招职位数、急招岗位、新设岗位线 → 推断业务重心与扩张节奏
- 薪资分位（对标自家同岗）→ 支撑 `compensation-band.md` 的市场对标输入
- 福利亮点差异 → 支撑雇主品牌与 `hr-toolset.md` 的 handbook/employer-branding 设计

## 6. 使用纪律

- 样本量 < 10 时，结论标注「样本不足，仅供参考」
- 薪资为「面议/范围宽泛」的，计入样本但单独标注，不强行取中位
- 城市差异必须单列（一线/新一线/二线费率不同），不得混算
- 所有对外引用标注采集日期，因平台数据时效性强

## 7. 不适用场景

- 自动化批量监控/告警（超出人工辅助边界，且涉平台合规风险）
- 候选人隐私挖掘（简历库、社交账号等需授权数据）
- 替代薪酬调研机构的结构化报告（本笔记为轻量补充，非专业调研）

## 8. PII 边界

- 公司名使用真实公开主体（市场情报场景允许），但不得关联任何具体候选人
- 不采集、不存储任何自然人姓名/联系方式
- 样例数据使用 `[公司名]` / `[城市]` 占位
