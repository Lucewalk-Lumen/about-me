# 甄澄 · 蒸馏师（Distill · v1.0.3 · 手动版）

单 Agent 通用型蒸馏专家 —— 把实际发生、实际有用的「操作与业务流程」（含偏好、纠正、经验）识别、提取、提炼并沉淀为结构化、可检索、可复用的知识资产，带验证门控、有界编辑、审计链与版本回滚。领域中立、**完全手动触发**（不接外部任务、不订阅定时器、不写后台守护）。产物**回灌宿主三层记忆**并写入**长期记忆**，另有一键**备份 / 恢复**（EXPORT / RESTORE）防止换机或重装丢失。

> 作者：Xing Bu。本包为手动触发版。卡片展示名（花名）为 **甄澄 / Zhen**，职业头衔为 **蒸馏师 / Distiller**，对外可统称「蒸馏师 甄澄」。蒸馏师**不替代** WorkBuddy 自带的被动记忆，而是把它的"流水账"炼成"可照做的操作资产"，再回灌同一套记忆——让下一次对话直接受益。

## 核心能力

- **操作蒸馏**：从用户主动投放的待蒸馏材料与会话内已完成的多步操作流程中，识别流程/技巧/纠正/经验四类蒸馏对象
- **结构化资产**：产出基因（gene）/流程包（capsule）资产体，带 trigger + 可执行步骤 + 边界
- **验证门控与审计**：三道验证（可操作/可复用/独特）+ trigger 收口后入库；append-only 审计链 + 版本化回滚
- **手动触发为主**：用户说「跑一下蒸馏」或「把这个流程蒸馏了」即触发；不订阅任何定时器、不接任何外部任务

## 和 WorkBuddy 自带记忆的区别（为什么还需要我）

WorkBuddy 本身就会被动记录对话（工作记忆 / 长期记忆）——那是"原始流水账"，记下了聊过什么，但不保证"下次能直接照着做"。蒸馏师补的是这最后一段：**把流水账里真正有价值的操作，提炼成带"何时用 + 怎么做 + 边界"的可复用资产**，并用三道验证门控（可操作 / 可复用 / 独特）把关质量。一句话——**宿主记忆负责"记"，蒸馏师负责"炼"；蒸馏师不替代宿主记忆，只让它的含金量更高。**

## 它怎么和宿主记忆联动（取之于宿主，用之于宿主）

- **取之于宿主（输入）**：蒸馏时把宿主工作记忆（当日 `任务文件夹/.workbuddy/memory/`）和原生任务记录当作"待蒸馏素材"，不必自己另建一份历史。
- **用之于宿主（输出）**：蒸馏产物回灌宿主工作记忆与长期记忆，下次对话自动拿到"操作级"而非"流水级"的信息（详见 `agents/distill.md` 的 Stage 5.5）。
- **随时调取（索引）**：所有资产由 `index.md` 检索索引 + 检索脚本统一管理，按关键词 / 触发信号 / 标签秒级调取。

## index.md 是干什么用的（运行时自动生成，不要手改）

你可能会在配置目录 `~/.workbuddy/distill-assets/index.md` 看到一个**自动出现**的 `index.md`——它不是你写的，也不是包里的文件，而是**蒸馏师每次入库后由脚本生成的"资产检索索引"**：

- **内容**：把每一条胶囊 / 基因浓缩成一行（id + 类型 + 触发关键词 + 标签 + 出处），方便人眼速览"我沉淀了哪些可复用做法"，也方便用编辑器直接 grep。
- **权威位置**：`~/.workbuddy/distill-assets/index.md` 是唯一权威索引；`capsules/index.md` 只在"导出 / 分发给别人"时由净化后的胶囊现场生成，是给接收方的快照，平时不用管。
- **怎么来的**：新增或变更资产后跑 `bin/query_capsules.py --rebuild-index` 就会重建；**由脚本生成，禁止手改**（手改会和资产库 JSON 漂移，导致检索 / 去重失灵）。
- **真正检索靠什么**：自动检索与去重以 `capsules.json` 等 JSON 资产库为准，`index.md` 只是给"人看 / 快速 grep"的镜像。
- 索引顶部写明了用途、底部附了检索 / 重建 / 隐私用法，可直接当说明书看。

- 「资产库里有没有可复用的 XX 流程」（按关键词 / 触发信号 / 标签检索胶囊）

## 资产库位置（占位说明）

- `配置目录/distill-assets/`：genes.json（操作模式）/ rejected.json（被拒候选）/ events.jsonl（审计链）/ `.first_run` 首次哨兵；**`index.md`（检索索引，脚本生成，唯一权威）也在此根目录**；`配置目录/distill-assets/capsules/`：capsules.json（流程包）+ 可选的 `index.md`（仅 SHARE 分发快照，不单独维护）
- `配置目录/distill-digest/YYYY-MM-DD.md`：本次精华
- `配置目录/distill-versions/vN/`：版本备份（保留最近 10 版，位于资产库之外，不进备份与分发件）
- `配置目录/zettel-index.md`：跨资产引用表
- `配置目录/inbox.md`：用户主动投放的待蒸馏材料
- `配置目录/inbox-archive/YYYY-MM-DD.md`：已处理投放的归档

> 实际路径以宿主平台配置目录为准；WorkBuddy 下配置目录即 `~/.workbuddy`（Windows 为 `%USERPROFILE%\.workbuddy`）。脚本内置默认值即该路径，也可用 `DISTILL_ASSETS_DIR` / `DISTILL_BACKUP_DIR` 等环境变量覆盖，便于在其它宿主或测试环境中使用。

## 打包分享

> **依赖与运行环境**：`bin/` 下为运行时脚本，仅依赖 **Python 标准库（Python ≥ 3.9）**，无需安装任何第三方包。
>
> 脚本一览：`audit_chain.py`（审计链写入与校验）、`check_backup_freshness.py`（备份新鲜度守卫）、`export_backup.py`（导出备份，跨平台，不依赖系统 `zip`）、`query_capsules.py`（胶囊检索 / 结构校验 / 索引重建）、`restore_backup.py`（从备份恢复）、`share_capsules.py`（生成分发包，默认净化）；`assets_lib.py` 与 `pkgmeta.py` 是上述脚本共用的内部库，通常无需直接调用。

### 命令行参数（完整）

> 日常使用不需要记命令——所有动作都可以用一句话触发。下表供排障、脚本化或手工调用时查阅。

**共同参数**（多数脚本适用）

| 参数 | 说明 |
|---|---|
| `--assets DIR` | 资产库目录。默认 `~/.workbuddy/distill-assets`；可用环境变量 `DISTILL_ASSETS_DIR` 覆盖 |
| `--out-dir DIR` | 输出目录（导出 / 分发包用）。默认 `~/Documents/distill-backup/`；可用 `DISTILL_BACKUP_DIR` 覆盖 |

**`check_backup_freshness.py`** — 备份新鲜度守卫

| 参数 | 说明 |
|---|---|
| `--warn N` | 提醒阈值天数（默认 3） |
| `--crit N` | 强烈建议阈值天数（默认 7） |
| `--quiet` | 仅在超阈值时输出；「从未备份过」等**异常状态仍会输出** |
| `--exit-code` | 用退出码表示状态：`0` 正常 / `1` 提醒 / `2` 强烈建议 / `3` 从未导出 |

**`query_capsules.py`** — 检索 / 校验 / 重建索引

| 参数 | 说明 |
|---|---|
| `关键词 ...` | 检索关键词（空格分隔） |
| `--all` | 列出全部资产（简表） |
| `--id ID` | 展示指定 id 的全文 |
| `--check` | 结构校验（不检索） |
| `--rebuild-index` | 由胶囊库重建检索索引 |
| `--top N` | 检索返回条数（默认 5） |
| `--json` | 以 JSON 输出（便于脚本消费） |

**`export_backup.py`** — 导出备份

| 参数 | 说明 |
|---|---|
| `--dry-run` | 只列将打包的内容，不实际打包 |
| `--list` | 只列出已有备份，不打包 |

**`restore_backup.py`** — 从备份恢复

| 参数 | 说明 |
|---|---|
| `--backup-dir DIR` | 备份目录。默认 `~/Documents/distill-backup/` |
| `--target-dir DIR` | 恢复目标目录。默认 `~/.workbuddy/distill-assets` |
| `--list` | 只列出可用 zip，不恢复 |
| `--force` | 跳过覆盖确认（**危险**，仅限非交互环境明确授权时使用） |

**`share_capsules.py`** — 生成分发包

| 参数 | 说明 |
|---|---|
| `--with-audit` | 含审计链的**原状版**（等价于备份 zip，含个人操作记录，不要外发） |
| `--dry-run` | 只列将打包的文件 |

**`audit_chain.py`** — 审计链校验

| 参数 | 说明 |
|---|---|
| `--verify ASSETS_DIR` | 校验该资产库的 `events.jsonl` 是否被篡改 |
| `--file PATH` | 直接指定 `events.jsonl` 路径（与 `--verify` 二选一） |

**环境变量**

| 变量 | 作用 |
|---|---|
| `DISTILL_ASSETS_DIR` | 覆盖资产库目录 |
| `DISTILL_BACKUP_DIR` | 覆盖备份目录 |
| `DISTILL_AUTHOR` | 覆盖审计事件的署名主体 |

## 协议约束（与本版本强相关）

1. **手动优先**：本版本不接外部任务、不订阅定时器、不写后台守护；用户须以对话指令启动每一轮。
2. **不自我修改**：本技能文件（agent MD / plugin.json / README / LICENSE / CHANGELOG / COPYRIGHT）只读，绝不被蒸馏流程改写。
3. **不统计自动化任务**：首次双轮的"历史补齐"仅看非自动化任务（被删会话 + 本地归档），不读取宿主平台的自动化任务表。
4. **首次双轮幂等**：首次两轮产出会被合并写入审计链，第二轮完成后落 `.first_run` 哨兵；哨兵存在则后续轮次走单轮流程。
5. **记忆回灌**：蒸馏结束后按「完整、简洁、不含开发语言」三条规约回灌工作记忆与长期记忆；只追加、不改写既有条目；记忆写入失败不阻塞蒸馏主流程。
6. **净化边界**：分发包默认剥离个人操作记录与私密指针（含索引内的指针），但**保留引用出处与角色署名**。

## 记忆回灌（与宿主记忆配合）

蒸馏产物除了进资产库，还会回灌宿主的记忆层：

| 层 | 落点 | 写什么 |
|---|---|---|
| 工作记忆 | `<任务文件夹>/.workbuddy/memory/` 下的当日日志与 `MEMORY.md` | 本次结论与依据、项目内反复适用的约定 |
| 长期记忆 | `~/.workbuddy/MEMORY.md` | 只写跨项目通用的用户偏好与硬性规矩 |

写作规约：**完整**（自带适用场景、结论与依据）、**简洁**（一行一条、一条一事）、**不含开发语言**（不出现路径、文件名、代码、命令、内部编号与版本号）。
