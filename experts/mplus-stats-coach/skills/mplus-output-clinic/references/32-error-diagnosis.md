# 32 · 报错诊断（M5-b）—— **无实证样本，走法理路径**

> ⚠ **本文件是全包唯一「零样本」分片。先读这一条，再读下面任何内容。**
>
> **实测事实**：官方 **555 份 `.out`** 中，行首锚定的 `*** ERROR` 命中 **0 份**（见 `knowledge/INDEX.md` §5.1、§5.2）。
> 即 **官方语料里没有任何一条报错样本**。因此本文件**不可能是「案例归纳」**，只能是**法理推演 + 输入层实证映射**。
>
> **由此产生三条硬约束（不得违反）**：
> 1. **禁止编造 Mplus 报错消息**。本文件**不给出任何逐字消息文本**——因为一条都没有实测来源。
> 2. **凡涉及输出侧报错的判断，一律标「未经真实运行复现」。**（P0-0b）
> 3. **用户只贴 `.inp` 时，禁止宣称「不会报错」。** 只能说明「语法层未发现问题」，并声明本层不覆盖输出侧。（P0-6）

---

## 一、为什么「没有样本」反而有解 —— 因为有另一条实测链

报错发生在两个不同阶段，**只有第二个阶段没有样本**：

| 阶段 | 判据（`.out` 中的锚点） | 本包证据状况 |
|---|---|---|
| **① 读输入** | `INPUT READING TERMINATED NORMALLY` 是否出现 | **有 519 份 `.inp` 实证** → 静态扫描可覆盖 |
| **② 模型估计** | `THE MODEL ESTIMATION TERMINATED NORMALLY` 是否出现 | **0 报错样本** → 只能走法理路径 |

**关键推论**：绝大多数「Mplus 报错」用户实际遇到的是**第 ① 阶段**——
段名拼错、缺分号、引用了未声明的变量、`NAMES` 与数据列数不符、`DATA` 缺 `FILE IS`、`CLASSES` 没配 `TYPE=MIXTURE`。
这些**恰恰是语法层能静态查出来的**，而我们手上有 519 份官方 `.inp` 作为实证底座。

> **所以 M5-b 的首要动作不是「猜报错含义」，而是**
> **先跑 `skills/mplus-syntax-lab/scripts/check_inp.py` 把 ① 阶段的问题排掉**，再看是否还剩下 ② 阶段的问题。

## 二、分流树（按「故障出现的位置」分流，不按「消息文本」分流）

> **设计说明**：因为无消息样本，本表**以故障出现位置为索引**，而非以消息为索引。
> 这是无样本条件下唯一不会编造的检索方式。

```
用户说「跑不出来 / 报错了」
│
├─ Q1  Mplus 有没有生成 .out 文件？
│   ├─ 没有 ────────────────→ 故障在启动前：路径 / 文件名 / 工作目录 / 授权 / 内存
│   │                          → 见 §三 A 组
│   └─ 有 ──→ 继续
│
├─ Q2  .out 里有没有 INPUT READING TERMINATED NORMALLY？
│   ├─ 没有 ────────────────→ 故障在「读输入」：**这一层本包有实证**
│   │                          → 见 §三 B 组 → 直接路由 mplus-syntax-lab
│   └─ 有 ──→ 继续
│
├─ Q3  .out 里有没有 THE MODEL ESTIMATION TERMINATED NORMALLY？
│   ├─ 有 ────────────────→ 估计也完成了，用户说的「报错」可能是**警告**误读
│   │                          → 路由 mplus-output-clinic 的 31-warning-taxonomy.md
│   └─ 没有 ────────────────→ 故障在「估计」：**本包无样本** → 见 §三 C 组（全部【推断待验证】）
│
└─ Q4  有没有行首 *** ERROR？
    └─ 有 ────────────────→ 官方语料 0 例，**本包无法比对**
                               → 执行 §四「取证据固定动作」，不得凭经验断言
```

**Q3 的「有」分支是最常见也最容易答错的一支**：用户把 `*** WARNING` 说成「报错」。
先看图 31，不要顺着「报错」这个措辞往下走。

## 三、三组分流后的动作

### A 组｜`.out` 未生成（启动前故障）

| 检查项 | 依据 |
|---|---|
| `.inp` 与 `.dat` 是否在**同一目录**（或 `DATA` 段路径正确） | UG「DATA Command」 |
| 路径与文件名是否含**空格 / 中文 / 非 ASCII** | 常见环境问题 |
| 工作目录是否可写（`.out` 要写到输入所在目录） | Mplus 默认行为 |
| 授权是否有效 | 官方安装与授权说明 |

> 这组**与模型无关**，不要往模型设定上引。

### B 组｜「读输入」失败 —— **本包有实证，优先走这一条**

按**查得率**排序（每条都有 519 份实证，规则编号对应 `mplus-syntax-lab/SKILL.md` 的规则表）：

| 优先 | 症状方向 | 规则 | 静态可查 | 实证 |
|---|---|---|---:|---|
| 1 | 段名拼写或段名非法 | `L01` | 是 | 519/519 注入器命中 |
| 2 | 段内语句**缺分号** | `L02` | 是 | 519/519 |
| 3 | `MODEL` 引用**未声明变量** | `L07` | 是 | 501/501 |
| 4 | `USEVARIABLES` 引用未声明变量 | `L15` | 是 | 98/98 |
| 5 | `NAMES` 缺失 | `L08` | 是 | 519/519 |
| 6 | `DATA` 缺 `FILE IS` | `L09` | 是 | 40/40 |
| 7 | `CLASSES` 无 `TYPE=MIXTURE` | `L06` | 是 | 216/216 |
| 8 | `MODINDICES` 与 `ESTIMATOR=BAYES` 冲突 | `L11` | 是 | 407/407 |
| 9 | `BOOTSTRAP` 与 `ESTIMATOR=BAYES` 冲突 | `L13` | 是 | 412/412 |

**动作**：让用户提供 `.inp`，跑

```bash
python3 skills/mplus-syntax-lab/scripts/check_inp.py <路径>/xxx.inp
```

`BLOCKER` 级命中即**几乎必然**导致「读输入」失败。**这是本包对报错诊断能给出的最强答案。**

> ⚠ 反向纪律：`check_inp.py` 报 **0 BLOCKER 也不等于「不会报错」**。
> 它只覆盖语法层（覆盖率见 `references/capability-boundary.md` §三，三口径并列）。
> 语法层干净只能说明**读输入阶段大概率能过**，**不能**推及估计阶段（P0-6）。

### C 组｜「估计」失败 —— **全部【推断待验证】，一律加标注**

以下为**按一般统计建模原理的可能方向**，**不是** Mplus 报错消息的释义，**没有任何语料支持**：

| # | 方向 | 可提示用户做的事 | 三态 |
|---|---|---|---|
| 1 | 起始值 / 迭代问题 | 增大随机起点数与迭代上限（查 UG「ANALYSIS Command」的 `STARTS` / `STITERATIONS`） | 【推断待验证】 |
| 2 | 非正定 / 不可识别 | 检查潜变量方差、载荷数与指标数是否足够 | 【推断待验证】 |
| 3 | 样本量 / 稀疏类别 | 检查最小类人数与交叉表空单元格 | 【推断待验证】 |
| 4 | 数据与声明不符 | 核对 `NAMES` 列数、缺失值标记、变量类型声明 | 【推断待验证】 |
| 5 | 估计器与模型类型不兼容 | 查 `13-estimator-guide.md` 的兼容矩阵 | 【推断待验证】 |

> **输出时必须逐条带【推断待验证】**，并说明「本包无官方报错实证样本，以上为按 UG 一般原理的方向性提示」。

## 四、取证据固定动作（**取代「凭经验猜」**）

用户报错时，**必须先要这三样**，缺一不可：

1. `.out` 中**从行首 `*** ERROR` 起的一小段**（约 10–20 行）—— 含错误标记与其后的上下文；
2. 该 `.out` 的**头部数行**（可读出 `Mplus VERSION` 与运行日期）—— 用于确定版本口径（`references/version-notes.md`）；
3. 对应的 `.inp` **原文** —— 用于跑 `check_inp.py`。

**拿到之后仍不得直接下结论**：官方语料 0 例报错，本包**没有任何可比对样本**。
正确输出是：

> ① 按 §二 分流树定位故障阶段；
> ② 若落在 B 组 → 用 `check_inp.py` 给**确定结论**；
> ③ 若落在 C 组或 Q4 → 给**方向性提示**并**显式标注「未经真实运行复现」**；
> ④ 给出官方文档锚点（见 §五）请用户核对**自持**手册。

## 六、与警告层的边界（**不要混用**）

| | 警告层（`31-warning-taxonomy.md`） | 报错层（本文件） |
|---|---|---|
| 样本 | **62 类 / 219 条 / 90 份**（实证） | **0 例**（缺失） |
| 可给结论 | 消息原文 + 分组 + 修法方向 | 只能给阶段分流 + 方向提示 |
| 标注 | 不需加「未复现」 | **必须**加「未经真实运行复现」 |
| 是否表示失败 | **否**（90 份含警告的 `.out` 全部正常结束） | 是 |

> 最后一条最重要：**用户说「报错」时，先确认他是不是把警告当成了报错。**
> 实测官方语料里，警告常见，报错罕见（0 例）。
