# version-notes.md · 版本差异与口径

> 用途：回答「**这个写法/这个问题在不同 Mplus 版本下是否一样**」时的唯一依据。
> 本文件只登记**有实测出处**的差异；无样本者一律标 **【缺失】不得推断**。
> 全部三态标注：**【实测】** 有命令输出支撑 · **【推断待验证】** 无直接证据 · **【缺失】** 语料无样本。

---

## 一、三个版本口径（**不可混用**）

| 口径 | 值 | 依据 | 用在何处 |
|---|---|---|---|
| **语法侧基准** | **9.1 语言代次** | 官方 `Version 9.1 Mplus Language Addendum` | 回答「怎么写」时的语法权威 |
| **官网当前最新版本号** | **9.1.1**（2026-09-16） | 官方版本历史页 | 识别用户报来的版本号 |
| **输出解析侧实证** | **6.0 – 8.8** | 官方 **555** 份 `.out` 逐文件实测 | 回答「`.out` 里这句是什么意思」时的实证边界 |

### 1.1 为什么「9.1」与「9.1.1」要分开记【实测】

官方版本历史页（`statmodel.com/verhistory.shtml`，页面日期 2026-10-07）逐字原文：

```
Mplus Version 9.1.1, September 16, 2026
Mplus Version 9.1.1 is now available.  Mplus Version 9.1.1 includes corrections to
minor problems that have been found since the release of Version 9.1 in May 2026.
Mplus Version 9.1, May 19, 2026
The Version 9.1 Mplus Language Addendum can be found on the website along with the
Mplus Version 8 User's Guide.
```

| 事实 | 含义 |
|---|---|
| 9.1.1 属**补丁**（"corrections to minor problems"） | **不引入新语言特性** → 语法权威仍是 9.1 |
| Language Addendum 仍名为 **Version 9.1** | 官方**没有**出「9.1.1 Language Addendum」 |
| 官方指引仍与 **Version 8 User's Guide** 并列 | 本包「UG 第 8 版」口径正确，非过时 |

> **禁止表述**：「语法基准已升到 9.1.1」——9.1.1 不改语言特性，此说法会给用户错误预期。

**9.1.1 修了什么（对用户有实际影响，须主动提示）【实测】**：官方原文点名 9.1 的一个缺陷，
**同时满足三条**才触发，且会**使结果失真**（"the results are distorted"）：

1. 版本 = **9.1**；2. **DSEM** 且 `TYPE = TWOLEVEL` 搭配观测变量的 `LAGGED` 选项；
3. `PROCESSORS` 数 **大于** 链数（默认 2 条，或 `CHAINS` 指定值）。

→ 用户若报 **9.1** 且写 DSEM + `TYPE=TWOLEVEL` + `LAGGED` + 多处理器，**必须提示升到 9.1.1**；
仅报「9.1」而未出现这三条组合时，**不得**泛化成「9.1 有问题」。

**输出侧版本分布【实测】**（口径 = 每份 `.out` 首部 `Mplus VERSION`）：

| 版本 | 份数 | 说明 |
|---|---:|---|
| `8.8` | 341 | 2022 年批量产出（UG 主体） |
| `8` | 95 | 2017 年批量产出（UG 主体） |
| `6.1` | 81 | 2010 年（UG 主体 5 + 补充集 76） |
| `6.11` | 16 | 2010 年（补充集） |
| `6` | 12 | 2010 年（补充集） |
| `Mplus DEVELOPMENT`（无版本号） | 10 | 2011 年构建（补充集 Penn） |
| **合计** | **555** | **无任何 9.x 样本** |

> ⚠ **最可能的真实路径落在空白区**：用户多半用 **9.1 / 9.1.1** 跑出 `.out` 交给本智能体解读，
> 而官方实证**到 8.8 为止**。故对**未见过版本号**必须走
> **显式告警 + 降级解读**，**不得静默按 8.8 口径解析**。

## 二、TECH8 可用性（**本轮实测最反直觉的一条**）

官方消息原文（`warning-library.jsonl` · `W07`，5 份命中）：

```
TECH8 option is available only with analysis types MIXTURE, RANDOM, or TWOLEVEL
with estimators ML, MLF, or MLR or ALGORITHM=INTEGRATION. Request for TECH8 is ignored.
```

**它看起来像一条「组合规则」，实测却不完全如此。**

### 2.1 实测混淆规模【实测】

口径：**只统计「输入回显中请求了 TECH8」的 `.out`**（而非全部文件）；
分母为**全部 555 份官方 `.out`**（含 39 份未入索引者）。

| 版本 | 请求 TECH8 | 实际报出该警告 | 报出率 |
|---|---:|---:|---:|
| `6.1` | 27 | **6** | 22% |
| `6.11` | 4 | 0 | 0% |
| `8` | 67 | 0 | 0% |
| `8.8` | 188 | 0 | 0% |
| `Mplus DEVELOPMENT` | 5 | **1** | 20% |
| **合计** | **291** | **7** | 2.4% |

> **口径注记（必须随数字一起给）**：上表分母是**全部 555 份**。
> 若把口径收窄到**包内已索引的 516 份配对输出**，则 `6.1` 为 **26**（少 1 份）、合计为 **290**，
> 报出仍为 7。差额来自 `penn__stard_run13`（v6.1，请求了 TECH8，但**无配对 `.inp`**、不在索引内）。
> **引用时必须写明是 555 口径还是 516 口径** —— 两者相差 1 份，但结论方向不变。
>
> 报出的 7 份 = v6.1 的 **6** 份（`penn__baysem_run1–6`）+ `DEVELOPMENT` 的 **1** 份（`penn__shortform_run10`）。

### 2.2 两个结论

1. **不是版本开关**：v6.1 里也有 21/27 份**不报**；所以「v6 一定报、v8 一定不报」是**错的**。
   （分母口径同 §2.1：555 份口径 27；516 索引口径 26 → 则为 20/26 不报，结论不变。）
2. **组合条件本身也没有被完全解出**：我按官方消息文本反推的规则
   （`TYPE ∈ {MIXTURE, RANDOM, TWOLEVEL}` 或 `ESTIMATOR=BAYES` 或 `ALGORITHM=INTEGRATION`）
   在 v6.1 上 **25/27 = 92.6%** 吻合（口径同 §2.1；516 索引口径则为 24/26 = 92.3%），**2 例反例**：

| 反例 | 写法 | 实测结果 |
|---|---|---|
| `penn__baysem_run22` | `TYPE = EFA 3 3` + `ESTIMATOR=ML` | **未报** |
| `penn__baysem_run2/4/5/6` | `TYPE = EFA 4 4` + `ESTIMATOR=ML` | **报出** |
| `ex11.5part1` | `TYPE = BASIC` | **未报** |

> **同为 EFA，`3 3` 与 `4 4` 结果相反** → 该分支**不可静态判定**。

### 2.3 因此本包的规定动作

| 场景 | 动作 |
|---|---|
| 用户分析版本 **≥ 8**，且要写 `TECH8` | **不提示**（v8/v8.8 请求 TECH8 的 255 份中 **0 份**报出） |
| 用户分析版本 **= 6**，且 `TECH8` + **无 `TYPE`** + 非 BAYES + 无 `ALGORITHM=INTEGRATION` | **`WARN`**（v6.1 该写法 2/2 全报） |
| 用户分析版本 **= 6**，且 `TECH8` + **有 `TYPE` 但取值非豁免** | **`INFO`**，文案必须写明「官方 6 份中 4 份报、2 份未报，**请以实跑为准**」 |
| 用户分析版本 **= 7** | **`INFO`** + 标 **【缺失】**：「官方语料无 Mplus 7 输出，边界未验证」 |
| 版本未知 | 按 **9.1** 语法讲，但对「是否报警告」**不作承诺** |
| 用户报 **9.1** 且写 DSEM + `TYPE=TWOLEVEL` + `LAGGED` + `PROCESSORS` > 链数 | **提示升 9.1.1**（官方点名该组合下 9.1 结果失真，见 §1.1） |

**禁止表述**：「写 `TECH8` 一定会报警告」——此话在 **291 份**（口径 = 全部 555 份 `.out` 中请求了 TECH8 者）样本中**错 284 次**；
即使按收窄的 516 索引口径（290 份）也是**错 283 次**。两种口径下这句话都是错的。

## 三、其他有实测出处的版本/行为差异

### 3.1 段名与语法形态

| 项 | 结论 | 三态 |
|---|---|---|
| **Mplus 不强制段序** | `ANALYSIS` 先于 `MODEL` 1 例、`VARIABLE` 先于 `DATA` 1 例、`PLOT` 先于 `OUTPUT` 1 例 | 【实测】519 份逐文件位置比对 |
| **`MODEL <标签>:` 标签不受限** | 实测出现 `C1/C2/C3/C4/C`、`G1/G2/G3`、`CB/CG/CW/CU/CY`、`DZ`、`FEMALE`、`1988`、`1989`，共 21 种 | 【实测】 |
| **`MODEL PRIOR:` 单数合法** | 1 例（`ug/ch5/mcex5.5part4.inp`），正文 `a1-a20~N(1.386,1);` | 【实测】 |
| **变量清单可缩写** | `USEV` 42 份 / `USEVAR` 4 / `USEVARIABLES` 51 / `USEVARIABLE` 1 | 【实测】 |
| **段名与内容可同行** | `DATA:\tFILE IS ex6.1.dat;` | 【实测】（修正前后识别数 14 → 89，差 6 倍） |
| **`TITLE` 不需分号、可极长** | 补充集实测最长 **2661 行** | 【实测】 |

### 3.2 警告与阈值

| 项 | 结论 | 三态 |
|---|---|---|
| **行宽 90 字符** | 阈值确证；但超限 6 份中**仅 4 份报出**（`ex5.28` 95 字符、`ex5.32` **131 字符**均未报） | 【实测】触发不可预测 |
| **变量名 8 字符** | 上限确证：官方 519 份 `.inp` 展开 `NAMES` 后，变量名长度 1–8 字符、**最大恰为 8**、**超限 0 个**（约 3,054 个）。⚠ 因语料守规，`.out` 中**无截断警告样本** → 不得声称"必报" | 【实测】 |
| **空 `MODEL PRIORS` 段合法** | **1 例**：`supp/penn__bayesian_run12.inp` 第 38 行 `Model priors:` 后仅注释；对应 `.out`（v6.1）**0 ERROR / 0 WARNING**、`INPUT READING TERMINATED NORMALLY` | 【实测】 |
| **贝叶斯 + `TECH8`** | 官方 `ex9.26 / ex9.27 / ex9.32 / ex9.40part2` 等 `.out` 含 `PSR VALUE DOES NOT INCREASE` 且 **0 ERROR / 0 WARNING** → 是标准用法，非错误 | 【实测】 |
| **段序** | **不存在"标准段序"**：官方 519 份中 `MODEL POPULATION` 先于 `MODEL`（蒙特卡洛输入必然如此）等系统性"反序"大量出现；62 类警告库中**无任何一类**与段序有关 | 【实测】 |

### 3.3 报错侧

| 项 | 结论 | 三态 |
|---|---|---|
| **官方语料报错样本** | **0 例**：555 份 `.out` 中 `*** FATAL ERROR` **0 例** | 【实测】 |
| **「未打印 TERMINATED NORMALLY」≠ 运行失败** | 519 份索引中 38 份未检出该字样（`out_status = NO_TERMINATION_MARKER`），但它们**全部**含 `Ending Time` / `Elapsed Time` → **运行正常结束**，只是 Mplus 未打印那行回显（集中在 EFA / 蒙特卡洛类分析：`ex4.6`、`mcex4.7`、`mcex5.24–31`、`mcex6.7/6.16` …） | 【实测】 |
| 因此 | 报错诊断**无实证样本**，走官方 FAQ 法理路径，输出**恒定标注「未经真实运行复现」**；**禁止**把「缺终止字样」讲成「没有正常结束」 | 强制 |

## 四、会话使用约定

1. 用户给的版本号与上表不一致时 → **先说明差异口径**，再回答。
2. 涉及上表任何一条 → 输出**必须**带版本注记（例：「此条在 Mplus 6.1 实测成立，8.x 已放宽」）。
3. 上表**未列**的版本相关行为 → 一律 **【推断待验证】**，不得写成结论。
4. 本文件是**版本差异的唯一入口**；`knowledge/INDEX.md` §六只给分布表，不重复本节。
