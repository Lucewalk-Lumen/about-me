# 课程伴学精灵 · 参考细则（identity.md）

> 引用方式：`${CODEBUDDY_PLUGIN_ROOT}/references/skill/identity.md`。下文 `§` 编号沿用学生端 主指令 原有编号。

### 1.1 身份校验（仅首次）：学号 + 姓名 双因子

读 `~/.workbuddy/student_sid.txt`（两行：第 1 行学号、第 2 行姓名）：
- 不存在 → 让用户**依次输入学号与姓名**（提示「学号，如 2024001」→「姓名，如 张三」）
 **输入完成后立即写暂存** `~/.workbuddy/student_sid_pending.json`
 （内容 `{"sid":"…","name":"…","ts":"<ISO时间>"}`）——**先落盘再校验**，
 上游（授权/发现/名册读取）任一环节失败，已输入的身份不丢失（修复）；
 会话重启发现存在暂存 → 先问「是不是 {{sid}} / {{姓名}}」，确认后直接复用，不必重输；
- 存在 → 静默复核（见下）

**用腾讯文档连接器逐课读名册**（每课有独立的 Hub 文件与名册）：
对 `data_hub_config.json` 的 `courses` **每个条目**，读其 `hub_sheets.roster` 表全量
（分页 has_more 继续翻页直至覆盖全表），按「学号」列 + 「姓名」列**双因子匹配**
（两侧均忽略首尾空白）：

- **命中**（某课名册中存在「学号」与「姓名」同时匹配的行）→ 读取该行「姓名」列（**真实姓名**）→
 **转正缓存**：把学号 + 姓名两行写入 `~/.workbuddy/student_sid.txt`，并**删除暂存文件** `student_sid_pending.json`
 → 后续以**真实姓名**称呼（如「你好，张三」）
 → 记住命中行所在的**课程条目集合**（course_id 集合；多课名册同时命中即多门），
 进入 §1.2 做课程自动匹配
- **学号存在但姓名不匹配** → 一句提示后**停止**（防错设计：不透露名册上的真实姓名）；
 **暂存文件保留**（学号可能没错，学生只需重输姓名）：

 > "学号 {{sid}} 与姓名不匹配，请核对后重新输入。若确认无误，请联系老师核对名册登记。"

- **学号不存在** → 一句提示后**停止**；**暂存文件保留**（可能是教师尚未把学生导入名册，稍后重试即用）：

 > "你的学号 {{sid}} 不在最新名册内，无法开始伴学。请核对学号，或联系老师把你的学号导入名册。"

 > [!] 上面**两条**话术在**四处**必须**逐字一致**：本节 §1.1、`socratic_agent_prompt.md` §10、
 > 名册由教师在教师端导入，学生端只做**双因子校验**；上面两条话术在本文档 §1.1 与 §6 错误表
 > 必须逐字一致。**不是「仍可伴学」**——匿名轨已取消。
 > **双因子是防错设计**：学生打错学号时姓名对不上即拒绝，避免把学情记到别人头上。

### 0.4 空间发现（首次接入的推荐路径）

> 阅读顺序注：本节逻辑上**先于** §1.1（先发现中枢、再做身份校验），编号沿用学生端 主指令 原有节号，阅读时请先读 §0.4 再读 §1.1。

教师以「知识库空间共享」交付时（常见形态），学生无需索要中枢文档链接，直接跑发现脚本：

```bash
python3 "${CODEBUDDY_PLUGIN_ROOT}/scripts/discover_hub.py" --course "<课程名>" --list-only # 列候选空间
python3 "${CODEBUDDY_PLUGIN_ROOT}/scripts/discover_hub.py" --course "<课程名>" --out "${CODEBUDDY_PLUGIN_ROOT}/data_hub_config.json"
```

脚本自动完成：`query_space_list`（筛课程伴学数据中枢空间）→ `query_space_node`（定位 Hub/Usage 智能表格）

> [!] **不要用 `search_file` 代替空间遍历**
> 关键词检索的索引**只覆盖近期访问过的文档子集**：实测用课程全名（如「组织学习理论」）搜索返回**空**，
> 而该空间确实存在；按「课程伴学」搜也只命中近期访问过的 4/9 个空间（其余 5 个 `last viewed` 较早的全部漏检）。
> **因此课程中枢发现一律走本脚本的空间遍历**，检索只作辅助、且其「搜不到」**不构成「不存在」的证据**。
→ `smartsheet.list_tables`（按表名 roster+course_versions / usage+summaries 分类）→ 读 course_versions
「课程」列取权威 course_id → 合并写入 `data_hub_config.json`。

**两种停止话术分流（不得混用同一句）**：

- **未授权 / 未发现空间**（discover_hub exit 1，候选为空）→ 引导授权：

 > "还没有发现老师共享的课程数据中枢。请确认老师已把课程知识库空间共享给你（成员邀请或空间权限），然后我们重试。"

- **空间已共享但表读不到**（候选存在但结构不全 / `543303` / `22001`）→ 联系老师：

 > "数据中枢已连接，但有一部分数据表暂时读不到。请联系老师检查数据中枢的表结构。"

**隐私红线不变**：发现过程产生的 file_id/sheet_id 只写 `data_hub_config.json`，不进对话、不进日志（见 `data_contract.md` §7.2）。

**学生身份 = 学号 + 姓名**（均来自名册表）。学生端**不使用花名 / 昵称 / 头像**——
那些是**伴学智能体**的属性，由教师维护（见 §1.3）。

roster 读取示例（对 `courses` 中每个条目各执行一次）——**必须翻页读全表**：
```json
// smartsheet.list_records（第 1 页）
{ "file_id": "<数据中枢配置：该课 Hub 文件>", "sheet_id": "<数据中枢配置：该课名册子表>", "offset": 0, "limit": 100 }
// 返回 has_more=true → 继续第 2 页（offset 逐次 +100），直到 has_more=false
{ "file_id": "<同上>", "sheet_id": "<同上>", "offset": 100, "limit": 100 }
```
读回**全部页**后按「学号 + 姓名」做本地匹配。

> [!] **禁止凭首页判「不在册」（实测缺陷）**
> 单页上限 100 条且 `has_more=true` **不自动翻页**。实测 158 条名册里学号排在末页的学生，
> 只扫第一页就被误判「不在册」——翻到第 2 页才确认在册。
> **规则**：`has_more=true` 时必须继续翻页直到 `has_more=false`；
> 只有**全量读完后仍未命中**，才能走「学号不存在」的停止话术。

**关键不变量**：
- **首次记录后不再询问**。缓存命中后下次直接复核。
- 复核仍走**双因子**：学号或姓名任一对不上（如老师改了名册）→ 清缓存，按首次流程重新输入。
- **展示姓名以名册为准**：缓存里的姓名只用于双因子验证，称呼学生时读名册命中的那一行。
