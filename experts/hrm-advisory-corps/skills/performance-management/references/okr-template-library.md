# OKR 模板库

> 内容范围：提供 OKR vs KPI 边界澄清、Objective 写法、KR 写法与 4 个 prompt 模板，面向 hrm-advisory-corps 国内 HR 场景。
> 适用范围：与 `performance.md` 的「OKR 设计（O + 3×KR）」章节配合使用，为 performance-management agent 提供完整 OKR 模板库 + 季度复盘框架 + 上下对齐检查清单 + 评分机制。

## 一、OKR vs KPI（边界澄清）

| 维度 | OKR（目标管理） | KPI（绩效考核） |
|------|----------------|----------------|
| 目标 | 挑战性目标，0.7 完成度 = 成功 | 必须 100% 完成的硬指标 |
| 评估 | 相对进度，鼓励挑战 | 绝对达成度，与薪酬挂钩 |
| 周期 | 季度（可月滚动） | 月度/季度/年度 |
| 透明度 | 全员公开 | 通常保密或有限公开 |
| 用途 | 战略对齐 + 方向聚焦 | 绩效衡量 + 奖金分配 |

**铁律**：OKR 不替代 KPI，两者**正交使用**——OKR 决定"做对的事"，KPI 决定"把事做对"。

## 二、好的 Objective（O 写法）

- **鼓舞人心**：不是数字，而是方向（"成为用户最信赖的教育平台"而非"日活 100 万"）
- **定性为主**：通常是一个动宾短语
- **有野心**：超出舒适区，0.7 完成度就算成功
- **可记忆**：3-5 字短语，全员能脱口而出
- **有时限**：自然绑在季度/年度周期

**反例**：
- "提升运营效率"（无方向）
- "营收增长 50%"（是 KR 不是 O）
- "做好用户服务"（太泛）

## 三、好的 Key Result（KR 写法）

- **可衡量**：必须有量化指标
- **有挑战**：超出舒适区（不是"完成日常工作"）
- **有截止日期**：明确时间点
- **3-5 个 / O**：太多失焦
- **结果导向**：不是"做什么"而是"做到什么"

**格式**：动词 + 量化指标 + 时限（如"NPS 从 40 提升到 60，6 月底前"）

## 四、季度复盘框架

每个 KR 必须产出 4 项内容：

1. **完成度评分（0-1.0）**：实际 / 目标。0.7 左右为成功，0.4 以下需找根因
2. **KR 分析**：达成 / 部分达成 / 未达成的根因（5-why）
3. **成功因素**：哪些动作/资源/团队行为促成（沉淀复用）
4. **改进空间**：未达成 KR 的补救 + 下一季度的预防措施

季度复盘输出格式：

```
【Q1 复盘】
- O1（目标描述）：完成度评分
 - KR1.1: 0.8 [OK]（成功因素：…）
 - KR1.2: 0.5 [X]（根因：…，改进：…）
- O2：…
【下季度建议】
- 保留：…
- 调整：…
- 新增：…
```

## 五、上下对齐检查清单

公司 → 部门 → 团队 → 个人四级 OKR 的对齐检查：

- [ ] 公司级 O 与部门级 O 是否承接（部门 O 是公司 O 的子集或关键路径）
- [ ] 部门级 O 之间是否有冲突（资源争抢 / 目标矛盾）
- [ ] 部门级 O 是否覆盖公司级 O 的所有 KR（无遗漏环节）
- [ ] 团队级 O 是否每个都向上对齐到部门 O（无悬空）
- [ ] 个人 OKR 是否 100% 向上对齐（避免个人目标与团队脱钩）
- [ ] 横向协作：跨部门 OKR 是否有"对接口人 + 共同 KR"（避免协作真空）

## 六、评分机制

### Google 0-1.0 评分
- 1.0：超出预期（罕见）
- 0.7：达成挑战目标（成功线）
- 0.5-0.6：部分达成
- 0.3-0.4：未达成但有学习
- 0.0-0.2：完全失败

### 与绩效奖金的解耦
- OKR 评分**不直接挂钩奖金**（避免为追求 0.7 而压低目标）
- KPI 评分**才挂钩奖金**（保底线）
- 两者各走各的评估通道

## 七、4 个常用 Prompt 模板（与 okr_tracker.sh 子命令一致）

### 1. `create` — 制定 OKR
```
你是OKR教练。制定OKR：1. Objective（鼓舞人心，定性，3-5 字短语）2. 3-5 个 Key Results（可衡量，有挑战，有截止日期）3. 每个 KR 的里程碑 4. 所需资源 5. 风险。用中文。
角色和目标：<用户输入>
```

### 2. `review` — 季度复盘
```
你是OKR评审专家。季度复盘：1. 完成度评分（0-1.0）2. 每个 KR 分析（达成/部分达成/未达成根因）3. 成功因素 4. 改进空间 5. 下季度建议。用中文。
OKR执行情况：<用户输入>
```

### 3. `align` — 战略对齐检查
```
你是战略对齐专家。检查 OKR 对齐：1. 公司→部门→个人的关联 2. 冲突识别 3. 缺失环节 4. 对齐建议。用中文。
各级OKR：<用户输入>
```

### 4. `score` — 评分输出
评分模板见「六、评分机制」一节，与 0-1.0 评分 + KPI 解耦原则配套。

## 十、不适用场景

- **销售提成类指标**：走 KPI（payroll-china.md），不混用 OKR
- **合规/红线指标**：KPI 强制项，不进 OKR（避免被"挑战性"稀释）
- **短期（<1 月）任务**：用 Task/todo 即可，无需 OKR
- **个人学习成长目标**：可单独立 OKR，但不与公司级强对齐
