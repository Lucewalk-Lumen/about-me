# org-planning 领域 playbook（私有）

本文件是该 specialist 的领域工作流基准，由 `agents/org-planning.md` 加载。共享契约见 `../hrm-solution/contracts.md`；共享引擎见 `../hrm-solution/scripts/`。

## 核心能力
1. **组织健康度诊断**：管理幅度、层级、IC/经理比、团队规模四维指标
2. **Headcount 需求预测**：岗位/层级/数量/优先级/成本预估
3. **架构模型比选**：职能型/事业部型/矩阵型/扁平型四选一
4. **招聘路线图**：分季度输出招聘计划与里程碑
5. **经营运营简报**：
   - 一页快照：现金/销售/管道/工单等核心指标，标注 [红/不通过]紧急/[黄/待优化]关注/[绿/通过]正常
   - 周一简报：本周 Top 3 优先级、待决事项（owner+期限）、关键会议
   - 周五复盘：本周成果、缺口与风险、下周预告
   - 季度复盘（QBR）：维度评分、战略主题、下季 3 大重点

## 分析框架

组织问题一律按下列六步顺序推演，不得跳步直接给架构结论：

1. **战略解码**：业务目标、增长阶段与关键战役 → 推导组织必须具备的能力项，明确"组织为什么要变"
2. **现状测绘**：团队清单、层级深度、汇报关系、编制占用与在招岗位，形成可计算的组织基线
3. **四维健康度诊断**：管理幅度、层级深度、IC/经理比、团队规模逐项对照 `references/org-health.md` 基准值，标出偏离档位
4. **缺口定级**：把健康度偏离与能力缺口合并为风险清单，按 P0（阻碍战略落地）/ P1（效率显著损耗）/ P2（观察项）定级
5. **架构模型比选**：职能型 / 事业部型 / 矩阵型 / 扁平型四选一，逐一比对适配条件、代价与迁移成本，写明淘汰其余三种的理由
6. **编制与路线图**：按 P0→P2 顺序转化为分季度 Headcount 计划与里程碑，每个岗位标注优先级、成本区间与依赖关系

框架约束：第 3 步必须以 `../hrm-solution/scripts/org_health.py` 的实际计算结果为输入，不得凭经验估算；第 5 步的推荐必须能追溯到第 1 步的战略结论。

## 工作流程
1. 收集组织数据（团队列表/层级/汇报关系）→ 整理为 JSON，键名严格按 `references/org-health.md`「输入结构」书写：顶层只允许 `teams` 与 `total_depth`，每个团队必填 `size`
2. 运行 `python3 ../hrm-solution/scripts/org_health.py org.json`（Windows 用 `python`）计算健康度；若返回退出码 2，说明输入 schema 不匹配，按 stderr 提示修正键名后重跑，**不得**拿空结果继续往下推导
3. 基于业务战略输出 Headcount 预测 + 架构推荐 + 招聘路线图
4. 经营简报：按需从业务数据抽取指标，按"结论先行、表格呈现、关注项分级"输出

## 输出规范

> **严重度分两层，勿混用**：
> - **引擎层**（`../hrm-solution/scripts/org_health.py` 直出）：`risks[].severity` 取枚举 `WARNING | CRITICAL`（即四维指标 `status` 的 `warning` / `critical` 大写；`healthy` 不入列）。这是机器的原始判定，**不得改写**。
> - **Playbook 层**（本 skill 面向人的风险定级）：`P0 | P1 | P2`，由 specialist 按「分析框架」第 4 步与「结构化输出模板 · 结论摘要 / 风险清单」，结合战略影响判定；与引擎枚举**正交**，不强制一一映射。

```json
{
  "org_health": { "span_of_control": {...}, "hierarchy_depth": {...}, "ic_manager_ratio": {...}, "team_size": {...} },
  "risks": [{ "type": "...", "severity": "WARNING|CRITICAL", "detail": "..." }],
  "headcount_plan": [...],
  "architecture_recommendation": { "model": "functional|divisional|matrix|flat", "rationale": "..." },
  "hiring_roadmap": [...]
}
```

## 护栏
- 不输出未经健康度诊断的 Headcount 建议
- 不对具体个人做出晋升/调岗决定
- 不涉及薪酬预算审批（转交 `compensation-strategy`）
- 不得编造统计数字、样本量、调研结果或行业基准；引用外部数据须注明来源与日期，不确定即标「需人工核实」
- DRI：组织规划总监
