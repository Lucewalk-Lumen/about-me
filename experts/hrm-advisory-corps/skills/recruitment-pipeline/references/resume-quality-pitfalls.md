# Resume Quality Pitfalls

> 与正篇 `resume-quality.md` 配套使用：正篇给规范，本篇给反例。
> 反例基于公开行业经验整理，**禁止编造**。每个对比对均给出「错点」「后果」「改写方向」。

## 1. 投递失败简历 vs 优秀简历（R1-R5 综合）

### 1.1 投递失败典型（命中 R1 拦截）

```
【工作经历】
2020-2023 XX 科技有限公司
- 负责产品相关工作
- 具备良好的沟通能力和团队合作精神
- 熟练掌握各种办公软件
- 积累了丰富的项目经验
```

| 错点 | 后果 | 改写方向 |
|---|---|---|
| 无量化（"丰富"是主观词） | 触发 R1 第 3 条（缺乏具体数字与结果） | 量化：项目数 / 周期 / 金额 / 转化率 |
| 无 STAR 结构 | 触发 R1 第 7 条 | 套 S/T/A/R 四段重写 |
| 模板化措辞（"具备良好的…能力"）| 触发 R1 第 1 条 | 落到工具/方法/成果 |
| 无目标岗位关键词 | R3 关键词覆盖 = 0 | 显式出现 JD 关键词 |

### 1.2 优秀对照

```
【工作经历】
2020-2023 XX 科技有限公司 高级产品经理
- 主导 B 端 SaaS 看板从 0 到 1 设计落地，覆盖 12 个客户场景
- 通过埋点+用户访谈重构注册流程，注册转化率 18% → 32%（提升 14pp）
- 协调 4 名研发 + 2 名设计，跨部门需求交付 2 周内完成
- 输出 3 份 PRD + 1 份 A/B 测试复盘文档，被产品组纳入模板
```

- R1 拦截风险：0/8
- R2 6 维评分：内容 9 / 量化 9 / 成果 8 / 精炼 7 / 逻辑 9 / 关键词 8
- R3 JD 匹配：核心关键词命中率 ≈ 80%

## 2. STAR 改写错误（命中 R4 反模式）

### 2.1 错误形态

```
负责了系统的优化工作，提升了系统性能。
```

| 错点 | 改写方向 |
|---|---|
| 无 S（情境） | 补业务背景：用户量、痛点、约束 |
| 无 T（任务） | 补角色与目标 |
| 无 A（行动） | 补具体技术方案 / 协调动作 |
| 无 R（结果） | 补量化结果：QPS / 延迟 / 用户反馈 |
| "提升了" 是无量化动词 | 改为 "降低 P99 延迟 240ms → 80ms（↓ 67%）" |

### 2.2 正确形态

```
【S】系统 P99 延迟 240ms，DAU 30 万时频繁超时投诉。
【T】作为后端 owner 需在 6 周内降至 100ms 以内。
【A】定位慢 SQL（N+1 + 缺失索引），引入 Redis 缓存热点行，
 数据库从 16 拆 32 库，灰度 4 周。
【R】P99 240ms → 80ms（↓ 67%），超时投诉 ↓ 92%，QPS 容量 2x。
```

## 3. ATS 解析失败（命中 R5 反模式）

| 反模式 | 后果 | 修复 |
|---|---|---|
| 表格 / 双栏 / 文本框 | ATS 解析后顺序错乱 | 改为单栏左对齐 |
| 标题用图片 / 艺术字 | 关键词覆盖率 = 0 | 标题用纯文本 |
| 技能罗列用图标 | ATS 不识别图标对应文本 | 改为文字 |
| 时间格式不统一（2020.03 / 2020-3 / 2020）| 时间线错乱 | 统一 "YYYY-MM" |
| 联系方式放在页眉 | 部分 ATS 抓不到 | 放在正文顶部 |

## 使用纪律（衔接正篇）

- 反例库不是「正确答案模板」——**禁止把反例当模板照抄**；反例是「错点清单 + 改写方向」
- 反例命中 1 个错点即应触发改写，不需全中
- 改写后必须回跑 R1 拦截检测，0/8 才算通过
- 改写保留候选人真实经历，**绝不编造成果**
