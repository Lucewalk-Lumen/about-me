# 寻访方法论 · 六步寻访法

> 本文件是 talent-sourcing 的执行层方法论文档，与 `SKILL.md` 的六步工作流一一对应。标准与阈值以 `SKILL.md` 为准，本文件提供操作细节。

## 总览

```
需求解析 → 供给判断 → 画像 → 搜索 → 初评 → 推荐
```

六步对应主工作流的环节 1-4：需求解析（环节 1）、供给判断与画像（环节 1 的延伸）、搜索（环节 2）、初评（环节 3）、推荐（环节 4）。环节 5（跟进交接）与环节 6（结果回写）按 `SKILL.md` 与共享契约执行，本文不重复。

## 第 1 步：需求解析（JD 六要素拆解）

把用人部门的口头/书面需求还原为可执行的寻访画像。六要素逐条过，缺项必须回问，不得脑补：

1. **战略定位与业务目标**：这个岗位挂在哪条业务线上，解决什么业务问题。决定寻访时向候选人怎么讲机会。
2. **核心挑战**：上任后 6-12 个月要啃的硬骨头。决定画像里哪项能力是「没它不行」。
3. **能力权重排序**：把能力要求权重化（合计 100），写入 `sourcing_profile.capability_weights`。排序逼用人部门做取舍，避免「什么都要」。
4. **隐性招聘诉求**：不会写进 JD 但真实存在的期望，写入 `sourcing_profile.implicit_expectations`。示例：该岗位前任因跨部门推动不力离开，隐含强 stakeholder 管理能力要求。获取方式：问「上一个做这个位置的人为什么离开 / 做得好的和做不好的差在哪」。
5. **准入门槛三档**：
   - 必备项（`must_have`）：缺一即不推荐，硬门槛。
   - 加分项（`nice_to_have`）：影响分级不影响准入。
   - 红线（`sourcing_profile.exclude`）：命中即硬过滤，不进 shortlist。红线必须具体可核验（如「3 段经历均 <1 年」），禁止性别/年龄/婚育/民族/宗教等歧视性条件。
6. **可直接搜索的人才标签组合**：`talent_tags` + `skill_keywords` 三级分类（见下节）。

产出：`requisition` JSON（J 系列）+ 一页寻访画像摘要。

### 关键词三级分类使用说明

`sourcing_profile.skill_keywords` 分三层，中英对照：

| 层级 | 字段 | 含义 | 用法 |
|---|---|---|---|
| 通用标准名 | `standard_terms` | 行业通行的标准技术/职能词 | 主匹配词，权重最高 |
| 细分赛道专属名 | `niche_terms` | 只在特定赛道/公司体系内使用的词 | 辅助定位目标公司与项目经历 |
| 行业通用别名 | `aliases` | 同一能力的别称/旧称 | 参与匹配但命中权重低于标准名 |

- `copy_ready_list` 是三类词拼好的空格分隔列表，可直接贴进招聘平台搜索框。
- 匹配引擎 `sourcing_matcher.py` 检索时三类词均参与：标准名与专属名按全权重计，别名按降权计（避免别名泛化导致的误命中排前）。
- 拆解时先写标准名，再补专属名（问「这个技能在目标公司里叫什么」），最后补别名。

## 第 2 步：供给判断

在动手搜索前判断这个岗位好不好寻：

- 查 `knowledge/talent-personas/` 有无对应画像：市场存量、活跃率、集中城市、薪酬基准（p50/p75）。
- 无现成画像时，按岗位层级与赛道做快速判断，结论只能是「易招 / 常规 / 稀缺」三档，并写明依据。
- 画像库中的市场数据若标「需人工核实」，引用时必须原样带出该标注，不得当作已核实事实。

## 第 3 步：画像与目标清单

- 寻访画像 = requisition 的 `sourcing_profile` + 供给判断结论。
- 目标公司清单：`sourcing_profile.target_companies` 联动 `knowledge/talent-maps/` 的 `tiers`（头部标杆/直接竞品/高潜力），并执行 `red_lines` 三条红线：
  - 剔除客户主体；
  - 规避经营异常主体（以国家企业信用信息公示系统为准，标注基准日期）；
  - 同城市占比 ≥40%，不足须补充周边同能级城市企业并标注说明。
- tiers 默认基准 10/8/2，可按岗位层级调整，调整后须在寻访画像摘要中注明。

## 第 4 步：搜索

- 渠道优先级：人才库存量（`talent_pool.py search`）→ 人才地图定向 → 渠道库中 status=active 的渠道。
- 搜索条件：技能（三级关键词）+ 城市 + 年限 + 目标公司清单过滤 + exclude 红线硬过滤。
- 匹配分口径（写入 SKILL.md，可调）：技能命中率×50% + 年限契合×20% + 城市匹配×15% + 目标公司/行业契合×15%。
- 每个命中结果必须带「命中依据」（命中了哪些关键词/条件），不允许只给分不给依据。

## 第 5 步：初评

- 寻访适配三维（触达难度 30% / 在职稳定性 35% / 薪酬契合度 35%）逐人打分，打分要点见 `SKILL.md`。
- A 级候选与关键岗位追加五维评分：CLI 调 `python3 ../../../hrm-solution/scripts/candidate_scorer.py --scores '<JSON>'`（相对本技能 scripts/ 目录的路径；Windows 用 `python`）。
- 两套分并列呈现、各自注明口径，不得混用。
- SBTI 测评字段（`profile.assessment`）本版本只作预留：候选人主动授权且已完成测评时才填入档案，初评不消费。

## 第 6 步：推荐

- 按 `SKILL.md` 分级规则归 A/B/C 级；不推荐者记录原因，档案依合规规则保留。
- shortlist 按 `references/shortlist-template.md` 产出 JSON + Markdown；触达话术双版本（平台版 ≤200 字 / 电话版 ≤350 字覆盖七要素）。
- 交付前：PII 脱敏 → 话术送 labor-compliance 审查 → 信封封装回传主理人。
