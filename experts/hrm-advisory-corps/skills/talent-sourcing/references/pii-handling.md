# PII 处理细则（对齐个保法）

> 法条出处：《中华人民共和国个人信息保护法》（2021-08-20 通过，**2021-11-01 施行**）。本文件是 talent-sourcing 的操作层细则；共享脱敏引擎为 `../hrm-solution/scripts/security/pii.py`。

## 六条规则与操作落实

| # | 规则 | 操作细则 | 法条依据 |
|---|---|---|---|
| 1 | 告知同意 | 入库前检查档案 `source.consent`：`obtained` 必须为 `true`，且 `obtained_at` / `scope` / `method` 三字段齐全；缺一即拒绝入库，向主理人报告缺失项 | 第十三条、第十四条 |
| 2 | 最小必要 | 寻访预建档只收岗位匹配必需字段（见 resumes schema）；身份证号、婚育、家庭信息一律不采集；需求方提出采集时拒绝并说明依据 | 第六条 |
| 3 | 脱敏存储 | 档案 JSON 只存脱敏视图（`phone_masked` / `email_masked`）；明文联系方式原则上不落盘，如确需中转仅存独立权限的 PII 保管区并记 `pii_vault_ref` 引用（当前版本不启用明文存储、无加密保管区实现，见 `PRIVACY.md`）；日志、信封、shortlist 报告一律脱敏后落盘 | 第五十一条 |
| 4 | 删除权 | 候选人要求删除时执行 `talent_pool.py delete <candidate_id>`：物理删除档案与保管区记录，并在 `resumes/_index.json` 的 `audit_log` 记录（时间、操作人、依据）；删除不可恢复，执行前经主理人确认 | 第四十七条 |
| 5 | 敏感个人信息 | 不收集敏感个人信息（生物识别、宗教信仰、医疗健康等）；寻访中意外获得的，立即从档案与上下文删除，并在回传中如实报告发生过 | 第二十八条、第二十九条 |
| 6 | 就业歧视红线 | 画像与筛选条件禁止性别/年龄/婚育/民族/宗教维度；红线（exclude）只允许写可核验的行为/经历条件 | 《中华人民共和国就业促进法》第三条、第二十六条 |

## pii.py 调用点

共享引擎路径（相对包根）：`skills/hrm-solution/scripts/security/pii.py`。

| 调用点 | 时机 | 用到的方法 |
|---|---|---|
| 档案入库 | `talent_pool.py add` 写入前 | `mask_phone` / `mask_email` 生成脱敏字段；`redact_pii` 兜底扫描 |
| 检索输出 | `talent_pool.py get / search` 输出前 | `redact_pii` 全量扫一遍，确保无明文泄露 |
| shortlist 报告 | 生成 Markdown/JSON 后、封装信封前 | `redact_pii` |
| 回传信封 | `envelope.py` 签名前 | `redact_pii`（信封内容必须已是脱敏态） |
| 日志落盘 | 任何日志写入前 | `redact_pii` |

调用约定：本技能的脚本（`scripts/talent_pool.py`、`scripts/sourcing_matcher.py`）在包内通过相对路径 import 共享脱敏引擎（包内相对位置：`../../hrm-solution/scripts/security/pii.py`，落地时按 INDEX.md 登记的跨技能引用路径执行）；上表五个调用点均已接入，任何新增写入路径必须先过脱敏再落盘。

## 数据来源合规清单（入库前置检查）

| 来源 | 合规要点 |
|---|---|
| 历史候选人（企业 ATS 沉淀） | 入库时确认原告知范围；超出原目的使用须重新取得同意 |
| 内推 | 推荐人须确认被推荐人已知晓并同意 |
| 候选人主动投递/授权 | 保存同意记录（时间、方式、用途范围） |
| 公开职业平台（经候选人授权的档案导出） | 仅限候选人本人操作导出的数据；平台条款禁止抓取的不得抓取 |
| 人才地图调研（公开信息整理） | 仅收集职业公开信息（公司、职位、公开履历），不收集私人联系方式 |
