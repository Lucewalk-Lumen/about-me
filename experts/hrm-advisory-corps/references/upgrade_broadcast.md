# 版本功能速览流程（首条消息必做）

> 本流程对应主理人「版本功能速览」职责：确保**版本更新、用户再次召唤时能知道本版本的功能要点**，
> 且**同一版本读过一次后不再重复打扰**。本文件是 `agents/hrm-advisory-corps-lead.md` 版本速览指针的子流程，
> 执行前先 Read 本文件，未读不得操作。

## 触发时机
每次新会话被召唤、收到首条用户消息时执行（在常规开场白之后、受理 HR 需求之前）。

## 步骤
1. 读本专家包根目录下 `.codebuddy-plugin/plugin.json` 取 `version`（记为 **V**）；读包根 `UPGRADE.md` 提取与 V 对应的「## v{V}」段落要点。
2. 读状态文件 `~/.workbuddy/hrm-advisory-corps/seen_upgrade.txt`（记录上次已播报版本；不存在视为从未播报）。
3. **若 V 与已记录版本不同**（或文件缺失 / 读取失败），向用户输出一段**独立区块**：
   ```
   【HRM 实战参谋团 · v{V} 功能速览】
   本次版本要点：…（取自 UPGRADE.md 该版本要点，精简 2–4 条）
   ```
   随后把 V 写回 `~/.workbuddy/hrm-advisory-corps/seen_upgrade.txt`（目录不存在先 `mkdir -p`；写失败不阻塞，下次仍会播报）。
4. **若 V 相同**，则**跳过**此提示，不打扰。

## 边界
- 本流程只读取包内清单与更新说明、只写一个状态文件，**不启动任何成员 Agent、不执行任何业务模块、不产生任何交付物**。
- 播报是纯文本告知，不得打断用户原本的诉求；他若已在提需求，先受理需求再顺带告知。

## 降级
若 `UPGRADE.md` 无法读取，则改为提示「本版本已更新，更新要点见包内 UPGRADE.md」，**不得静默省略**。

## 状态文件约定
- 路径：`~/.workbuddy/hrm-advisory-corps/seen_upgrade.txt`（仅存一行版本号文本，如 `1.0.0`）。
- 写权限受限时不阻塞：写失败则下次会话仍会播报，属安全兜底。
