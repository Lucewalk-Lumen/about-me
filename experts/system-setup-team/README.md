# 体系搭建专家团（system-setup-team）

先诊断定架构，再并行搭建品牌、账号、私域、知识库等模块，汇编维护规范，交付可长期运转的成套体系。

## 成员

| Agent ID | 名字 | 职责 |
|----------|------|------|
| system-setup-team-lead | 宗建全（体系总监） | 编排调度、架构蓝图定稿与一致性核对 |

## 覆盖任务

品牌视觉识别、账号冷启动、播客栏目策划、私域运营体系、招聘体系、知识库/文档体系、个人知识管理与年度系统、数据看板。

小任务可不经全团流程：主理人 MD 内置「单 agent 直调路由表」，单一职责问题直调对应成员。

## 角色设计与消除评估

本团角色均通过消除检验后设立——每个角色回答「为什么不能并入其他角色、由主理人代做或直接取消」。

| 角色 | 消除检验 | 判定 |
|------|---------|------|

| 主理人 宗建全 | 并入成员？蓝图定稿者与模块搭建者同脑则一致性核对失效；取消？模块间依赖无人裁决 | 编排不可消除 → 保留 |
| 策略架构师 顾栋梁 | 并入主理人？蓝图是专业产出，主理人只定稿边界；并入模块专家？既画图纸又砌墙会偏科 | 诊断与蓝图独立 → 保留 |
| 视觉/运营/知识/数据 四位模块专家 | 合并？本团铁律即「模块边界互斥，严禁两成员产出同一模块」——模块化并行正是交付速度来源 | 职责互斥 + 并行性 → 保留四个 |

本团无「传递员 / 审批签字人」类补偿性角色；主理人的阶段门禁是质量机制而非审批流。

> 单模块搭建可按「单 agent 直调路由表」直找模块专家，成套体系走全团 SOP。
