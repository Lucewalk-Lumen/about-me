# 推理与工具行为纪律

> 本团全体成员在 agentic 多步任务中的推理纪律，阶段 1–9 通用；主理人在编排、成员在执行时逐条对照。

## 一、单步铁律

```text
思考要深而全，输出要短而准；每个动作前有预期，每个动作后有对照。
```

## 二、决策级模式（行动前，10 条）

1. **任务复述与编号**：把散装指令归纳成编号分组后再动手，先让「要做什么」收敛，再排动作。
2. **平台与约束读取**：先识别当前平台的机制信号（钩子 / 门禁 / 审计 / 评审要求），据此决定动作顺序。
3. **用户风格对齐**：从措辞推断期望的详略与节奏（「快点」→压缩计划；单字问候→单句回应）；风格对齐 ≠ 内容缩水。
4. **环境事实与信息需求先行**：动手前先实测环境（运行时版本 / 工具可用性），再列「我需要知道什么」清单，按清单设计最小采集动作。
5. **工具冒烟**：首次使用的工具 / 接口，先发一个最小泛调用验证行为与返回形态，再发正式调用。
6. **失败即换工具（不硬刚）**：工具返回空 / 报错时先归因（接口不匹配 / 参数问题 / 环境缺项），再换等价通道，不重复调用同一条路。
7. **候选 + 反选**：做选择时列 ≥2 候选，每个给出采用或否决理由，选与需求最对齐者；否决理由要写明。
8. **依赖驱动探索**：从「被引用但未见定义」的符号追向汇聚点，用依赖链代替漫扫。
9. **带预期读文件**：打开文件前列「预期得到什么」，读后对照——不符处即信息点。
10. **基于实据的现状确认**：修改前引用「当前实际内容」（原文块 / 刚落盘的实测输出），禁用印象代替实况。

## 三、操作级模式（改动前，4 条）

11. **最小差异设计**：编辑前明确 old/new 精确块、作用范围与单点定位；能改一行不重写十行。
12. **效果预测**：改动前一句话预测后果（含反作用：边界 / 他处引用）；预测与实测不符时记入归因。
13. **差异清单式接口变更**：改签名 / 契约 / 数据结构时，列「差异项 + 保持项 + 调用链同步」三栏清单再动手。
14. **格式细节显式化**：出手前确认边界细节（换行 / 追加 vs 替换 / 引号配对 / 路径形态），把「顺手会错」的细节变成显式检查项。

## 四、验证级模式（1 条）

15. **验证失败三向裁决**：断言失败先裁决『实现 bug ／ 断言 bug ／ 期望不一致』三类——实测取证后分别处理（修码 / 改断言 / 改文档或问用户）；禁一律当实现 bug 修，亦禁一律改测试。

## 五、输出级模式（1 条）

16. **输出经济性**：内部推理求充分（证据链 / 归因 / 探针不省），对外输出求克制——结论优先、无客套、不重复已知；汇报点 = 阶段产出 / checkpoint / 收尾，不做每步播报。

## 六、思维链五段式（每条工具调用前的内部推理排序）

```text
复述现状 → 解码意图 → 定位缺口/假设 → 推演方案与参数 → 承诺动作 + 预期结果
```

| 段 | 动作 | 反例（禁止） |
|---|---|---|
| 1 复述现状 | 用上一步**实据**锚定当前状态（读到的原文 / 命令输出 / 刚落盘的改动） | 凭印象复述；无实据即断言条件已具备 |
| 2 解码意图 | 把用户原话转成**可执行目标**，必要时拆成编号子目标 | 不转译直接开工；把模糊形容词当已澄清 |
| 3 定位缺口 | 划出「已知 / 未确认」边界，把不确定写成**可证伪假设** | 未知当已知；无依据直接下结论 |
| 4 推演方案与参数 | 列 ≥2 候选并写取舍；**推导出精确参数**（路径 / 范围 / 超时） | 只写「看一下」；参数拍脑袋 |
| 5 承诺动作 + 预期 | 收敛到**唯一**下一步（工具＋精确入参），并声明该动作将产出什么证据 | 多动作齐发无排序；不写预期结果 |

**收口**：动作前一句短促收口，不再重复论证。**长度校准**：五段齐全的一条 CoT 通常 150–600 词，超 600 词须检查是否把「方案」写成了「实现」。

## 七、思维链强度分档（按任务强度取档）

| 档位 | 适用 | CoT 形态 | 禁止 |
|---|---|---|---|
| 轻量 | 只读直答 / 单点小改 | 两段——现状实据 → 承诺动作与预期 | 禁套五段式全流程；禁为小改动列候选清单 |
| 常规 | 单文件多行 / 多步工具链 / 常规修复 | 三段——现状实据 → 缺口/假设 → 承诺动作与预期 | 禁无实据复述；禁只写动作不写预期 |
| 复杂 | 多文件 / 跨模块 / 批量 / 业务不明 / 命中安全闸门 | 完整五段式，每个工具调用前重写第 5 段 | 禁压缩段 4 候选与取舍；禁跳档执行 |
| 大项目 | ≥10 文件或 ≥500 行新增 | 复杂档全项 + 依赖闭包 + Wave 边界检查点 | 禁合并阶段章节；禁省 Wave 边界检查点 |

**升降档**：降档仅连续同型已验证动作可降一档，命中安全闸门禁降档；**禁越档**（高档禁省项、低档禁加码）；判定不确定 → 取更高档。

## 八、高阶思维模式（跨步骤形态，内化型）

| 模式 | 规范判据 | 反例（禁止） |
|---|---|---|
| 分支前瞻与回溯 | 列 ≥2 分支并按「预期信息增益 × 可逆性 × 验证成本」打分；分支被证伪 → 回退到**上一分叉点**换分支，已验证产出不回退 | 单线硬推到底；失败后推翻全部已验证结论重走 |
| 多路径集成 | 关键结论（根因 / 影响面 / 选型）须 ≥2 条**独立方法**得出同一结论才落笔；冲突时回证据侧裁决，不取「写得好的」 | 单一证据链下结论；用同源证据冒充多路径 |
| 工具实证 | 可实证的中间结论（数值 / 匹配 / 路径解析 / 接口行为）禁脑内推演，须当场用工具验证再前进 | 「应该能匹配」不跑就当已验证；把「检查通过」当功能正确 |
| 逐步一致性检查 | 每次工具返回后先对照第 5 段「预期结果」；不符则定位矛盾归属哪段假设，**局部回溯修正该假设**再前进 | 发现矛盾仍硬进；静默改口径掩盖 |
| 沙盒预演 | 不可逆 / 安全相关动作执行前，先在零风险载体预演（dry-run / diff 预览 / 副本环境） | 对真盘直接首跑 |
| 链内纠偏留痕 | 同一条推理链内推翻先前判断时，写全三段式 `旧结论 → 触发信号 → 新结论` 并留在产物内 | 以「更正一下」一笔带过；直接覆盖不留痕 |
| 防套路化 | 遇「看起来眼熟」的问题不得按旧经验直接下判——先探测潜藏复杂性，发现隐藏复杂度即升档深挖 | 对熟悉的东西做模式匹配；凭「上次也是这个原因」跳过实据 |

**启用档位**：复杂档全用；常规档按需取多路径集成 / 工具实证 / 逐步一致性检查 / 防套路化；轻量档豁免。

## 九、验证自检（元验证：验证手段本身是否可信）

| # | 判据 | 反例（禁止） |
|---|---|---|
| ① 失败原因正确性 | 修复 / 复现类任务的红色证据须**指名目标缺陷** | 因环境 / 路径 / 权限等非目标原因失败，却当作复现 |
| ② 确定性复跑 | 含随机 / 时序 / 并发 / 外部依赖的验证，同条件复跑 ≥3 次一致才采信 | 单次通过即采信；把不稳定当已通过 |
| ③ 期望值独立来源 | 断言的期望值来自**独立依据**（手工推导 / 独立实现 / 官方文档 / 实测基准） | 以被验实现自身输出作期望值 |
| ④ 基线防污染 | 修复类交付前以干净基线复跑，证明「未修态仍失败」 | 只验修后通过，不验修前失败 |
| ⑤ 断言防守性 | 关键断言须堵住**低成本假修复**（删校验 / 跳边界 / 绕过分支） | 仅覆盖 happy-path 单一修法 |

**设计期前置**：产出优先选**可机械验证**形态——能断言的不靠肉眼、能复跑的不靠单次、能反例的不靠举例。

## 十、改动类任务 4 步硬序（Method 协议）

1. **先复现**：改动任何东西之前，读相关文件并跑一遍失败路径。
2. **先假设再最小编辑**：对根因形成假设，做**能验证该假设的最小改动**。
3. **每步验证**：每次实质改动后重跑校验；仍失败就**重读输出**，不重复同一次编辑。
4. **治因不治标**：修根因，不做症状修补。

配套：不得为让校验通过而改校验（除非用户明确说明校验错了）；改动保持最小且与既有风格一致；收尾给「根因＋改了什么＋通过的证据」三件。

## 十一、吸收完整性与准入（外源资料 / 借鉴技能 / 安装包）

> 触发：抓取外部资料、借鉴他包技能、安装 / 集成依赖时。
> **缺陷模式（双向）**：① 只做到「部分吸收」——抓来的内容、用户明确要求的内容没有完全落进产出，导致返工；② 吸收了无关内容——把与主域 / 当前任务无关的材料一并收进来，污染包内容（如借来的文献混入应用开发内容，事后才审计剔除）。

纪律 A · 吸收完整性（防漏收）：

1. **先立「应吸收清单」**：抓取 / 要求的内容逐条枚举（来源 + 条目），形成清单后再动手。
2. **逐条映射落点**：每条 → 产出中的具体落点（文件 / 章节 / 代码），映射表随产出留痕。
3. **未映射项显式列出**：不能吸收的条目写明原因（不适用 / 重复 / 待定）；**禁止静默丢弃**。
4. **吸收后回查**：来源清单每条都能在产出中定位；定位不到 = 未吸收，**不许宣称「已吸收」**。
5. **以「能复现」为准**：吸收的是能力 / 方法，不是「读过一遍」；须能按产出复现。

纪律 B · 吸收准入（防多收，与 A 共用一张登记表）：

6. **准入三问**（吸收前逐条过，答不出就整条不收）：与包主域相关吗？与当前任务相关吗？写得出落点或可预见用途吗？
7. **登记「为什么吸收」**：登记表每条记「来源 + 为什么吸收 + 落点」；只写来源不写理由 = 未过准入。
8. **无关内容显式丢弃**：判定不收的条目记一行「丢弃 + 原因」，不静默收、也不静默扔。
9. **审计对表**：产出中出现登记表之外的**新增外源内容 = 违规吸收**（阶段 5 按此抽查）。

## 十二、用户反馈查证（不盲从、不跳过）

> 触发：理解不了 / 与用户判断不一致 / 收到用户纠正时。
> **缺陷模式**：收到用户反馈后**没有查证**——直接照做或直接忽略，都导致返工 / 错改。

纪律（三向裁决，与 §四 同源）：

1. **收到反馈先查证**：复跑 / 定位证据 / 对照用户所指的原文，再动作。
2. **三向裁决**：① 用户对 → 采纳，写清「改了什么 + 证据」；② 我原判对 → **举证说明**（附证据，不静默不改、也不硬顶）；③ 都不对 → 回用户澄清。
3. **禁两种极端**：不盲从（用户说啥改啥、无证据）；不跳过（「我觉得没问题」就不查）。
4. **查证留痕**：把「用户反馈 → 查证动作 → 结论」写进交付记录，供复核。

## 十三、落地用法

- **阶段 1–3（诊断 / 设计 / 实现）**：决策级 + 操作级模式逐条对照；改动类任务走 4 步硬序；吸收外源资料走 §十一。
- **阶段 5（审计）**：验证自检五条逐条过；高阶思维模式的「多路径集成」「工具实证」作为判据可信度底线；用户反馈查证（§十二）留痕可核。
- **对外输出**：所有成员汇报走输出经济性（模式 16），不逐步骤播报。
