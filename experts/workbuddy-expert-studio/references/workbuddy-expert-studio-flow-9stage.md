# 专家开发九阶段 SOP（本团方法论文献）

> 性质：本团方法论文献，由工程实践蒸馏、按成员职责切分；各成员在自己的 agent 定义里引用对应阶段。

本文是「证据驱动双环流水线」的浓缩：内环（质量环）保证每个判据真会红也真不冤枉好人；外环（演进环）把每轮可复用做法蒸馏成资产回灌。

---

## 阶段 1 · 立项与诊断（agent-diagnostician）

- 拿到被驳回的包，第一件事不是改，是**证伪用户的猜测**。
- 固定动作：解包→全量静态分析（不抽查）→本机实测关键命令保留原始输出→按五维（构成完整性/任务完成度/指令遵从性/事实辨别性/规则遵从性）推演→三档标注（实测 / 静态推断 / 推断待验证）→写明局限。
- 结论分三档标注，推测不与根因混淆。
- 某课件类专家包 v1.1.3 被疑「文档连接器」问题，诊断结论是「否」——真因是「核心任务与评测沙箱可无授权演示的能力无交集」（示例，已脱敏）。

## 阶段 2 · 结构设计（agent-architect）

- 包骨架（跨运行时约定）：agent-card / UNIVERSAL-STANDARD / PORTABILITY / plugin.json / agents/ / skills/。
- Agent 结构六要素（约束成员文档形状）：角色定义 / 擅长领域 / 分析框架 / 数据获取 / 结构化输出 / 回传要求（与 harness 的「构成六要素」同名不同义，勿混用）。
- 协作拓扑：建团→路由→中转（成员不直连）→回传→门控；硬门控由主理人统一守。
- P0 红线：P0-1 禁 emoji 图标（用 SVG/标准字形）；P0-2 禁 Indigo→Pink 渐变+发光+毛玻璃 AI 模板；P0-3 禁 AI 模板味文案。P0-1 针对**交付物**的功能图标 / 视觉资产；方法文献内部的严重度 / 状态文本符号不在此列。
- 自引用路径：用平台根目录变量，不假定等于会话工作目录；每种写法各一条扫描，确认有匹配再谈全通过（C005）。

## 阶段 3–4 · 实现与分片 + 质量校验（agent-engineer）

- 头号隐形杀手：平台约 2 万字符专家指令注入上限，超出静默截断；官方校验脚本不查此项。
- 分片：按平台真实口径量主文件（回车符计入）；超 1.8 万字符即规划分片；正文只留流程+铁律+路由表，长细则移分片。
- 计长口径（假绿高发区）：平台 `utf8.length`，CRLF 的 `\r` 计入；Python 文本模式会折 CRLF 少算字符→门禁误判通过。
- 能力边界具体到数字（条目数/唯一颜色数/字节量），不写「可优化」。
- 门禁落进构建脚本：存在性 / 旧词扫描 / 长度 / 分片完整性；加功能同轮补门禁（G009）。
- 门禁必须验证真会红：挪走文件→必 FAIL；恢复→必 PASS；清掉伪造替身（G003）。

## 阶段 5 · 审计与取证（agent-auditor）

- 判据一：审脚本必须真跑一遍，拿声称产物清单逐个核对（C003）。
- 判据二：结构化文件先写后检等于没检——内存构造→解析预检→写盘→读回再验（G002）。
- 判据三：假红与假绿同等对待；某教学类专家包曾把 15 个知识库文件名报 GBK 乱码、62 处断链——乱码只在 Git Bash 解压环节，zip 内 utf8flag=True 正常（示例，已脱敏）。
- 判据四：静态扫描命中逐条甄别，不甩命中数。
- 判据五：清点脚本自引用不动点，首跑少算自己一件，读数取第二跑（G006）。
- 判据六：豁免精确到文件/模式，报 0 必须变异自证（G007）。

## 阶段 6 · 干净打包（agent-packager）

- 三条禁令：禁指向上一轮名字 / 禁相对路径 / 改完必须复跑验证。
- 换版本九步（C004）：解压隔离→读清单与版本→查市场登记→目录比对新增→扫高危调用→备份→覆盖并回读→跑校验+重注册→核对版本四处一致。
- 校验必须在沙箱副本跑，绝不真包。
- 替换器与被判定方分离：正则批量替换会吃历史短语空格，另写独立复核脚本。

## 阶段 7–9 · 验收放行 + 版本治理 + 沉淀资产（agent-release-chronicler）

- 官方校验器通过 ≠ 可以上线；某文献分析包官方校验返回 is valid，深度审查仍发现 11 项实质缺陷（幽灵依赖 scipy、成员缺 displayName、头像断链）（示例，已脱敏）。
- 验收清单可脚本复跑（期望值/当前值/严重度 + 一键复跑；FAIL/WARN/PASS）。
- 版本单一真源：plugin.json 的 version；CHANGELOG 不作为版本依据。
- 计数漂移「移除」而非「改对」：让门禁实时报出，文档指向门禁。
- 蒸馏六段资产 R(原始依据)/I(意图)/A1(正向实证)/A2(触发信号)/E(执行步骤+完成标准)/B(边界与失效模式)；三关：可操作/可复用/独特。

## 协作契约（贯穿全程）

- 删除是红线：默认用移动代替删除；任何删除先显式征求同意。
- 越界写入需声明，结束后清理并如实记录落点。
- 交付要落盘并主动打开。
- 结论必须证据驱动，附原始命令与输出，区分已验证/建议/待确认。
- 临时产物分离：临时副本/变异实验/打包暂存放系统临时目录，工作区只放最终交付物。

## 阶段 9 经验卡片格式（沉淀）

任务收尾时把可复用做法落成经验卡片，字段：

- **场景**：任务类型 + 触发条件（什么情况下会遇到）
- **方法**：核心方法 / 关键步骤 / 涉及技能
- **避坑**：常见错误 + 解决方案
- **效果**：成功 / 失败 / 部分成功 + 效率提升 + 可复用性（高 / 中 / 低）
- **延伸**：还能用在哪些地方 / 类似场景推荐
- **标签**：`#类型 #技能 #价值等级`
