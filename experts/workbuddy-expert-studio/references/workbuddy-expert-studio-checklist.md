# 可直接复用的检查清单

> 性质：本团工程实践清单，按九阶段重排，供各阶段落盘勾选。
> 使用：每个 run 由对应成员在阶段目录落盘勾选；主理人汇总门控。

## 开发前
- [ ] 先跑一条最基础命令试探环境可用性
- [ ] 探查任务确认用受管隔离解释器路径可用
- [ ] 明确本次是「首装」「换版」还是「包内改动」——三者流程不同

## 设计时（阶段 2）
- [ ] 主文件长度按平台口径（回车符计入）估算，预计超 1.8 万字符就规划分片
- [ ] 多成员包的引用路径每种写法各写一条扫描，并确认扫描有匹配
- [ ] 自引用统一用平台根目录变量，不写死相对路径
- [ ] 能力描述具体到数字（条目数、唯一颜色数、字节量），不写「可优化」

## 编码时（阶段 3–4）
- [ ] 结构化文件：内存构造 → 解析预检 → 写盘 → 读回验证
- [ ] 脚本输出用 `[OK]`/`[FAIL]` 纯文本标记，不用 emoji
- [ ] 不用 `set -e` 一刀切，改逐步显式检查返回值
- [ ] 探针落成独立脚本再执行，不内联跑带正则/转义代码

## 提交前（阶段 4–5）
- [ ] 每条新判据都有正例 + 反向控制（绿红双证）
- [ ] 每条新门禁都做过「挪走文件看它真会红」的负向对照
- [ ] 验证用的伪造替身文件已清理
- [ ] 豁免精确到文件/模式，输出打印豁免清单与理由
- [ ] 扫描报 0 的项都做了变异自证
- [ ] 所有脚本真跑过一遍，产物存在且非空
- [ ] 沙箱副本跑官方校验器，exit 0

## 打包落位（阶段 6）
- [ ] 输出路径不指上一轮名字、不用相对路径
- [ ] 压缩包条目数、0 字节文件、根目录前缀、版本字段全部核对
- [ ] 旧版已备份，文件数一致
- [ ] 覆盖后回读版本号
- [ ] 校验脚本先切目录再执行
- [ ] 已重新注册市场（若适用）
- [ ] 包内各处版本号一致

## 记录（阶段 7–9）
- [ ] CHANGELOG 遵循官方体例（扁平 bullet，新增 / 优化 / 修复 开头，句尾不加句号），版本号不写死在其他文件里
- [ ] 计数类数字实时从门禁取，不写死
- [ ] 报告分「已验证 / 部分验证 / 待确认」，写明本轮局限
- [ ] 可复用做法已投进蒸馏投放箱
