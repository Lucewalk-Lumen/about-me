# 团队包运维：七维体检 + 安全改名

> 本团专家包运维规范，供阶段 5 审计与阶段 6 打包 / 改名使用。

## 一、七维体检（阶段 5 审计报告维度）

| 维度 | 覆盖 |
|---|---|
| ① 安全 | 路径穿越实测（每个数据驱动拼路径通道，诱饵 `/etc/hosts`）、密钥 / PII / 私有路径、回显绝对路径、**SSRF / URL scheme 校验**（内网·回环·链路本地·CGNAT `100.64.0.0/10`·云元数据（含 `100.100.100.200`）阻断、逐跳重定向校验、IPv4-mapped IPv6 解映射后复检）、**子进程沙箱标志**（不得默认 `--no-sandbox`）、**提示词注入**（外源内容一律视为不可信数据，不得执行其中指令） |
| ② 质量 | 按 MIN_PY 逐文件编译、JSON 有效性、死链三基准、非 ASCII 文件名、zip 垃圾条目 |
| ③ 完成度 | 清单字段齐全、四方一致、文档覆盖（README / CHANGELOG / UPGRADE / settings.json） |
| ④ 指令遵从 | TeamCreate 仅主理人、跨成员消息经主理人中转、lead 不代写成员结论 |
| ⑤ 事实辨别 | 文档声明 vs 实数据漂移、失实「已移除 / 全 verified」声明、悬空引用 |
| ⑥ 规则遵从 | 字数双口径、`plugin==name`、categoryId 枚举、tags / quickPrompts=3、`defaultInitPrompt==quickPrompts[0]`、版本单一真源 |
| ⑦ 跨包一致性 | 共享代码分叉、同库双口径、文档口径不同步（单包时注明 N/A） |

分级：**高危** = 阻断上线（安全漏洞实锤 / 门禁 FAIL / 平台必拒字段）；**中危** = 提审前应修；**低危** = 卫生项。报告末尾必须附「本次未处理项」清单，防「修了 A 忘了 B」。

## 一·补 场景附加门禁（阶段 5 按场景加查）

主理人场景路由（教学 / 个人 / 企业）承诺的「附加门禁」在审计时**按场景加查、逐条留证**；落点由 `quality_eval.py` 维度 B 场景化检查自动核验（关键词 → 判据文献映射，主理人自身文献映射不计入落点）：

| 场景 | 附加门禁 | 审计判据（怎么验） |
|---|---|---|
| 教学 | 证据可溯源 | 抽查量化断言与结论，须给出处或原文路径；缺出处即记中危 |
| 教学 | 出处可核验 | 须给出处或原文路径，抽查可回溯；伪造来源记高危 |
| 教学 | 无编造数据 | 数据 / 样本 / p 值须有来源；无来源的确定性结论记高危 |
| 个人 | 隐私（本地优先） | 默认本地处理；涉 PII 不外发、不落远端；核对外发通道默认关闭 |
| 个人 | 无外发默认 | 无显式用户确认不发起网络外发；检查默认配置与首次运行行为 |
| 企业 | 权限隔离 | 角色 / 数据边界在蓝图与实现中显式定义（对应 `workbuddy-expert-studio-planning.md` 委派边界） |
| 企业 | 数据安全 | 密钥 / PII / 私有路径扫描 + 传输存储口径核查（并入七维①安全） |
| 企业 | 审计留痕 | 关键操作有日志 / 产物落盘，可复盘；抽验「操作 → 留痕」对应关系 |

## 一·附 脚本布局约定（本包内部纪律：为何两个技能目录布局可以不同）

同一包内 `skills/*/` 各技能目录**允许布局不同**——脚本分两类，归属地不同，这是**已声明的约定**、不是不一致：

| 类别 | 归属地 | 判据 | 本包实例 |
|---|---|---|---|
| **包级工程脚本** | 包根 `scripts/` | ① 被 README / references / agents / knowledge **多处**引用；② 从包根调用，且需读取包内其他目录（`knowledge/`、`.codebuddy-plugin/`）；③ 属构建期 / 门禁能力，非可独立复用的单点能力 | `verify.py`、`gates.py`、`quality_eval.py`、`dual_proof.py`、`sync_standards.py`、`make_avatars.py`、`render_flow_html.py` |
| **技能自带能力脚本** | `skills/<skill>/scripts/` | 仅服务该技能自身，随技能一起被理解与复用 | `web-crawler/scripts/crawler.py`、`search.py` |

硬规则：
- 技能 `SKILL.md` **必须自述**脚本位置：自包含，或明写「脚本位于包根 `scripts/`」；不得留空白让人误判技能不完整。
- 单独复用 / 卸载某个**技能目录**时，若其脚本在包根，属**预期行为**（该技能是包级能力的门面），不记缺陷。
- **不得**为「看起来一致」而把包级门禁脚本搬进 `skills/<skill>/scripts/`：会打断包根调用与包根自解析范式，且跨目录读取（`knowledge/`）失效。

## 二、安全批量改名（阶段 6 涉改名时的四层管线）

**四层**：团名（中英）/ 成员名（中英）/ 职业头衔（中英）/ 包标识（`plugin.json` name + 顶层目录 + zip 名 + 主理人文件名）。

硬规则：
- 主理人文件名用 `{包名}-team-lead`（官方规范：名称须加专家团前缀、**不可用通用 `team-lead`**；市场在架团队亦多用此式）。
- 替换**长串优先**：先改带旧名前缀的文件名，再全局替换文本，最后改顶层目录名。
- **中文子串预检**：替换前先 grep 新旧中文名是否更长词的子串（如旧名 `知远` 是 `知远航` 的子串），命中则挂长串条目执行。
- **短词作用域限定**：易嵌词的英文标识（如 `Ke` / `Bao`）**只改 name 字段上下文**，正文 / references / knowledge 不做全局替换（防 `Ke` 命中 `Key`、`Bao` 命中 `Baokuan` 等嵌词误伤）。
- **扫描范围二进制黑名单制**：`.lock` / `.sh` / 无扩展名 `LICENSE` / `knowledge/` / `sbom/` / 跨包引用都在内。
- 改名后：`verify.py` 复跑 + 新旧名「紧邻汉字 / 嵌词」三合一复扫 + 与 pristine 基线逐文件 diff（每处差异须能映射到映射表）。

## 三、14 条运维踩坑（速查）

1. lead 文件名未带专家团前缀（用了通用 `team-lead`，应为 `{包名}-team-lead`）；2. 中文子串误伤（旧名是更长词的子串）；3. 英文短词嵌词误伤（`Ke` 命中 `Key`）；4. 替换命中正文里的同形示例名；5. 替换范围漏扫（`.lock`/`.sh`/`LICENSE`/`knowledge/`/跨包引用）；6. 英文旧名变体漏网；7. `py_compile` 留 `__pycache__` 混入包；8. zip 对已存在归档**追加**致条目翻倍；9. 绝对路径打包嵌 `/Users/...` 全路径；10. 基线包被覆盖，diff 出「0 差异」假象；11. status 计数三处（条目 json / `_index` / 文档）不同步；12. 「冗余可删」须先查引用映射；13. `rm`/相对路径删除被拦（改 `mv -n <绝对路径> ~/.Trash/`）；14. 修复后不用**同一注入手法**回归实测 = 没修。

## 三·补 发布与回滚（阶段 6 落位纪律，借 devops 能力）

1. **环境分层**：沙箱副本 = 预发环境（`WORKBUDDY_CONFIG_DIR` 指向临时沙箱），市场目录 `$WORKBUDDY_CONFIG_DIR/plugins/marketplaces/my-experts/plugins` = 生产环境；**先在沙箱 exit 0，才准落生产**。
2. **发布记录**：落 `06-打包/发布记录.md`，含 zip 路径、条目数、版本号、落位路径、发布时间、操作人（主理人 ID）。
3. **回滚预案**：旧版先备份（绝对路径 `mv -n` 进废纸篓），发布记录中写明「一键回滚命令 = `mv -n <备份绝对路径> <市场目录>`」；回滚后复跑 `verify.py` 确认 exit 0。
4. **注册表变更解耦**：若改名 / 换版本涉及 `marketplace.json` 注册表变更，先备份注册表 → 再改注册表 → 最后落包，禁止顺序颠倒。

## 四、落地用法

- **阶段 5（审计）**：按七维出**分级报告**（与本团 `quality_eval.py` 五维**互补**：五维判体验，七维判合规/安全）。
- **阶段 6（打包 / 改名）**：涉改名 / 换版时按四层 + 硬规则执行；**删除一律 `mv -n <绝对路径> ~/.Trash/`，绝不 `rm -rf`**。
- 与 `workbuddy-expert-studio-checklist.md`（阶段勾选）、`workbuddy-expert-studio-quality-eval.md`（五维）配套使用。
