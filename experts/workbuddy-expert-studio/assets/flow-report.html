WorkBuddy 专家开发工坊 · 九阶段流水线

九阶段一步步推进：先对齐需求，再设计、撰写、检查、打包与验收；每一步都可复跑、可追溯。

齐衡 · 交付总监（主理人）沈证 · 立项诊断官高构 · 结构设计官柯码 · 实现分片官严证 · 取证核查官包洁 · 干净落位官史衡 · 验收沉淀官
阶段 1 立项与诊断 负责：沈证

拿到被驳回的包，第一件事不是改，是证伪用户的猜测。

  • 解包 → 全量静态分析（不抽查）
  • 本机实测关键命令，保留原始输出
  • 按多维标准推演，三档标注（实测 / 静态推断 / 推断待验证）
纪律：结论分三档标注，推测不与根因混淆
阶段 2 结构设计 负责：高构

定包骨架与协作拓扑，把结构纪律落成清晰约定。

  • 包骨架：目录结构、清单、成员与技能组织
  • 成员结构六要素：角色 / 领域 / 框架 / 数据 / 输出 / 回传
  • 协作拓扑：建团 → 路由 → 中转（成员不直连）→ 回传 → 质量把关
纪律：设计红线：禁用 emoji 图标、渐变发光毛玻璃、AI 模板味文案
阶段 3 实现与分片 负责：柯码

长文档会自动拆分，确保不超出平台能完整读取的长度。

  • 主文件按平台口径估算长度，超限即规划拆分
  • 正文只留流程、规则与索引，长细则移入分片
  • 能力边界具体到数字，不写「可优化」
纪律：长度按平台口径统计，确保拆分判断准确
阶段 4 质量校验 负责：柯码

把每一步的检查标准写成自动校验，随流程一起运行。

  • 检查文件是否齐全、用词是否规范、篇幅是否超限、分片是否完整
  • 新增功能时，同轮补上对应校验
  • 确保校验真的会拦住问题：缺失文件必报错、复原后必通过
纪律：每条校验都要验证：既会正确拦截、也不误伤
阶段 5 审计与取证 负责：严证

审查脚本必须真跑一遍，拿产物清单逐个核对。

  • 结构化文件写完再读回核对（先写后检等于没检）
  • 静态扫描命中逐条甄别，不甩命中数
  • 报告零命中时，必须用反例自证
纪律：误报与漏报同等对待，不为通过而放宽标准
阶段 6 干净打包 负责：包洁

三条禁令：禁指向上一轮名字 / 禁相对路径 / 改完必复跑验证。

  • 换版本九步：解压隔离 → 比对 → 排查风险 → 备份 → 回读
  • 校验在副本环境进行，不在正式产物上直接改
  • 替换与复核分离（另写独立复核）
纪律：校验在副本进行；替换后另写独立复核
阶段 7 验收放行 负责：史衡

官方校验器通过 ≠ 可以上线；深度审查仍可能发现实质缺陷。

  • 验收清单可脚本复跑（期望值 / 当前值 / 严重度）
  • 一键复跑，结果分通过 / 告警 / 失败
纪律：官方校验通过不等于无缺陷，深度审查不可省
阶段 8 版本治理 负责：史衡

版本号以插件清单为唯一真源；更新日志不作为版本依据。

  • 计数类数字实时取自校验结果，不手写
  • 文档引用校验结果，不手写口径
纪律：版本单一真源；四处一致性核对
阶段 9 沉淀资产 负责：史衡

把可复用做法落成经验卡片，回灌演进环。

  • 蒸馏六段资产 R/I/A1/A2/E/B，三关：可操作 / 可复用 / 独特
  • 经验卡片字段：场景 / 方法 / 避坑 / 效果 / 延伸 / 标签
纪律：删除是红线：默认移动代替删除，删除先征求同意
