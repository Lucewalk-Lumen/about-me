# 技术选型速查表

> 供 **L2 及以上学生**做技术选型判断时查阅（面向学习者，不是给架构师速查的）。表中版本号为**编写时验证过的参考组合**，实际部署须按环境核实并调整。

> **来源**：ERP 教学团（`erp-teaching-team`）· `references/` · 本团自建参考清单

## 一、推荐技术栈（编写时验证过的参考组合）

| 层次 | 选型 | 版本 | 说明 |
|------|------|------|------|
| 前端框架 | Vue | 3 | 组合式 API |
| UI 组件 | Element Plus | 最新稳定 | 中后台生态成熟 |
| 构建 | Vite + Pinia | — | Pinia 管状态 |
| 反向代理 | Nginx | — | 静态资源 + 代理 |
| 后端框架 | Spring Boot | 3.x | 需 JDK 17+ |
| 安全 | Spring Security + JWT | 6.x | |
| AI 框架 | Spring AI | 最新 | 对接 Ollama |
| ORM | MyBatis-Plus | 3.x | |
| 数据库 | PostgreSQL | 17 | 需 pgvector 扩展 |
| 向量库 | pgvector | 最新 | 与 PG 同库，减少运维 |
| 模型服务 | Ollama | 最新 | 本地推理 |
| 主模型 | qwen2.5:7b | — | 主智能体 / RAG |
| Embedding | bge-m3 | — | 语义向量化 |
| 文档解析 | Apache Tika | — | 多格式解析 |

**为什么 PostgreSQL + pgvector 而不是独立向量库**：
- 单库减少运维成本（中小企业 IT 团队普遍人手紧张）
- 业务数据与向量数据同源，检索时可 JOIN
- 备份恢复一套搞定

## 二、模型选型决策

| 场景 | 主模型 | Embedding | 部署 |
|------|-------|-----------|------|
| 开发验证 | qwen2.5:7b | bge-large-zh | 本地 Ollama |
| 小规模生产 | qwen2.5:7b | bge-m3 | 本地 Ollama |
| 中等生产 | qwen2.5:7b 或更大 | bge-m3 | 本地集群 |
| **敏感数据** | 全私有化 | 本地 | **数据不出内网** |

**资源换算参考**：
- qwen2.5:7b 运行需约 8-10GB 内存
- 生产环境建议至少 32GB 内存
- 换 32B 模型需显著更多资源，**不建议中小企业尝试**

## 三、需求规模与方案匹配

| 人员规模 | 系统形态 | AI 部署 | 理由 |
|----------|----------|---------|------|
| < 200 | 单体 + 门面隔离 | 本地单机 | 微服务运维成本会压垮团队 |
| 200-1000 | 单体起步，预留 Feign | 本地单机/双机 | 确有需要再拆 |
| > 1000 / 多组织 | 可考虑微服务 | 集群 | 需评估运维能力 |
| **IT 团队 < 5 人** | **强制单体** | **单机** | **不要上微服务 + K8s** |

## 五、模型调用方式

Spring AI 通过 `OllamaChatClient` 对接本地 Ollama：

```java
// 方式 1：接入 Ollama 本地模型
OllamaChatClient client = OllamaChatClient.builder()
    .baseUrl("http://localhost:11434")
    .modelName("qwen2.5:7b")
    .build();
```

对外输出 OpenAI 标准格式的模型，便于后续切换到云服务而不改上层代码。

## 六、连接路径判断速查

```
厂商有开放 API 且文档完整？
  ├─ 是 → API 直连（首选）
  └─ 否 → 只需读数据？
            ├─ 是 → 只读库
            └─ 否（需写）→ RPA 兜底
```

| 接法 | 维护成本 | 失效风险 | 建议 |
|------|----------|----------|------|
| API 直连 | 低 | 依赖厂商版本 | 首选 |
| 只读库 | 中 | 表结构变更 | 次选（读场景） |
| RPA | **高** | **界面变动即失效** | 尽量避免 |

## 七、架构演进预留

**单体起步时就要预留的三个点**（未来拆分会省大量返工）：

1. **AI 智能模块与业务模块门面式隔离** —— AI 层只能通过 Facade 调业务层
2. **预留 Feign 接口** —— 需要拆分时，AI 层核心代码无需改动
3. **文档管理独立设计** —— RAG 知识库独立于业务库

## 八、安全红线

| 红线 | 原因 |
|------|------|
| **AI 层不处理数据库事务** | 事务逻辑统一收敛至业务层 |
| **写操作必须二次确认** | ERP 错误写操作是真金白银损失 |
| **不直接暴露 Service/Mapper** | 防止 AI 破坏业务逻辑 |
| **敏感数据不外传** | 私有化部署，数据不出内网 |
| **RAG 答案必须标注来源** | 禁止编造，增强可信度 |
