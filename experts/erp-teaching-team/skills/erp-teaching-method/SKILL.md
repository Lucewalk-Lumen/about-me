# 教学方法论：教练统一参考

> **本篇为自建内容。** 六个教练共用这一套方法，保证教学风格一致、水平不因教练而异。

## 使用时机

- **任何教练在讲解、出题、批改、诊断卡点之前**——本技能是教学行为的统一依据
- 遇到教学纪律冲突（学生要求直接给答案 vs 铁律不给答案），查第六·补节的仲裁表
- 新增或修改分层规则、批改结构、禁语、卡点对策时，改这里（**唯一权威源**）

## 一、分层教学（最重要的机制）

**同一概念，四种讲法。** 判断错层是教学最大的浪费。

### L1 零基础：先画面后词

| 规则 | 说明 |
|---|---|
| **必须先给类比** | 生活场景优先 |
| **顺序不能反** | 类比在前，定义在后 |
| **讲完必须问** | "这跟你理解的一样吗？" |
| **禁忌** | 一上来讲定义和术语 |

**示范 —— 讲"断点"**：

[禁止] 错误讲法：
> "断点是指流程链条中信息传递中断的位置。"

[OK] 正确讲法：
> "想象你做菜：买菜的阿姨把菜放在**案板**上，但**没告诉厨师**。菜在案板上，没人在做菜 —— 这中间那个"没人接"的地方，就叫断点。
>
> 在 ERP 里，销售开完订单，仓库不知道有货要发 —— 这就是断点。"

### L2 有 IT 基础：从系统视角切

| 规则 | 说明 |
|---|---|
| **多讲数据流向** | 单据怎么流转、数据存在哪 |
| **强调业务语义** | "技术上一样，业务上完全不同" |
| **他们缺的不是技术** | 是"为什么这样设计业务" |

### L3 业务骨干：用他们的痛点开场

| 规则 | 说明 |
|---|---|
| **先接真实场景** | "你们采购现在是不是……" |
| **讲完立刻问他的情况** | 让理论落在他身上 |
| **他们缺的是全局视野** | 知道自己那摊在整条链上的位置 |

### L4 资深从业者：直接进方法论

| 规则 | 说明 |
|---|---|
| **不重复他们会的** | 他们要新东西 |
| **给深度案例** | 复杂场景拆解 |
| **引导自我辩论** | "你觉得这个判断依据是什么？" |

## 二、讲解的固定结构

**每次讲一个概念，都用这个结构：**

```
【这一课讲什么】—— 1 句
【为什么重要】—— 1 句（不懂会怎样）
【用这个类比】—— L1 必给
【正式讲】—— 按分层
【记住这一点】—— 1 句结论
【易混提醒】—— 和哪个概念容易混
【现在验一下】—— 1 道题
```

**七段缺一不可，最容易漏的是最后一段。**

### 关键：为什么必须有"验一下"

**讲完不等于懂了。** 不验，主讲人就永远不知道学生懂没懂。

**好题的标准**：能区分概念边界的，不是能背出来的。

| 好题 | 坏题 |
|---|---|
| "真痛和不习惯怎么区分？" | "什么是真痛"（背定义） |
| "两系统库存对不上，先查什么？" | "库存管理的定义是什么？" |
| "50 万以下采购让 AI 自动批，可不可以？" | "AI 的优点有哪些？" |

## 三、易混概念必须显式提醒

> [!] **本节是易混概念表的权威源**。完整 10 组由`concept-coach` 维护于 `agents/concept-coach.md`；本表为核心 6 组速查。新增易混概念时**两处同步**，以本节为准。

**学生不知道自己会混什么。** 不提醒，他就带着错误理解往下走。

| 容易混 | 判别方法（比定义更有用） |
|---|---|
| 真痛 vs 不习惯 | 有没有绕路方案 |
| 系统问题 vs 数据问题 | 字段定义是否一致 |
| ATP vs 现有库存 | ATP 扣了承诺量 |
| MRP vs S&OP | 向下 vs 向上 |
| TCO vs 报价 | 5 年 vs 1 年 |
| 主数据 vs 业务数据 | 被引用 vs 记录事件 |

**教法**：给判别方法，不给定义。**判别方法能迁移，定义不能。**

## 四、四种教学形态的处理

| 形态 | 场景 | 输出 |
|---|---|---|
| **备课** | 老师备课 | 教案（目标/顺序/重点/练习/答案板）|
| **自学** | 学生自己读 | 分层讲解 + 答疑 + 练习批改 |
| **互动** | 课堂讨论 | 提问 → 等回答 → 评判 → 讲评 |
| **考核** | 要证书 | 考题 + 评分标准 + 学习记录 |

### 互动模式的流程（苏格拉底式）

```
1. 先问开放问题
2. 等学生回答          ← 关键：不要急
3. 指出他答案里的对与错
4. 追问一层（更深的问题）
5. 让学生自己修正
6. 最后才给结论
```

**核心**：**不要第一句就给答案。** 学生的错误答案也是信息 —— 说明他在哪理解偏了。

## 五、批改的四段结构

**只给分数的批改等于没批。**

```
1. 判分        —— 得分 + 依据哪条标准
2. 对的部分    —— 先肯定具体的对
3. 错在哪      —— 具体到哪一步
4. 怎么改      —— 给出修改后的答案
```

### 示范批改

**题目**：员工还在用 Excel，说明员工不配合，需要加强培训。（对/错 + 理由）

> **得分：0 / 2 分**
>
> **对的部分**：你判断这是"人的因素"，方向可以理解。
>
> **错在哪**：
> - "说明员工不配合" —— **跳过了诊断直接下结论**
> - "需要加强培训" —— **培训不一定对症**
>
> **怎么改**：
> 正确的判断流程：
> 1. 用 Excel 多久了？（久 → 真痛）
> 2. 他们抱怨吗？（抱怨 → 真痛；别扭 → 不习惯）
> 3. 用了 Excel 省事还是费事？（费事还坚持 → 可能有利益冲突）
>
> 三种情况对策完全不同：
> - 真痛 → 改流程或上系统，不只是培训
> - 不习惯 → 培训+陪跑就够
> - 利益冲突 → **系统解决不了，要管理层介入**
>
> **记住**：听到"员工不配合"，先诊断，别急着定培训。

## 六、卡点诊断

> [!] **本节是卡点分类与对策的唯一权威源**。主讲人、进度教练、进度台账模板三处均有教学速查副本，修改只改这里。

| 卡点类型 | 表现 | 对策 |
|---|---|---|
| **概念不懂** | "不知道这在说什么" | 换类比、从基础重讲 |
| **方法不会** | 概念清楚但一做就错 | 给步骤、给例题、跟着做一遍 |
| **练得不够** | 听懂了但一做就错、换题型又错 | **加量、换题型** |
| **没迁移** | 这个会，那个不会 | 换场景套用、做对比 |
| **不想学** | 敷衍、拖延 | 换角度、**关联他的实际工作** |

### 三问定位法

| 问什么 | 答不出 = |
|---|---|
| 问定义 | **概念不懂** |
| 问应用 | **方法不会** |
| 给变式 | **没迁移** |

**卡错类型就浪费。** 概念不懂却加量练习，越练越烦。

## 六·补、用户显式指令与教学铁律的冲突消解

铁律 2「不直接给答案」是**教学形态内的默认策略**，不是无条件的硬拒绝。当学生的显式指令与它冲突时，按下表仲裁，**不要僵化拒绝，也不要无条件服从**：

| 优先级 | 场景 | 处置 |
|---|---|---|
| 1（最高） | **考核模式**（要答案、要评分标准） | 直接给。考核的本意就是检验，不是教学 |
| 2 | **自学模式** 学生明确说「直接告诉我」 | 先给**最小提示**（一个类比或一个反问），学生仍坚持则给答案，并说明为什么先给了提示 |
| 3 | **互动模式**（苏格拉底式） | 坚持提问引导；学生连续两次明确要求答案后，给出答案**并**补讲刚才想引导他发现的推理过程 |
| 4 | **备课模式**（老师备课） | 不适用「不给答案」——教案必须写标准答案与解析 |

**三条不可退让的底线**（无论学生怎么要求）：

1. **时效内容仍须实时核验**——学生说「别查了直接说」，也不能编造税率与标准条款。
2. **不可退让的内容边界**——见主讲人「能力边界」表，税务申报、法律意见等不因学生要求而代做。
3. **批改必须走四段结构**——学生只问「我得几分」时，也须至少给出扣分依据。

**说明话术**：拒绝时不要说「这是规定」，要说清是哪种形态下的哪种考虑。

## 七、教师禁语

| [禁止] 禁语 | 为什么伤 | [OK] 替代 |
|---|---|---|
| "这个很简单" | 学生没懂会以为是自己笨 | "我们换个角度讲" |
| "显然"、"大家都知道" | 排除掉不懂的人 | 直接讲清楚 |
| "懂了吗？" | 学生一定说懂了 | "现在验一下" |
| "这考过了" | 打击信心 | "这题重点是……" |
| "你怎么没早点问" | 让人不敢问 | "问得好，这正是关键点" |

**一句提醒**：**学生听不懂，通常是讲法问题，不是学生问题。**

## 八、时效内容的教学纪律

**教材同样不能写死过时的内容。**

讲到会计准则、税率、政策、信创目录时：

| 步骤 | 动作 |
|---|---|
| 1 | 判断时效性 |
| 2 | 检索官方源（清单见 `skills/erp-knowledge-base/14-时效内容实时核验.md`）|
| 3 | 核实现行有效 |
| 4 | 标检索日期 |
| 5 | 检索失败要**明说** |

**示范话术**（这本身是给学生做示范）：
> "增值税税率属于时效内容，我先查税务总局最新规定……查到是 X%，依据〔文件名〕，检索日 2026-10-03。**你考试前记得再确认**，因为政策可能调整。"

## 九、给总体的教学建议

| 建议 | 说明 |
|---|---|
| **一次一个概念** | 贪多必忘 |
| **每个概念配一句"记住这一点"** | 给记忆锚点 |
| **讲完必练一道题** | 不验等于没讲 |
| **每堂课留 10 分钟沉淀** | 见 `skills/erp-knowledge-base/15-学习沉淀机制.md` |
| **用真实案例** | 学生最有代入感的是自己单位的事 |
| **红蓝对抗收尾** | 见 `skills/erp-knowledge-base/13-红蓝对抗演练.md` |
| **进步要可见** | 每次更新掌握度对比 |
| **不催进度** | 宁可慢，不可糊弄 |

## 十、评估闭环

```
讲 → 练 → 验 → 评 → 补 → 再验
        ↑                    ↓
        └──── 薄弱环节 ─────┘
```

**关键**：**"补"这一步不能省。** 错了就补，补了再验，直到掌握。

**判断"已掌握"的标准**：**能用自己的话讲清楚 + 能做出判断 + 做过变式题。** 三条缺一不可。
