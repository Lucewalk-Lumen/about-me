# 选型与方案评估：甲方立场

> **本篇为自建内容。** 借鉴"成熟度优先""TCO 5 年""克制二开"等行业共识，评估框架、必问清单、话术识别表为本团重写。

## 立场声明

**我们代表使用系统的企业，不卖系统。**

这决定所有判断：不为任何厂商说话，也不被销售话术带走；敢说"不值得买"、"这个阶段不该上系统"。

**因此本篇不使用"供应商中立"的说法。** 中立不来自"同时推荐几家"，而来自**"不替任何一家说话"**。推荐几家是给企业选择权，不是为了显得公平。

## 一、第一步：先判断该不该买

**很多企业该做的不是选型，是先修流程，或者干脆什么都不做。**

> **此处 M 指成熟度（maturity），区别于教学分层的 L1-L4。** 级别定义与六维评分见 `./02-ERP诊断方法.md`。

| 成熟度 | 该做什么 |
|---|---|
| M1 手工记账 | **先规范流程，不要上系统** |
| M2 单点孤岛 | 打通主干 |
| M3 集成化 | 主数据治理 |
| M4 数据化 | 此时才谈 AI |
| M5 智能化 | Agent 才有意义 |

**若一家手工记账的小企业要上集团级 ERP，你必须直接劝退。这是职责，不是失职。**

详见 `./02-ERP诊断方法.md`。

## 二、规模档位匹配

| 规模 | 人员 | 建议档位 | 关键提醒 |
|---|---|---|---|
| 微型企业 | < 50 | 轻量 SaaS / 零代码 | 别上重平台，运维成本会压垮小企业 |
| 小型企业 | 50-200 | 标准 SaaS / 行业版 | 优先行业成熟模板，**不要重度定制** |
| 中型企业 | 200-1000 | 平台型 | 可上平台，必须配专职运维 |
| 大型企业 | > 1000 | 企业级平台 | 需专业实施商，创始人自研必失败 |

**重要**：200 人但 3 个工厂 5 条产品线，比 800 人单厂更需要平台。**不要只看人数。**

## 三、部署形态四选

| 形态 | 适用 | 优势 | 代价 |
|---|---|---|---|
| **本地部署** | 强监管、数据不出境 | 完全自主、可深度二开 | 重 CAPEX、运维负担、升级滞后 |
| **公有云 SaaS** | 中型、标准化诉求强 | 轻运维、快上线、持续更新 | 数据主权风险、定制受限、订阅累积 |
| **私有云** | 集团/数据敏感 | 弹性与主权兼顾 | 成本高于纯 SaaS、仍需运维 |
| **混合** | 渐进迁移、合规与弹性折中 | 平滑过渡 | 集成与治理双线复杂度 |

**TCO 结构差异**：本地前期 CAPEX 高、后期 OPEX 持续；SaaS 无 upfront、订阅逐年累积。**测算必须区分。**

## 四、ERP 演进五阶段

| 阶段 | 核心目标 | 管理边界 |
|---|---|---|
| **MRP** | 按订单算准"何时买什么料" | 仅生产物料 |
| **MRP II** | 产-供-财一体计划 | 企业内部制造 |
| **ERP** | 全职能（人财物产供销）集成 | 单一企业 |
| **ERP II** | 连客户/供应商/渠道 | 企业间价值链 |
| **云/可组合** | 按需拼装、云原生 | 生态 + 数据驱动 |

**关键认知**：演进不是"旧的死了"，而是**层层叠加**。今天仍有大量 MRP II 内核跑在 S/4HANA 底层。**不要唯版本论** —— 对方推荐"更新版本"时，要问清是内核升级还是上层套件。

## 五、必问五问（每次都问）

| # | 问题 | 为什么 |
|---|---|---|
| 1 | **标准功能**能覆盖我需求的百分之多少？剩下的要二开多少？ | 二开比例决定未来升级难度 |
| 2 | **有没有标准开放 API**？文档公开吗？我能自己对接吗？ | **没 API 的系统三年后是 AI 化死路** |
| 3 | 上线后**数据能否完整导出**？什么格式？ | 决定被不被绑架 |
| 4 | **五年总成本**是多少？逐项列出来。 | 只比首年是无效对比 |
| 5 | 如果我要换供应商，**迁移成本和时间**是多少？ | 议价能力 |

**第 2 条最容易漏，却最重要。** 哪怕企业当下不做 AI，**没有 API 的系统三年后会成为 AI 化的死路**。

## 六、识别销售话术

| 话术 | 真实含义 | 追问 |
|---|---|---|
| "AI 原生架构" | 可能只是营销词 | 具体什么模型？数据在哪？在哪跑？ |
| "零代码扩展" | 扩展后无人能维护 | 谁维护这些扩展？升级怎么办？ |
| "快速实施，2 个月上线" | 前期配置，后期二开 | 总工期多少？含二开吗？ |
| "完全满足需求" | 标准功能 + 大量二开 | 标准覆盖多少？二开多少？ |
| "可扩展性强" | 扩展要钱 | 扩展怎么计费？ |
| "降低 TCO" | 只比首年 | 五年总成本？含哪些？ |
| "国产化替代风险低" | 可能是营销 | 核心技术依赖谁？ |
| "行业最成熟" | 单一厂商视角 | 有几家在做同样事？ |
| "开箱即用" | 你的流程要改 | 我们的流程一样吗？改多少？ |

## 七、需求优先级三分类

| 优先级 | 定义 | 处理 |
|---|---|---|
| **必需** | 缺了系统跑不起来 | 硬门槛 |
| **锦上添花** | 有了更好，没有也能活 | 用标准功能解决，不为此付费 |
| **明确不要** | 听说很好但现在用不上 | **明确排除，不为它付钱** |

**主动问"明确不要什么"。** 这一栏往往比"必需"更能决定成本 —— 大部分预算花在"听说很好"的功能上。

## 八、Fit-to-Standard：克制二开

**二开不是不能做，是要先算三笔账**：

| 账 | 问题 |
|---|---|
| **必要性** | 标准功能真的做不到吗？确认过配置与流程调整？ |
| **成本** | 二开 + 每次升级的适配成本，谁承担？ |
| **升级影响** | 厂商大版本升级时，这些二开会不会被废弃？ |

**二开率高 = 升级噩梦。** [!] 教学案例：某项目定制比例达 **78%**（**教学用参考值，匿名案例、非统计样本；正式引用须按 `14` 篇五步法核实出处**），最终变成没人敢动的黑盒。

**建议**：能用配置解决就不二开；必须二开时登记造册，评估长期维护。

## 九、翻车点预判

| 翻车点 | 症状 | 预防 |
|---|---|---|
| 需求模糊 | 各部门要的东西冲突 | 需求分优先级，冲突项拍板 |
| 责任人不清 | 上线后没人管流程 Owner | 每流程指定唯一 Owner |
| 数据不干净 | 旧系统数据迁移后对不上 | 迁移前先治理 |
| 培训不足 | 能用但没人愿意用 | 关键用户制 + 考核挂钩 |
| 过度定制 | 按要求改，改完不稳定 | 优先标准功能 |
| 预算被砍 | 中途砍二开 → 半成品 | 二开预算单列 |
| 补丁凑合 | "改一改凑合用" | 先算旧系统退出成本 |
| **无开放 API** | 三年后接不上 AI | **选型阶段就纳入** |

## 十一、给教师的话

**本篇的教学价值在立场，不在工具。**

- **"甲方立场"是根本教学点** —— 任何顾问的可信度，取决于他有没有站在说话对象那一边
- **必问五问是最实用的清单** —— 学生可立刻套用
- **话术识别表适合做角色扮演** —— 让学生扮厂商，练习追问

**常见学生误区**：以为顾问应该"客观中立"、各打五十大板。**应引导他们理解：没有立场的顾问没有价值。**
