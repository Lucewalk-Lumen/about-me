# 投资论证：五年 TCO 与 ROI 三情景

> **本篇为自建内容。** 核心原则「TCO 看 5 年不看报价」是行业共识，但分类口径、效益四象限与判定规则为本团重写。

## 铁律

| # | 铁律 | 说明 |
|---|---|---|
| 1 | **TCO 看 5 年，不看报价** | 许可费是冰山一角 |
| 2 | **七类成本缺一不可** | 漏任何一类都会低估（明细见第一节） |
| 3 | **必须三情景并列** | 基准/预期/悲观，**不得只报预期** |
| 4 | **效益分四象限** | 可量化性不同，入分子方式不同 |
| 5 | **必做敏感性分析** | TCO 上浮、效益下修 |
| 6 | **悲观为负必须诚实报出** | 触发劝退提示，不粉饰 |
| 7 | **禁止估算冒充真实报价** | 来源须为真实报价单或合同 |

## 一、五年 TCO 七类构成

| 类别 | 内容 | 易漏点 |
|---|---|---|
| **许可 License** | 软件授权/订阅、用户数、模块 | 漏用户扩容费 |
| **实施 Implement** | 实施顾问、蓝图、配置、上线 | **漏并行运行成本** |
| **运维 O&M** | 年度维保、人力、云资源 | 漏隐性支持 |
| **基础设施 Infra** | 服务器/数据库/网络/灾备 | 漏等保加固 |
| **二开 Custom** | 二次开发、接口、报表 | **漏升级重做成本** |
| **培训 Train** | 用户培训、变革管理 | 漏持续赋能 |
| **内部投入 Internal** | 关键用户工时机会成本 | **最常被完全忽略** |

**内部人员投入常占总投入 20-30%**（[!] 教学用经验区间，非行业统计；不同企业差异极大，须按自身实际测算）。 项目期间 IT 和业务骨干被抽调，机会成本必须计入。

### 测算口径约定

- 单位统一为"万元/年"或"万元/5年"，全表一致，避免混用
- 重大投资可附 NPV/IRR，**折现率须标假设**（如 8%）并做敏感
- 仅计直接可归属成本，机会成本单列不进 TCO 分子
- **金额来自真实报价单/合同，禁止估算冒充**
- 涉税口径以引用当日官方发布为准

## 二、ROI 三情景

| 情景 | 假设 | 效益口径 |
|---|---|---|
| **基准 Baseline** | 仅实现标准功能，无额外增益 | 成本可量化节省 |
| **预期 Expected** | 标准+最佳实践，顺利落地 | 基准 + 效率/合规增益 |
| **悲观 Pessimistic** | 延期/范围蔓延/adoption 低 | 仅部分效益，TCO 上浮 |

### 公式

```
ROI = (累计效益 − 累计 TCO) / 累计 TCO × 100%
回收期（月）= 累计 TCO ÷ 年净效益 × 12
```

### 计算示例

- 5 年 TCO = 1000 万；预期年净效益 = 300 万；5 年累计效益 = 1500 万
- ROI = (1500 − 1000) / 1000 = **+50%**；回收期 = 1000 / 300 ≈ **3.3 年**
- 悲观年净效益 = 120 万 → ROI = (600 − 1000) / 1000 = **−40%**，**回收期永不达成**

> **悲观为负是重要信号**，必须显式报出，让决策者知道最坏情况。

## 三、效益四象限

| 象限 | 示例 | 可量化性 | 是否入 ROI 分子 |
|---|---|---|---|
| **经济效益** | 人工节省、库存下降、降本 | 高 | [OK] 入 |
| **合规效益** | 避免罚款、审计通过 | 中 | 折算风险金入 |
| **效率效益** | 月结提速、审批自动化 | 中 | 折算人力入 |
| **风险规避** | 内控防错付、数据不出境 | 低 | [禁止] **不入**，作定性"减震"论据 |

### 效率收益必须打折

```
年化人力收益 = 单次节省分钟 ÷ 60 × 人工时薪 × 年发生次数
可计入收益 = 年化人力收益 × 折算系数（通常 0.3-0.5）
```

**为什么打折**：省下的时间不等于省下的钱。员工省 2 小时可能只是多刷了会儿手机。只有真正减少加班、减少外包、减少招聘，才能算真实收益。**诚实地打折，比夸大数字更有说服力。**

### 差错成本

```
年化差错成本 = 年发生次数 × 单次损失
单次损失 = 返工工时 + 客户赔付 + 库存差异损失
```

## 四、敏感性分析（必做）

至少算这三组：

| 变量 | 变动 |
|---|---|
| **TCO 上浮** | 实施/二开超支 +20% / +40% |
| **效益下修** | adoption 仅达 60% / 80% |
| **折现口径** | 附 NPV/IRR（标折现率假设） |

### 判定规则

```
若悲观情景 ROI < 0 且回收期 > 投资周期
  → 明确标"当前不值得，建议延后或轻量方案"
```

**这条不可妥协。** 即使业务方很想听"值得"，也必须照实说。

## 五、决策建议判定

| 结论 | 条件 |
|---|---|
| **建议做** | 基准情景回收期 < 18 个月 |
| **建议小范围试点** | 回收期 18-36 个月，或不确定性高 |
| **不建议做** | 回收期 > 36 个月，或核心收益无法量化 |

**"不建议做"是最有价值的输出。** 项目顾问的责任不是促成，是给出真实判断。

## 六、常见测算错误

| 错误 | 后果 |
|---|---|
| 只算首年许可费 | ROI 严重虚高 |
| 漏内部人员投入 | 低估 20-30%（教学经验区间） |
| 效益不打折扣 | 收益虚高 2-3 倍 |
| 只报预期情景 | 决策者看不到风险 |
| 漏二开升级重做成本 | 三年后追加预算失控 |
| 漏并行运行成本 | 切换期成本被低估 |

## 八、给教师的话

**本篇适合作为案例教学**：

- **打折这一节最值得讲** —— 学生最容易算出一个漂亮但不可信的 ROI
- **悲观情景是诚实之魂** —— 敢于报负数，才是专业顾问
- **"内部投入最常被忽略"** —— 让学生自己算一遍，看漏掉它会低估多少

**常见学生误区**：以为 ROI 越高方案越好。应引导他们问：**"悲观情景下会怎样？"**
