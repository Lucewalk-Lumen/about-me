# 业务域深度（三）：财务 R2R 与内控要件

> **本篇为自建内容。** 财务是 ERP 的核心记录系统，也是 AI 最不该随意触碰的地方。

## 一、R2R 全链路（Record-to-Report）

```
业务单据 → 凭证（Journal）→ 记账（Post）→ 结账（Close）
→ 报表（Report）→ 合并（Consolidate）→ 分析
```

**核心原则**：**总账是唯一真相源（SoR）**。所有业务事件最终都要落到凭证，且凭证要能追溯回业务单据。

## 二、业财一体：业务事件到凭证自动化

### 什么是业财一体

**业务发生时，凭证自动生成，而不是事后手工补。**

| 模式 | 凭证来源 | 问题 |
|---|---|---|
| **手工记账** | 月底人工汇总、补录 | 滞后、易错、无法实时分析 |
| **事后补录** | 业务发生后手工录凭证 | 依赖自觉，月底集中爆发 |
| **业财一体** | 业务单据触发自动生成 | 实时、可追溯、口径一致 |

**业财一体的价值**：财务数据从"月底才知道"变成"随时可查"。

### 关键映射：科目映射

**业务单据 → 会计科目的对应关系表**，这是业财一体的核心资产。

| 业务事件 | 借方 | 贷方 | 常见问题 |
|---|---|---|---|
| 采购入库 | 原材料 / 存货 | 应付账款 / 暂估应付 | 暂估与实际差异如何调整 |
| 采购开票 | 暂估应付 | 应交税费（进项）/ 存货 | 税额与不含税价分离 |
| 销售出库 | 主营业务成本 | 库存商品 | 成本结转时点 |
| 销售开票 | 应收账款 | 主营业务收入 / 应交税费（销项） | 价税分离 |
| 生产领料 | 生产成本 | 原材料 | 领料单与工单绑定 |
| 生产完工 | 库存商品 | 生产成本 | 完工确认时点 |

**为什么科目映射是核心**：它决定了**业务数据能否自动变成会计语言**。映射错了，自动凭证就是错的。

**常见断点**：
- 科目映射表不维护 → 新业务手工处理 → 自动化断点
- 映射规则不明确 → 各人做法不同 → 口径不一
- **业务部门和财务对不上同一件事** → 反复对账

## 三、集团合并报表

### 合并做了什么

**把母子公司各自的报表，合并成集团一张表。**

**核心是"抵消"**：集团内部交易不能重复计算。

**三类关键抵消**：

| 抵消类型 | 抵消什么 | 为什么 |
|---|---|---|
| **内部交易抵消** | 集团内 A 卖给 B 的收入与成本 | 内部销售不是集团的收入 |
| **内部往来抵消** | A 的应收 与 B 的应付 | 内部债权债务不对外 |
| **投资与权益抵消** | 母公司的长期股权投资 与 子公司的净资产 | 投资与被投资方要抵掉 |

**举例**：A 公司以 100 万买 B 公司 30% 股份。合并时：
- 母公司的"长期股权投资 30 万"要抵掉
- B 的"实收资本 + 资本公积"中对应 30 万要抵掉
- 差额（商誉/合并价差）保留

### 合并的难点

| 难点 | 说明 |
|---|---|
| **会计期间不一致** | 子公司可能提前结账 |
| **币种不同** | 折算汇率如何取 |
| **准则不同** | 内部准则与准则差异调整 |
| **关联交易识别** | 隐性关联交易难识别 |
| **数据时效** | 子公司数据上报不及时 |

**常见断点**：合并报表是 Excel 手工做的 → **数据滞后、口径不一、无法追溯**。

## 四、多准则与多准则差异

**集团在不同地区经营，可能适用不同会计准则。**

| 常见准则 | 适用 |
|---|---|
| **企业会计准则（CAS）** | 中国境内 |
| **IFRS** | 境外上市、国际融资 |
| **US GAAP** | 美国上市 |

**准则差异需要"差异调整表"**，把各子公司按本准则编的报表，调节到集团统一准则口径。

**常见难点**：
- 收入确认时点差异
- 资产减值模型差异
- 租赁准则差异
- 金融资产分类差异

**建议**：**多准则集团应在系统层面支持差异配置，而不是 Excel 手工调整。**

### 共享服务中心（SSC）

**集团把各子公司的重复职能集中到一个中心处理。**

| 模式 | 说明 | 适合 |
|---|---|---|
| **集中式 SSC** | 全部集中到中心 | 规模大、标准化高 |
| **共享服务** | 中心提供支持，各子公司保留部分 | 过渡形态 |
| **自营** | 各子公司全自己做 | 子公司独立性强 |

**可集中的职能**：财务共享（记账、报表）、HR 共享（招聘、薪酬）、采购中心、IT 共享。

**SSC 的价值**：
- **规模效应** —— 同样的工作做更多遍，成本更低
- **标准化** —— 统一口径，减少各子公司差异
- **专业深化** —— 集中的人更专业

**SSC 的难点**：

| 难点 | 说明 |
|---|---|
| **子公司抗拒** | 失去控制权，怕被"看不见" |
| **服务响应慢** | 集中后离业务远，响应不及时 |
| **成本归属** | 谁承担 SSC 的成本 |
| **人才流失** | 中心岗位缺乏吸引力 |

**常见断点**：**SSC 建了，但子公司仍然自己做** —— 因为服务跟不上，子公司绕过中心自己干，中心成了额外成本。

**建议**：**SSC 的成功取决于服务响应速度，而非节约比例。** 先保证响应，再谈节约。

## 五、转移定价（Transfer Pricing）

**集团内部公司之间交易，用什么价格？**

### 为什么需要

| 目的 | 说明 |
|---|---|
| **绩效评价** | 让各子公司按"真实"业绩考核 |
| **税务筹划** | 定价影响利润在哪国产生 |
| **成本控制** | 诱导成本降低的行为 |

### 三种方法

| 方法 | 依据 | 适用 |
|---|---|---|
| **成本法** | 成本 + 加成 | 成本中心 |
| **可比非受控价格法** | 外部市场价 | 有独立市场的子公司 |
| **转移价格法（TP）** | 成本 / 售价 / 市价等组合 | 大多数集团 |

**典型的"double double" 问题**：一个集团内的两家公司，买卖价都高于或低于市场价，双方管理层都会争 —— **不是数字问题，是内部治理问题**。

**建议**：转移定价制度必须由集团层面制定并强制执行，**不能由子公司自行决定**。

## 六、内控与职责分离（SoD）

### 什么是 SoD

**职责分离（Segregation of Duties）**：关键操作不能由一个人从头做到尾。

| 不分离的风险 | 举例 |
|---|---|
| **自己采购自己收货** | 员工自己请购、收货、付款 |
| **自己制单自己审批** | 员工自己录入凭证、自己批准 |
| **采购收款一人办** | 同一账户既付款又对账 |
| **开发人员碰生产** | 改代码的直接连生产库 |

**为什么重要**：**所有舞弊都发生在职责不分离的地方。**

### 内控矩阵

**把"哪个岗位能做什么、不能做什么"写清楚，系统强制执行。**

| 角色 | 可做 | 不可做 |
|---|---|---|
| 采购员 | 发起采购申请、询价 | 审批采购单、付款 |
| 采购主管 | 审批采购单 | 付款执行 |
| 仓管员 | 收货、发货 | 修改单价、审批采购 |
| 财务会计 | 录入凭证 | 银行付款 |
| 财务主管 | 审核凭证、付款审批 | 录入自己制单的凭证 |

**内控矩阵的价值**：**把制度从"规定"变成"系统不许你做"**，不依赖人自觉。

### 内审

| 内审职责 | 说明 |
|---|---|
| 流程合规检查 | 有没有绕过审批 |
| 权限审查 | 有没有不该有的权限 |
| 数据抽查 | 有没有人为调数 |
| 制度执行评估 | 制度是不是空文 |

**特别提醒**：**如果内控是"为报表好看而调数"，一律否决。** ERP 的账是给审计和稽查看的，不是给面子看的。

## 七、营运资金指标

| 指标 | 含义 | 改善方向 |
|---|---|---|
| **DSO**（应收账款周转天数） | 平均多少天收回现金 | 缩短（加速回款） |
| **DPO**（应付账款周转天数） | 平均多少天付款 | 合理利用账期 |
| **DIO**（存货周转天数） | 库存平均放多少天 | 缩短（减少积压） |
| **CCC**（现金转换周期） | DSO + DIO − DPO | 缩短（回款快、存货少、账期长） |

**CCC 是营运资金的核心指标**。CCC 缩短 10 天，1000 万营收的企业可释放约 27 万现金。

**常见断点**：营收增长了但现金反而紧张 —— **通常是 CCC 恶化，尤其 DIO 上升（库存积压）**。

## 八、财务域的 AI 机会与红线

| 场景 | 可行性 | 说明 |
|---|---|---|
| 发票 OCR 与录入辅助 | | 规则明确，人工复核 |
| 对账辅助（银行流水对账） | | 规则明确，AI 匹配 |
| 异常费用识别 | | 找异常，不是判定合规 |
| 报表自动生成 | | 确定性计算 |
| 财务分析问答 | | 基于 RAG 检索内部数据 |
| **科目映射决策** | 低 | **涉及会计判断** |
| **合并抵消规则判断** | 低 | **复杂会计判断** |
| **税务处理决策** | [禁止] **禁止** | **须专业税务人员** |

### 三条红线

| # | 红线 | 原因 |
|---|---|---|
| 1 | **AI 不得自动过账** | 凭证是账务凭证，须人确认 |
| 2 | **AI 不得修改总账余额** | 总账是唯一真相源 |
| 3 | **AI 不得决定税务处理** | 税务合规是专业判断，有法律责任 |

**核心原则：AI 帮财务"做得更快"，不替财务"做决定"。**

## 九、给教师的话

**本篇的教学价值在于"财务是底线"这个认知。**

- **业财一体是 ERP 的核心价值** —— 讲清"业务事件自动变凭证"这一点，学生才懂 ERP 为什么值钱
- **合并抵消是难点也是亮点** —— 学生一旦理解"内部交易不能重复计算"，就懂财务的本质
- **SoD 内控是最实用的部分** —— 可让学生画自己公司的内控矩阵，立刻发现风险
- **CCC 是最直观的抓手** —— 让学生算自己公司的 CCC，差 10 天就是真金白银

**红线那一节必须讲透** —— 学生最容易犯的错是"AI 能干很多事"，不知道财务有不可逾越的边界。

**常见学生误区**：
- 以为财务是"记账部门"，不重视 —— **财务是数据质量的责任人**
- 把 AI 用在凭证决策上 —— **越权且危险**
