# ERP 诊断方法：从现象到根因

> **本篇为自建内容。** 借鉴了成熟 ERP 诊断的结构思路（成熟度分级、维度评分），但内容、方法与案例为本团重写，事实依据为公开行业数据与**匿名教学案例**。

## 一、先分清：不是所有问题都值得用系统解决

**诊断的第一原则是分类，不是开方。** 很多企业为"不习惯"上了新系统，花光预算还招来怨声。

| 判断 | 识别方法 | 对策 | 千万别做 |
|---|---|---|---|
| **真痛** | 已在用 Excel/手工绕路，且有人抱怨 | 改流程或上系统 | [禁止] 只培训 |
| **不习惯** | 没人主动抱怨，只是觉得"别扭" | 培训 + 陪跑 | [禁止] 为此改系统 |
| **能力不足** | 想做但没人会 | 先培训再谈自动化 | [禁止] 指望自学 |
| **利益冲突** | 靠旧流程掌握信息优势或审批权 | 管理层强制推动 | [禁止] **系统解决不了** |
| **口径冲突** | 两系统同名字段含义不同 | 先统一口径 | [禁止] 反复清洗数据 |

**一线真实原声**（判断的起点）：

| 听到什么 | 先别急着 | 先问自己 |
|---|---|---|
| "员工还在用 Excel" | "员工不配合" | 他们绕路多久了？为什么不换回系统？ |
| "数据对不上" | "系统 bug" | 两个系统字段含义一样吗？ |
| "各部门互相甩锅" | "沟通不足" | 每个流程有唯一 Owner 吗？ |
| "系统不够用" | "功能太少" | 业务真正跑起来需要什么？ |

## 二、成熟度五级：决定该走哪一步

**核心认知：跳级必付代价。** 手工记账的小企业上集团级配置，是灾难不是捷径。

> **此处 M 指成熟度（maturity），区别于教学分层的 L1-L4。** 本篇用 M1-M5 表示成熟度级别；L1-L4 保留给"学生分层"（零基础/有 IT 基础/业务骨干/资深从业者）。规模档位另用 S0-S4（见 `./11-供应商生态与合规.md`）。

| 级别 | 名称 | 典型特征 | 该做什么 |
|---|---|---|---|
| **M1** | 无系统 / 纯手工 | Excel 或纸质记账，数据靠人工汇总 | **先建编码基线和单点账套，不要上系统** |
| **M2** | 单点 / 孤岛 | 财务或进销存有独立软件，模块不连通 | 打通主干（财+采销） |
| **M3** | 集成化 ERP | 核心模块同一套 ERP 跑通，流程闭环 | **主数据治理** |
| **M4** | 数据化 / 平台化 | 主数据统一、多维分析、初步自动化 | MDM + 分析自动化 |
| **M5** | 智能化 | AI 嵌入业务、预测驱动 | Agent / Copilot 才有意义 |

**判断标准（问三个问题）**：

1. 主数据有编码规则吗？一个物料有几个码？
2. 跨部门流程闭环吗？还是要人工导出 Excel？
3. 上过系统吗？用得怎么样？

**常见误判**：把"M2 孤岛"当成"M3 集成"去看 AI 问题。数据在两个系统里对不上，不是因为 AI 不会算，而是因为它压根没在一个口径上。

## 三、六维评分：定位最弱的一环

**评分锚点：1=无/混乱；2=局部/手工；3=基本覆盖但有断点；4=标准化且闭环；5=智能/自演进。**

| 维度 | 权重 | 1 分的样子 | 5 分的样子 |
|---|---|---|---|
| **流程** | 25% | 全靠线下/Excel | 闭环、审批内嵌 |
| **数据** | 20% | 无编码规则，主数据混乱 | 数据资产化、质量自动监控 |
| **集成** | 15% | 模块不连通 | 无双写冲突 |
| **系统** | 15% | 无系统 | 可升级、信创适配 |
| **组织** | 15% | 无人负责、变革阻力大 | 角色清晰、数字素养高 |
| **AI** | 10% | 无 | 已落地且有护栏 |

**综合分** = 流程×0.25 + 数据×0.20 + 集成×0.15 + 系统×0.15 + 组织×0.15 + AI×0.10

| 综合分 | 级别 | 下一步 |
|---|---|---|
| 1.0-1.8 | M1 | 先建单点账套与编码基线 |
| 1.9-2.6 | M2 | 打通主干 |
| 2.7-3.4 | M3 | 主数据治理 |
| 3.5-4.2 | M4 | MDM + 分析自动化 |
| 4.3-5.0 | M5 | 智能化 |

**短板约束（重要）**：若流程/数据/集成任一维 < 2，而综合分偏高，**以最低关键维定级**。**平均分最会骗人。**

## 四、断点识别：找到数据断在哪里

**逐域排查**，找交接处、等待处、手工录入处。

### 销售域
- 销售开单后，仓库能否实时查到库存？（**最经典的断点**）
- 订单变更后，生产/采购是否收到通知？
- 退货是否闭环？退货后库存自动回冲吗？
- 客户档案在销售、采购、财务三处各录一遍吗？

### 采购域
- 采购申请→订单→到货→入库→发票→付款 全链可追溯吗？
- 到货与质检是否分离？
- 采购价格与库存成本联动吗？（否则毛利算不准）
- 紧急采购有单独流程吗？（混在常规里会拖慢整体）

### 库存仓储域
- 库存账实一致吗？差多少？
- 批次/序列号覆盖全流程吗？
- 安全库存/呆滞库存有预警吗？
- 盘点能执行吗？（不是只在系统里算账）

### 生产域
- BOM 版本唯一吗？
- 工单下达后自动查缺料吗？
- 领料退料与工单绑定吗？
- 报工实时影响库存吗？
- 生产进度与订单交期联动吗？（否则插单没依据）

### 财务域
- 应收应付与业务单据自动关联吗？
- 对账还要人工导出核对吗？
- 成本核算自动还是有手工调整？
- **财务是不是所有报表的唯一出口？**（若是，说明数据未在业务层收敛）

## 五、根因追问顺序（数据不一致类）

**顺序不能颠倒，跳过第一步会做无用功。**

```
1. 定义检查：字段定义是否一致？（口径问题优先于数据问题）
      ↓ 一致
2. 来源检查：数据从哪来？手工录入还是接口同步？
      ↓
3. 时点检查：什么时候开始错的？当时有什么变更？
      ↓
4. 权限检查：谁能改？改动是否留痕？
      ↓
5. 责任检查：录入的人知道会错吗？有校验吗？
```

**核心判断**：若两系统字段定义不同，那不是数据错误，是设计缺陷。**任何清洗都是徒劳的，必须先统一口径。**

## 六、五个反复出现的失败模式

来自公开行业资料与匿名教学案例的提炼，每一条都对应项目上反复出现的问题。**本节不含本团实证统计** —— 引用前请自行核实来源区间。

| 模式 | 现象 | 根因 | 对策 |
|---|---|---|---|
| **表格补丁化** | ERP 上线后仍要 Excel 补一张表 | 报表/看板/审批留痕没进系统 | 补齐主流程外的能力，而非责怪员工 |
| **录入惩罚** | 一线觉得"用系统比自己记更麻烦" | 一线没受益，只承担录入成本 | **先让一线受益**：自动带出、减少重复录入 |
| **老员工断层** | 关键岗位离职后流程无人接续 | 流程只在个人脑子里 | 知识穿墙：文档化 + 关键用户制 |
| **执行层缺位** | 系统配了但车间不用 | 车间没参与设计，缺执行层 Owner | 执行层必须参与设计，不只是被通知 |
| **需求错位** | 系统功能与真实业务不匹配 | 需求由 IT 收集，非业务主导 | 跟业务一起工作两周再定需求 |

**"录入惩罚"是最贵的错误**：要求一线多录三个字段，却不给他减少任何工作 —— 必然失败，且会持续损失采纳率。

## 七、优先级排序

```
优先级 = (改造收益 × 发生频次) / 实施成本
```

**注意**：按"哪个最值得改"排序，不是按"哪个最痛"排序。**最痛的地方未必最值得改** —— 如果成本极高，绕过去更划算。

## 九、五个反复出现的误判

| 误判 | 表现 | 纠偏 |
|---|---|---|
| **数据问题当系统问题** | 报 bug、提需求 | 先做数据治理 |
| **管理问题当技术问题** | 要求加功能 | 先定责任机制 |
| **能力问题当态度问题** | 说员工不学 | 先培训再谈考核 |
| **流程问题当系统问题** | 说 ERP 不好用 | 先重构流程 |
| **价值问题当需求问题** | 领导要 AI | 先算清收益 |

**这五个模式解释了大多数 ERP 项目的失败。** 遇到问题先判断它属于哪一类，不要急着提技术需求。

## 十、常见误用

- **拿行业均值套自己** → 先定行业、规模、业务复杂度
- **平均分掩盖短板** → 用短板约束定级
- **为"不习惯"改系统** → 这是最贵的错误
- **诊断当实施方案** → 诊断只回答"哪里不对"，落地另有人管
- **跳过真痛直接上 AI** → 数据未就绪时，AI 会产出错误结论
