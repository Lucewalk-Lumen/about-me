# 业务域深度（四）：人力 HCM、物料仓储与生产扩展域

> **本篇为自建内容。** 这三域的共同特点是：**与现场强相关，最容易脱离系统运行。**

## 一、人力域 HCM（Hire-to-Retire）

### 全链路

```
组织与编制 → 招聘 → 入职 → 培训发展 → 薪酬社保个税
→ 考勤排班 → 绩效 → 晋升调岗 → 离职
```

**核心原则**：**人事数据是"活的"数据** —— 人员在流动，数据必须跟着动。

### 关键控制点

| 环节 | 控制点 | 失控后果 |
|---|---|---|
| 组织与编制 | 编制上限、超编审批 | 人力成本失控 |
| 招聘 | 用人申请与编制绑定 | 无编制先招人 |
| 入职 | 资料完整、账号权限开通 | 离职后账号未回收（**安全风险**） |
| **薪酬** | 工资表复核、发放签批 | 算错工资、离职争议 |
| **社保个税** | 基数与比例合规 | **用工合规风险** |
| 考勤 | 异常处理规则 | 加班费争议、假勤纠纷 |
| **权限** | 离职即回收 | **重大安全风险** |

### 组织与编制管理

| 概念 | 说明 |
|---|---|
| **组织架构** | 部门、岗位、汇报关系 |
| **编制** | 每个部门允许的人数上限 |
| **职级体系** | 岗位价值序列 |
| **成本中心** | 费用归集的最小单元 |
| **人力成本** | 薪酬 + 社保 + 福利 + 培训 + 招聘费用 |

**为什么编制重要**：**没有编制约束，招聘就没有刹车。** 人力成本通常是企业第二大成本。

### 薪酬与个税社保（合规敏感区）

**这是 HR 域风险最高的部分。**

**核心原则**：
- **薪酬数据须可追溯** —— 谁改的、改了什么、为什么
- **个税社保须以当期官方规定为准** —— **本篇不提供具体税率与算法**
- **薪酬表的复核必须有人** —— 不能全流程自动化

**[!] 教学提醒**：涉及个税、社保基数、公积金比例的内容，**必须查引用当日官方规定**，本团知识库不提供税务结论。

### 人力的 AI 机会

| 场景 | 可行性 | 说明 |
|---|---|---|
| 简历初筛 | | 规则明确 + AI 辅助，**但须避免歧视** |
| 考勤异常识别 | | 规则明确 |
| 薪酬数据校验 | | 找异常，不做判定 |
| 员工问答机器人 | | 基于制度文档 RAG |
| 绩效分析 | | 需跨部门协同 |
| **招聘决策** | [禁止] **禁止** | **涉及人的判断，且有法律风险** |
| **薪酬决定** | [禁止] **禁止** | **重大利益，须人决策** |

## 二、物料域与仓储 WMS

### 物料主数据是整个 ERP 的地基

**这一条比任何功能都重要。**

| 问题 | 后果 |
|---|---|
| 一物多码 | 库存分散、报表不准、MRP 失效 |
| 计量单位不统一（pcs/箱/千克混用） | 数量错、发料错 |
| 分类随意 | 报表无法汇总、无法分析 |
| 主数据无 Owner | 越建越乱 |

**主数据治理的铁律**：
1. **物料编码规则必须统一** —— 谁都不能随意新增
2. **必须有主数据 Owner** —— 明确谁负责审批新增/变更
3. **必须有 Steward** —— 日常维护专人
4. **变更必须留痕** —— 谁改的、什么时候、为什么

**一物多码是所有 ERP 问题的头号根源。** 查库存不准，先查编码。

### 库存管理

| 概念 | 说明 | 关键点 |
|---|---|---|
| **批次管理** | 按生产日期/到期日管理 | 食品、药品、化工**必须** |
| **序列号** | 每件唯一标识 | 高价值、可追溯、维修类 |
| **保质期** | 有效期管理 | 过期预警、临期预警 |
| **库位管理** | 精确到货架位 | 高价值物料、小仓库必做 |
| **盘点** | 账实核对 | **不在系统里算账，必须真盘** |
| **移库** | 仓内位置转移 | 轻仓可不上 |
| **呆滞料** | 长期无动销库存 | 识别与处置机制 |

**批次的真正价值**：**从"过期风险"变成"可追溯"**。出了问题能精准召回，而不是全批报废。

### WMS（仓储管理系统）

| 能力 | 说明 | 适用规模 |
|---|---|---|
| **上架管理** | 收货后推荐库位 | 中大型仓库 |
| **拣货管理** | 波次、批次、路径优化 | 中大型仓库 |
| **复核** | 出库前二次核对 | **所有规模都该做** |
| **波次作业** | 合并订单批量拣货 | 订单量大时 |
| **库位优化** | 高频品类近出入库口 | 优化项 |
| **循环盘点** | 分区循环盘 | 中大型仓库 |

**小仓最该做的三件事**：**复核、循环盘点、批次管理** —— 这三个投入小、收益大。

**常见断点**：
- 仓库只有收货权，没有复核 → 错发漏发无法追溯
- 线上单据齐，线下实物乱 → **账实不符**
- **盘点只在系统里"算账"，没去现场真盘**

### 物料的 AI 机会

| 场景 | 可行性 | 说明 |
|---|---|---|
| 批次追溯 | | 规则明确，查询+告警 |
| 呆滞料识别 | | 规则明确 |
| 库位推荐 | | 需历史动销数据 |
| 拣货路径优化 | | 纯算法问题，效果确定 |
| 库存健康诊断 | | 数据分析 |

**前提**：**物料主数据不干净，以上全部无效。** 先治理主数据。

## 三、生产与扩展域

### MRP-MES 衔接

**ERP 负责计划，MES 负责执行。**

| 系统 | 管什么 | 特征 |
|---|---|---|
| **ERP** | 订单、计划、BOM、成本、库存 | 长周期、面向经营 |
| **MES** | 工单执行、报工、设备、工艺、质量 | 短周期、面向车间 |
| 衔接点 | **工单下达、报工回写** | **断点高发** |

**衔接断点的典型表现**：
- 排产计划下了，MES 里没工单 → 车间还在用 Excel 排产
- 车间报工了，ERP 不知道 → 库存不准、成本算不出
- **工单状态两边不一致** → 计划与执行脱节

**建议**：**接口必须双向且有状态校验。** 报工是 ERP 成本核算与库存的输入，**报工不上传 = 账不准**。

### 生产核心对象

| 对象 | 说明 | 常见问题 |
|---|---|---|
| **BOM** | 物料清单 | **多版本混乱**（最常见） |
| **工艺路线** | 加工步骤、工时、设备 | 与实际不符 |
| **工单** | 生产指令 | 状态与车间不同步 |
| **工作中心** | 产能单元 | 产能数据不准 |
| **工艺参数** | 加工要求 | 变更未受控 |

**BOM 版本管理是重点**：

| 错误 | 后果 |
|---|---|
| 多个有效版本同时存在 | 采购按旧版买料、生产按新版用料 |
| 变更无审批 | 谁都能改 BOM |
| 变更后库存未重算 | 在制品成本错 |

**建议**：**BOM 必须单一有效版本 + 变更审批 + 生效日期控制。**

### 项目管理与 WBS

| 概念 | 说明 |
|---|---|
| **WBS** | 工作分解结构，把项目拆成可估算可跟踪的层级 |
| **项目预算** | 人工、材料、外包、其他 |
| **项目成本** | 实际发生 vs 预算 |
| **里程碑** | 关键节点，用于进度控制 |

**典型断点**：**项目成本进了财务的总账，但没进项目台账** → 算不出项目是赚是亏。

**建议**：项目须有独立核算能力，或至少有清晰的项目编码贯穿所有单据。

### 设备维护 EAM

| 概念 | 说明 |
|---|---|
| **设备台账** | 设备清单、参数、寿命 |
| **预防性维护 PM** | 按周期保养 |
| **预测性维护 PdM** | 按状态（振动、温度）提前预警 |
| **故障维修** | 报修、派工、备件 |
| **备件管理** | 库存、领用 |

**PM 的真正价值**：**从"坏了修"到"按期保"** —— 减少非计划停机。

**常见断点**：**设备台账不准，保养计划排不出来** —— 往往因为设备编号混乱。

### 质量与工艺

| 概念 | 说明 |
|---|---|
| **来料检验 IQC** | 供应商来货检验 |
| **过程检验 IPQC** | 生产过程抽检 |
| **出货检验 OQC** | 成品出货前检验 |
| **不合格处理** | 退货、返工、让步接收、报废 |
| **质量追溯** | 从成品追到原料批次 |

**质量追溯的 ERP 价值**：**如果没有批次追溯，出问题只能整批召回** —— 这是真金白银的代价。

## 四、三个域的共同规律（诊断重点）

**HCM、物料、生产扩展域的断点高度集中在三处**：

| 断点 | 表现 | 根因 | 对策 |
|---|---|---|---|
| **现场不上系统** | 车间、仓库、HR 都在用 Excel | 现场觉得用系统更麻烦 | **先让现场受益**，见 `./06-组织落地与验收.md` |
| **主数据不准** | 编码乱、字段缺、台账错 | 无 Owner、无审批 | 先治理主数据 |
| **接口断裂** | MRP-MES、HR-财务、项目-总账 断 | 接口无人维护 | 明确接口 Owner |

**特别提醒：这三域最容易"系统上线了，现场照旧用 Excel"。** 因为现场是"用的人"，不是"管的人" —— **只有让现场受益，改革才落地**（详见 `./06-组织落地与验收.md` 的"先让使用者受益"）。

## 五、给教师的话

**本篇的教学价值在于"地基"这个认知。**

- **主数据是地基** —— 三域都强调这一点，让学生理解为什么"先治理主数据"是铁律
- **现场不上系统是最常见的失败** —— 可让学生回想自己实习/工作中见过的场景，共鸣强
- **"让现场受益"是本篇与其他篇的连接点** —— 与 `./06-组织落地与验收.md` 呼应
- **红线（HR 决策、税务、薪酬）必须讲** —— 学生最易越界的地方

**常见学生误区**：
- 以为买了 ERP 就自动打通 —— **接口需要人维护**
- 以为系统里有数据就等于准 —— **主数据不准，一切白搭**
- 以为现场不上系统是"态度问题" —— **是"收益问题"**

**动手建议**：让学生画自己实习单位的物料编码规则，标出一物多码的实例。见过实例的人，才真懂为什么要先治理主数据。
