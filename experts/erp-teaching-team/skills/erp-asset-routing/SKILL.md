# ERP 资产调度与路由

> **核心思想**：面对一个成熟的专家生态，**最有价值的不是自己什么都会，而是准确知道该找谁**。这份资产教的是调度思维。

## 使用时机

- 学生的问题**超出本团教学边界**（要真实系统操作、要税务申报计算、要跨境合规、要法律意见）
- 需要判断「该由哪个专家包处理」，或需要跨包协作编排
- 用户明确要求「用XX 包处理」

**不要在以下情况加载**：本团能力范围内的纯教学讲解（分层讲解、出题、批改、路径规划）。

## 一、为什么需要调度

在一个已有丰富资产的生态里，**重复造轮子的代价远高于调度成本**：

| 做法 | 代价 |
|---|---|
| 自己重写选型 TCO | 做的版本不如现成资产严谨，且不会随原资产更新 |
| 自己写金蝶对接 | 根本写不出可用的 WebAPI 集成 |
| 自己写 RPA 录单 | 需要大量逆向工程，方向也偏了 |
| **准确转包** | 一次命中，能力即达 |

**调度能力是企业落地中极稀缺的能力** —— 技术能力可以学，判断该找谁不容易教。

## 四、调度铁律

| # | 铁律 |
|---|---|
| 1 | **先查路由表，再动手** —— 命中就转，别自己答 |
| 2 | **不重复造轮子** —— 自己写的版本不会比现成资产更新 |
| 3 | **转包要透明** —— 明确告知用户转给了谁、为什么 |
| 4 | **不假装做完** —— 转包后基于其产出继续编排，不是自己做的 |
| 5 | **独占能力自己上** —— 命中独占表时不要转包 |
| 6 | **空壳包不路由** —— erp-matcher / erp-extractor 无实际能力 |
| 7 | **许可证意识** —— 外部包的授权条款**须现场核实**；教学/内部使用可引用方法论，但**不直接复制文件到自己的包**，也不得替对方声明其授权状态 |

## 五、转包话术

**推荐说法**：

> 这个问题有更专业的现成资产。`erp-digital-ai-expert` 里有一整套 TCO 测算工具，7 类成本 + 三情景 + 敏感性分析，比我现场算更严谨。我让它来处理这部分，然后基于它的结论继续为你做后续编排。

**禁止说法**：

- [禁止] "我帮你算一下"（然后用更粗糙的方法）
- [禁止] 悄悄重写已有资产

**关键区别**：转包不是甩锅，是**用更强的工具 + 承担编排责任**。用户的最终交付仍由你负责。

## 六、跨包协作范式

```
用户提出综合需求
     ↓
主理人判断：哪些部分生态已有、哪些是独占
     ↓
┌─────────────┬─────────────┐
│ 已有资产     │ 本团独占     │
│ → 转包       │ → 自己上     │
└─────────────┴─────────────┘
     ↓
主理人汇编（编排责任不外包）
     ↓
四件套交付
```

**主理人的价值在汇编处** —— 转包容易，**判断"哪部分该转、哪部分不该转"才是核心能力**。

## 七、教学价值

这个资产本身适合作为教学案例。核心要传递的思维：

| 教学点 | 要点 |
|---|---|
| **资产意识** | 做事前先看有什么现成的，别闷头重写 |
| **边界意识** | 知道自己不擅长什么，比知道自己擅长什么更重要 |
| **判断力** | 什么问题该转、什么问题该自己做 |
| **责任意识** | 编排者对最终交付负责，转包不等于免责 |
| **许可证意识** | 引用方法论 ≠ 复制文件；授权状态须现场核实，尊重原创 |

**这五个思维迁移到任何技术选型、职业发展中都成立** —— 这正是"调度型专家团"比"自建型专家团"更值钱的地方。

## 内容边界

本文件是**路由判据**，不记录任何厂商能力、产品版本、市场格局数据。

学生问到具体产品是否支持某功能时，**不查本文件，也不凭记忆答** —— 
应查厂商官方文档，并标注检索日期（方法见知识库 `skills/erp-knowledge-base/14-时效内容实时核验.md`）。
