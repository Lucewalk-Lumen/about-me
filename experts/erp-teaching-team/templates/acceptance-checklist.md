# 上线验收标准与 30/60/90 天复盘模板

> 使用说明：**项目成功 ≠ 系统上线成功。** 本模板用于量化验收，避免用"基本达成""总体良好"糊弄。

> **来源**：ERP 教学团（`erp-teaching-team`）· `templates/` · 可单独复制使用

---

## 一、核心原则

1. **上线不是终点，是起点** —— 很多企业把"系统成功切换"当项目结束，三个月后才发现大家都在用 Excel 绕路
2. **指标必须可量化** —— 说不出数字的验收标准就是没有验收标准
3. **未达标要说未达标** —— 模糊表述等于没有验收

## 二、基线数据采集（上线前必须做）

**没有基线就无法证明改善。以下数据必须在切换前采集。**

| 指标 | 基线值 | 采集方式 | 采集人 | 采集日期 |
|------|-------|----------|--------|----------|
| 订单到出库时长 | | 系统时间戳对比 | | |
| 库存准确率 | | 盘点抽查 % | | |
| 跨部门交接等待时长 | | 流程节点时间戳 | | |
| 一线单笔操作耗时 | | 实际计时（取 20 笔均值） | | |
| 月度对账耗时 | | 财务记录 | | |
| 差错次数（月） | | 历史记录 | | |
| 报表出具时长 | | 实测 | | |

**基线缺失的处理**：若无法取得历史基线，**在切换后第 1 周建立新基线**，并明确说明"因缺少历史数据，无法证明改善幅度，仅能证明新系统下的绝对水平"。

## 三、四个核心验收指标

| 指标 | 为什么重要 | 目标值 | 30天 | 60天 | 90天 |
|------|------------|-------|------|------|------|
| **订单到出库时长** | 老板最容易听懂的业务指标 | 缩短 ≥ __% | | | |
| **库存准确率** | 反映数据治理成效 | 提升至 __% | | | |
| **跨部门交接等待时长** | 反映协同改善 | 缩短 ≥ __% | | | |
| **一线操作耗时** | 反映真实减负 | 缩短 ≥ __% | | | |

**建议目标值参考**：
- 订单到出库时长：缩短 20-40%
- 库存准确率：提升至 95-98%
- 一线操作耗时：缩短 30-50%

> [!] 上述区间为**教学用参考值，不是行业统计值，也无案例出处**。此类基准属知识库 `skills/erp-knowledge-base/14-时效内容实时核验.md` 所列「需核验」类别。使用前须按企业自身基线实测确定，或另行引用可核验的行业来源并注明出处；不得把参考区间当作对客户的承诺指标。

### 验收结论（必须明确）

**只能选一个，不允许模糊表述**：

- □ **全部达标，项目成功** —— 后续建议：__（深化优化 / 推广到其他工厂 / 接入 AI 能力）
- □ **部分达标（__ 项未达标），需追加整改** —— 未达标项：__ 整改动作：__ 责任方：__ 截止：__
- □ **未达标，项目未达预期** —— 根本原因：__ 后续决策：__（整改 / 调整范围 / 考虑替换）

**明确禁止的表述**：
- [禁止] "基本达成预期"
- [禁止] "总体良好，仍有优化空间"
- [禁止] "整体在预期范围内"

## 七、责任机制验收

**消灭"全是系统错、全是你的错"的根本办法是每个流程有唯一 Owner。**

| 关键流程 | 唯一 Owner | 考核指标 | 是否挂钩 | 考核周期 |
|----------|-----------|----------|----------|----------|

**验收标准**：
- □ 每个关键流程都有**唯一** Owner（不是"共同负责"）
- □ 每个 Owner 的考核指标包含该流程的量化指标
- □ 流程变更需 Owner 同意，不能由 IT 单方面改

**若某流程没有唯一 Owner，该流程的验收结论直接判为"未达标"。**

## 八、风险兜底

**若 90 天后指标未达标，提前准备的应对方案：**

| 情形 | 根因可能 | 应对方案 | 决策人 |
|------|----------|----------|--------|
| 一线绕路用 Excel | | 补培训 / 简化流程 / 加考核 | |
| 部门间互相甩锅 | | 管理层强制 + 唯一 Owner | |
| 库存持续不准 | | 数据治理未完成 | |
| 报表出不来 | | 需求未在蓝图阶段定义 | |
| 系统本身不稳定 | | 厂商责任，要求整改 | |
