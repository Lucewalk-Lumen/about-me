# case-07：新资料批量采集入库（登记 + 护栏 + 落位）

> 场景分类：采集入库 ｜ 涉及成员：罗采（主）、林归类、苏航、库正 ｜ 对应 Workflow：W4

## 1. 场景

用户攒了一批新资料（几十份 PDF / 笔记 / 网页剪藏 / 会议纪要），想批量登记进知识库。用户要求「先出归类清单我确认后再放进库」，不允许不经确认就直接写入；同时要守住入库护栏（格式归一化、重复检测、批量上限），入完库还要更新索引。

## 2. 前置条件

- 库形态：已有目录体系（无体系时先转 W5 冷启动或 W1 整理归类）。
- 用户需准备：待入库资料的路径或来源清单；目标宿主（本地 Obsidian/LLM Wiki 直接给路径，IMA/乐享需对应连接器已授权）。
- 环境就绪：按 `$PKG_ROOT/skills/kb-governance-playbook/references/environment-setup.md` 确认工具已装、库已建。

## 3. 指令示例

> 这批新资料帮我登记入库：先出归类清单，我确认后再放进知识库；入完库把索引也更新一下。

## 4. 预期产出

- 罗采产出：入库登记表 + 候选清单（含格式归一化建议、重复检测脚本输出、护栏校验结论）。
- 林归类产出：落位建议（每条候选对应的目标目录/池）。
- 确认断点：批量入库执行前必须用户逐批确认（批量上限 ≤50 文件/批）；索引写入前同样确认。
- 苏航产出：索引更新方案（新条目挂入对应 MOC，标注新增双链）。
- 数字依据：重复检测以 `duplicate_detect.py` 输出为准，不口算替代。

## 5. 涉及成员与分工

| 成员 | 本案例中的职责 | 产出 |
|---|---|---|
| 库正 | 建团编排、确认权门禁、跨成员信息中转 | 任务单 / 待确认清单 |
| 罗采 | 登记、提取、归一化、入库护栏校验 | 入库登记表 + 候选清单 |
| 林归类 | 落位建议（目录/四池归属） | 落位映射表 |
| 苏航 | 入库后索引更新、双链建议 | 索引更新方案 |
