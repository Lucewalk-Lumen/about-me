# 四池成熟度（four-pool-maturity）

> 适用成员：罗采（idea 池入口）、林归类（四阶段文件夹）、关晋（门槛与拒绝话术）

## 1. 四个池各装什么

| 池 | status 取值 | 装什么 |
|---|---|---|
| 灵感池（idea） | idea | 碎片想法、临时记录、待验证观点、未展开的案例线索。允许不完整，先丢进来，不要求当下分类或成形 |
| 半成品池（draft） | draft | 已看得出主题，但观点、结构、材料或结论还在打磨。允许零散、允许反复改 |
| 正式池（official） | official | 定稿过、能稳定复用的资产，以及主题索引本身。进到这里就是「已确认资产」，只建议、不擅改 |
| 归档池（archive） | archive | 过时、被新版本替代、暂不适用的内容。进这里是为了留历史，不是删掉 |

## 2. 阶段只表示加工到哪一步

不要按「课程/项目/客户/工具/年份」建一层层主题子目录。阶段文件夹只回答「这份内容成熟没成熟」，主题归类交给索引。一篇内容可同时挂多个主题，靠多个索引和双向链接实现，正文不复制。

## 3. 状态自洽

文件夹位置、笔记 status 字段、元数据三者应相互印证。发现对不上（如放在正式池但 status 还是 draft），列为待确认事项，不替用户擅自改阶段。

## 4. 元数据基线（新建或进入整理的内容至少带）

| 字段 | 用途 |
|---|---|
| created | 第一次建成日期，识别新增 |
| updated | 最近实质改动日期，判断长期未迭代 |
| source | 来源（会议/课程/项目沟通/外部素材），追溯与可信度判断 |
| status | idea / draft / official / archive |
| owner | 审核人/负责人。正式资产必填，防止「不知道谁确认的」被随便复用 |
| valid_for | 适用范围（产品/地区/场景/时间窗）。写不清边界的资产容易被拿去答它管不了的问题 |

## 5. 晋级门槛三档

### 5.1 idea → draft（5 条，具备大部分即可）

1. 能说清一个主题、问题或现象。
2. 能提炼出初步观点、判断或假设。
3. 至少有一样依据——亲身经历、案例、观察或素材与来源。
4. 能判断大概服务什么场景、什么对象。
5. 有继续展开的方向，或能提出下一步要验证的问题。

观点成不成熟、文字漂不漂亮都不卡，关键是它已经从「碎片」变成「能继续加工的内容单元」。

### 5.2 draft → official（8 条，原则上同时满足）

1. 核心问题和适用场景明确。
2. 结论、方法或主张基本稳定。
3. 结构完整，读者不靠口头补充也能看懂。
4. 关键案例、依据、步骤或示例齐全。
5. 已经实际使用、验证、复盘或人工确认过。
6. 已明确要挂到哪一个或多个主题索引。
7. 没有影响复用的关键缺口，也没有没标明的待验证结论。
8. 具备正式资产的命名、版本和引用关系。

写得完只是基础，能稳定复用才算定稿。

### 5.3 official → archive

被新版本替代、过时、暂不适用。归档三件事：归档时间、归档原因、被哪个新版本替代（详见 archive-protocol.md）。

## 6. 拒绝话术模板

### idea→draft 拒绝

- 当前判断：暂不建议从 idea 迁移到 draft
- 已具备：……
- 关键缺口：……
- 需要确认：……
- 建议补完后再判断：……

追问优先围绕：这条灵感到底想说明什么？对应什么具体场景或问题？有没有亲历案例、数据、对话或素材能撑？你希望它最后长成课程、方案、方法论还是别的资产？下一步最该验证或补什么？

### draft→official 拒绝

- 当前判断：暂不建议进 official
- 已满足条件：……
- 尚未满足：……
- 关键风险：……
- 需要确认或补充：……
- 建议下一轮修改重点：……

追问优先围绕：这份内容最终给谁用？对方拿到能不能独立执行或复用？哪些结论验证过、哪些还是假设？关键步骤、案例、模板或示例齐不齐？和现有正式内容有没有冲突？该挂哪些主题索引？要不要保留版本号、来源和替代关系？

## 7. 候选清单只建议，不移动

每次评审输出晋级候选清单，字段至少含：内容标识、建议动作（进 draft / 进 official / 暂缓）、成熟度判断、已满足条件、待补缺口、建议挂载的主题、需要用户确认的变更。清单供审核，文件不自动搬。

## 8. 门槛纪律

门槛档位（标准/严格）由主理人或用户定；评审可收紧、不可放宽。拒绝必须附门槛条目与补证据话术，不允许只回「暂不适合」。
