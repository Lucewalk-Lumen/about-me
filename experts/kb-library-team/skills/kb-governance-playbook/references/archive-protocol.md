# 归档协议（archive-protocol）

> 适用成员：安档

## 1. 铁律

1. **只归档，不删除**：任何知识条目永不删除。过时、被替代、暂不适用的统一进归档池，保留原文。
2. **归档不等于丢弃**：旧内容仍可被检索和复盘，只是默认不作为当前有效结论直接引用。
3. **日志只追加**：归档日志（按 templates/archive-log-template.md）只追加新行，不改写历史行；发现历史日志有误时新起一行更正。
4. **原始素材只进不出**：归档原件不得改写、覆盖或移出。

## 2. 归档三件事（每条必写）

1. 归档时间。
2. 归档原因（被替代 / 过时数据 / 失效工具 / 不适用结论 / 与正式内容冲突）。
3. 被哪个新版本替代（无替代版本时写明「无替代，仅退休」）。

同时标注：是否仍有复盘、历史追溯或案例演变价值。

## 3. 判断重点（归档候选评审）

- 有没有明确的新版本替代它？
- 有没有过时数据、失效工具或不适用结论？
- 和当前正式内容冲不冲突？
- 是否仍有复盘、历史追溯或案例演变价值？

判断不了时：**建议降级观察，而非硬归档**。

## 4. 替代关系登记

| 字段 | 说明 |
|---|---|
| 旧版条目 | 归档目标 |
| 新版条目 | 替代者（无则填「无替代」） |
| 替代说明 | 差异要点（新版改了什么） |
| 引用方清单 | 指向旧版的互链条目（交苏航改指新版或标注失效） |

## 5. 回滚路径（每个归档动作必附）

归档建议单中写明回滚操作步骤：从归档区恢复原位 → 恢复 status 字段 → 恢复索引挂载 → 日志追加一行「回滚」记录。回滚同样是写操作，须用户确认。

## 6. 版本号与快照（库级）

- 语义化版本 `主.次.修`：结构变更递进主版本、新增内容递进次版本、修订递进修订号。
- 快照触发：主版本发布前、重大调整前、定期（建议每月一次）。
- 快照内容：目录树、条目清单（标题/来源/日期/版本）、配置、最近一期巡检报告。
- 回滚触发参考（假设估算口径，用户可调）：内容错误率 >5%；检索命中率下降 >20%。

## 7. 更正三分类（巡检发现「写错了」时的处置）

| 分类 | 含义 | 处置 |
|---|---|---|
| 权威来源 | 事实只住在这条里 | 改这条 |
| 复述 | 别处又写了一遍 | 替换为链接 |
| 历史记录 | 记录「当时相信什么」（归档/日志/带日期文件名的终态条目） | 保留，不改 |

## 8. 流程（W7 版本归档 SOP 对应）

1. 安档出归档建议单（候选 × 三件事 × 替代关系 × 引用方 × 回滚路径）。
2. 用户逐条确认。
3. 执行：条目移入归档区（或按宿主形态打 archive 标记）→ 日志只追加登记 → 引用方清理建议交苏航。
4. 齐证复核引用完整性。
