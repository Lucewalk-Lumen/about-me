# 版本更新播报流程（首条消息必做）

> 本流程对应管家「版本更新播报」职责：确保**线上版本更新、教师再次召唤时能知道更新了什么**，
> 且**同一版本读过一次后不再重复打扰**。本文件是 `agents/ai-butler.md` 版本播报指针的子流程，
> 执行前先 Read 本文件，未读不得操作。

## 触发时机
每次新会话被召唤、收到首条用户消息时执行（在常规开场白之后、打开工作台或播报待办之前）。

## 步骤
1. 读本专家包根目录下 `.codebuddy-plugin/plugin.json` 取 `version`（记为 **V**）；读包根 `UPGRADE.md` 提取与 V 对应的「## v{V}」段落要点。
2. 读状态文件 `~/.workbuddy/ai-butler/seen_upgrade.txt`（记录上次已播报版本；不存在视为从未播报）。
3. **若 V 与已记录版本不同**（或文件缺失 / 读取失败），向用户输出一段**独立区块**：
   ```
   【教师工作台 · v{V} 更新提示】
   本次主要更新：…（取自 UPGRADE.md 该版本要点，精简 2–4 条）
   ```
   随后把 V 写回 `~/.workbuddy/ai-butler/seen_upgrade.txt`（目录不存在先 `mkdir -p`；写失败不阻塞，下次仍会播报）。
4. **若 V 相同**，则**跳过**此提示，不打扰。

## 边界
- 本流程只读取包内清单与更新说明、只写一个状态文件，**不触碰工作台数据、不启动本地桥、不建任何自动化**。
- 播报是纯文本告知，不得因此打断用户原本的诉求；他若已在执行任务，先完成任务再顺带告知。

## 降级
若 `UPGRADE.md` 无法读取，则改为提示「本版本已更新，更新要点见包内 UPGRADE.md」，**不得静默省略**。

## 状态文件约定
- 路径：`~/.workbuddy/ai-butler/seen_upgrade.txt`（仅存一行版本号文本，如 `1.1.4`）。
- 写权限受限时不阻塞：写失败则下次会话仍会播报，属安全兜底。
